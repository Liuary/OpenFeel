# 阶段"执行前必须有写实计划"：门禁落点、转移表与 plan.md 机制

> 研究日期：2026-11-24 ｜ 阶段：`v1.6.0-stage-132` ｜ 对应需求：REQ-056（并覆盖 REQ-058 的模式问题）
> 范围：`src/core/flow-manager.ts`、`src/core/plan/**`、`src/commands/flow.ts`、`src/commands/project.ts`（只读）。
> 路径均相对仓库根。本文回答三件事：门该挂在哪、为什么不能靠改转移表、`plan.md` 今天由谁维护。

## 背景与问题

1. **症状**：阶段可以在一份 `plan.md` 都没有的情况下推进到 `exec_running`。审查与归档时无法回答"当初打算怎么做、改法是什么、验收判据是哪几条"。
2. **第二次症状**：计划写在会话里、仓库里没有，或仓库里那份是几行占位。它不影响任何门，于是"计划"这一层事实上是纯人工约定。
3. **触发改造的判断**：`plan → exec → review` 这条链必须成为**相位条件**（门），而不是转移表上的可选边。
4. **为什么不能只改表**：内置 full 表本就有 `plan_pending → plan_passed` 的直边；fast 表允许 `plan_review → plan_passed`；`--review-tier skip` 还会把 `plan_review` 从目标侧裁掉并收缩边。加边永远能被合法绕过。
5. **第三个坑**：复位路径`resetStagePhase` 是独立的相位写入口，不复用 done 门；新门若不在此复检，复位就是绕过口。

## 结论

1. 唯一阶段相位写入口是 `FlowManager.advanceStagePhase`（`flow advance` 与 `flow wizard` 都委托它）。门**必须**挂在这里；命令层镜像只负责 `--json` 的错误形状，不承担拦截。
2. 现成范式是 done 硬门：位置在 blocking REV 门之后、任何写盘之前 ⇒ 拒绝路径零写盘零审计。计划门照抄这个位置与形状。
3. CLI 从不创建、不校验、不读写 `plan.md`：`src/` 里唯一的命令层命中只是**计数**。所以要新增对称的路径求解函数（照抄 `status.md` 的三级回退），并新写"存在**且**写实"判据。
4. 判据要复用单一来源（占位标记常量 + 整行锚定正则），禁止在门内写第二份字数/占位规则。
5. `general` 的"无流水线"是显式裁定（空表语义），不要为它造阶段表——把强制链下移到**需求生命周期**。`fast` 表已含计划审查与代码审查，补上门即达标，同样不改表。
6. 复位路径必须与 exec 门同口径：`--force` → 留痕放行（`gate_overrides` + 缺项快照）；不加 → 拒绝且零写盘。
7. 存量风险要提前认：`.openfeel/plan/v1/` 下有 9 个 `stage-*` 目录没有 `plan.md`，门一上线首先卡住这些阶段。

## 证据

- `src/core/flow-manager.ts:1782` — `advanceStagePhase(stageName, phase, triggeredBy, opts)`：唯一相位写入口签名。
- `src/core/flow-manager.ts:1818-1830` — blocking REV 门：`targetPhase === 'done'` 时拒绝，注释明写"`--force` 仅降级警告"、无逃生口。
- `src/core/flow-manager.ts:1839-1844` — done 硬门：位置在 blocking REV 之后、`:1847` 写相位之前；拒绝路径零写盘。**这就是计划门的模板位置**。
- `src/core/flow-manager.ts:5231` — 占位标记常量单一来源；`:5239` 为其**整行锚定**正则（`plan.ts` / `flow.ts` 的 `fill` 字段共用同一判定）。
- `src/core/plan/path.ts:434-465` — `findStageStatusPath` 三级回退（精确路径 → `**/stage-NN/` 递归 → 历史 `stages/` 兜底）；**缺对称的 `findStagePlanPath`**，这是最自然的落点。
- `src/core/plan/stage.ts:97` — `ensureStageSkeleton` 的注释与实现只保证 `overview.md` / `status.md` 骨架（幂等"已存在不覆盖"）；CLI **不创建 plan.md**。
- `src/commands/project.ts:112` — `fg.sync(['.openfeel/plan/*/plan.md', '.openfeel/plan/*/*/plan.md']).length`：全仓唯一提到 `plan.md` 的命令层代码，**只做计数**。
- 实测目录（2026-11-24 05:0x）：`.openfeel/plan/v1/` 下 117 个 `stage-*` 目录，108 个有 `plan.md`、**9 个没有**（stage-11/12/13/60/119/120/121/122/124）。
- `src/commands/lint.ts:141-144` — 只有 A 类 issue 驱动退出码；计划的"填充度"若接 lint 只能做 advisory，否则存量阶段立刻全红。
- `src/core/plan/stage.ts:106-196` — `overview.md` 骨架只有目标/依赖/操作方案三节（**无验收节**），阶段计划的"写实"不能按验收判据体例硬套。

## 改造动作

- **T5**（阶段计划门）：新增 `describeStagePlanGate` / `formatStagePlanGate`（与 done 门同形），插入 `advanceStagePhase` 的 done 门之后、写盘之前，条件 `targetPhase === 'exec_running' && fromPhase !== 'exec_running'`；`--force` → `detail.gate_overrides=['plan']` + `detail.gate_missing` 快照；`resetStagePhase` 对 `to === 'exec_running'` 复检同一谓词并同口径留痕。判据 **A4 / A4b / A6**。
- **T5**（路径单点）：`src/core/plan/path.ts` 新增 `findStagePlanPath`（照抄三级回退）与 `findRequirementPlanPath`（全局固定 `.openfeel/plan/reqs/REQ-NNN.plan.md`，不随阶段/版本漂移）。
- **T6**（偏差回写）：需求级 `plan.sha256`（前 12 位）盖章 + `planDeviationBlocker`，挂在 `to === 'done'` 且 done 门通过**之后**（顺序：正文门 → 计划门 → review/verify → 偏差门）。判据 **A5**。
- **T7**（模式收紧，**不改阶段表**）：把 `plan → exec → review` 落在需求生命周期（`in_progress` / `done` 前置），适用面写死三种组合；`flow phases --mode general` 空表语义不变。判据 **A8 / A8b**。
- **T13**（文档对账）：`docs/commands.md` 补新门与"阶段表为何不变"的口径，避免下一轮又有人去改 `FAST_TRANSITIONS`。

## 未验证项

- **被拦的活跃阶段确切名单**：9 个空 `plan.md` 目录里哪些仍是活跃阶段，需要读 `status.md` 才能判断，本次按边界禁读。
- **"写实"门槛对现行体例的适配**：阶段计划拟用"整份 ≥2×40 字符且非纯占位行"，未在真实 `plan.md`（如 stage-131 的 46 行中文序号体例）上跑过判据。
- **版本级旧计划是否会被误判**：`.openfeel/plan/v1/v1.2.4/plan.md` 这类版本级多阶段计划，若被当作某阶段计划，门会"假放行"。该口径未定义。
- **`findStagePlanPath` 的递归成本**：照抄三级回退意味着每个在办需求都做一次 glob，门内是否可接受未实测。
- **`--force` 在 wizard 路径**：规划为不传 `allowGateOverride`（交互可重试），未验证 wizard 的交互重试体验。

## 复现/验证方法

- 门位置：读 `src/core/flow-manager.ts:1782-1850`，确认 done 门在写相位之前；`git grep -n "advanceStagePhase(" -- src/`（调用方应只有命令层两处）。
- CLI 不碰 plan.md：`git grep -n "plan\.md" -- src/`（应只命中 `src/commands/project.ts:112` 与 i18n/templates）。
- 存量面（本次命令）：PowerShell 下 `Get-ChildItem .openfeel/plan/v1 -Directory -Filter 'stage-*'` 后对每个目录 `Test-Path <dir>/plan.md` → 117 / 108 / 9。
- 转移表不可替代门：`git grep -n "plan_pending" -- src/core/flow-manager.ts`（full 表的 `plan_pending` 直边仍在）。
- T5 落地后：`node bin/openfeel.js flow advance --stage v1.6.0-stage-NNN --to exec_running` → exit 1、`error.code='STAGE_PLAN_GATE'`、缺项在 `detail`；加 `--force` → exit 0 且 `flow.json.log` 末条含 `gate_overrides`。
- T5 复位同口径：`node bin/openfeel.js flow stage reset <stage> --to exec_running`（无 `--force` 应拒绝且零写盘）。
