# REQ-015：1.5.6 批次：preflight 全覆盖（其余写命令统一 helper + warn/off 集成测试）

> 本文件为需求正文（人读副本，由 openfeel req 机械铺骨架）。**机读权威恒为 `.openfeel/flow.json` 的 `requirements` 条目**；两者不一致时以 flow.json 为准。下方状态为创建时快照，不追写实时状态。

## 状态

draft（创建时快照；以 flow.json 为准）

## 摘要

v1.5.5 只给 4 个核心写命令接了 preflight（`flow advance` / `plan stage add` / `req add` / `req claim`）。独立审查指出其余写 `flow.json` 的命令仍可绕过 strict：`flow review add` / `flow review resolve` / `flow review update` / `flow review remove`、`stage set` / `stage task`、`flow stage set` / `flow stage reset` / `flow stage remove`、`plan scheme create` / `plan scheme publish`、`flow attempt`、`flow archive`、`config set`（`--sync-stages`）等。本需求把这些入口收敛到同一 helper，并补齐 warn/off 与非法参数的集成测试。

## 目标与验收

**目标**
1. 在 `src/core/preflight.ts` 提供单一 `enforcePreflightOrFail()`（或等价 helper），统一「strict 拒绝 / warn 仅 TTY / off 放行」与错误信封形态，避免每个命令各写一份。
2. 其余写命令接入该 helper（至少）：
   - `flow review add` / `flow review resolve` / `flow review update` / `flow review remove`
   - `stage set` / `stage task` / `flow stage set`（依赖写入用 `--deps`）/ `flow stage reset`（`--to <phase>`）/ `flow stage remove`
   - `plan scheme create` / `plan scheme publish` / `flow attempt`
   - `flow archive`（版本归档）
3. `OPENFEEL_PREFLIGHT=strict` 下，上述命令在缺失/过期 preflight 时拒绝，且**零写盘**；`warn` 非 TTY 静默放行；`off` 放行。
4. 补测试：
   - 每个新接入命令至少一个 strict 拒绝路径（可用命令级测试或 helper 单测 + 抽检）；
   - `warn` 非 TTY stderr 零输出；`off` 正常执行；
   - 非法参数先报参数错误，再报 preflight（顺序断言，至少 `req claim` / `stage set`）。

**验收**
- `OPENFEEL_PREFLIGHT=strict` + 删除 `.preflight.json`：上述全部写命令 exit 1，错误信息含「请先运行 openflow flow next」且 flow.json 字节不变。
- 先 `flow next` 再执行：全部通过。
- `warn` 非 TTY：全部通过且 stderr 无 preflight 文案。
- 全量测试 / tsc / lint / dsh 通过；不新增 JSON 契约变更（如复用既有错误码）。
