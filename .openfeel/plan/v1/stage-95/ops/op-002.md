# op-002：错误层与 runCli 统一入口（退出码 0/1/2/3 + legacy errorKind）

- **阶段**：v1.2.2-stage-95
- **前置**：op-001 **hard**（契约助手 `json-output.ts`、映射表与冻结表）。
- **负责 Agent**：openfeel-executor
- **最多重试**：3
- **对应计划**：T2（§三 T2 全段，含 R-cp-1 退出码裁定与 R-cp-2 legacy `errorKind`）+ T5 legacy 段 + T6 错误文案；验收 §五.2；风险 R-95-2 / R-95-8 / R-95-9；REV-95-001 / 002。
- **方案期裁定（本 op 相关，全量见 `ops/deps.yaml`）**：
  - **D-95-06（关键裁定：`flow advance` 的 JSON 模式激活）**。P0-3 验收要求「JSON 模式下 `flow advance` 非法相位/无路径/blocking REV 输出 envelope」，但实测 `flow advance` **没有** `--json` 选项；若在根命令新增全局 `--json`，Commander 同名选项会把子命令的 `--json` 吞到根（实测：根与子命令同名 flag 时子命令 `options.json === undefined`），会破坏既有 18 出口。**裁定**：仅在 `flow advance` 上新增本地 `.option('--json', ...)`，作为**错误封装开关**（成功输出保持人类文本，不新增成功 JSON 出口）；命令层不得读 `options.json`，一律读 `isJsonMode()`（预扫描单点）。注册 `--json` 选项计数由 18 → 19，但**成功 JSON 出口仍为 18**（契约文档 §7 已登记；op-001 D-95-05）。
  - **D-95-07（`failCli` 控制流）**：`failRefusal` / `failCli` 在错误路径上**先输出、置 `process.exitCode = exitCode`，再 `process.exit(exitCode)`**（后者保证即时终止；前者保证测试 mock exit 时既有 `process.exitCode` 断言仍成立）（与既有 `process.exit(1)` 语义一致；测试中 `process.exit` 被 mock 后须靠调用方 `return` 防穿透）；`failInternal` 默认 exit 3。`runCli` 顶层 catch **不**调用 exit，而是置 `process.exitCode` 后返回，保证 `logCliDone` 记录真实退出码。
  - **D-95-08（Commander 用法错误机制）**：在 `src/cli/index.ts` 模块加载期安装一次 `program.exitOverride(cb)` 与模式感知 `configureOutput({writeErr})`：`cb` 对 `exitCode===0`（help/version）放行（Commander 原生 `process.exit(0)`）；JSON 模式下 `throw` 该 `CommanderError`（由 `runCli` catch 转 `INVALID_ARGUMENT` envelope + exit 1）；非 JSON 模式调用 `process.exit(err.exitCode)`（行为与现状逐字等价）。`writeErr` 仅在 `isJsonMode()` 为真时静默（防止 Commander 人类错误文本混入 stdout/stderr）。
  - **D-95-09（legacy `errorKind`）**：`flow archive*` / `req *` 的 `{schemaVersion,error:'...'}` 载荷**只追加末尾顶层 `errorKind`**；`error` 恒为 string、既有键序零改动；`archive-write-failed` → `errorKind:'internal'` 且退出码 1→3（分类补全，登记为有意变更），其余 legacy → `refusal`/1。
  - **D-95-10（迁移边界）**：只迁移计划 T2 点名的失败路径；`init`/`migrate`/`update`/`model`/`flow review *`/`flow stage add` 等人类专用失败路径保持现状；不改成功输出、不改人类文案、不改 0/1/2 语义（内部错误新增 3）。
  - **D-95-11（统一 internal 归类）**：`flow health --fix` 写盘失败与 `flow advance` 多步循环中的意外异常归 `INTERNAL_ERROR`/`internal`/exit 3（原 exit 1，登记为分类补全）；其余可修正的输入/状态问题一律 refusal/1。

## 目标

新增单一权威错误码表（12 行，内嵌 `kind` 与 `exitCode`）与命令层错误出口（`failRefusal` / `failInternal` / 并发 envelope），在 `runCli` 建立 JSON 模式单点与统一 catch；把计划点名的文本型失败迁移为稳定 `code` + `kind`；为全部 legacy 结构化失败载荷末尾追加 `errorKind`。既有 0/1/2 语义零改动，3 为新增内部错误码。

### 2. `src/commands/shared/errors.ts`（错误出口）

- [ ] 新增类型与函数：
  ```ts
  export interface ErrorEnvelope {
    schemaVersion: 1;
    error: { code: CliErrorCode; kind: CliErrorKind; message: string; detail: unknown };
  }
  export interface FailCliInput {
    code: CliErrorCode;
    message: string;                 // 本地化主文案（JSON envelope.message）
    detail?: unknown;                // 可定位字段；缺省 null
    stderrLines?: string[];          // 非 JSON 模式逐行 stderr（缺省 [message]）；用于逐字保持既有文案
  }
  export function emitErrorEnvelope(input: FailCliInput): void; // 仅 stdout 输出 envelope（不退出）
  export function failCli(input: FailCliInput): never;          // emit + process.exit(spec.exitCode)
  export function failRefusal(input: FailCliInput): never;      // 断言 kind==='refusal' 后委托 failCli
  export function failInternal(err: unknown, options?: {
    message?: string; stderrLines?: string[]; detail?: unknown;
  }): never;                                                     // INTERNAL_ERROR / exit 3
  ```
- [ ] `emitErrorEnvelope`：`emitJson({ schemaVersion: 1, error: { code, kind, message, detail: detail ?? null } })`；**stdout 单文档**。
- [ ] `failCli`：`isJsonMode()` → `emitErrorEnvelope`；否则 `for (const line of stderrLines ?? [message]) console.error(line)`；随后 `process.exitCode = spec.exitCode; process.exit(spec.exitCode);`（先置码后退出，兼容既有 `process.exitCode` 断言）。
- [ ] `failInternal`：同上先置 `exitCode=3` 再 `process.exit(3)`；`message` 缺省 `t('common.errorTmpl', getCliLang(process.cwd()), { msg })`；`detail` 缺省 `{ name, message }`（`err` 为 Error 时附 `stack`）；走 `failCli({ code:'INTERNAL_ERROR', ... })`。

### 3. `src/cli/index.ts`（JSON 模式单点 + 统一 catch + Commander 机制）

- [ ] 模块加载期（`program` 创建后）安装一次：
  ```ts
  program.exitOverride((err) => {
    if (err.code === 'commander.executeSubCommandAsync') return;
    if (err.exitCode === 0) return;            // --help / --version：Commander 原生 exit 0

  });
  ```
- [ ] `runCli()` 开头：`const argv = process.argv.slice(2); setJsonMode(resolveJsonMode(argv));`（op-003 再在此后插入 `--version --json` 与 `--project` 预扫描）。
- [ ] `try { program.parse(); } catch (err) { handleCliError(err); }`；`logCliDone` 读取 `process.exitCode`。
- [ ] 重写 `handleCliError(err): void`（原 `never`）：
  1. `runtimeLog('error', ...)`（逐字保留既有消息前缀）。
  2. `isFlowConcurrentError(err)` → `handleConcurrentConflict(err, getCliLang(process.cwd()))`（exit 2）。
