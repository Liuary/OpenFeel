# op-002：FlowManager 适配 — 全局 phase 到阶段级 phase 的核心逻辑重写
- **阶段**：v4.1-stage-03
- **前置**：op-001（PipelineSchema 重构，类型定义先行）
- **负责 Agent**：Executor
- **最多重试**：3

## 目标

将 `FlowManager` 中所有使用 `pipeline.phase`（旧 `PipelinePhase`）的地方适配为新架构：全局用 `MetaPhase`（`active/paused/done`），阶段用 `PipelinePhase`。新增 `advanceStagePhase(stageName, phase)` 方法替代 `advancePhase`。

## KB 参考

- 参见 kb/patterns.md #Phase Zod enum 硬化、#ValidationResult errors/warnings 分离 — 新 phase 校验沿用已有模式
- 参见 kb/patterns.md #CLI 原子管理模式 — FlowManager 内部变更不影响 CLI 命令层调用方式
- 参见 kb/troubleshooting.md #流水线文件引用断裂连锁修复 — 大量引用点变更时注意全局一致性

## 实施步骤

- [ ] 1. `read` 本方案文件完整内容（必做）
- [ ] 2. **修改导入** — 从 `pipeline-schema.js` 新增导入 `MetaPhase`、`META_PHASES`、`MetaPhaseSchema`
- [ ] 3. **修改 `defaultFlowData()`** — 将 `pipeline.phase` 默认值从 `'plan_pending'`（PipelinePhase）改为 `'active'`（MetaPhase）
- [ ] 4. **新增 `advanceStagePhase(stageName: string, phase: PipelinePhase)` 方法**（约 80 行，签名为 `void`）：
  - 校验 `stageName` 在 `this.data.stages` 中存在
  - 校验 `phase` 通过 `PipelinePhaseSchema.safeParse` 为合法 PipelinePhase（非法时走 `fuzzyCorrectPhase` 兜底）
  - 更新 `this.data.stages[stageName].phase = targetPhase`
  - 同步更新 `this.data.pipeline.current.stage` / `.op`（从该 stage 的 ops 中找到当前 pending 的 op）
  - 同步更新 `this.data.pipeline.phase` 为 `'active'`
  - 追加日志（`appendLog`）和公共日志（`publicLogger.logPhaseChange`）
  - 同步更新 stage.status（调用已有 `mapPhaseToStageStatus` — 若存在）
  - 阶段完成时自动结束计时（相位为 `done` 时调用 `endStage`）
- [ ] 5. **标记旧 `advancePhase` 为 `@deprecated`** — 保留方法体但内部委托给 `advanceStagePhase`（根据 `opId` 解析 stageId），追加 `console.warn` 提示使用新 API
- [ ] 6. **适配 `validate()` 方法**（约 20 行变更）：
  - `pipeline.phase` 校验从 `PipelinePhaseSchema` 改为 `MetaPhaseSchema`
  - 新增遍历 `stages` 中每个 stage 的 `phase` 字段进行 `PipelinePhaseSchema` 校验
  - 自动修正（`fuzzyCorrectPhase`）应用于 stage phase 而非 pipeline phase
- [ ] 7. **适配 `recoverContext()` 方法**（约 15 行变更）：
  - `phase` 字段改为从 `pipeline.current.stage` 对应的 stage phase 读取
  - 若 `current.stage` 存在，返回其 stage.phase；否则返回 `null`
- [ ] 8. **适配 `summary()` / `getSummary()` / `verboseSummary()`**（约 30 行变更）：
  - `phase` 展示改为 `pipeline.phase`（MetaPhase：`active/paused/done`）
  - 新增行展示当前活跃阶段及其 phase（取 `current.stage` 对应 stage.phase）
  - `getSummary()` 接口不变但值含义变化
- [ ] 9. **适配 `canAdvance()` 方法**（约 10 行变更）：
  - 将 `this.data.pipeline.phase` 替换为从 `opId` 解析出的 stage phase
  - 根据 stage phase 在 `pipelineConfig.transitions` 中查找合法目标
- [ ] 10. **适配 `hasTransition()` / `getAvailablePhases()`**（约 10 行变更）：
  - 接受可选的 `stageName` 参数，使用 stage 的 phase 进行查找
  - 无 stageName 时回退到 `current.stage` 对应 phase
- [ ] 11. **适配 `addAutoFixReview()`**（约 5 行变更）：
  - 前置条件校验从 `pipeline.phase !== 'review_failed'` 改为检查对应 stage 的 phase
- [ ] 12. **适配 `healthCheck()` 的 `checkFlowJson()`**（约 15 行变更）：
  - 校验 `pipeline.phase` 用 `MetaPhaseSchema`
  - 新增校验各 stage phase 的合法性
- [ ] 13. **适配 `repair()` 方法**（约 20 行变更）：
  - `pipeline.phase` 修复用 `MetaPhaseSchema`
  - 新增各 stage phase 的修复逻辑（非法值 → 默认 `plan_pending`）
- [ ] 14. **适配 `checkCrossFileConsistency()`** — 若引用了 pipeline.phase，改为引用 stage phase
- [ ] 15. **适配 `mapPhaseToAgent()`** — 现在输入参数应为 stage phase（来自 `current.stage`）
