# op-003：dev_last.md 模板扩展 + Feel 启动逻辑
- **阶段**：v5.0
- **前置**：op-001（依赖 Profile 类型定义）
- **负责 Agent**：Executor
- **最多重试**：3

## 目标

扩展 `dev_last.md` 模板（增加"用户偏好""决策历史""上下文快照"三个节），并更新 Feel prompt 使其启动时自动加载全局 profile + 项目记忆、合并偏好，做决策时自动追加到决策历史。

## 背景

当前 dev_last.md 仅有"上次操作状态""待续事项""关键决策""经验暂存"四个节。v5.0 需扩展为：
1. **用户偏好**：Feel 启动时从 `~/.config/openfeel/profile.yaml` 读取并合并的偏好快照
2. **决策历史**：跨会话累积的技术/架构决策记录（追加而非覆盖）
3. **上下文快照**：精简的恢复上下文信息，帮助 Feel 在新会话中快速理解当前状态

参见 `.openfeel/plan/v5/v5.0/plan.md`、kb/patterns.md #新增 Agent 全链路更新清单模式。

## 实施步骤

### 步骤 1：扩展 dev_last.md 模板

- [ ] 1.1 在 `AGENTS.md` 中找到当前 dev_last.md 模板（位于「私域 > 个人操作状态」章节），新增以下三个节到模板中：

  **用户偏好**（新增节，紧跟「上次操作状态」之后）：
  ```markdown
  ## 用户偏好
  - 语言：{lang}
  - 自动推进：{auto_advance}
  - 审查模式：{review_mode}
  - 沟通风格：{communication}
  - 确认阈值：{confirm_threshold}
  ```

  **上下文快照**（新增节，位于「待续事项」之前）：
  ```markdown
  ## 上下文快照
  - 当前流水线阶段：{phase}
  - 活跃阶段：{active_stages}
  - 上次操作摘要：{一句话}
  ```

  **决策历史**（新增节，位于「关键决策」之后）：
  ```markdown
  ## 决策历史
  （本会话新增的决策以 `- [x] {date}：{决策描述}` 格式追加于此）
  ```

- [ ] 1.2 调整现有节顺序：上次操作状态 → 用户偏好 → 上下文快照 → 待续事项 → 关键决策 → 决策历史 → 经验暂存

- [ ] 1.3 更新模板说明文字：Feel 启动时从 `readProfile()` 读取全局偏好填充「用户偏好」；会话中做技术/架构决策时自动追加到「决策历史」；每次写入 dev_last.md 时更新「上下文快照」

### 步骤 2：更新 Feel prompt（.opencode/agents/feel.md）

- [ ] 2.1 在 feel.md 的「会话启动自检」（当前不存在——但实际上 Feel 在会话启动时有自检逻辑）区域，或新建「记忆体系」节，增加以下启动流程：

  ```markdown
  ## 记忆加载

  Feel 启动时必须按以下顺序加载记忆体系：

  1. **全局画像**：调用 `readProfile()`（src/core/config.ts），读取 `~/.config/openfeel/profile.yaml`。
     文件不存在时使用默认值（zh-CN / disabled / full / concise / medium）。
  2. **项目记忆**：读取 `.openfeel/users/{username}/dev_last.md`，提取「上次操作状态」「关键决策」「待续事项」。
     文件不存在时跳过（首次会话）。
  3. **合并偏好**：
     - 语言偏好优先使用全局画像中的 `user.lang`
     - `auto_advance` 优先使用全局画像中的 `preferences.auto_advance`
     - 沟通风格使用全局画像中的 `preferences.communication`（影响 Feel 的输出详略程度）
     - 确认阈值使用全局画像中的 `preferences.confirm_threshold`
  4. **更新 dev_last.md**：将合并后的偏好写入「用户偏好」节。
  ```

- [ ] 2.2 在 feel.md 的「注意事项」或合适位置增加决策追加规则：

  ```markdown
  ## 决策追加

  会话中做出技术/架构决策（包括：选择技术方案、拒绝备选方案、调整设计方向、接受 trade-off）时，Feel 必须在最终写入 dev_last.md 前，以 `- [x] {date}：{决策描述}` 格式将新决策追加到「决策历史」节（不覆盖已有条目）。

  决策判断标准（满足任一即记录）：
  - 涉及新依赖引入或版本抉择
  - 涉及架构模式选择（如选 YAML 而非 JSON）
  - 涉及用户偏好变更（如修改 auto_advance 设置）
  - 涉及流程调整决策（如跳过某阶段的原因）

  非决策不记录：常规代码推进、Bug 修复选择、已确定方案中的细节填充。
  ```

- [ ] 2.3 新增 Feel 结束时的写入规则——在现有「信息落档」节附近补充：

  ```markdown
  ### 会话结束写入

  Feel 每次结束前必须更新 `.openfeel/users/{username}/dev_last.md`：
  1. 填充「用户偏好」节（从全局画像读取当前值）
  2. 追加本会话新决策到「决策历史」节（`- [x] {date}：{描述}`）
  3. 更新「上下文快照」节（当前流水线阶段、活跃阶段、上次操作摘要）
  4. 更新「上次操作状态」和「待续事项」节（保持现有逻辑）
  ```

## 困难点

| 困难点 | 方案 | 优劣分析 |
|--------|------|----------|
| dev_last.md 模板当前定义在 `AGENTS.md` 中，修改可能影响其他 Agent 行为 | **方案 A**：仅在 AGENTS.md 中修改模板 | 优：改动最小，模板与其他行为约束在同一文件内一致维护；劣：AGENTS.md 内容较长 |
| | **方案 B**：将模板抽取到 `src/core/templates-data/dev-last/` | 优：模板独立管理，支持多语言；劣：引入新的模板类型，需修改 build.js + template-loader，**过度设计**（参见 AGENTS.md 第 2 条） |
| | **选 A**。dev_last.md 是运行时状态文件，不是部署模板，无需纳入多语言模板管线。修改 AGENTS.md 是最小改动方案。 |
| Feel 启动时调用 `readProfile()` | Feel 可通过 `task(Executor)` 委托读取，或通过 `bash` 执行 CLI 获取 | 推荐：Feel 在 prompt 中声明"启动时让 Executor 调用 readProfile() 并返回结果"。Feel 本身不应直接 import TypeScript 模块，保持 Agent 与代码解耦 |
