## 一、REV-005 原文核对（逐字）

> **问题描述（隔离 fixture 实测）**
> B5-2 新增的多步推进路径解析**未归一化 stage 名**：`flow.ts:686` 用 `data?.stages[options.stage]?.phase` 以**短名**直接索引 `stages`（flow.json 键为全名 `v1.0.0-stage-NN`）→ `undefined` → currentPhase 回退 `common.unknown`（「未知」）+ `getAvailablePhases` 空 → **拒绝推进**。
> - **复现**：`flow advance --stage stage-01 --to done --dry-run` → 「当前阶段 phase: 未知」「当前可达目标：（空）」exit 1（**功能失效**）；
> - **全名可用**：`--stage v1.0.0-stage-01 --to done --dry-run` → 正常打印完整路径（plan_pending → … → done，**8 跳**）exit 0；
> - **影响**：`--stage stage-01` 是 help 文档推荐格式（`如 stage-03`）→ 主用法完全不可用；同样疑点波及 `:687 getAvailablePhases(options.stage)` 与 `:635 autoRepairInconsistency(options.stage)`。
> **修正要求**：op-004 实现处（`flow.ts :683/:686/:687` 及 `findPhasePath` 调用链）以 `normalizeStageId(options.stage) ?? options.stage` 归一化后再索引/传参（与 `plan.ts`/`flow.ts` 其它 stage 解析点同范式）；补回归断言「短名与全名 `dry-run` 输出等价」。

**转述核对结论**：摘要与原文**一致**，无出入。原文额外点名**两处复核项**（`:687 getAvailablePhases`、`:635 autoRepairInconsistency`）——本官已独立复核（§二），**确认均存在同类缺陷**。
