# op-001：Feel 角色定义 —— 日志纪律解耦 + 轻量决策边界 + 决策归属区分
- **阶段**：v1.0.0-stage-33
- **前置**：无（批次 1 可并行）
- **负责 Agent**：Executor
- **最多重试**：3

## 目标

修复反馈问题 1（日志纪律错误豁免调研类委托）与问题 3 的 Feel 侧边界，并在「决策追加」节联动 REV-006（长期决策 → decisions.md ADR）。涉及 feel.md 双层模板源（agents + opencode/agents）各双语 + 部署实例，共 5 文件。

## ⚠️ 前置（关键实测发现，务必先读）

计划/REV-001 假设 `templates-data/agents/{lang}/feel.md` 与 `templates-data/opencode/agents/{lang}/feel.md` **逐字符一致**。**实测不符**：

- `agents/{zh-CN,en}/feel.md`（update 路径，AGENT_TEMPLATES）含「冲突检测 / Conflict Detection」节（zh 312-330 行 / en 311-329 行，21 行），是 stage-32 新增内容；
- `opencode/agents/{zh-CN,en}/feel.md`（init 路径，OPENCODE_AGENT_TEMPLATES）**缺**该节（比 agents 层少 21 行）；
- `.opencode/agents/feel.md`（部署实例）与 `agents/zh-CN/feel.md` **一致**（含冲突检测节）。

**结论**：**禁止整文件复制**（会抹掉或错位冲突检测节）。必须对 3 处改动**按节定点编辑**。本 op 的 3 处改动所在节（日志记录纪律 / 小改阈值 / 决策追加）在两层的「日志记录纪律」「小改阈值」行号相同；「决策追加」节因 opencode 层缺冲突检测而**整体上移 21 行**，故统一用**锚点文本**定位，不用死行号。

本 op 不修复该发散（属 stage-32 遗留，超出本 stage 范围），仅在方案中如实标注。此发散不影响 `npm run build`（build 对两层独立校验，无跨层比对）。

## 实施步骤

> 三处改动内容在 zh/en 与两层模板源间完全一致，逐个文件应用相同编辑。以下「锚点」为定位依据，「旧文/新文」为精确替换文本。

### 改动 1：日志纪律解耦（问题 1）

锚点：节 `### 必须记录的事件`（zh）/ `### Events That Must Be Logged`（en）下的第三条。

zh-CN（4 个 zh 文件：agents/zh-CN/feel.md、opencode/agents/zh-CN/feel.md，以及部署实例 .opencode/agents/feel.md 共 3 处；en 同理）：

- 旧：`- 委托 Executor / 事务官 执行的操作（记录：委托目标、op 编号、产出摘要）`
- 新：`- 委托任意下游 Agent（含 general / explore / utility 等调研类 Agent）执行的操作（记录：委托目标、op 编号、产出摘要）。不受任务类型豁免——调研类委托同样须落日志`

en：

- 旧：`- Delegating operations to Executor / Utility Agent (record: delegation target, op number, output summary)`
- 新：`- Delegating operations to any downstream Agent (including research-type agents such as general / explore / utility) (record: delegation target, op number, output summary). No task-type exemption — research-type delegations must also be logged`

### 改动 2：轻量决策边界（问题 3，Feel 侧）

锚点：节 `## 小改 vs 大规模规划的阈值`（zh）/ `## Threshold for Small Changes vs. Large-Scale Planning`（en）末尾提示行之后（zh 在 `> 满足行数或文件数任一条件即升级到对应级别。` 之后；en 在 `> Meeting either the line count or file count threshold upgrades to the corresponding level.` 之后），**新增一个 `###` 小节**：

zh-CN：

```markdown
### 轻量决策边界

**轻量决策**指对话式选型：Feel 与用户通过 `question` 工具澄清并敲定技术方向或设计取舍，产出的是「结论」而非「正式计划文档」，不产出 plan.md。此类决策由 Feel 直接处理，无需委托 Planner。

仅当需要**产出正式计划文档**（plan.md，含阶段划分、任务表、约束表）或达到上方规模阈值时，才委托 Planner。
```

en：

```markdown
### Lightweight Decision Boundary

A **lightweight decision** is a conversational selection: Feel and the user clarify and settle a technical direction or design trade-off through the `question` tool, producing a "conclusion" rather than a "formal plan document" — no plan.md is produced. Such decisions are handled by Feel directly, without delegating to Planner.

Only when a **formal plan document** (plan.md, including stage division, task table, constraint table) is needed, or the scale thresholds above are reached, should Feel delegate to Planner.
```

### 改动 3：决策归属区分（REV-006 联动）

锚点：节 `## 决策追加`（zh）/ `## Decision Appending`（en）首段末尾之后（zh 在 `……不覆盖已有条目）。` 之后；en 在 `……do not overwrite existing entries).` 之后），**新增一段**：

zh-CN：

```markdown
**决策归属区分**：长期决策（技术选型、架构方向、跨会话有效的设计取舍）除追加到 dev_last.md「决策历史」节外，还须以 ADR 格式同步写入 `.openfeel/dev/decisions.md`；会话临时决策（流程调整、单次取舍）仅记录在 dev_last.md「决策历史」节。
```

en：

```markdown
**Decision ownership**: Long-term decisions (technology selection, architecture direction, cross-session design trade-offs) must be synced to `.openfeel/dev/decisions.md` in ADR format in addition to being appended to the dev_last.md "Decision History" section; session-scoped temporary decisions (process adjustments, one-off trade-offs) are recorded only in the dev_last.md "Decision History" section.
```
