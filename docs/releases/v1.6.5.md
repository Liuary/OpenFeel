# v1.6.5 发布说明

- **来源阶段**：v1.6.5-stage-138
- **需求**：REQ-072、REQ-073、REQ-074（本批次**一次性**发布）

## 变更摘要

- **`config unset <key>`（REQ-073 / A73.1—A73.4）**：项目配置删除入口 —— `defaults.X`（不限 schema）、`defaults` 整段、无点号的顶层段（如退役的 `models:`）；同一 YAML Document `deleteIn` 后原子写回，注释与键序保留。`--json` = `{schemaVersion,key,removed,path}`（出口 #52；不存在时末位 `reason` + exit 1；`--global` → `INVALID_ARGUMENT`/1 零写盘）。DSH `feel_verify action=config_unset` 复用同一 CLI，工具数仍 15。
- **`npm run release -- --bump patch|minor|major`（REQ-074 / A74.2）**：版本只在发布窗口动 —— 目标版本由上次发布基线递增、已等于目标则 `no-op` 零写盘、只写 4 个版本字段；`--bump` 才要 `--confirm`（`--publish` / `--push` 不变），`minor` / `major` 要 `--reason`，距上次发布 < 24h 再发 patch 额外要 `--confirm-twice`（只 warn，非硬门）。
- **本批次清单**：`--bump` 先打印 REQ / 阶段 / 改动文件，只含目标版本或该版本阶段的 done 需求（17 条旧 done 被过滤）；改动文件数取 `git rev-list -1 HEAD -- .openfeel/flow-archive/<上次版本>.json` + `git diff --name-only` 并 `git status --porcelain` 去重，不依赖 tag。
- **提示词与模板的克制机制（REQ-074 / A74.1 / A74.3 / A74.4 / A74.5）**：feel_mode 提示段新增版本纪律（四组渲染 ≤1200 字符 / ≤25 行，zh 802/919、en 1070/1186）；`DEV_CORE` 与 `.openfeel/dev/dev_core.md` 新增「版本与范围纪律」；reviewer 模板加速过度设计五判据 + 计划外改动必须落 blocking REV，planner 计划结构加「不做清单」「允许改动」；`docs/VERSIONS.md` 发布节奏与五项发布指标（只定义口径）。
- **guard 发布预演白名单（REQ-072 / A72.1—A72.6）**：仓库自身 `node scripts/release.mjs` 的纯 dry-run（`--dry-run` / `--skip-build`）class 4 warn 放行 + 审计 `release-dry-run-allowlisted`，realpath 绑定含 `.openfeel/` 的项目根（TEMP / 仓外同名脚本仍拒绝）；真实发布 / 提交参数与 A67.5 断言零改动。migrate / update 的全局配置测试改为真隔离（mock `homedir()` + `HOME`/`USERPROFILE`/`CLAUDE_CONFIG_DIR`），真实全局文件 sha256 不变。
- **版本**：两包 lockstep 1.6.5、`openfeel.requiresCli >=1.6.5`；`dsh/ADAPTER.md` 新增 `## v1.6.5` 小节。

## 语义

- **新增能力**：`config unset`（含 `--json` 出口 #52，计数 51/52 → **52/53**）、release `--bump` 独立模式与批次清单。
- **不变**：既有 51 个出口的键集 / 键序 / 类型；`STEPS` 六步链与 `test/scripts/release.test.ts` 既有 20 个 `it`；`npm run release` 的 class4 分类与 `--publish` / `--push` 语义；`flow.json` 状态机与一切不变量。

## 未达 / 不实现（如实登记）

- `npm test` **连续 3 次 0 failed 未达**（4 次实测仅 1 次满绿，失败全在 runner 层并发 / 超时；根因未复现，不放宽超时、不禁并行掩盖）。
- dashboard / metrics 采集与展示、批次锁 `BATCH_LOCKED`、`<24h` 硬门 —— 本版只写定义与 warn，实现登记为后续需求。

## 升级与验证

- **升级**：`npm i -g openfeel@v1.6.5`（本地开发：`npm run build` 后用 `node bin/openfeel.js`）
- **验证**：`npx tsc --noEmit` → `npm test` → `npm run build`（两遍幂等）→ `cd dsh && node test/contract.js && node test/verify.js && node test/guard.js && node test/preflight.js` → `node bin/openfeel.js lint i18n` → `npm run release -- --dry-run --bump patch`（已是 1.6.5 → `no-op`）

## 发布流程

- 发布走 CI 自动发布（唯一标准路径）：push 到 master 且 `package.json` 版本与 npm 已发版本不同 → CI 的 publish job 自动 `npm publish`（`openfeel` + `openfeel-dsh`）；不需要手动 `npm publish`，也不必打 tag。
- 版本号 lockstep：`package.json` / `dsh/package.json` = 1.6.5、`openfeel.requiresCli` = `>=1.6.5`。
