## 关键决策（困难点显式列出）

### 困难点 1（遗留风险 4）：GETTING_STARTED.md Line 83 `flow advance --stage stage-01` 断裂

- **事实**：`flow advance --stage <id>` 命令层直接调用 `mgr.advanceStagePhase(options.stage, ...)`（flow.ts:491），`advanceStagePhase` 直接 `this.data.stages[stageName]` 查找（flow-manager.ts:946），**不做短名规范化**。op-003 后 `plan stage add stage-01` 注册的键是 `v1.0.0-stage-01`，quickstart 后续 `flow advance --stage stage-01` 会抛「阶段 'stage-01' 不存在」。
- **决策 2 依据**：`flow advance --stage` 参数 = 权威 stageId（`v1.0.0-stage-34`），非短名。
- **处理**：GETTING_STARTED.md Line 83 的 `--stage stage-01` → `--stage v1.0.0-stage-01`，`--op stage-01.op-001` → `--op v1.0.0-stage-01.op-001`。
  - 佐证：`parseOpId` 用 `lastIndexOf('.')`（flow-manager.ts:501），`v1.0.0-stage-01.op-001` 可正确切出 stageId `v1.0.0-stage-01` + op `op-001`。
  - 保留 Line 71/74 的 `plan stage add stage-01` / `plan scheme create stage-01`（短名别名合法，决策 6）。
- **备选方案（不采纳）**：给 `flow advance --stage` 加短名规范化（`normalizeStageId`）。不采纳理由：超出本 stage 6 op 范围（flow advance 短名兼容属命令层增强，与「路径统一」主题偏离，且决策 2 已明确该参数为权威 stageId）；若后续需要可另立 stage。

### 困难点 2（REV-006）：GETTING_STARTED.md 编码

- Reviewer 实测 `docs/GETTING_STARTED.md` 与 `docs/commands.md` 均为 **UTF-8 无 BOM**（非计划原标 GBK）。
- **处理**：编辑时按 UTF-8 无 BOM 保存（Edit 工具默认 UTF-8 不带 BOM），**不使用 GBK**。若引入 BOM 或 GBK 会导致乱码。原计划 op-006 任务 2 的「GBK」警告为事实性错误，按 REV-006 修正为「UTF-8 无 BOM」。
