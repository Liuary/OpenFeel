# op-005：三入口职责分层与 `stage create` 弃用提示

- **阶段**：v1.1.2-stage-41
- **状态**：completed
- **前置**：op-002（hard，三入口统一接入 `validateStageId` + 建议名）；op-004（soft，`plan stage add` 帮助文案与之同区域，建议 op-004 完成后再收口）
- **负责 Agent**：openfeel-executor
- **最多重试**：3

## 目标（含反馈条目）

澄清三个「阶段创建」入口的职责分层并交叉引用，把 `stage create` 标记为 **deprecated**（运行时 stderr 提示，**非 TTY 静默**，功能保留），三入口统一接入 stageId 校验；同步文档关系表。

**对应反馈**：`docs/phase-5/06-openfeel-tooling-feedback.md` 问题 #9（低）「`stage create` 与 `plan stage add` 职责重叠、易混」。
**对应决策**：P4（**不删除任何命令**，改为「两层 + deprecated 提示 + 统一校验」）。

> 参见 kb/patterns.md #init/update 重启提醒对称输出模式（非 TTY 静默）、#纯全局部署命令模式（职责分层的既有先例）、#CLI 错误诊断增强模式。

## 关键设计决策

1. **两层职责模型**（写死）：

   | 入口 | 层级 | 行为 | 定位 |
   |------|------|------|------|
   | `openfeel plan stage add <name>` | **完整层（推荐）** | 建 `plan/{series}/stage-NN/` 目录（`overview.md` + `status.md`）+ 注册 `flow.json` | 唯一建目录入口 |
   | `openfeel flow stage add <stageId>` | **注册层** | 仅注册 `flow.json`，不建目录 | 轻量注册 / 特殊场景 |
   | `openfeel stage create <stageId>` | **注册层（deprecated）** | 与 `flow stage add` 等价（均走 `FlowManager.addStage`） | 兼容保留，引导迁移 |

2. **不删除命令**：`stage create` 物理删除会回退 stage-30 引入的兼容性并破坏既有文档引用（`docs/commands.md`、`manual/cli/commands.md`），故仅 deprecated。
3. **弃用提示规则（写死）**：
   - 输出到 **stderr**；
   - **仅 TTY** 输出（`process.stdout.isTTY` 为真）；**非 TTY 静默**（避免污染 CI 输出，复用 init/update 既有对称静默惯例）；
   - 文案引导：改用 `openfeel flow stage add <stageId>`（注册层等价入口）。
4. **弃用期与兼容性策略**（须写明）：
   - 保留**至少一个 W 版本**（v1.1.x 系列内不删除）；正式移除**不早于 v1.2**，且须另立计划与用户确认；
   - `--help` 中命令仍可见（`description` 标注「已弃用」），不影响既有脚本（行为不变，仅 TTY 下多一行 stderr）；
   - CI/管道场景（非 TTY）**零输出变化**；
   - 文档（`docs/commands.md`、`manual/cli/commands.md`）标注「推荐 `plan stage add` / `flow stage add`」。
5. **统一校验**：三入口 action 开头均接入 op-002 的 `validateStageId` + `suggestStageId`（非法 → stderr 原因 + 建议名 + exit 1）。
