# REQ-070：彻底不预设模型：移除 opencode agent 默认 model 与框架注入

> 本文件为需求正文（人读副本，由 openfeel req 机械铺骨架）。**机读权威恒为 `.openfeel/flow.json` 的 `requirements` 条目**；两者不一致时以 flow.json 为准。下方状态为创建时快照，不追写实时状态。

## 状态

draft（创建时快照；以 flow.json 为准）

## 摘要

虽然默认 config 模板已不预设模型，但 opencode 适配器的 agent 模板 frontmatter 仍写死 `model: deepseek/deepseek-flash`（10 份），opencode-config 也向用户配置注入 vision/reviewer 的默认 model，skills 仍把 deepseek 当默认/主力/异种。这与「用户选什么模型就用什么」冲突，需要彻底移除框架级默认，只保留用户按需的 global/project 配置。

## 目标与验收

### 目标

彻底贯彻「不预设模型」：移除 opencode 适配器 agent 模板里的 `model:` 默认值（10 份 zh/en）、移除 `opencode-config.ts` 的框架默认模型注入，并调整 `openfeel model` 的 `default` 层语义——只保留 global/project 两层按需配置，模型由用户平台/会话选择。

### 验收

- A70.1 `src/core/templates-data/opencode/agents/{zh-CN,en}/openfeel-{executor,explorer,reviewer,utility,vision}.md` 的 frontmatter 不再有 `model:` 行（10 份，零命中）。
- A70.2 `src/core/opencode-config.ts` 的框架默认注入（`openfeel-vision`/`openfeel-reviewer` 的 `{ model: ... }`）移除；不再向用户 opencode.jsonc 补任何 agent model。
- A70.3 `openfeel model` 的 `default` 层：`get` 返回 null/`unset`（不再从 frontmatter 读默认）；`set --scope default` 明确拒绝并提示改用 `global`/`project`；`global`/`project` 两层行为与解析优先级（project > global > 平台默认）保持不变，相关测试同步。
- A70.4 skills（`openfeel-model-check` / `openfeel-model-config` / `openfeel-cli-usage`）不再把 `deepseek-v4-pro`/`deepseek-flash`/`glm-5.1` 描述为默认/主力/异种约定，改为「不预设，按需配置/平台选择」。
- A70.5 文档：README（模型相关段）、`docs/commands.md` 的 model 节、`docs/VERSIONS.md` v1.6.3 节、`CHANGELOG` `## [1.6.3]`；版本 root/dsh 1.6.3，`requiresCli >=1.6.3`。
- A70.6 全量验证：`npm test`、`tsc --noEmit`、`npm run build`（两遍幂等）、dsh 四测、`lint i18n`、`release --dry-run` 全绿；push master 后由 CI 自动发布 1.6.3（不手动 publish）。
- A70.7 其余模板正文的中性化：`templates-data/agents-md/{zh-CN,en}.md` 与 `claude/constraint/{zh-CN,en}.md` 的「多模态模型 (deepseek-flash)」改为「多模态模型（由平台提供）」；opencode agent 正文 8 处「（如 DeepSeek V4 Pro）」改为「（例如你选择的模型）」；dsh 工具/文档的 scope 枚举去掉 `default`（两层级），`dsh/ADAPTER.md` 的 requiresCli 抬到 `>=1.6.3` 并加 v1.6.3 小节。
