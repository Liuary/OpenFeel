## 目标

14 个 skill 目录加 `openfeel-` 前缀并同步 `SKILL.md` frontmatter `name:`；`NEW_SKILL_NAMES` / `buildUpdatedJsonc` / `getIncomingContent` 随新名；`/opfx:` 命名空间按类型准确引用并清零（含 REV-305 的 `/opfx:status` 改写）；源码注释 `/opfx:*` 同步清理。

> 参见 kb/architecture.md #opencode 全局/项目 agent 与 skill 合并语义（同名覆盖非确定 → 名唯一前提）；kb/patterns.md #跨平台行尾归一化模式。

## 关键设计决策

1. **14 skill 重命名清单**（目录名 + `SKILL.md` frontmatter `name:` 同步）：

```
agent-model-check→openfeel-agent-model-check   bug-acceptance→openfeel-bug-acceptance
check-kb→openfeel-check-kb                     get-bugs→openfeel-get-bugs
get-stage-status→openfeel-get-stage-status     health→openfeel-health
model-check→openfeel-model-check               model-config→openfeel-model-config
recover→openfeel-recover                       roadmap→openfeel-roadmap
search-kb→openfeel-search-kb                   sync-status→openfeel-sync-status
update-stage-status→openfeel-update-stage-status   wizard→openfeel-wizard
```

2. **CLI 子命令与 skill 同名词区分（N6）**：`openfeel health` / `openfeel flow recover` / `openfeel roadmap` / `openfeel wizard` / `openfeel model-check` / `openfeel model-config` 是 **CLI 子命令**，不改；仅 skill 名提及改。`roadmap` 同时是 CLI 与 skill，在 feel.md 表中**双列引用**（命令 `openfeel roadmap` + skill `openfeel-roadmap`）。
3. **`getIncomingContent` skill 正则无需改**：L1802 `/^\.opencode\/skills\/(.+)\/SKILL\.md$/` 的 `.+` 天然匹配新名；`SKILL_DEFINITIONS` 键由 build 自动带前缀。仅需确认 `SKILL_DEFINITIONS` 生成段重生成（op-004）。
4. **`NEW_SKILL_NAMES` 仅加前缀，不扩列表**：现列 8 项（L1209-1218），逐项加 `openfeel-` 前缀；**不**把列表扩展到 14 项（属历史范围问题，非本阶段职责）。

**根版 skills 块手动更新（REV-401 修订）**：

根 `opencode.jsonc`（项目根目录）L8-18 的 `skills` 块是**手写静态配置**，与模板版 `templates-data/opencode/opencode.jsonc` 的 `SKILLS_PLACEHOLDER`（由 build 生成）**无关**，重命名后不会自动更新。当前根版仅 9 条旧路径（`get-bugs` / `check-kb` / `bug-acceptance` / `sync-status` / `get-stage-status` / `update-stage-status` / `model-check` / `model-config` / `agent-model-check`），而模板版由 build 生成**全部 14 条**（另含 `health` / `recover` / `roadmap` / `search-kb` / `wizard` 5 条）。

**判断：补齐到 14 条（对齐模板），而非维持 9 条。**理由：
1. 根版是本仓库 opencode 的**实际运行配置**，skills 块决定哪些 skill 被显式注册；缺失的 5 条 skill 目录（`health`/`recover`/`roadmap`/`search-kb`/`wizard`）**已存在**于 `.opencode/skills/`（会话 available_skills 可证），但未在配置中注册，属历史遗漏，与模板版行为分叉。
2. stage-36 目标即「命名前缀统一 + 单源」，重命名后根版若仍只改 9 条，则本仓库（自举实例）与新项目部署的 skill 集合分裂，违背本阶段主旨。
3. 补齐动作 = 缺失 5 条按同名映射加 `openfeel-` 前缀补入，改动小、无风险。

最终根版 `skills` 块应为 14 条（全部带 `openfeel-` 前缀，键名与模板版生成结果一致）：
