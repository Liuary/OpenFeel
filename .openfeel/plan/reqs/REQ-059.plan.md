# REQ-059 计划：开发账本持续更新（写操作自动同步 + done 前硬门）

> 依据：`.openfeel/plan/v1/stage-132/plan.md` §1.1（判据 A9/A9b）、§2（T8）、§3 门禁表、§9 R5。本文件不新增任务、不改判据。

## 目标

- **目标**：所有写成功出口自动同步（时间戳前进、`due=false`）；`archiving→done` 前若仍 `due` 则抛 `DEV_SYNC_STALE`（同一 `--force` 通道留痕），失败原因经 stderr 可见。
- **问题**：`dev/` 与 `dev_last.md` 只在 `flow advance` 且满足「首次 / 超 30 分钟 / 节点相位」时才写；`stage set`、`req advance`、`req verify` 之后账本是陈旧的，`statusSync.due` 只提示、没人执行。
- **问题**：`syncDevStatus` 的失败被静默 `try/catch` 吞掉，于是"永远 due"与"从不报错"同时存在，跨会话恢复会读到过期交接。
- 来源：`plan.md` §1.1 的 A9 / A9b。

## 验收判据

判据沿用 `plan.md` §1.1，本需求对应 **A9 / A9b**。必跑命令（仓库根）：

```bash
node bin/openfeel.js stage set v1.6.0-stage-132 --status planned   # 写成功出口
node bin/openfeel.js dev status --json                             # A9：last_sync 前进、due=false
node bin/openfeel.js req advance REQ-0NN --to in_progress          # 另一出口，重复核 last_sync
node bin/openfeel.js dev sync                                      # A9：exit 0，changed 可判
sed -n '/openfeel:auto:begin/,/openfeel:auto:end/p' .openfeel/dev/current.md   # AUTO 块随写操作更新
npx vitest run test/core/dev-status.test.ts test/core/flow-manager.test.ts
```

- **A9b 只认构造法单测**：`test/core/flow-manager.test.ts` 注入 `syncDevStatus` 抛错（或把临时工作区 `.openfeel/dev/` 置只读）后调 `advanceStagePhase('…','done')`，断言抛 `DEV_SYNC_STALE`；`allowGateOverride` 放行且 `detail.gate_overrides` 含 `'dev_sync'`。**不得**以"理论上会拦"充数——写操作出口已自动同步，正常 CLI 序列无法自然复现该门。
- 合入前/后跑阶段级 **A11** 全量回归。

## 风险

- **静默失败造成"永远 due 又永远拦"**（`plan.md` R5）：归档被堵死。规避——`maybeSyncDevStatus` 必须回传 `error` 并由命令层 `console.warn` 一行；`done` 门保留 `--force` 出路。
- **成本上升**：若每次读命令都同步，`dev_last` 写入频繁。规避——`blockChanged()`（`dev-status.ts:244-256`）已保证状态未变不重写；自动同步**只在写成功出口**调用，读命令一律不调。
- **门误伤归档**：把 `dev_sync` 塞进 `describeStageDoneGate`/`requirementDoneBlocker` 会改变既有归档判据。规避——`describeStageDoneGate`（`:1936-1955`）**不动**，本门是 `advanceStagePhase` 内的独立检查。
