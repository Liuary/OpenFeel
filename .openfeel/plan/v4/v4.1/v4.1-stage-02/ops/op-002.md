## 目标

将 `planner.md` 从 50 行扩充到 80–100 行，明确 Planner 与 Feel 的职责划分、计划粒度判定标准、以及拒绝重复计划的机制。

> 参见 kb/architecture.md #15→7 Agent 精简体系 — Planner 职责可由 Feel 兼任，但作为独立 Agent 需明确何时独立唤起。

## 实施步骤

- [x] 1. 读取当前 `.opencode/agents/planner.md` 完整内容
- [x] 2. 在 `## 核心职责` 之前新增 `## 唤起条件` 节：
  - 何时 Feel 将 Planner 作为独立子 Agent 唤起：大规模规划（≥ 2 个阶段或 ≥ 5 个文件变更）、多阶段计划、跨模块架构变更
  - 何时 Feel 自行处理（兼任 Planner）：单阶段小调整、单文件 ≤ 30 行修改、已有计划补充
- [x] 3. 在 `## 核心职责` 中第 1 条之后，新增 `## 计划粒度判定标准` 节：
  - **小规模**：单阶段、< 5 个文件 → Feel 自行处理
  - **中等规模**：1 个阶段但 ≥ 5 个文件 → Feel 可选择唤起 Planner
  - **大规模**：≥ 2 个阶段或跨模块架构变更 → 必须走 Planner → Reviewer 完整流程
  - **判定依据**：以 `deps.yaml` 中的阶段数和文件列表为准
- [x] 4. 新增 `## 拒绝条件` 节：
  - 当 Feel 请求的计划**已存在**且无重大偏离时，Planner 应**拒绝重复制定**
  - 拒绝时反馈 Feel：`"计划 {plan-id} 已存在，当前偏差：{diff}。建议补充现有计划而非重新制定。"`
  - 重大偏离的判定标准：核心目标变更、阶段数变化 ≥ 2、≥ 50% 任务重新定义
- [x] 5. 扩充 `## 与其他 Agent 的关系` 节，新增与 Feel 的边界说明：
  - Feel 兼任 Planner 时，大型计划仍应唤起独立 Planner 以确保审查独立性
  - Planner 产出必须经 Reviewer 审查后方可进入 Schemer 阶段
- [x] 6. 在 `## 模型选择` 中补充：当 Feel 自行处理小型计划时，不唤起 Planner；Planner 仅在大规模规划时被 Feel 作为独立子 Agent 调用
- [x] 7. 最终检查：`wc -l` 确认行数在 80–100 范围内
