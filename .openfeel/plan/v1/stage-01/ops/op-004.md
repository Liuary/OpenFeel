# op-004：feel 空白项目自动搭建 + migrate 清理旧 core.md + 兼容过渡

- **阶段**：v1.1.1-stage-01
- **前置**：op-002（hard——feel.md 引用 `openfeel init --workspace-only` 依赖 op-002 子命令）；op-003（hard——migrate 清理全局 core.md 依赖 op-003 已切换全局 AGENTS.md + state remap）
- **负责 Agent**：openfeel-executor
- **最多重试**：3

## 目标

feel.md 模板新增「空白项目自动搭建 .openfeel/」节（非 feel agent 不触发，实现路径简化为一句 `openfeel init --workspace-only`）；migrate 扩展：检测全局旧 core.md → 提示清理 + 存量项目 AGENTS.md 保留 + 提示（不强制删除）。

> 参见 kb/architecture.md #存量项目迁移架构（legacy 检测 + deployGlobalAsset 复用 + 回滚边界）；kb/patterns.md #迁移命令模式（detect→backup→deploy→split→clean→report + rollback + --dry-run）；kb/architecture.md #全局部署架构。

## 关键设计决策

1. **feel.md 空白项目自动搭建（REV-1902 修订）**：实现路径简化为「检测无 `.openfeel/` 时运行 `openfeel init --workspace-only`」，复用 op-002 的非交互轻量子命令，**不重复实现工作区创建逻辑**。明确「**非 feel agent 不触发**」——仅 Feel 在空白项目启动时执行，避免每个 agent 会话都触发搭建。

2. **migrate 清理措辞（REV-1910 修订）**：「迁移」→「清理」。检测**全局** `~/.config/opencode/openfeel/core.md`（旧资产，非项目 `.opencode/instructions/core.md` 判据③）→ 报告 + 提示清理；不纳入 `detectLegacy` 五条判据（保持项目 legacy 语义不变），作为独立兼容检测项。

3. **存量项目 AGENTS.md 保留 + 提示**：update/init 不再部署项目 AGENTS.md 后，存量项目根 `AGENTS.md` 属用户项目约束；migrate 检测其存在 → 提示「已收归全局，可保留或手动删除」，**不强制删除**（§五 #1）。

4. **`detectLegacy` 判据③ 不变**：项目 `.opencode/instructions/core.md` 仍作为 legacy 布局判据（§五 #2，已由 stage-39 覆盖），本 op 不重复实现。

### 步骤 2：`src/core/migrate.ts`——新增兼容检测

2a. import 增 `getGlobalAgentsMdPath`（用于提示文案，可选）；保留 `getGlobalCoreMdPath`。

2b. 新增检测函数：

```ts
/** 兼容过渡检测（v1.1.1）：全局旧 core.md 与存量项目 AGENTS.md（均不强制删除，仅提示） */
export interface DeprecatedCompatReport {
  globalCoreMdExists: boolean;   // ~/.config/opencode/openfeel/core.md 旧资产
  projectAgentsMdExists: boolean; // 项目根 AGENTS.md（已收归全局）
}

export function detectDeprecatedCompat(projectPath: string): DeprecatedCompatReport {
  return {
    globalCoreMdExists: existsSync(getGlobalCoreMdPath()),
    projectAgentsMdExists: existsSync(resolve(projectPath, 'AGENTS.md')),
  };
}
```

2c. `migrateProject` 返回结果（`MigrateResult`）增 `deprecated: DeprecatedCompatReport` 字段；主流程中调用 `detectDeprecatedCompat(projectPath)` 填充（dry-run 与实际执行均返回）。

2d. **全局旧 core.md 清理**：实际执行（非 dry-run）时，若 `globalCoreMdExists`，输出提示并**可选删除**——按「不强制」原则，默认仅提示不删；新增可选标志 `--clean-global-core-md` 时才 `rmSync(getGlobalCoreMdPath())`（全局资产不备份、不还原，REV-1201）。为控制复杂度，本 op 采用**仅提示 + 独立 `--clean-global-core-md` 标志**（默认 false）。

## 风险与注意

- **migrate 项目/全局边界**：`detectDeprecatedCompat` 的 `globalCoreMdExists` 检测的是**全局**资产（跨项目），在 migrate（项目作用域命令）中仅作「提示」，删除须显式 `--clean-global-core-md`，避免项目级命令意外删全局文件。
- **feel.md 双语同步**：zh-CN/en 两文件对称插入（patterns.md #AGENTS.md 模板同步模式 / 双语 CLI 交互模式），且 build 单源断言会校验 OPENCODE_AGENT_TEMPLATES 与源一致。
- **`--clean-global-core-md` 与回滚边界**：全局 core.md 删除不备份、不还原（REV-1201 全局资产不还原），manifest 不记录该删除；删除前在日志提示用户。
- **feel.md 变更需重启**：openfeel 已部署项目的 feel agent 提示词在 `openfeel setup`/`update` 后重生成才生效，勿在本 op 内假设立即生效。
