# op-003：会话启动修复规则（feel.md 主 + core-instructions 辅，双语）

- **阶段**：v1.1.0-stage-38
- **前置**：op-002（hard，`update_infos.md` 读写逻辑与格式已定稿）
- **负责 Agent**：openfeel-executor
- **最多重试**：3

## 目标

落地「会话启动检查 `~/.openfeel/update_infos.md` 并修复、完成后提醒重启」约束：feel.md（主，承载具体修复动作）+ core-instructions（辅，提示性强制兜底），zh-CN + en 双语同步。**修复动作（读 + 检查 + 用 edit 工具勾选条目 + 提醒重启）仅落 feel.md；core-instructions 只加提示性约束（REV-902）。** Feel 是 opencode primary agent，不能 import TS 模块，勾选动作用 edit 工具编辑 `update_infos.md`（`- [ ]` → `- [x]`），不调用 `resolveUpdateInfo`/`clearUpdateInfos`，不新增 CLI 命令（REV-1003）。

> 参见 kb/patterns.md #init/update 重启提醒对称输出模式（重启提醒 TTY 判断）；feel.md 现有「冲突检测」节（L319-337，前例）与 core-instructions「会话启动自检」节（L9-36，前例）。

## 关键设计决策

1. **REV-902 职责切分**：feel.md 承载「读 `update_infos.md` → 逐条检查 → 用 edit 工具勾选清除 → 提醒重启」的**完整修复动作**（Feel 是 primary agent，启动自检属其职责，且有「冲突检测」前例）；core-instructions 只在「会话启动自检」节加一条**提示性约束**（引导用户/Feel 检查，**不自行修改**该文件）。
2. **REV-909「追加」条目的「人工确认」语义**：区分两类条目的清除策略——**「异常」条目**（标记解析失败）目标文件现已含完整标记 → 异常自愈，可自动勾选清除；**「追加」条目**（无标记追加）即使文件现已含标记，追加的受管区可能仍残留在标记区外造成**内容重复**，**不静默清除**，提示用户人工确认无重复后再勾选。这是 prompt 层语义（Feel 提示、用户确认），勾选动作 = 用 edit 工具把条目 `- [ ]` 改为 `- [x]`，代码层不强制。
3. **TTY 对称**：提示方式对称现有「冲突检测」——TTY 输出待处理列表，非 TTY（CI/CD）静默跳过，不污染日志。
4. **不引入新 Agent、不新增 CLI 命令（REV-1003 修订）**：修复动作在 Feel 职责内，不新增 Agent、不新增 CLI 命令。Feel 是 opencode primary agent，**不能 import TS 模块**（`resolveUpdateInfo`/`clearUpdateInfos` 无法被 Feel 调用），故 feel.md 中的清除动作**改为用 edit 工具直接编辑 `~/.openfeel/update_infos.md`**（将对应条目 `- [ ]` 改为 `- [x]`），与 Feel 可用工具对齐。`resolveUpdateInfo`/`clearUpdateInfos` 函数保留在 update-infos.ts（供未来 CLI/其他调用方使用），但 feel.md 不调用。

## 实施步骤

### 步骤 1：feel.md（zh-CN）新增「update_infos 检查修复」节

在 `src/core/templates-data/opencode/agents/zh-CN/feel.md` L337（「冲突检测」节末行 `4. 若 update_state.json 不存在...`）之后、L339「## 决策追加」之前插入：

```markdown
## update_infos 检查修复

Feel 启动时检查 `~/.openfeel/update_infos.md`（若文件存在）：

1. 读取该文件，遍历「追加」与「异常」两类条目，按条目记录还原目标文件路径（绝对路径，或「相对路径 (项目: 根)」二元组）。
2. 逐条处理：
   - **异常条目**（标记解析失败）：目标文件现已含完整 begin/end 标记 → 异常已自愈，用 edit 工具将对应条目的 `- [ ]` 改为 `- [x]` 勾选清除该条目。
   - **追加条目**（无标记追加）：即使目标文件现已含标记，追加的受管区可能仍残留在标记区外造成**内容重复**，**不静默清除**——提示用户人工确认是否存在重复内容，确认后用 edit 工具将对应条目 `- [ ]` 改为 `- [x]` 勾选。
3. 提示方式对称「冲突检测」：终端为 TTY 交互环境时输出待处理列表与确认引导；非 TTY（如 CI/CD）静默跳过。
4. 修复完成后，提醒用户重启会话（全局 agent/约束已变更，需重启加载）。
5. 全部条目勾选后，可删除该文件或保留骨架（无需单独清空 API）。
6. 若文件不存在：**静默跳过**（尚未发生过追加/异常）。
```

### 步骤 2：feel.md（en）新增对应节

在 `src/core/templates-data/opencode/agents/en/feel.md` L337（「Conflict Detection」节末）之后插入（与 zh-CN 对称）：

```markdown
## update_infos Check & Repair

At startup, Feel checks `~/.openfeel/update_infos.md` (if the file exists):

1. Read the file, iterate over both "Appended" and "Anomaly" entries, and resolve each target path from the recorded entry (absolute path, or the "relative path (project: root)" tuple).
2. Process each entry:
   - **Anomaly entry** (marker parse failure): if the target file now contains a complete begin/end region, the anomaly has self-healed — use the edit tool to change that entry's `- [ ]` to `- [x]` to check it off.
   - **Appended entry** (appended without marker): even if the target file now contains markers, the appended managed region may still linger outside the region causing **content duplication** — **do not silently clear**; prompt the user to manually confirm there is no duplication, then use the edit tool to change that entry's `- [ ]` to `- [x]` to check it off.
3. Prompting mirrors "Conflict Detection": in a TTY interactive environment, print the pending list and confirmation guidance; in non-TTY (e.g. CI/CD), silently skip.
4. After repair, remind the user to restart the session (global agents/constraints have changed and require a reload).
5. Once all entries are checked, the file may be deleted or kept as a skeleton (no separate clear API needed).
6. If the file does not exist: **silently skip** (no append/anomaly has occurred).
```

## 风险与注意

- **REV-902 严格**：core-instructions 的约束是「提示性」——引导用户/Feel，**不得**在其中写「修复 update_infos.md」「编辑勾选」等修复动作（修复动作仅 feel.md）。
- **REV-909 边界**：「追加」条目的「人工确认」是 prompt 层引导（Feel 提示用户），不是强制代码逻辑；勾选动作 = edit 工具编辑 `- [ ]` → `- [x]`。op-004 只做模板静态断言 + 函数单测，不做行为级 E2E（REV-907）。
- **REV-1003 Feel 不可 import TS**：feel.md 是 Feel（opencode primary agent）的 prompt，Feel 不能 import `src/core/update-infos.ts` 的 `resolveUpdateInfo`/`clearUpdateInfos`。故 feel.md 措辞统一为「用 edit 工具编辑 `~/.openfeel/update_infos.md`」，不新增 CLI 命令。`resolveUpdateInfo`/`clearUpdateInfos` 函数保留（未来 CLI 或其他调用方），op-004 函数单测仍覆盖。
- **插入位置精确**：feel.md 插在「冲突检测」节后、「决策追加」节前；core-instructions 插在「会话启动自检」节私域文件清单末行后、「设计原则」节前。不得插错节（否则破坏既有结构）。
- **模板改动须 build 重生成**：不 build 则 `template-loader.ts` 仍注入旧文案，`openfeel update` 部署的仍是旧 feel.md/core。
