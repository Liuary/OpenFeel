# REQ-059：开发账本必须持续更新：dev/ 与 dev_last.md 交接摘要门禁

> 本文件为需求正文（人读副本，由 openfeel req 机械铺骨架）。**机读权威恒为 `.openfeel/flow.json` 的 `requirements` 条目**；两者不一致时以 flow.json 为准。下方状态为创建时快照，不追写实时状态。

## 状态

in_progress（创建时快照；以 flow.json 为准）

## 摘要

开发账本长期不更新：本仓 `.openfeel/dev/current.md` 与 `users/Liuary/dev_last.md` 最后写入停在 2026-11-20，之后 4 天有大量活动却没有刷新。Agent 不写账本不是懒，而是**没有任何机制要求它写**：自动同步只挂在 `flow advance` 成功之后，而需求导向下大部分操作是 `req *`，不触发同步；DSH 也没有 `feel_dev` 工具。

## 目标与验收

**目标**：账本在需求/阶段写操作后自动同步；`due` 从「只提示」变成「自动执行 + 到 done 前硬门」。

- A9 需求/阶段写操作成功后自动触发 `maybeSyncDevStatus()`（状态未变不重写），`dev_last.md` 与 `current.md` 的 AUTO 块刷新。
- A9b `archiving→done` 前 `due===true` → `DEV_SYNC_STALE` 硬门，`--force` 放行并审计；正常路径因先自动同步不会触发（构造法单测取证）。
- A9c DSH 新增 `feel_dev action=sync|status`，返回 `{ok,lastSync,due,changed,wrote[]}`，计数 14→15。
- A9d 同步失败不再吞异常：返回 `error` 并由调用方 stderr 一行提示。

## 问题

1. 自动同步只有两个触发点（`openfeel dev sync` 手工、`flow advance` 成功后 best-effort），`req/stage/archive` 都不触发。
2. `statusSync.due` 只出现在 dashboard 提示里，`computeWorkflowGate` 完全不看它 —— 既不拦截也不强制。
3. DSH 13 个 `feel_*` 工具没有 dev，提示里要求用 shell 跑 `openfeel dev sync`，与「状态写只用 feel_*」冲突，实际没人执行。
4. 交接摘要（`dev_last.md` AUTO 块）不刷新 → 新会话恢复成本高。

## 初步规划

1. `src/core/dev-status.ts` 抽 `maybeSyncDevStatus(projectPath)`（复用 `blockChanged` 去重）。
2. 在 `stage.{set,task,verify}`、`req.{advance,complete,review,verify,body}`、`flow.advance` 的成功出口调用。
3. `flow-manager.advanceStagePhase` 加 `DEV_SYNC_STALE` 门（done 前，可 force，审计 `gate_overrides:['dev_sync']`）。
4. DSH `feel_dev` 工具 + 测试；提示词改为调用该工具。
