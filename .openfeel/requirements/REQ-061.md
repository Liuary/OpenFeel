## 摘要

v1.6.0 发布时卡在 npm token 失效（whoami 401 / publish 404），且发布步骤散在人工对话里：archive → build → 双包 publish → market index → 提交归档产物 → tag/push。done 相位下 agent 不能 commit，导致 release notes、stage 摘要、checkpoints 长期滞留未提交。CHANGELOG 版本段靠手写，REQ/REV 信息没有复用。

## 目标与验收

### 目标

把「archive → build → 双包 publish → market index → 归档提交 → tag → push」收敛为一条命令，并在 npm 认证缺失时早停；同时让 done 后产生的归档产物能随发布一并提交，CHANGELOG 版本段可从 REQ/REV 生成草稿。

### 验收

- A61.1 `npm run release -- --dry-run` 在干净工作树跑通：版本一致性校验（root/dsh/CHANGELOG）→ build → 双包 publish（dry-run 不真发）→ `market:index` → 归档产物提交 → tag；任一检查失败 exit 1 且不进入后续步骤。
- A61.2 `npm whoami` 失败时脚本早停并打印 `npm login` 指引（不打印 token）；真实发布只在 `--publish` 且认证通过时执行。
- A61.3 `CHANGELOG.md` 的版本段可由脚本从 `flow-archive/<version>.json` 的 REQ 标题 + stage 摘要的 REV 结论生成草稿（`--notes-only` 只生成不发布），人工确认后才写入。
- A61.4 归档产物（`.openfeel/log/archive-<stage>.md`、`docs/releases/<version>.md`、done 后 checkpoints）在发布流程中可被白名单提交，不再长期滞留为未提交。
