- **状态**：pending
- **前置**：无
- **负责 Agent**：openfeel-executor

## 目标

修复「`meta.last_req_seq` 只随新建递增、不感知归档」导致的 ID 复用：本仓 v1.5.8 归档 REQ-025~030 后计数器仍为 24，新建需求会分配出与归档条目重复的 ID。写侧在版本归档时抬升计数器（根因），读侧在分配前并入归档最大号（存量修补）。

## 实施步骤

- [ ] 1. `src/core/flow-archive/archive-ops.ts` 新增只读函数 `archivedRequirementMaxSeq(projectPath): number`：遍历 `listArchivedRequirements(projectPath)`，用 `REQ_ID_PATTERN`（`src/core/req/types.ts`，非全局正则）解析 `requirement.id`，返回最大序号（空集/异常 id → 0）。头注释说明「last_req_seq 不感知归档」的根因与调用方。
- [ ] 2. `src/core/req/requirement-ops.ts` 新增纯内存 `raiseRequirementSeqFloor(data: FlowData, floor: number): void`：`data.meta.last_req_seq = max(requirementSeqFloor(data), floor)`；非法 floor（非有限数 / ≤0）忽略；不改动 `requirements`；落盘仍由调用方 `save()` 承担。
- [ ] 3. `src/commands/req.ts`：`add`（`addRequirement` 调用前）与 `split`（`splitRequirement` 调用前）各插入一行 `raiseRequirementSeqFloor(data, archivedRequirementMaxSeq(process.cwd()))`；import 相应符号。
- [ ] 4. `src/commands/flow.ts` 的 `flow archive <version>`：**在 `:2440-2447`（`data.requirements = remainder.requirements` 覆写）之前**用 `splitForArchive` 构造的 `archive.requirements`（或 `file.requirements`）求最大序号，调用 `raiseRequirementSeqFloor(data, max)`；必须位于 **dry-run 分支（`:2400-2428`，零写盘契约）之外**。需求切分单点在 `src/core/flow-archive/grouping.ts:splitForArchive`（纯函数，保持纯净，不加副作用）。
- [ ] 5. 不新增 CLI 子命令；不改 JSON 契约键集。
