# op-002：T2 knowledge/config/view/plan 读命令 --json（8 个命令面）与错误接入

- **阶段**：v1.2.2-stage-97（读命令 `--json` 全量补全）
- **前置**：op-001（hard；JSON 分支写法与错误接入风格定稿）
- **负责 Agent**：openfeel-executor
- **最多重试**：3
- **对应需求/审查**：REQ-001 / DSH P0-2（`knowledge search|list|index|dedup`、`config get|effective`、`view list`、`plan scheme list`）；REV-97-002（本 op 新增 8 个成功出口，累计 24→32；阶段末 33 由 op-004 汇总）

## 目标

为 8 个只读命令面新增 `--json` 成功出口；人类输出逐字不变；业务拒绝接入 `failRefusal`，内部异常在 JSON 模式走 `failInternal`（人类模式保持既有 exit 1 文案）。本 op 完成后累计成功出口 32 / 注册选项 33。

## 方案期裁定（计划 §四 Q2/Q4/Q7 定稿）

- **Q2/Q8（`knowledge search` 内容形态）**：`content` 给全文（`searchKnowledge` 返回值，含关键词 `**` 高亮），`summary` 给与人类输出同源的前 100 字摘要（抽 `summarizeContent` 单点，人类渲染同用）。默认 `limit=10`，全文体量可控；不为 JSON 另设截断。
- **Q4（`config get` 全局/项目形态）**：
  - 项目模式：`{schemaVersion,scope:'project',key,value}`；`key` 为用户输入原值（与人类回显一致），`value` 为 `string | null`；无 key → `INVALID_ARGUMENT` refusal 1（人类 exit 1 逐字）。
  - 全局模式无 key：`{schemaVersion,scope:'global',values:{...}}`，6 个固定键按人类输出顺序；缺省值 `null`（人类显示空串，契约 op-004 标注差异）。
  - 全局模式有 key：`{schemaVersion,scope:'global',key,value}`；不存在 → `value:null` + exit 0（人类同）。
  - 全局 profile 解析告警（`parseError`）：JSON 模式写 stderr（不进入文档），exit 0 维持。
- **Q7（`plan scheme list` 的 `fill`）**：直接复用 `detectFillState(scheme.content)`（`Scheme.content` 恒为 string，不存在 null 分支）；`draft` 复用既有 flow.json 扫描的 `draftIds` 集合（按 opId 匹配，保持既有口径，不新增第二套判定）。
