# REQ-068 计划：版本号纠正 1.7.0→1.6.1 + 发布改走 CI 自动发布并登记规则

> 依据：`.openfeel/plan/v1/stage-134/plan.md` §一（**A68.1—A68.8**）与 §二（T1—T6）。本文件只做需求级拆解，**不改判据含义、不新增需求外任务**。
> **2026-11-25 v3（计划审查 REJECT 后按实测修订）**：提示词预算改**渲染态**（`renderFeelPrompt`）；CI 语义纠正为「push 到 master 且版本变化才发，**tag/release 不触发**」；`release.mjs` 默认行为纠正（默认只 version+build，market/archive-commit/tag 需 flag）；版本替换范围收窄；风险补齐。细节见阶段计划 §五 F1—F6。

## 目标

- **做什么**：把版本号从 1.7.0 纠正为 **1.6.1**（补丁版；`package.json` + `dsh/package.json` lockstep），把发布流程改为「**push 到 master 且版本与 npm 不同 → CI `publish` job 自动 `npm publish`**」，并把**两条规则**登记到提示词与开发规则文件：① CI 自动发布（禁手动 `npm publish`）；② **版本号分级**——默认按补丁 `x.y.Z` 推进，结构性/行为性变更才升 minor，破坏性才升 major，小改不跳级。
- **事实锚点（实测）**：远端 npm 当前 `openfeel@1.6.0` / `openfeel-dsh@1.6.0`；`.github/workflows/ci.yml` 是 `on: [push, pull_request]`，publish job `needs: build-and-test`、`if: github.ref == 'refs/heads/master'`、按 `npm view openfeel/openfeel-dsh version` 判定版本变化 → **push master 且版本变化才发；tag/release 不触发；不需要手动 publish**。`scripts/release.mjs` 默认只做 `version`+`build`，`publish`/`market`/`archive-commit`/`tag` 默认 `skipped`，分别需 `--publish`/`--with-market`/`--commit-archive`/`--tag`；`--push` 尚不存在（需新增）。`test/scripts/release.test.ts` 现 **13 条 it**。本地 1.7.0 提交 `dd73dfaf` 尚未 push。
- **提示词锚点（渲染态实测）**：`renderFeelPrompt` → zh enabled **720 字符/14 行**、zh disabled **837/17**、en enabled **1027/13**、en disabled **1143/16**；上限 1200 字符/25 行 → **EN 补句 ≤50 字符**（余量 57）、**ZH 补句 ≤60 字符**。源 `dsh/lib/surface/prompt.js`（`FEEL_BODY_ZH` 598/11、`FEEL_BODY_EN` 804/10）只是中间量；4 份 `feel.md` 逐字镜像；`src/core/template-loader.ts` 是 `build.js` 生成物（禁手改）；parity `test/cli/feel-prompt-parity.test.ts` 5 用例；预算断言须**另建** `test/cli/feel-prompt-budget.test.ts`。
- **边界**：`v1.7.0-stage-133` 阶段 ID 作为**历史标识保留**（`flow.json` 禁手改）；只改 `src/ dsh/ docs/ scripts/ test/ package.json`；`.openfeel/**` 只改本阶段计划/需求正文的「当前版本」表述；不改 `flow.json` / `status.md` / `log/**` / `kb/**` / `dist/**` / `docs/market/**`；**不 push、不打 tag、不真实 publish**（发布归人类）。

## 风险

- **替换打穿测试/历史**：`dsh/test/**` 与 `test/**` 里 `v1.7.0` 文案与 stage id 混杂（`dsh/test/verify.js:1259`、`test/scripts/release.test.ts:279/291/293`）→ 只用 `1\.7\.0(?!-stage-133)` 边界式替换 + 逐文件 diff；排除 `.openfeel/**`、`dist/**`、`docs/market/**`、CHANGELOG 历史段；A68.3 用 `git grep -P` 排除式验收（残余仅 7 行 stage id）。
- **打穿既有 13 条 release 用例**：改 status 词或 reason 文案会让用例红 → 冻结词表、保留 `publish skipped` 子串、`--publish` 契约不变、默认 market/archive-commit/tag 仍 `skipped`、`publishMode` 仅由 `skipped` 改 `ci`（实测无 `=== 'skipped'` 断言）；确需改只改口径不删断言。
- **误 push 触发 CI 发版**：本阶段**不 push、不打 tag**；T4 验证阶段禁止 push；push 只在用户确认后、全部落地且 `node scripts/release.mjs --dry-run --skip-build` 绿时由人类一次性执行（`dd73dfaf` 一旦 push，CI 立即按版本差发布）。
- **规则文件写不进去**：`.openfeel/dev/dev_core.md` 不在 `PROTECTED_OPENFEEL_PATHS`（`dsh/lib/guard.js:766-787`），相位门可能仍拒 → 失败由 Feel/人类落盘，executor 给 patch 并登记偏差（T3、T5 都碰该文件，串行）。
- **EN 渲染预算超限**：en-disabled 已 1143，上限 1200 → 余量 **57** 字符；写多句解释即超 → 英文补句 **≤50 字符**（候选「Default patch bump; minor/major only if breaking.」= 49）、中文 ≤60；落地前后各跑一次 C7 渲染态测量；超了只压措辞，**不抬预算、不删既有检查点**。
- **parity 5 处哈希不一致**：只改 `prompt.js` 忘了 4 份 `feel.md`，或手改/格式化 `template-loader.ts` 生成物 → parity 红、提示词分叉；唯一做法是源 → 逐字复制 4 份 `feel.md` parity 块 → `npm run build` 重生成 → 5/5。
- **模板未同步**：只改本项目 `.openfeel/dev/dev_core.md`、没改 `src/core/templates.ts` → 新项目 `init` 仍无 CI 发布规则，A68.5「让新项目自带」落空 → 模板写通用规则（不写死日期），用 `grep -n "CI\|npm publish" src/core/templates.ts` + `npx vitest run test/core/init.test.ts` 双证。
- **预算测试写死数字**：断言精确长度会让 T5 每次微调都改测试 → `feel-prompt-budget.test.ts` 只断言 `<=1200` / `<=25`，基线数字只记在计划里。
