### B9-1（前置·必须最先执行）真实 Windows 终端乱码实测（TTY vs 管道）

- **目的**：判定 F1 的「乱码」在当前版本是否可复现，以及复现场景（交互 TTY / 管道），据此决定 A7。
- **实测矩阵（四种组合，逐一记录）**：

  | # | 终端 | 场景 | 命令 | 记录 |
  |:--:|------|------|------|------|
  | 1 | `powershell.exe`（5.1，`chcp` = 936） | **交互 TTY** | `node bin/openfeel.js flow status` | 是否乱码（截图/文本） |
  | 2 | `powershell.exe`（5.1） | **管道/重定向** | `node bin/openfeel.js flow status > out.txt` + 读取 out.txt | 是否乱码 |
  | 3 | `pwsh` 7 | 交互 TTY | 同上 | 是否乱码（对照） |
  | 4 | 任意 | `--json` | `node bin/openfeel.js flow status --json` | 是否乱码（预期否：纯 ASCII 键 + 可能含中文值） |

- **辅助取证**：`chcp`、`[Console]::OutputEncoding`、`$OutputEncoding`、`node -p "process.stdout.isTTY"`、`node -p "process.platform"`。
- **产出**：实测结论（乱码/不乱码 + 场景 + 证据）写入：
  1. 本 op 的执行报告（私有日志）；
  2. `.openfeel/manual/`（编码建议小节）—— **正文由归档官维护**，本 op 提供要点并登记 op-010 文档同步清单；
  3. `CHANGELOG` 若涉及行为变更则在 op-010 收口时登记。
- **禁止**：实测中**不得**修改用户终端设置、不得执行 `chcp`（仅**读取**当前值）。

### B7-1（中）尊重 `NO_COLOR` 环境变量

- **文件:行号**：`src/cli/index.ts`（CLI 入口；命令注册与 `applyHelpI18n` 所在文件）
- **现状**：`rg "NO_COLOR|no-color|setDefaultEncoding|chcp"` → **0 命中**（实测）；输出**当前无 ANSI 颜色**（无着色实现）。
- **改后**：
  1. 新增内部判定（单一入口）：
     ```ts
     /**
      * 是否启用彩色输出。
      * 优先级：--no-color（显式关闭） > NO_COLOR 环境变量（非空即关闭） > 默认（当前实现无着色 → 恒 false）。
      */
     function shouldUseColor(): boolean
     ```
  2. 规格遵循 **no-color.org**：`process.env.NO_COLOR` 存在且**非空** → 关闭着色（**不解析其值**）。
  3. 当前无着色实现 → 该函数为**契约与未来保护**（零可见变化）；补中文注释说明「未来引入着色时必须经此判定」。

### B7-2（中）全局 `--no-color` 选项

- **文件:行号**：`src/cli/index.ts`（`program` 构造处）
- **改后**：`program.option('--no-color', t('help.global.noColor', lang))`；`shouldUseColor()` 读取解析结果（commander 的 `--no-color` → `opts.color === false`）。
- **i18n**：`help.global.noColor`（zh/en 对称）。
- **行为变更**：**是（新增选项）**；纯新增（不影响既有调用）。

### B7-3（低）`--json` 与人类可读输出的「颜色无关性」契约（写入注释 + 测试）

- **改后**：在 `--json` 输出路径（op-001 落地）旁补注释与断言契约：「`--json` 输出**不含 ANSI**，且不受 `--no-color`/`NO_COLOR` 影响（本就无颜色）」。测试见 §六。
