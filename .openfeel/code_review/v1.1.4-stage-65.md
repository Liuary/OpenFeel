## 经验与建议

- **恢复能力分层而非替换**：缺省保持全量（向后兼容）+ `--stage` 收窄单子树 + `--dry-run` 只读预览，三种能力共存；**以磁盘为基底构造**待写数据（仅回写单子树），使「pipeline 其余字段不动」成为结构性保证而非逐字段回填。
- **恢复路径「顺序即优先级」**：`health` 诊断 → `stage reset` 精准 → `restore --stage` 回退 → **全量 restore 为最后手段** → `health --fix` 对账；显式声明每步写盘边界（`reset`/`restore` 改 `flow.json`，`--fix` 仅回写 status.md）。
- **对称能力**：`flow stage reset` 是 `flow advance` 的对称复位（允许回退 + 受值域/REV 约束 + 不触发归档 commit），补齐「推进 ↔ 复位」闭环。
- **dry-run 复用只读预览**：`restoreCheckpoint --dry-run` 直接复用 `previewRestore(...).ok`，避免第二套差异计算。
- **版本收口清单（A/B/C/D/E）**：按内容特征判定，`package-lock.json` 手工改两行禁 `npm install`、`.openfeel/config.yaml` 单行 `edit` 禁整文件 `write`。
