# REQ-060：DSH 提示词失效根因与改造：从「建议」到「不可忽略」

## 摘要

DSH 对提示词的遵守度极差：要求派子 Agent 却自己干、要求更新账本却不更新、要求先建阶段却直接动手。调研结论是**结构性问题**，不是模型能力问题：

1. **无强制后果**：只有 preflight（先读后写）和写入门禁有结构性拒绝，所以这两条遵守率高；「派子 agent / 更新账本 / 建 todo」没有任何检查点，违反成本为 0。
2. **指令与调用点脱耦**：规则全在约 5000 字符的 prose 里（79 行 / 13 节 / 51 处加粗），排在 order 40；工具返回的 `next` 恒指另一个读工具，模型永远收不到「你该派发了」。
3. **自身文本反向鼓励自己干**：「一次 edit 改多处」「建 todo 并汇报」与「调度者不是执行者」同权；同一节里两条互相矛盾；提示要求 `openfeel dev sync` 却没有对应工具。

## 目标与验收

**目标**：把关键规则从「建议」变成「不可忽略」——提示词结构性重写 + 运行时提醒 + 动作型工具面，并留下研究结论与量化方法。

- A10 提示词 ≤1200 字符 / ≤25 行，只保留角色 + 3 条「条件→动作→拒绝形态」检查点；Free Mode 附录 ≤120 字符。
- A10b 5 处副本（prompt.js + template-loader + claude/opencode feel.md）同哈希，parity 测试 5/5。
- A10c 每步提醒：优先 `post-execute.additionalContexts`，不可用则 `systemPrompt.context` 降级，结论写 `.openfeel/tmp/stage-132/spike.md`。
- A10d `feel_status.nextAction` 与 `feel_next` 同源，动作型（dispatch/command/idle），goal 无占位。
- A10e 研究结论落 `docs/research/prompt-adherence-2026-11-24.md`，含根因、三档改造、五项指标与 A/B 判据。

## 问题

- 长提示词把政策、工具参考、运维细则混成一块，关键禁令被稀释。
- 提示与工具面不耦合：说了要做，但没有对应动作入口，也没有反馈闭环。
- 缺少可观测指标，无法量化「遵守率」，也无法验证改造是否有效。

## 初步规划

2. reminder spike：30 行验证 post-execute 可用性，降级链写清。
3. `next-action.js` 纯函数 + 接入 status/next。
4. 研究文档化，指标定义与验证方法。
