# op-003：CLI 命令适配 — flow advance --stage 必选 + flow status 按阶段展示
- **阶段**：v4.1-stage-03
- **前置**：op-002（FlowManager 适配完成，advanceStagePhase 可用）
- **负责 Agent**：Executor
- **最多重试**：3

## 目标

适配 `src/commands/flow.ts` 中所有 CLI 子命令以适应多阶段独立 phase 架构：`flow advance` 的 `--stage` 参数升为必选，`flow status`/`flow overview`/`flow current` 改为按阶段展示。

## KB 参考

- 参见 kb/patterns.md #CLI 原子管理模式 — CLI 命令通过 FlowManager 方法操作，不直接 edit flow.json
- 参见 kb/troubleshooting.md #Agent prompt CLI 命令引用应预验证 — 所有新命令/参数应在方案中预验证存在性
- 参见 kb/architecture.md #Flow CLI 严格校验 — --stage 必选属于校验增强

## 实施步骤

- [ ] 1. `read` 本方案文件完整内容（必做）
- [ ] 2. **适配 `flow advance` 子命令**（约 30 行变更）：
  - 将 `--stage <id>` 从 `.option()` 改为 `.requiredOption()`（`--stage` 必须提供）
  - 错误提示优化：缺少 `--stage` 时输出"错误：--stage 参数必须指定阶段 ID（如 stage-03）"
  - 内部调用从 `mgr.advancePhase(opId, to, stage, force)` 改为 `mgr.advanceStagePhase(stage, to)` 
  - 保留 `--op` 选项但仅用于日志/展示，不再作为主要参数
  - `--to` 值的校验逻辑不变（PipelinePhaseSchema + transitions），但校验上下文基于 stage phase
  - `--force` 逻辑不变（走 fuzzyCorrectPhase 兜底）
- [ ] 3. **适配 `flow status` 子命令**（约 15 行变更）：
  - 基础模式输出增加各阶段 phase 展示：
    ```
    当前活跃阶段: stage-03 (exec_running)
    流水线状态: active
    ```
  - 阶段耗时统计部分增加每阶段的 phase 显示
- [ ] 4. **适配 `flow status --verbose` 模式**（约 10 行变更）：
  - "当前阶段" 行展示 pipeline.phase（active/paused/done）+ 各 stage phase
  - "下游 Agent 就绪状态" 基于活跃 stage 的 phase 构建
- [ ] 5. **适配 `flow overview` 子命令**（约 15 行变更）：
  - `phase` 显示来自当前 stage phase（非全局 phase）
  - 阶段总览表格新增 `phase` 列显示每阶段当前所处的流水线阶段
  - 表格列格式：`stageId: phase status ops进度 marker`
- [ ] 6. **适配 `flow current` 子命令**（约 8 行变更）：
  - 显示全局状态（active/paused/done）+ 当前 stage + stage phase + 当前 op
  - 示例输出：
    ```
    全局状态: active
    阶段: stage-03
    阶段阶段: exec_running
    当前操作: stage-03.op-001
    重试次数: 0
    ```
- [ ] 7. **适配 `flow recover` 子命令**（约 5 行变更）：
  - "流水线阶段" 行从中断点 stage 的 phase 读取（原从 RecoveryContext.phase）
- [ ] 8. **适配 `flow wizard` 子命令**（约 10 行变更）：
  - 交互式推进时增加 stage 选择步骤（如存在多个 stage）或自动使用 `current.stage`
  - 循环中 phase 读取改为从 stage phase 取值
  - 终态判断：pipeline.phase === 'done' 或所有 stage phase 均为 'done'
- [ ] 9. **适配 `flow health` / `flow repair`** — 底层 FlowManager 方法已适配（op-002），命令层无需额外变更
- [ ] 10. 运行 `npx tsc --noEmit` 验证编译通过
- [ ] 11. 运行 `node dist/cli.js flow --help` 确认 `advance` 子命令帮助中 `--stage` 显示为必选（`<required>`）
