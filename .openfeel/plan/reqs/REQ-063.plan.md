## 目标

- **目标**：需求生命周期加真正的审查窗口（`in_progress → review_pending → done`，可回退），让「先审后完成」有相位可挂；给 `req claim/advance/complete` 补 `--json` 与错误码，消灭「gate 码只能靠 human 文案 + exit 1 取证」的妥协；`review_pending` 下 `--to done` 缺审/缺验分别返回稳定两码。
- **现状证据**：`REQ_STATUSES`（`src/core/req/types.ts:11`）只有 7 值，无 `review_pending`；`ALLOWED_TRANSITIONS`（`src/core/req/requirement-ops.ts:830-836`）里 `in_progress: ['done', …]` 是**直连**；`applyStatusChange`（`:860-898`）已有 `RequirementGateCode`（`:51`，仅 `invalid_status|body_empty|plan_missing|plan_deviation`），done 门失败在 `:878` 一律返回 `invalid_status`（命令层再用 `doneGateMessage`（`src/commands/req.ts:120-130`）按 `requirementDoneBlocker` 分流文案，**没有机器可读码**）；`req claim`（`src/commands/req.ts:552`）、`advance`（`:828`）、`complete`（`:1022`）**没有 `--json`**，v1.6.0 的 `REQ_BODY_GATE`/`REQ_PLAN_GATE`/`REQ_PLAN_DEVIATION` 因此未进 `src/core/errors.ts`（stage-132 §十一 修订注 REV-016）。
- **边界**：`requirementDoneBlocker`（`src/core/req/requirement-ops.ts:217-232`）的三值与判定顺序（stage_phase → review → verification）**不改**；`describeStageDoneGate`（`src/core/flow-manager.ts:1936-1955`）**不改**；聚合收口旁路（`requirement_auto_complete`）行为不变。

## 验收判据

判据沿用**需求正文原编号**（只增不改），本需求对应 **A63.1 / A63.2 / A63.3 / A63.4**。必跑命令（仓库根，`REQ-R` 为临时工程内夹具需求，前置：`process.cwd()` 指向 `mkdtempSync` 临时目录）：

```bash
node bin/openfeel.js req advance REQ-R --to review_pending --json   # A63.1 正向第一跳（exit 0）
node bin/openfeel.js req advance REQ-R --to done --json             # A63.2 缺审/缺验 → exit 1 + 两码之一
# ↑ 补齐 `req review … --result pass` 与 `req verify … --result pass` 后重跑同命令 → exit 0
node bin/openfeel.js req advance REQ-R --to in_progress             # A63.1 回退（exit 0）
node bin/openfeel.js req advance REQ-R --to done                    # A63.1 直连被拒（exit 1，文案含 review_pending）
node bin/openfeel.js req advance REQ-R --to done --force            # A63.1 force 留痕（gate_overrides=['req_review']）
node bin/openfeel.js req claim REQ-R --json                         # A63.3 JSON 通道（成功/失败形状）
npx vitest run test/core/req.test.ts test/core/req-lifecycle.test.ts test/cli/error-envelope.test.ts
node bin/openfeel.js lint i18n
```

- **A63.1**：`getAllowedNextStatuses('in_progress')` 含 `review_pending`、**不含** `done`；`getAllowedNextStatuses('review_pending')` 含 `done` 与 `in_progress`；`flow.json.log` 的 `requirement_status` 条目依次为 `in_progress→review_pending`、`review_pending→done`（回退则反向）；`in_progress` 态直接 `--to done` → exit 1 且文案含 `review_pending`；`--force` → exit 0 且 `detail.gate_override.gate_overrides=['req_review']`。
- **A63.2**：三态断言——① 只缺 review：exit 1、stdout 恰一个 JSON、`error.code==='REQ_REVIEW_REQUIRED'`；② 只有 review pass、缺 verify：exit 1、`error.code==='REQ_VERIFY_REQUIRED'`；③ 两者均 pass：exit 0。**内部** `requirementDoneBlocker` 三值与判定顺序不变（`test/core/req.test.ts` 的 `T027.1` 三态用例零改动仍绿）。
- **A63.3**：`req claim/advance/complete --json` 均「stdout 恰一个 JSON 文档」；`REQ_BODY_GATE`/`REQ_PLAN_GATE`/`REQ_PLAN_DEVIATION` 进 `src/core/errors.ts` **且**进 `test/cli/error-envelope.test.ts` 契约表。
- **A63.4**：既有 done 门三态与 `test/core/flow-manager.test.ts` 的 done 门穷举用例**零改动**通过；`req board --json` 分组键＝旧 7 键 **+ `review_pending`**（新增不替换）；`lint req`/`dashboard` 键集只增不改；出口计数三处（`docs/json-contract.md` 头行 + `test/commands/knowledge.test.ts:384-401` + `test/cli/json-contract.test.ts`）同批为 **50/51**。

## 风险

- **打穿状态机**：加状态时顺手放宽 `blocked→done` 或保留隐式 `--force` 直连。规避——流转表是单点（`:830-836`），`req-lifecycle.test.ts` 穷举所有 `from→to` 组合；`--force` 只经 `buildGateOverrideAudit`（REQ-062 交付，含 `from`/`to`）留痕，不写第二条表。
- **done 门语义变化**：`requirementDoneBlocker` 若被改动（比如加入 `review_pending` 前置或改判定顺序），既有 `T027.1` 三态断言会红。规避——done 门判据（`:217-232`）**一字不改**；`review_pending` 只是**额外的相位前置**（流转表 + 相位门），新语义只体现在 `:878` 的「码化」与命令层映射。
- **两码混淆**：`stage_phase` 也被吞成 `REQ_REVIEW_REQUIRED` 会让「阶段还没进 exec_running」冒充「没审」。规避——只在 `blocker==='review'|'verification'` 时返回新码，`stage_phase` 保持 `invalid_status`（文案仍走 `doneGateMessage` 的 `doneGateTmpl`）。
- **计数锁漂移**：三个新出口 + 计数测试 + 文档同批；缺一处即 `input` 锁红（阶段计划 §六 R5）。`release` 不占出口编号（阶段计划 §1.2 选择 A）。
- **引用面漏改**：`list --status`/`board`/`next`/`release-check`/dashboard/lint 六处引用需求状态，任一漏改会出现「状态存在但分组不认」。规避——`grep -rn "'in_progress'" src/` 全量核对，并让 `req board --json` 的分组键含 `review_pending`（只增不改）。
