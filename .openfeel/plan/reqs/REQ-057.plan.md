# REQ-057 计划：主会话只调度（子 Agent 分角色执行并记录派发）

> 依据：`.openfeel/plan/v1/stage-132/plan.md` §1.1（判据 A7）、§2（T9、T13）、§5.4/§5.5。本文件不新增任务、不改判据。

## 目标

- **目标**：把"派发"变成一个**有记录的动作**——`feel_dispatch` 落 `.openfeel/dev/dispatch.jsonl`（受 guard 保护，工具直写被拒），`feel_status` 可见 `dispatch.records`，`feel_next().dispatch` 用真实 stage/phase/agent 填充。
- **问题**：`feel_mode` 对"用子代理"只是建议，主会话继续包办写文件；上下文爆掉后才暴露，且事后无法审计"到底是不是 Feel 自己写的"。
- **问题**：`dsh/lib/adapters/dispatch.js:12-35` 的派发模板 `goal` 字段是 `<一句话目标…>` 占位，`feel_next().dispatch` 是死模板；`.openfeel/dev/` 下没有任何派发台账。
- 来源：`plan.md` §1.1 的 A7。

## 验收判据

判据沿用 `plan.md` §1.1，本需求对应 **A7**。必跑命令（仓库根）：

```bash
# A7 工具层：feel_dispatch({stage,phase,targetAgent,role,goal,files,returnFormat}) 后 feel_status
wc -l .openfeel/dev/dispatch.jsonl            # 增 1 行，字段齐全、dispatchId 唯一
node bin/openfeel.js lint i18n                 # 适配器侧文案键对等
cd dsh && node test/contract.js && node test/verify.js && node test/guard.js && node test/integration.js
```

- 断言要点：`feel_status.dispatch.records ≥1`；用 `write` 工具直写 `dispatch.jsonl` → guard `deny`；工具计数 13 → **15**；`feel_next().dispatch.goal` 不含 `<一句话目标`。
- 合入前/后跑阶段级 **A11** 全量回归。

## 风险

- **用户裁定 ② 是"强提示不硬拦"**：`dispatch.required` 恒 true，不做角色门，也不新增 `dsh/cordis.patch.yml` 键。规避——不做写文件前的工具级拦截，只记录 + 提示；越界靠审计发现而非阻断。
- **guard 名单结构写错**：真实结构是 `{match:'file'|'dir'|'md', segments, hint}`（仿 `:687`/`:688`），不是 `{path,kind}`。规避——照抄既有条目，`matchProtectedEntries`/`matchProtectedPath` 不改。
- **`origin`/`delegationDepth` 未验证**：研究只确认 DSH `SessionHeader` 有该字段，适配器现只读 `header.cwd`。规避——T9 第一步 spike，不可读就省略这两个字段并记 `ADAPTER.md`，**不得**因此改审计 schema 版本。
