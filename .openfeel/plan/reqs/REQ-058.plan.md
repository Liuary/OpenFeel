# REQ-058 计划：模式语义收紧（general/fast 也必须 plan→exec→review）

> 依据：`.openfeel/plan/v1/stage-132/plan.md` §1.1（判据 A8/A8b）、§2（T5、T7）、§3 门禁表、§8.1 迁移。本文件不新增任务、不改判据。

## 目标

- **目标**：不改阶段转移表，把 plan → exec → review 的强制链落在**需求生命周期**上；`fast` 由 T5 的计划门达标（表本就够，**不改表**）。
- **问题**：`general` 模式的需求/阶段语义是"无流水线"——阶段转移表为空（`resolveTransitionsForMode` 的 `general → {}`），需求侧也没有任何强制链，等于免计划、免审查。
- **问题**：`fast` 语义模糊：表里其实已含 `plan_review` + `review`，但没有任何"计划存在且写实"的判据，所以"fast 有审查"只是名义上的。
- 来源：`plan.md` §1.1 的 A8 / A8b。

## 验收判据

判据沿用 `plan.md` §1.1，本需求对应 **A8 / A8b**。必跑命令（仓库根）：

```bash
node bin/openfeel.js flow phases --mode general --json                    # A8①：transitions 仍为空（回归保护）
node bin/openfeel.js req advance REQ-0NN --to in_progress                 # A8②：无计划 → REQ_PLAN_GATE
# 补 .openfeel/plan/reqs/REQ-0NN.plan.md 后
node bin/openfeel.js req advance REQ-0NN --to in_progress                 # A8③：exit 0
node bin/openfeel.js req review REQ-0NN --result pass --note "..."        # 先满足 done 门
node bin/openfeel.js req verify REQ-0NN --result pass --kind test --evidence "..."
node bin/openfeel.js req advance REQ-0NN --to done                        # A8④：缺回写证据 → REQ_PLAN_DEVIATION
node bin/openfeel.js flow advance --stage <无 plan.md 的 fast 阶段> --to exec_running   # A8b → STAGE_PLAN_GATE
npx vitest run test/core/req.test.ts test/commands/flow.test.ts
```

- 断言要点：A8① 的 `transitions` 必须仍为空；A8④ 补写 `## 偏差与回写` 实内容后同命令 exit 0。
- 合入前/后跑阶段级 **A11** 全量回归。

## 风险

- **把强制链写成阶段转移表**（R3）：表面"改了"实际死代码，且 T90.x 断言会红。规避——只动需求生命周期；`pipeline-schema.ts` 本阶段**无任务改动**。
- **存量 general 需求首次流转被批量拦**（§9.2 规则 5）：造成"补计划"负担超预期。规避——先由 `lint req` 的 `fill.emptyPlan` 列出规模；数量超预期时停手报 Feel，由用户决定是否一次性 `plan_waiver`（不默认开放）。
- **双判/重复文案**：T7 与 T5 同时判有阶段需求会产生两套提示。规避——组合③ 写死返回 null，只留 T5 一条文案链。
