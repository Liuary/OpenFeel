- **阶段**：v1.1.0-stage-37
- **前置**：op-001（hard）、op-000（soft，结论已在 op-001 以「绝对路径」落地，本 op 校验一致）

- **最多重试**：3

## 目标

落地 P2：框架 core 约束部署到 `~/.config/opencode/openfeel/core.md`（op-002/003 已实现，本 op 校验）；全局 opencode.jsonc `instructions` 引用绝对路径（op-001 已实现，校验）；项目 opencode.jsonc 不写 instructions（op-001 `buildProjectOpencodeJsoncObj` 已实现，校验）；并**退役 op-002/003 后已无人消费的死模板**（`opencode.jsonc` + `.gitignore`）。

> 参见 kb/architecture.md #模板单源架构（templates-data/opencode 唯一权威源）；kb/architecture.md #opencode 全局/项目 agent 与 skill 合并语义。

## REV-608 评估结论（保留独立 op 的理由）

op-004 的**核心产出是模板退役 + build.js 清理**（死模板 `opencode.jsonc`/`.gitignore` + 步骤 7 注入 + `validateOpencodeTemplates` 校验项删除 + template-loader 重生成），这是 op-002（init 代码）/ op-003（update 代码）**均不触碰的 build.js 与模板源域**；core.md 部署与 instructions 引用本 op 仅**校验不重写**，验收标准与 op-002/003 无重叠。故保留独立 op，聚焦「P2 校验 + 死模板清零」。

## 关键设计决策

1. **`~` 引用改用绝对路径（op-000 结论）**：全局 `instructions` = `[getGlobalCoreMdPath()]`（绝对路径，已由 op-001 `buildGlobalOpencodeFrameworkObj` 落地），本 op 校验不写 `~` 形式。
2. **死模板退役清单**：`opencode_jsonc` 与 `gitignore` 两个模板自 op-002 起无消费者（项目 opencode.jsonc 改由 `buildProjectOpencodeJsoncObj` 生成、`.gitignore` 不再部署到项目）；`instructions`（core.md 源）与 `adapter`（仓库自举 ADAPTER.md，build.js 步骤 8 仍用）**保留**。
3. **AGENTS.md 边界**：项目 `agents-md` 模板保持「项目级约束」定位；框架约束已全局化（core.md）。**内容裁剪留 stage-39**（本 op 仅校验 + 记录边界，不删改模板正文），与计划兼容性策略一致。
