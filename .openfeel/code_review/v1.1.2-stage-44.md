## 心得建议

1. **平台语义必须实测取证，不能凭文档/直觉**：本次三条既有认知被实测推翻（顶层 `permission` 不生效 / `write` 有效 / 自动追加全局 allow），全部靠隔离 HOME + 行为级判别器纠正。
2. **行为级判别器优于静态配置读取**：`ask` 在 `debug agent --tool` 下会**自动放行**（只能判 deny），必须用 `opencode run`（非 TTY 自动拒绝）才能区分 ask/allow。
3. **「补键」可能是行为变更而非显式化**：结论取决于平台默认值，须先确证默认（本例 `ask` → `allow`），否则安全口径评估失真。
4. **发现文档错误时不越界改他方文档**：在 findings 如实记录「未复现 / 冲突」并转审查/归档处置，比就地改写更利于审计追溯。
5. **待归档的勘误项须有明确 owner**：REV-003 显式标注「转归档阶段」并在阶段结论中保留，避免 low 项无人认领的漏网。
