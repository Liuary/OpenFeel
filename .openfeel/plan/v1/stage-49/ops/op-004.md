## 必查项（六维度）

1. **正确性**：build 各步骤与**双注入对象**（`SKILL_DEFINITIONS` / `OPENCODE_SKILL_DEFINITIONS` / `AGENT_TEMPLATES` / `AGENTS_MD_TEMPLATES` / `OPENCODE_AGENT_TEMPLATES`）的**一致性断言覆盖**（新增 skill/agent 是否自动纳入、断言是否对照同一权威源）。
2. **一致性**：zh/en **双语同步**（agents-md、agents）逐项 diff；skill 为中文单语（既有约定）；生成段与 `.opencode/` 自举含生成标记（**禁手改**）。
3. **文档-实现对齐**：agent frontmatter（`description`/`mode`/`model`/`reasoning_effort`/`permission`）与 opencode schema 对齐；`permission` 键集（含 `external_directory`，stage-44）zh/en 一致。
4. **边界与健壮性**：模板 `{项目名称}`/占位符替换；受管区标记（`<!-- openfeel:begin/end -->`）三态在 `agent.md`/`AGENTS.md` 的行为；`malformed` 降级。
5. **安全面**：**部署口径（新增必查 #7，见下）**；模板中是否含绝对路径/凭据；skill 指令是否可被注入误用。
6. **过度设计**：17 个 skill 是否存在职责重复（如 `openfeel-agent-model-check` vs `openfeel-model-check` vs `openfeel-model-config`）；`templates.ts` 与 `template-loader` 生成段是否双源。

### 必查 #7：部署型模板命令口径（**BUG-003 + REV-48 REV-009② 归属**）

- **裁定（写死，双口径）**：
  - **部署到用户环境的模板/skill**（用户项目通常无本仓 `bin/`）→ **`openfeel <cmd>`** 为主口径；并在文首加注「本仓自举/开发场景请用 `node bin/openfeel.js <cmd>`」。
  - **仓库内文档/手册/计划**（本仓执行场景）→ 保持 `node bin/openfeel.js <cmd>`（stage-48 H7；归 **U6** 复核）。
- **当前不符（证据）**：
  - `openfeel-cli-usage/SKILL.md` 约 **26 处**、`openfeel-wizard/SKILL.md` 约 **3 处**为 `node bin/openfeel.js`（stage-48 op-003 统一所致）→ 部署到用户环境后**不可执行**；
  - agent / agents-md 模板保留裸 `openfeel` → 与 REV-48 REV-009② 裁定一致（**正确**，不改）。
- **归属**：本项归 **U4**（模板/skill 口径）；U6 复核仓库内文档口径；**修复归属建议 = 后续补丁阶段**（low 非阻塞，stage-49 纯审查不修）。
- **取证命令**：
  ```bash
  rg -c "node bin/openfeel.js" src/core/templates-data/opencode/skills/openfeel-cli-usage/SKILL.md
  rg -c "node bin/openfeel.js" src/core/templates-data/opencode/skills/openfeel-wizard/SKILL.md
  rg -n "openfeel setup|openfeel flow wizard" src/core/templates-data/opencode/skills
  rg -n "^node bin/openfeel.js|node bin/openfeel.js" src/core/templates-data/opencode/agents/zh-CN/*.md   # 期望：0（agent 模板应裸 openfeel）
  ```
