# op-003：全局 `--project` 与 `--version --json`

- **阶段**：v1.2.2-stage-95
- **前置**：op-001 **hard**（`json-output.ts` 扫描器/`withSchemaVersion`/`emitJson`）+ op-002 **hard**（`failCli`/`emitErrorEnvelope`/`isJsonMode`；`src/cli/index.ts` 串行）。
- **负责 Agent**：openfeel-executor
- **最多重试**：3
- **对应计划**：T3（全局 `--project`，含 REV-95-003 四项边界）+ T4（`--version --json`）+ C2/C6 扩展路径；验收 §五.3/§五.4；风险 R-95-3/R-95-4；REV-95-003/005。
- **方案期裁定（本 op 相关，全量见 `ops/deps.yaml`）**：
  - **D-95-12（关键实测裁定：同名 `--project` 的 Commander 语义）**。实测（Commander）：根命令与子命令同名 flag 时，即使 `--project X` 写在子命令之后，**根选项也会消费该 token**，子命令 `options.project === undefined`，而 `optsWithGlobals().project` 可取到值。若 dedup 继续用 `options.project`，生产路径会退化为 cwd。**裁定**：保留 dedup 本地 `.option('--project <path>')`（help/语法零变化，C2 扩展路径），动作改用**单点解析函数** `resolveProjectPathForCommand(raw)`：
    - `runCli` 预扫描成功时返回预先解析的绝对路径（**禁止**对原始相对值二次 resolve，避免 chdir 后重复拼接）；
    - 直接 `program.parseAsync`（测试/库调用）无预扫描时，回退 `resolve(process.cwd(), raw ?? '.')`（保持既有 `knowledge dedup --project X` 语义）。
    - 多个 `--project` 解析后路径不一致 → `INVALID_ARGUMENT`（refusal/1）；一致 → 允许。
  - **D-95-13（语言边界实测修正）**：`bin/openfeel.js` 在调用 `runCli()` **之前**执行 `applyHelpI18n(program)`，因此 help 文案语言按**原始 cwd**解析；`runCli` 内 chdir 后，命令动作里的 `getCliLang(process.cwd())` 按**目标项目**解析。计划 T3.1 的「applyHelpI18n 在 chdir 后」表述与实测不符，**以实测为准**：契约文档登记「help 文案语言 = 原始 cwd；命令输出/错误文案 = 目标项目」。不移动 `applyHelpI18n`（避免改变 bin 顺序与双重应用）。
  - **D-95-14（`--log-file` 原始 cwd）**：`bin` 的 `installRuntimeLog()` 在 `runCli()`（chdir）之前执行，`resolveRuntimeLogConfig` 内 `resolvePath(override)` 天然按原始 cwd 解析。**本 op 不改 bin**；以测试证明「先解析后 chdir」的路径不变。
  - **D-95-15（`--version --json` 顺序）**：在 `setJsonMode` 之后、`applyProjectOption` 之前短路（纯信息命令，不依赖项目；非法 `--project` 不阻断版本查询）。输出 `{schemaVersion:1,version,node}`；`version` 复用 `package.json`，`node` 用 `process.version`（含 `v` 前缀）。纯文本 `--version`/`-v` 路径零改动。
  - **D-95-16（`--project` 错误分类）**：缺失值/空值/多值冲突 → `INVALID_ARGUMENT`（refusal/1）；路径不存在、非目录、chdir 失败 → `PROJECT_NOT_FOUND`（refusal/1）。消息语言按**原始 cwd**（目标路径可能不存在）。
  - **D-95-17（i18n 归属调整）**：`help.global.project` 与 3 条 project 错误文案键由本 op 随代码同批新增（避免 op-003 期间缺键告警/死键）；op-004 负责最终 `lint i18n` 基线与 C1~C6 同步核对。计划 T6 的 i18n 收口职责不变。

## 目标

### 2. 新增 `src/cli/project-option.ts`（单点解析 + chdir）

- [ ] 实现并导出（签名固定）：
  ```ts
  /** 提取全部 --project 值（含 --project=；缺失值置标志） */
  export interface ProjectArgResult {
    values: string[];
    missingValue: boolean;
  }
  export function extractProjectArgs(argv: string[]): ProjectArgResult;
  /** 单值便捷入口：取最后一个出现值（无则 null） */
  export function extractProjectArg(argv: string[]): string | null;
  /** 预扫描应用：成功 chdir 并返回 true；失败输出错误并返回 false（测试 mock exit 时） */
  export function applyProjectOption(argv: string[], originalCwd?: string): boolean;
  /** 命令层单点解析：预扫描结果优先；否则回退 resolve(cwd, raw ?? '.') */
  export function resolveProjectPathForCommand(raw?: string): string;
  /** 测试隔离：清空预扫描结果 */
  export function resetProjectRootForTest(): void;
  ```
- [ ] `extractProjectArgs` 复用 `scanArgv`（`src/commands/shared/json-output.ts`），**禁止第二套扫描逻辑**；仅处理 `--project <path>` / `--project=<path>`。
- [ ] `applyProjectOption` 流程：
  1. `const cwd = originalCwd ?? process.cwd()`；`const lang = getCliLang(cwd)`。
  2. `missingValue` → `failCli({ code:'INVALID_ARGUMENT', message:t('common.projectMissingValueTmpl', lang), detail:{ option:'--project' }, stderrLines:[t('common.projectMissingValueTmpl', lang)] }); return false;`
  3. `const resolved = values.map(v => resolve(cwd, v));`；`new Set(resolved).size > 1` → `INVALID_ARGUMENT` + `common.projectConflictTmpl`（detail `{ option:'--project', values: resolved }`）。
  4. 无值 → `resolvedProjectRoot = null; return true;`
  5. `statSync(abs)`：失败或 `!isDirectory()` → `PROJECT_NOT_FOUND`（detail `{ path: abs, reason: 'not-found' | 'not-directory' }`）。
  6. `process.chdir(abs)`；失败 → `PROJECT_NOT_FOUND`（detail `{ path: abs, reason:'chdir-failed' }`）。
  7. `resolvedProjectRoot = abs; return true;`
- [ ] `resolveProjectPathForCommand(raw)`：`if (resolvedProjectRoot) return resolvedProjectRoot; return raw ? resolve(process.cwd(), raw) : process.cwd();`
- [ ] 文件头中文注释写明：单进程单命令 → chdir 每进程至多一次；`--log-file` 在 bin 中先于本函数解析；help 文案语言按原始 cwd。
