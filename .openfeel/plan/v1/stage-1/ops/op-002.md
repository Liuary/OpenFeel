## 目标

在 CLI 侧加入 `feel_mode: enabled|disabled`（默认 enabled）的配置层与解析单点，打通命令面（get/set/effective）与 preflight 降级；`disabled` 只放松流程强制，不动状态机 / done 门 / 归档判据。

## 实施步骤

- [ ] 1. `src/core/config.ts`：
  - `ConfigDefaultsSchema` 加 `feel_mode: z.enum(['enabled','disabled']).optional().default('enabled')`；
  - `DEFAULT_CONFIG.feel_mode = 'enabled'`；`Config.defaults` 与 `ResolvedConfigDefaults` 加键；`resolveConfigDefaults` 的循环键数组加 `feel_mode`；
  - `ProfilePreferencesSchema` 加 `feel_mode`（值域 zod enum），**不加**进 `DEFAULT_PROFILE`；
  - 新增 `resolveFeelMode(projectPath): { value: 'enabled'|'disabled'; source: 'config.yaml'|'profile.yaml'|'builtin' }`：直接读原始 YAML（项目 `.openfeel/config.yaml` 的 `defaults.feel_mode`，其次 `getGlobalProfilePath()` 的 `preferences.feel_mode`），只认显式声明；非法/缺失逐层回落；读侧宽容（抛错视为无）。
- [ ] 2. `src/core/flow-manager.ts`：
  - `EFFECTIVE_CONFIG_KEYS` 追加 `'feel_mode'`；
  - `buildCascadeConfig` 在 profile 层读取 `preferences.feel_mode`（原始 YAML，与现有 `auto_advance` 同款），写入 `profileDefaults.feel_mode`；status.md 无该字段（不加匹配）；
  - 订正 2796-2802 与 2921 附近注释：profile 现在承载 `auto_advance` 与 `feel_mode`，`workflow_mode` 仍不承载。
- [ ] 3. `src/commands/config.ts`：
  - `GLOBAL_ALLOWED_KEYS` 加 `'preferences.feel_mode': ['enabled','disabled']`；`GLOBAL_PROFILE_KEYS` 加该键；
  - `config get --global` 的人类输出（六行硬编码，约 185-190 行）补第七行；`--json` 分支随 `GLOBAL_PROFILE_KEYS` 自动覆盖；
  - `config get --all` 的键序列加 `feel_mode`（固定五键序：execution_mode/auto_advance/merge_mode/workflow_mode/feel_mode）。
- [ ] 4. `src/core/preflight.ts`：
  - 新增内部 `resolvePreflightMode(projectPath)`：env 为 `off` → off（最高优先）；否则若 env=strict 且 `resolveFeelMode(projectPath).value === 'disabled'` → `warn`；其余保持 env 语义；
  - `checkPreflight` 用该函数取 `mode`（保证 `check.mode` 与实际判定一致）；`preflightGate` 逻辑不变；
  - 订正 `src/commands/shared/preflight-gate.ts:12` 的「preflight.ts 零改动」注释。
- [ ] 5. `CONFIG_TEMPLATE_ZH/EN`（config.ts 内）加 `feel_mode: ${DEFAULT_CONFIG.feel_mode}` 及注释（说明可关闭流程强制、阶段级不可覆盖）。
- [ ] 6. 文案面同步（「四键」这类硬编码）：
  - `src/core/i18n-data/zh-CN.ts` 与 `src/core/i18n-data/en.ts` 的 `config.get.all` 文案；
