# op-002：agent 重命名（8 个加 `openfeel-` 前缀 + P5 读取兼容 + normalizeAgentName）

- **阶段**：v1.1.0-stage-36
- **前置**：op-001（hard，须在收敛后的单树上重命名）
- **负责 Agent**：Executor
- **最多重试**：3

## 目标

8 个 agent（planner/schemer/executor/reviewer/feel-tester/utility/vision/archiver）全链路加 `openfeel-` 前缀，`feel` 保持原名；`mapPhaseToAgent` 返回新名；新增 `normalizeAgentName()` 实现读取兼容（大小写归一 + 幂等）；写入点全部改新名；`opencode.jsonc` 的 `agent.*` 键同步。不迁移 `flow.json` 历史。

> 参见 kb/patterns.md #新增 Agent 全链路更新清单模式（反向适用：9 项全链路清单）；kb/patterns.md #版本号重映射边界判定模式（区分「文件名」与「文本引用」）；kb/architecture.md #opencode 全局/项目 agent 与 skill 合并语义（名唯一是 stage-37 前提）。

## 关键设计决策

1. **子串陷阱安全策略（N6）**：`feel` ⊂ `feel-tester` ⊂ `openfeel-feel-tester`。采用「**先重命名文件/目录，再按 agent 名从长到短 + 负向断言做精确文本替换**」：
   - 文件级：`git mv` 8 个 agent 文件（`feel.md` 不动），文件名即新名，天然无子串误伤。
   - 文本级：替换顺序**最长优先**——`feel-tester` → `openfeel-feel-tester` 必须先于其它；`feel` 一词**永不替换**（既不改裸 `feel`，也不触碰已带 `openfeel-` 前缀的串）。
   - 统一用负向 lookbehind `(?<!openfeel-)` 守卫，杜绝二次前缀化：正则 `/(?<!openfeel-)\b(planner|schemer|executor|reviewer|utility|vision|archiver)\b/g` 与 `/(?<!openfeel-)\bfeel-tester\b/g`。
   - `openfeel` 项目名本身不含以上裸词，无 `feel` 规则误伤。
2. **normalizeAgentName 设计（REV-303/304）**：纯函数，导出供全库读取点复用。**内部 `toLowerCase()` 归一大小写**（解决 `scheme.ts` 写 `'Executor'`、`mapPhaseToAgent` 返回 `'executor'` 的不一致）；幂等（已是 `openfeel-*` 原样返回）；`feel`/`none`/`unknown`/非 agent 值（`flow-manager` 等）原样保留。
3. **P5 读取兼容范围**：仅 agent 名（skill 名不写 flow.json，无需兼容）；不批量改写历史 flow.json/日志/status.md。

### 步骤 2：运行时映射 + normalizeAgentName（flow-manager.ts）

**`mapPhaseToAgent`（L1504-1524）返回新名**：

```ts
  /** 将 PipelinePhase 映射为负责 Agent 标识（返回新名，供新写入使用） */
  private mapPhaseToAgent(phase: PipelinePhase): string {
    const prefix = phase.split('_')[0];
    switch (prefix) {
      case 'plan':
        return 'openfeel-planner';
      case 'scheme':
        return 'openfeel-schemer';
      case 'exec':
        return 'openfeel-executor';
      case 'review':
        return 'openfeel-reviewer';
      case 'test':
        return 'openfeel-feel-tester';
      case 'archiving':
        return 'openfeel-archiver';
      case 'done':
        return 'none';
      default:
        return 'unknown';
    }
  }
```

**新增 `normalizeAgentName`（模块级 `export function`，REV-405 修订：**不得置于 `FlowManager` 类内部——L1524 是 `mapPhaseToAgent` 方法闭合处，仍在类内**。放置位置为 **`FlowManager` 类闭合 `}`（L2793）之后**、`mapPhaseToStageStatus`（L2804）之前的模块级区域；`LEGACY_AGENT_NAME_MAP` 常量一并置于此处。备选：文件顶部 import 区（L27 之后）下方、`FlowManager` 类定义（L260）之前的辅助函数区）**：

```ts
/** 旧 agent 名 → 新名映射（读取兼容用；skill 名不在此列） */
const LEGACY_AGENT_NAME_MAP: Record<string, string> = {
  planner: 'openfeel-planner',
  schemer: 'openfeel-schemer',
  executor: 'openfeel-executor',
  reviewer: 'openfeel-reviewer',
  'feel-tester': 'openfeel-feel-tester',
  utility: 'openfeel-utility',
  vision: 'openfeel-vision',
  archiver: 'openfeel-archiver',
};

/**
 * 归一化 agent 名：旧名 → 新名（读取兼容 P5）。
 * 内部 toLowerCase() 归一大小写（'Executor' vs 'executor'，REV-304）。
 * 幂等：已是 openfeel-* 原样返回；feel / none / unknown / 非 agent 值（如 flow-manager）原样保留。
 */
export function normalizeAgentName(name: string): string {
  if (!name) {
    return name;
  }
  const key = name.trim().toLowerCase();
  // 已是新名（openfeel- 前缀）→ 原样返回，避免二次前缀化
  if (key.startsWith('openfeel-')) {
    return key;
  }
  return LEGACY_AGENT_NAME_MAP[key] ?? key;
}
```

## 风险与注意

- **自举风险**：改名后本仓库运行中会话的 agent 名变更，阶段收尾须提醒重启 opencode（op-004 步骤 4）。
- **子串误伤**：严格执行「最长优先 + `(?<!openfeel-)` 负向断言 + `feel` 不替换」；改名后全库 grep + 幂等断言兜底。
- **大小写（REV-304）**：`normalizeAgentName` 必须 `toLowerCase()`，否则 `scheme.ts` 大写 `'Executor'` 与 `mapPhaseToAgent` 小写 `'executor'` 比较失效。
- **`type: utility` vs `subagent_type: utility`**：前者任务标签不改、后者 agent 名改（op-002 任务 4 注意）。
- **叙述性文字**：human-readable 称呼按语义酌情保留，犹豫项标注回退，不得一刀切替换导致语义错乱。
