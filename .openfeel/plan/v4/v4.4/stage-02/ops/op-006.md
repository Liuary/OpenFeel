## 目标

对 op-001 至 op-005 的全部改动进行端到端回归验证，确保：(a) 日志上下文记录正确、(b) REV 闭环有效、(c) git 脏区警告生效、(d) 日志骨架自动创建、(e) Agent 提示词更新到位、(f) 全量测试通过无回归。

## 实施步骤

### 1. 日志上下文验证（op-001）

- [ ] 1a. 启动项目，通过 Feel 触发流水线推进（或直接调用测试脚本），验证 flow.json 日志中最近 `advance_stage_phase` 条目的 `agent` 字段不再恒为 `'flow-manager'`，而是记录实际触发者
- [ ] 1b. 使用 `openfeel flow log --last 5` 查看日志，确认 `agent` 字段正确
- [ ] 1c. 检查公域日志目录 `.openfeel/log/` 最近条目：确认不再出现逐条的 `advance_stage_phase` 状态变更，仅出现里程碑级别的 `stage_completed` 记录

### 2. REV 闭环验证（op-002）

- [ ] 2a. 手动在 `.openfeel/flow.json` 的 `reviews` 数组中添加一条 open 且 `blocking=true`（或未设置 blocking）的 REV 条目，其 `op` 字段匹配当前活跃阶段
  ```json
  {
    "id": "REV-TEST-001",
    "op": "v4.4-stage-02.op-test",
    "status": "open",
    "priority": "high",
    "title": "测试阻塞 REV",
    "filed_by": "test",
    "filed_at": "2026-07-14T00:00:00.000Z",
    "blocking": true
  }
  ```
- [ ] 2b. 执行 `openfeel flow advance --stage v4.4-stage-02 --to done` → 预期：拒绝推进，错误信息包含 `REV-TEST-001` 及标题
- [ ] 2c. 执行 `openfeel flow advance --stage v4.4-stage-02 --to done --force` → 预期：仍拒绝推进（输出额外 `--force` 不可绕过的警告），exit code ≠ 0
- [ ] 2d. 将测试 REV 的 `blocking` 改为 `false` 或不设置 → 再次执行推进 → 预期：正常推进（非阻塞 REV 不拦截）
- [ ] 2e. 清理测试 REV 条目（或直接编辑 flow.json 删除测试条目后重新执行 `openfeel flow repair`）

### 3. git 脏区检查验证（op-003）

1. **REV 测试数据污染**：手动向 flow.json 添加测试 REV 条目后，需在测试完成后清理。建议测试前备份 flow.json（`cp flow.json flow.json.test-bak`），测试后恢复。
