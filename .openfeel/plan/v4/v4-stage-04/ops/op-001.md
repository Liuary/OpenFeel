# op-001：Reviewer / Feel Tester 快速通道

- **阶段**：v4-stage-04
- **前置**：无（批次内独立 op）
- **负责 Agent**：Executor
- **最多重试**：3

## 目标

在 reviewer.md 和 feel-tester.md 中增加快速通道判定逻辑：当单次审查代码量 < 200 行 + Executor 自测全部通过 + 测试覆盖率达标时，Reviewer 跳过完整 5 维度审查、Feel Tester 快速验收放行。

## 实施步骤

- [ ] 步骤1：`read` 本方案文件完整内容
- [ ] 步骤2：读取 `.opencode/agents/reviewer.md` 和 `.opencode/agents/feel-tester.md` 确认当前结构
- [ ] 步骤3：修改 `reviewer.md`，在「审查流程」节前新增「快速通道」节：
  - 判定条件三要素：代码量 < 200 行 + Executor 自测全部通过 + 覆盖率 ≥ 80%
  - 命中快速通道时：跳过完整 5 维度审查，提交 `FAST-PASS-{NNN}` 标记（非阻塞），直接推进到 `review_passed`
  - 快速通过仍须提交审查结论摘要（至少 1 条 REV 标记，`blocking=false`）
- [ ] 步骤4：修改 `feel-tester.md`，在「测试类型」节后新增「快速验收」节：
  - 判定条件同上（从 flow.json 或审查标记获取快速通道标记）
  - 命中时：运行测试套件一次确认通过，验收即通过
  - 未命中时：走完整测试验收流程
- [ ] 步骤5：确保两个 Agent prompt 中快速通道的条件描述一致（交叉引用）

## 产出文件

- `.opencode/agents/feel-tester.md`（修改）

- [ ] `feel-tester.md` 中存在「快速验收」节，条件与 Reviewer 一致
- [ ] 两个 Agent 文件中代码行数阈值一致（均为 200 行）
