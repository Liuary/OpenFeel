## 实施步骤

- [x] 步骤1：`read` 本方案文件完整内容
- [x] 步骤2：读取 `src/core/pipeline-schema.ts`、`src/core/flow-manager.ts`、`src/commands/flow.ts` 全文
- [x] 步骤3：**pipeline-schema.ts** — 新增 `StageStats` 接口：
  ```typescript
  interface StageStats {
    start_time: string;   // ISO 8601
    end_time: string;     // ISO 8601，未完成时为空
    duration_ms: number;  // 毫秒，未完成时为 0
  }
  ```
- [x] 步骤4：**flow-manager.ts** — 扩展 `FlowData.stages` 的类型，每个 stage 增加可选的 `stats` 字段：
  - 新增 `startStage(stageId)` 方法：记录 `start_time`
  - 新增 `endStage(stageId)` 方法：记录 `end_time`，计算 `duration_ms = end_time - start_time`
  - 新增 `getStageStats(stageId)` 查询方法
  - 在 `advancePhase()` 中自动调用：当 phase 推进到终态（`done` / `plan_passed` 等）时自动调用 `endStage()`
- [x] 步骤5：**flow-manager.ts** — 新增 `recoverContext()` 方法：
  - 从 `flow.json` 读取 `pipeline.phase` / `pipeline.current` / `stages` 状态
  - 从对应 `status.md` 读取当前阶段详细状态（执行模式、阻塞原因、任务完成度）
  - 返回结构化的 `RecoveryContext` 对象：`{ phase, currentOp, stageStatus, blockedBy, pendingTasks }`
- [x] 步骤6：**flow.ts** — 展示增强：
  - `flow status` 默认输出中增加各阶段耗时行（已完成阶段显示 duration）
  - `flow status --verbose` 中增加跨会话恢复信息（上次会话状态摘要）
  - 新增 `flow recover` 子命令，调用 `recoverContext()` 输出完整恢复上下文
