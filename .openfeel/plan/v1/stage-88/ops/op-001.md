## 目标

以**实测先行**回答一个二值问题并全程留痕：opencode 侧 subagent 能否经嵌套 `task` 直接调度下一级 subagent（**go / no-go**）；同时复核 Claude 侧「subagent 不可调 Task」（v1.1.6-stage-69 Q1 是否仍成立）并核验 Handoff 直发通道的证据等级。**未实测的能力不得作为既成事实**；受限一律「保守默认 + 如实留痕」。

## 实施步骤

- [ ] 1.1 **环境与零污染基线快照（对照面）**
  - 记录：`opencode --version`、`claude --version`、OS / Shell；真实 `~/.config/opencode/` **文件清单 + 逐文件 sha256 + max mtime**；`~/.openfeel/` 文件数与 mtime；认证文件实际位置与 mtime（**不打印任何 token / 凭证内容**）。
  - 全部原始输出贴入报告（三要素：命令 + 版本 + 环境）。
- [ ] 1.2 **隔离 HOME 双设 + 隔离生效断言（kb 四步法 ①~②）**
  - **双设**：`HOME` 与 `USERPROFILE` **同时**指向 `%TEMP%\openfeel-oc-verify\home`（Windows 仅设其一**不生效**——kb 判据）。当前 shell 会话内设置（子进程继承），**不使用 `setx`**（不污染用户环境）。
  - 断言：`opencode debug paths` 的 `home` / `config` / `data` / `state` **全部**指向隔离目录；**贴原始输出**。
  - **STOP 条件**：出现 `config dir mismatch` 或任一路径指向真实 HOME → **立即停止**，判定「隔离未生效」，本节记为「环境受限」并转 1.7 保守分支（**不得**在真实全局目录上继续试验——R-88-9）。
- [ ] 1.3 **fixture 铺放（隔离目录内）**
  - 将 6 份改造副本（`openfeel-{planner,schemer,reviewer,archiver,utility,vision}` × `{zh-CN,en}`）铺入隔离的 `{config}/agents/`（`config` 路径以 1.2 的 `debug paths` 输出为权威）；`feel` / `executor` / `feel-tester` 按现状**原样**复制（提供完整注册表）。
  - 改造副本 = 在**隔离目录内**对仓库源副本（`src/core/templates-data/opencode/agents/{zh-CN,en}/`）手工增补 `  task: "allow"` 行（**插入位：紧跟既有 `grep: "allow"` 行之后**）——**不得改动仓库内任何模板**（仓库源改动归 op-002）。若本 op 在 op-002 之后执行 → 直接取 op-002 产物（两者等价；报告须注明取源方式）。
  - 复制认证文件入隔离目录（用后随目录删除；**不回写、不外传、不打印**）。
- [ ] 1.4 **静态 ruleset 复核（计划 C5 条 ⑤）**
  - `opencode debug agent openfeel-planner`（并抽 `openfeel-schemer` / `openfeel-reviewer`）→ 记录 effective ruleset 中 `task` 是否出现且值非 `deny`。
  - **工具局限登记（写进报告）**：`debug agent` 对 `ask` 自动放行、仅强制 `deny` → **不可**据此判 allow / ask（kb 判据）。
- [ ] 1.5 **行为级判别（权威判据；计划 C5 条 ⑥）**
  - 命令：`opencode run --agent openfeel-planner "<探针 prompt>"`；探针 = **只读、低代价**：要求 `openfeel-planner` **直接调度 `openfeel-executor`** 执行一条无害命令（例：输出固定字符串 `nested-task-probe` 的 node 单行命令）并把结果回传。
  - 非 TTY 下 `ask` 会**自动拒绝并打印 `permission requested: ...`** → 可区分 allow / ask / deny。
  - **判定三要素**（缺一即 no-go）：① 子 agent 是否成功**调起下一级会话**；② 目标 agent 是否**被正确指定**（Q13 四项观察：是否创建子会话 / permission 是否继承 / 递归深度限制或挂起 / 目标指定方式）；③ 结果是否**回传父会话**。
  - 建议同跑 `--format json` 留结构化原始输出；报告贴**逐字输出摘要 + 命令**。
  - **受限分支**：run 因认证 / 网络 / 模型不可用而无法完成 → 标注「未实测（环境限制）」并走 1.8 降级分支（**不得**以静态证据冒充行为证据——Q3 禁止项）。
- [ ] 1.6 **清理与零污染核对（kb 四步法 ④）**
  - 删除隔离目录 `%TEMP%\openfeel-oc-verify\`（整体）；清除本 shell 会话的 `HOME` / `USERPROFILE` 覆盖。
  - 重跑 1.1 对照面：真实 `~/.config/opencode/` **文件清单 + 逐文件 sha256 + max mtime 逐项一致**；`~/.openfeel/` 文件数与 mtime 一致 → 零污染断言（逐项列表写入报告）。
- [ ] 1.7 **Claude 侧 Q1 复核 + Handoff 通道核验（T1.2）**
  - **Q1 复核（尽力行为级）**：`CLAUDE_CONFIG_DIR` 指向隔离目录 → 铺放 agents + CLAUDE.md + **复制作数认证 + `settings.json`** → 铺一份**带 `Task` 的 subagent fixture**（试探性，**不入仓**）→ `claude -p` 派发该 subagent 并要求其调度另一 subagent → 观察是否报「工具不可用 / 未知工具」。记录 `claude --version`。
  - **受限处置（预置，计划 T1.2 原文口径）**：隔离 config 无认证 → `Not logged in`、或环境受限无法派发 → **标注「未实测（环境限制）→ 沿用 Q1 保守默认（subagent 不可调 Task）」**，**不得**声称实测通过。
  - **Handoff 通道核验（证据分级，硬性）**：
    - ① **静态在位**（本 op 完成）：feel 模板 ×4 的 `[HANDOFF: {agent_name}]` 解析 4 步 + 目标表**逐份实测在位**（登记 file:line，见「背景锚点」）。
    - ② **行为级**（**主会话（Feel）职责**——本 op executor 不越界）：实际链路「子 agent 返回 `[HANDOFF: openfeel-executor]` → 主会话同轮解析并派发 → 结果回传」，三要素（触发 → 解析 → 派发）由 Feel 在阶段报告（op-003）补录。
    - 报告须为 ② **预留条目**并标注**当前证据等级**（「行为级已实测」/「仅静态在位」/「未实测（未触发）」）——**禁止**自造链路证据（降级红线）。
- [ ] 1.8 **判定表与降级触发（Q3 定稿判据）**
  - **go** = 1.4 静态含 `task` 且非 deny **且** 1.5 行为级三要素齐备；**其余一律 no-go**（含「未实测」）。
  - **降级红线（触发时逐条执行并留痕）**：① opencode 侧**保留** permission 扩展（零成本、为未来平台能力留门）；② 两 harness **统一以 Handoff 直发为主通道**；③ 模板文案**如实**（不把「可直接 `task` 调起」写成既成事实——注：T2.2 骨架不点具体通道工具，**go / no-go 两分支下均成立**，见 Q3 相容性条款 `plan.md:255`）；④ 本报告 + 阶段报告双处留痕。
  - **与模板落文的交界**：本 op **不产出**任何模板文案（归 op-002）；本 op 只产出**口径结论**（go/no-go + 是否降级 + Q13 观察结果）。
