# op-003：聚焦与单一真源：stage add 原子聚焦 + flow next 派生 + status.md 派生写 + deps 序列化（P1-1/P1-2）

- **阶段**：v1.3.3-stage-104
- **状态**：pending
- **前置**：无（与 op-001/op-002 文件集不重叠：本 op 改 `plan/stage.ts`、`advanceStagePhase`、`flow next`、dsh serializer）
- **负责 Agent**：openfeel-executor
- **最多重试**：3
- **对应问题**：P1-1（`plan stage add` 后 `flow next` 报无活跃阶段）、P1-2（责任 Agent 双真源、deps 渲染 `[循环引用]`）

## 目标

让「注册」与「聚焦」原子化；让 `flow next` 在 current 缺失时可只读派生；让 `status.md` 的受管字段成为 flow.json 的**派生视图**（仅 CLI 写）；修掉适配器序列化器把 DAG 重复引用误判为环的问题。

## 涉及文件

- `src/core/plan/stage.ts`（`addStage` 聚焦 + 骨架责任 Agent 初值）
- `src/core/flow-manager.ts`（`advanceStagePhase` 派生写 status.md；`syncStatusFields` 单点）
- `src/commands/flow.ts`（`flow next` 无 current 时派生 + 多活跃 tie-break）
- `dsh/lib/tools/shared.js`（`stringifySafe` 祖先栈判环）
- `dsh/lib/adapters/dashboard.js`（`deps` 显式复制数组，双保险）
- `dsh/test/integration.js` 或 `dsh/test/verify.js`（序列化用例，按现有 dsh 测试布局择一）
- `test/commands/plan.test.ts`、`test/core/flow-manager.test.ts`、`test/commands/flow.test.ts`

## 实施步骤

- [ ] 1. `plan/stage.ts addStage`：`registerStage` 后、`save()` 前，原子设置 `pipeline.current = { stage: parsed.fullStageId, op: '' }`；保持 `flow stage add` / `stage create`（走 `FlowManager.addStage`）行为不变。
- [ ] 2. 骨架 status.md：`- **当前责任 Agent**：` 初值由 `user` 改为 `skeletonMgr.getResponsibleAgent('plan_pending')`（= `openfeel-planner`，与 `flow next` 同源单点）；`上一责任 Agent` 保持 `none`。
- [ ] 3. `flow next`：`activeKey` 为空时**只读派生**——优先 `pipeline.current.stage`（若仍活跃，覆盖 current 悬空场景），否则按 `Object.entries(data.stages)` 插入序取首个 `phase !== 'done'`；命中后照常填充 phase/legalNextPhases/guards，并在 guards 末位追加一条「由 stages 派生（current 为空）」提示；**不写盘**。
- [ ] 4. `advanceStagePhase`：在 `stage.status = newStatus` 后调用新私有方法 `syncStatusFieldsManifest(key, targetPhase, fromPhase)`：
  - 仅写**受管字段**：`状态`（`mapPhaseToStageStatus` 结果）、`当前责任 Agent`（`mapPhaseToAgent(targetPhase)`）、`上一责任 Agent`（`mapPhaseToAgent(fromPhase)`；`plan_pending` 首次推进时保留 none）、`更新时间`（`YYYY-MM-DD HH:mm`）；
  - 复用按阶段锁 + 原子写；**一次读→一次写**（新增 `writeStatusFields(statusPath, fields)` 单点，内部走既有 `withFileLock`/`atomicWriteFileSync`）；
  - status.md 缺失 / 字段缺失 → 跳过（不新建文件、不报错、不阻塞推进）；
  - 显式注释：**仅 CLI 派生写；Agent 手改 status.md 仍由 guard 拒绝**。
- [ ] 5. `dsh/lib/tools/shared.js`：`stringifySafe` 改为**祖先栈**判环（进入对象/数组时入栈，返回时出栈；同层重复引用正常复制，只有真环写 `[循环引用]`）；保留 BigInt → 字符串、异常兜底。
- [ ] 6. `dashboard.js`：`focus.deps` / `stages[].deps` 改为 `[...deps]` 复制（与序列化器修复互为双保险）。
- [ ] 7. 测试：
  - `plan stage add` 后 `flow.json.pipeline.current.stage` = 新阶段；`flow next --json.stage` = 新阶段（无需 advance）。
  - `flow next` 在 current 空 + 两个活跃阶段时 → 取插入序首个；`pipeline.current` 仍为空（只读）。
  - `advance` 后 status.md 的「状态 / 当前责任 Agent / 更新时间」与 flow.json 一致（`flow next.responsibleAgent` 同值）。
  - `stringifySafe`：`{a:x,b:x}`（同数组）→ 两处完整数组；真环（`x.self=x`）→ `[循环引用]`；BigInt 正常。
- [ ] 8. 局部测试 + `npx tsc --noEmit` 0；`node --check dsh/lib/tools/shared.js dsh/lib/adapters/dashboard.js`。
