# op-003：DSH 适配器：feel_mode 镜像解析 + workflowGate 放宽 + 自由模式提示词 + 工具输出

- **阶段**：v1.5.17-stage-1
- **状态**：pending
- **前置**：op-002（CLI 侧 `resolveFeelMode` 语义已定，镜像必须与之一致）
- **负责 Agent**：openfeel-executor
- **最多重试**：3

## 目标

让 DSH 适配器每轮同步读取 feel_mode：`disabled` 时不再催建需求/阶段（workflowGate 放宽），系统提示切「自由模式」，但保留门禁自检（guard-*）与数据完整性硬门提示；`feel_status` / `feel_next` 暴露当前模式与来源。

## 实施步骤

- [ ] 1. 新增 `dsh/lib/adapters/feel-mode.js`（纯 JS、同步 IO）：
  - `resolveFeelMode(projectRoot)` → `{ value: 'enabled'|'disabled', source: 'config.yaml'|'profile.yaml'|'builtin' }`；
  - 项目：`<root>/.openfeel/config.yaml` 的 `defaults:` 块下 `feel_mode:` 行（窄解析：行首缩进 + 键名 + 值）；
  - 全局：`~/.config/openfeel/profile.yaml`（`os.homedir()`）的 `preferences:` 块下 `feel_mode:`；
  - 只认显式声明；非法值/读取失败跳过；两者都无 → `{ enabled, builtin }`；
  - 头注释声明：**镜像 `src/core/config.ts:resolveFeelMode`**，两侧同矩阵测试；并说明为何不用「CLI 写状态文件」方案（改配置后未发生 CLI 调用时会滞后，违背即时生效）。
- [ ] 2. `dsh/lib/adapters/workflow-gate.js`：调整顺序——guard 三条自检保持最前；仅把 `no-active-stage` 分支替换为：
  - `snapshot.feelMode?.value === 'disabled'` → `{ required: false, reason: 'feel-mode-off', message: '', actions: [] }`；
  - 其余（enabled/缺失）保持既有 no-active-stage 文案逐字不变；
  - **`workflowGateTitle` 约束（防回归）**：`feel-mode-off` 的 `message` 恒为 `''`，且**不新增** case（落入 `default` 分支时返回空 message → `headlineWarning` 返回空串）；严禁给它任何文案，否则会产出「⚠ 自由模式」类标题；
  - 更新头注释（v1.5.17：软关闭）。
- [ ] 3. `dsh/lib/surface/prompt.js`：
  - `renderFeelPrompt({ projectRoot, detected, language, feelMode })`；
  - `disabled` 时：`<feel_mode>` 开头状态行改为「Feel 模式已启用（feel_mode=disabled：自由模式）」，并新增「## 自由模式（feel_mode=disabled）」节：不强制建需求/阶段、由你判断是否需要流程、先读后写降级为提示、**仍保留**的状态机/done 门/归档判据/写入门禁清单、归档与发布仍需用户确认；其余章节（角色/派发契约/状态记录等）保留；
  - `enabled` 时输出**逐字不变**；中/英两份同步。
- [ ] 4. `dsh/lib/index.js`：`text()` 内 `resolveFeelMode(resolved.projectRoot)` 并传入 `renderFeelPrompt`；未初始化 bootstrap 分支不传（本版不感知）。
- [ ] 5. `dsh/lib/tools/index.js`：
  - `feel_status` / `feel_next`：`snapshot.feelMode = resolveFeelMode(resolved.cwd)`（在 `computeWorkflowGate` 之前）；
  - `compactStatusSnapshot` 增加 `feelMode: snapshot?.feelMode ?? null`；
  - preflight 展示一致：若 `feelMode.value === 'disabled'` 且 `preflight.mode === 'strict'` → 展示 `mode: 'warn'`；
  - `feel_next` 的 plan 输出附 `feelMode`。
- [ ] 6. 不改 `adapters/cli.js` 的 `OPENFEEL_PREFLIGHT: 'strict'` 注入（降级权威在 CLI 侧 op-002；避免两处语义分叉）。
