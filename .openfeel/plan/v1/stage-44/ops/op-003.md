## 变更目标

在 `op-002` 修改权威源后运行 `npm run build`，重生成 `template-loader.ts` 的 `AGENT_TEMPLATES` / `OPENCODE_AGENT_TEMPLATES` 生成段与 `.opencode/agents/*.md` 自举实例，并确认构建的**单一源一致性**校验通过。

**需求映射**：`docs/phase-5/07-openfeel-permission-issue.md` §四建议 1 的**部署链路**（权威源 → build 注入 → `openfeel setup` 部署）；kb「模板单源架构」。

> 参见 kb/architecture.md #模板单源架构（templates-data 唯一权威源 + 双注入对象 + 单源一致性断言）、kb/patterns.md #构建脚本多语言循环生成模式、#跨平台行尾归一化模式。

## 关键设计决策

1. **只经 build 生成**：`template-loader.ts` 生成段与 `.opencode/**` 均为**构建产物**，**禁止手改**（有 `AUTO-GENERATED-BEGIN/END` 锚点与生成标记）。
2. **双注入对象**：build 步骤 2 → `AGENT_TEMPLATES`（权威源原始模板，供 `loadAgentTemplate`）；步骤 5 → `OPENCODE_AGENT_TEMPLATES`（供 `openfeel setup/update` 部署）。二者均含 `permission`，须**同时**反映补键。
3. **自举重生成**：build 步骤 8（`build.js:1040-1098`）清空并重建 `.opencode/agents|skills|instructions|ADAPTER`（含生成标记）。
4. **最小 diff 纪律**：期望 diff 仅限（a）`src/core/template-loader.ts` 内与 agent permission 相关的生成段 +（b）`.opencode/agents/*.md`。**若出现无关 diff**（如 skills/AGENTS-md/config 模板段无端变化），说明存在既有漂移 → **记录并上报 Feel**，不得强行提交掩盖。
5. **不做版本收口**：版本号/CHANGELOG 归 stage-43（U1 清单），本 op 不触碰。

## 风险与回滚

| # | 风险 | 缓解/回滚 |
|---|------|-----------|
| 1 | 手改生成段（R4） | 全部经 build；锚点/生成标记保证可识别 |
| 2 | 无关 diff（既有漂移） | 决策 4：记录上报，不掩盖；回滚 = `git checkout` 生成段后重跑 build |
| 3 | build 断言失败（模板不一致） | 检查 op-002 是否漏改某语言/某文件；修复后重跑 |
| 4 | `.opencode/agents` 旧名残留 | build 步骤 8 先清空再重建；`git status` 核验无旧名 |
| 5 | 误引入版本/CHANGELOG 改动 | 决策 5：本 op 不碰版本载体 |
| 6 | 两次 build 结果不一致（非幂等） | 验收 4 显式断言幂等；不一致则上报（属构建缺陷，另立） |
