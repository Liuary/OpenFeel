# op-004：审计日志补齐（`register_stage` 与 `register_op`）+ `scheme.ts` 兜底冲突检测

- **前置**：无 hard（`stage-41` 已执行完毕，其 `path.ts` 已导出 `validateStageId`（`:102`）/ `findStageDirConflict`（`:179`），本 op ③ 直接复用）；与 op-001/op-002/op-003 同改 `flow-manager.ts` → **串行**（deps.yaml 互斥组）
- **负责 Agent**：openfeel-executor
- **最多重试**：3

## 目标（含反馈条目）

为两处缺失的写路径补 `flow.json` 审计日志：`registerStage` → `register_stage`、`plan scheme create`（`syncToFlowJson`）→ `register_op`；并接入 `stage-41` 遗留的 `scheme.ts` 兜底自动注册路径的冲突检测。

**对应反馈**：`docs/phase-5/06-openfeel-tooling-feedback.md` 问题 #7（中）「关键 CLI 状态变更不写审计日志」。
**对应决策**：P7（**仅补缺口**，不重构既有 10 处 `appendLog`）+ REV-42-002（双轨日志说明）+ REV-v1.1.2-stage-41 REV-003（`scheme.ts` 兜底路径冲突检测归并本 op）。

> 参见 kb/patterns.md #CLI 原子管理模式、#flow.json 乐观并发校验模式、#stageId 三格式解析 + plan 目录双向映射模式。

## 关键设计决策

1. **仅补缺口（P7）**：只在 `registerStage`（现 `:718-737`）与 `scheme.ts syncToFlowJson` 补日志；**不重构**既有 `appendLog` 调用点（现 8 处：`:1081`/`:1159`/`:1291`/`:1729`/`:1748`/`:1766`/`:1854`/`:2505`）。
2. **action 命名对齐既有风格**：既有为 `add_stage`、`advance_stage_phase`、`attempt_fail_exhausted`、`auto_fix_review`、`register_op`（本 op 新增）等「动词_名词 / 名词_动词」蛇形；本 op 新增 `register_stage`、`register_op`，均为「动词_名词」，风格一致。
3. **双轨语义（REV-42-002，写死并注释）**：

   | action | 来源方法 | 入口命令 | 层级 | agent |
   |--------|----------|----------|------|-------|
   | `add_stage` | `FlowManager.addStage`（`:1136`，日志 `:1159`） | `flow stage add` / `stage create` | **注册层**（仅 flow.json） | `flow-manager` |
   | `register_stage` | `FlowManager.registerStage`（`:718`） | `plan stage add` | **完整层**（建目录 + overview/status + 注册） | `cli` |
   | `register_op` | `scheme.syncToFlowJson` | `plan scheme create` | op 注册 | `cli` |

   `add_stage` 与 `register_stage` **入口不同、层级不同，非重复**；须在代码注释 +（stage-43）skill 文档中说明，避免审计查询歧义。
4. **幂等不写日志**：`registerStage` 同 stageId 已存在时 `return`（幂等跳过）→ **不写** `register_stage`；`addStage` 已存在时抛错 → 不写。保证日志只记录**实际新增**。
5. **兜底路径冲突检测不静默吞错**：`syncToFlowJson` 的自动注册分支位于大 `try/catch`（`:135-145`，非并发错误**静默忽略**）内，若 `throw` 会被吞。故冲突/非法时采用 **`console.warn` + `return`（跳过自动注册）**，使缺口显式可见且不破坏「op 文件已创建」的既有契约。
6. **不额外写「兜底 register_stage」**：兜底自动注册与本条 `register_op` 同批发生，`register_op` 已含 `stageName`，不重复写 `register_stage`（避免双记）。
7. **既有观察项（非缺陷）**：`init.ts:381` 也调用 `registerStage(demoStageId, [])` → `openfeel init` 的 flow.json 将含一条 `register_stage` 日志。属**正确审计**（init 是 CLI 状态变更），保留。

## 精确改动点（文件:行号 → 现状 → 改后）

### 改动 1：`src/core/flow-manager.ts` `registerStage`（现 `:718-737`）补 `register_stage`

- 现状（结尾）：
  ```ts
  this.data.stages[stageName] = {
    name: stageName,
    phase: 'plan_pending' as PipelinePhase,
    status: 'planned',
    deps,
    ops: {},
  };
  }
  ```
- 改后：在赋值之后、方法结束前追加：
  ```ts
  this.data.stages[stageName] = {
    name: stageName,
    phase: 'plan_pending' as PipelinePhase,
    status: 'planned',
    deps,
    ops: {},
  };
  // 审计日志（P7）：仅在实际新增时写入；同 stageId 幂等跳过时不写。
  // 注：与 addStage 的 'add_stage' 双轨——add_stage=注册层（flow stage add/stage create），
  //     register_stage=完整层（plan stage add），入口不同非重复（REV-42-002）。
  this.appendLog({ time: '', agent: 'cli', action: 'register_stage', detail: { stageName, deps } });
  }
  ```
- 说明：`appendLog`（`:1871`，public）已可用；调用方 `plan/stage.ts:104` 随后 `save()` 落盘。

### 改动 2：`src/core/plan/scheme.ts` import 扩充（`:9`）

- 现状：`import { parseStageId } from './path.js';`
- 改后：`import { parseStageId, validateStageId, findStageDirConflict } from './path.js';`

### 改动 3：`src/core/plan/scheme.ts` `syncToFlowJson` 兜底自动注册（现 `:107-115`）接入冲突检测

- 现状：
  ```ts
  if (!flowData.stages[stageName]) {
    flowData.stages[stageName] = {
      name: stageName,
      phase: 'plan_pending' as PipelinePhase,
      status: 'planned',
      deps: [],
      ops: {},
    };
  }
  ```
- 改后：
  ```ts
  if (!flowData.stages[stageName]) {
    // 兜底自动注册前先校验：非法 stageId / (series, stageDir) 冲突
    // （补齐 stage-41 op-002 的绕过缺口，REV-v1.1.2-stage-41 REV-003）
    const v = validateStageId(stageName);
    if (!v.ok) {
      // 不静默吞错（外层 try/catch 会吞非并发错误）：显式告警并跳过自动注册
      console.warn(`[WARN] ${v.reason}；已跳过 flow.json 自动注册（op 文件已创建）。`);
      return;
    }
    const conflict = findStageDirConflict(projectPath, stageName);
    if (conflict) {
      console.warn(
        `[WARN] 阶段 '${stageName}' 与 '${conflict}' 映射同一 (series, stageDir)；` +
        `已跳过 flow.json 自动注册（op 文件已创建），请检查 stageId。`,
      );
      return;
    }
    flowData.stages[stageName] = {
      name: stageName,
      phase: 'plan_pending' as PipelinePhase,
      status: 'planned',
      deps: [],
      ops: {},
    };
  }
  ```
  > 注：`stageName` 由 `createScheme` 经 `parseStageId(...).fullStageId` 规范化，`validateStageId` 恒通过；此处为**防御性**（防未来调用方绕过规范化）。

### 改动 4：`src/core/plan/scheme.ts` `syncToFlowJson` 补 `register_op`（现 `:118-134`）

- 现状：注册 op 到 `flowData.stages[stageName].ops[opId]` 后直接 `flowMgr.save();`（`:134`）。
- 改后：在 `save()` **之前**追加：
  ```ts
  // 审计日志（P7）：op 注册成功，记录 register_op（agent=cli）
  flowMgr.appendLog({ time: '', agent: 'cli', action: 'register_op', detail: { stageName, opId } });

  flowMgr.save();
  ```
- 说明：`flowMgr`（`:99` `new FlowManager(projectPath)`）的 `appendLog` 为 public；`save()` 落盘（受 `flow.lock` 保护，既有）。

## 新增/修改的接口签名

## 参数与校验规则（日志写入条件）

| 路径 | 写入条件 | action | detail |
|------|----------|--------|--------|
| `registerStage` | 实际新增阶段（非幂等跳过） | `register_stage` | `{ stageName, deps }` |
| `syncToFlowJson` | op 注册成功（进入 `save()` 前） | `register_op` | `{ stageName, opId }` |
| `addStage`（既有） | 实际新增 | `add_stage` | `{ stageId, phase }` |
| 幂等/冲突/非法 | — | **不写** | — |
