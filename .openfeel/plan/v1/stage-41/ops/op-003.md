- **状态**：completed
- **前置**：op-002（hard，复用其 `parseStageId` 体系与校验文案；本 op 不依赖其冲突检测函数，但建议在其后执行以避免同文件并发改动 `flow-manager.ts`）
- **对应 REV（修正）**：REV-004（medium/blocking：补「被其它阶段 `deps` 引用」安全校验）、REV-005（low：修正 dry-run 骨架）、REV-006（low：日志快照）

## 目标（含反馈条目）

新增 `openfeel flow stage remove <stageId>`，安全移除误建阶段：默认拒绝「`ops` 非空」「当前活跃阶段」「被其它阶段 `deps` 引用」三项，`--force` 越过，`--dry-run` 预览不写盘；移除后 `pipeline.current.stage` 不悬空；写 `remove_stage` 审计日志（含引用者与被删阶段快照）。

**对应反馈**：`docs/phase-5/06-openfeel-tooling-feedback.md` 问题 #1（高）「缺移除阶段命令，遗留阶段只能 `--force` 强推 done 退役（遗留永久 done 阶段与 `--force` 日志）」。
**对应决策**：P11（安全校验 + `--dry-run` + current 兜底 + `remove_stage` 审计日志）。
**对应 kb**：#CLI --dry-run 安全预览模式（必须遵循）、#flow.json 乐观并发校验模式（退出码 2 复用）。

## 关键设计决策（须写死的裁定）

1. **移除范围**：**默认仅注销 `flow.json` 中的 stage 注册，不删 `plan/{series}/{stageDir}/` 目录**（避免误删计划产物）。仅 `--purge` 显式删除目录。
2. **`--purge` 二次确认**：
   - TTY 环境：交互式 `confirm` 二次确认（复用 `@inquirer/prompts`，与 `flow wizard` 同源）；
   - 非 TTY 环境：**拒绝**，须显式配合 `--force`（跳过确认）。
   - `--force` 时跳过交互确认。
3. **`--force` 语义**：越过「`ops` 非空」「当前活跃阶段」「被其它阶段 `deps` 引用」三项**安全校验**；不等同于 `--purge`（删目录仍需 `--purge`），也不绕过 `--dry-run`。
4. **`pipeline.current` 兜底（写死）**：移除后若 `pipeline.current.stage === stageId` →
   - 按 `stages` **插入序**回退「首个 phase ≠ `done` 的阶段」：`current.stage = 该键`，`current.op = 该阶段首个 `pending`/`executing` op 的 id，无则 `''`；
   - 若不存在非 done 阶段 → 清空 `current = { stage: '', op: '' }`。
   - 兜底与 `advanceStagePhase` 的 current 逻辑**场景不同**（P3a：advance 场景不回退），二者不矛盾。
5. **`deps` 引用校验（REV-004，写死）**：
   - **依赖来源**：`flow.json.stages[].deps`（类型 `string[]`，见 `flow-manager.ts:95`；写入路径 `registerStage :704/:715`、`addStage :1128`、`plan/stage.ts:103`）。**本 op 是该字段的首个读取方**（既有读取仅 `archive/merge.ts:85` 归档汇总）。
   - **匹配规则**（兼容存量与短名）：`dep === stageId`（精确），**或** `dep` 与 `stageId` 经 `parseStageId` 解析后 `(series, stageDir)` 相同（视为同一阶段，兼容 `--deps stage-05` 短名写法）。**存量 stage 可能缺 `deps` 字段**（实测 `v1.0.0-stage-04` 即无），故以 `Array.isArray` 守卫。
   - **方向 1（被依赖方被移除）**：扫描其余 stages 命中者集合 `refs`；`refs` 非空 → **默认拒绝**（提示列出引用方，与 ops/current 同级）；`--force` 越过。
   - **方向 2（引用者自身被移除）**：其 `deps` 随阶段一并删除，**不影响被引用阶段**，无需额外校验；快照 `snapshot.deps` 留存其依赖声明以便重建。
   - **明确结论（是否清理悬空项）**：`--force` 移除**不自动清理**引用者 `deps` 中的悬空项。理由：`deps` 为**声明式引用**（可指向未注册/未来阶段，见 op-004 决策 2），静默改写他人数据属范围外副作用；保留原样 + 日志记 `referencing` 与阶段快照，使依赖图失真**可审计、可追溯**。清理悬空引用须走后续显式操作（重新 `plan stage add` / 手工修正）；未来可加 `--prune-refs`（**本阶段不实现**）。
6. **可移除性检查抽为公共方法**（REV-005）：新增 `FlowManager.checkRemovable(stageId, {force}): RemovalCheck`（只读），供 `removeStage` 与 `flow stage remove --dry-run` **共用**，消除「dry-run 骨架不校验」的骨架-验收矛盾。`force=true` 时 `ok` 恒 `true`（阶段存在前提下），但 `opCount/isCurrent/referencing` **仍如实返回**，供审计日志记录破坏性操作上下文。
7. **审计日志（REV-004 + REV-006）**：`appendLog({ time:'', agent:'cli', action:'remove_stage', detail:{ stageId, purged, referencing, snapshot } })`，其中
   - `referencing` = `string[]`（引用被删阶段的其它 stageId；`--force` 越过后仍有值）；
   - `snapshot` = `{ phase, status, deps, opKeys }`（被删阶段摘要，使误删可从审计日志重建）。
8. **并发保护**：`mgr.save()` 复用乐观并发校验；命令层 `catch` → `isFlowConcurrentError` 输出可重试提示 + `exit(2)`。
9. **不级联删除**：默认不删目录，故无 `status.md` / REV / Bug 引用级联问题；`--purge` 即整体删除目录（含其中文件）。

## 精确改动点（文件:行号 → 现状 → 改后）

### 改动 1：`src/core/flow-manager.ts` 新增 `checkRemovable()` 与 `removeStage()`（置于 `addStage()` `:1141` 之后）

**触发条件**：`FlowData.stages[].deps` 在 `StageData` 中为必填（`:95`），但存量数据可能缺失 → 全程 `Array.isArray` 守卫。

```ts
/** 阶段可移除性检查结果（供 removeStage 与 flow stage remove --dry-run 共用，REV-005） */
export interface RemovalCheck {
  /** 是否允许移除（force=true 且阶段存在时恒 true） */
  ok: boolean;
  /** ok=false 时的拒绝原因（中文，供 CLI 直接展示） */
  reason?: string;
  /** 阶段 ops 数量 */
  opCount: number;
  /** 是否为 pipeline.current.stage */
  isCurrent: boolean;
  /** 引用该阶段的其它阶段（flow.json.stages[].deps 命中者，REV-004） */
  referencing: string[];
}

/**
 * 检查阶段是否可安全移除（只读，不写盘）。
 *
 * 判定顺序：ops 非空 → 当前活跃阶段 → 被其它阶段 deps 引用。
 * force=true 时越过三项校验（ok 恒 true，阶段不存在除外），但 opCount/isCurrent/referencing 仍如实返回。
 *
 * deps 匹配：精确相等，或 dep/target 经 parseStageId 解析后 (series, stageDir) 相同（兼容短名）。
 * 存量 stage 可能缺 deps 字段（StageData.deps 虽为必填，历史数据未必），以 Array.isArray 守卫。
 */
checkRemovable(stageId: string, options: { force?: boolean } = {}): RemovalCheck {
  if (!this.data) {
    return { ok: false, reason: '流水线数据未加载', opCount: 0, isCurrent: false, referencing: [] };
  }
  const stage = this.data.stages[stageId];
  if (!stage) {
    return { ok: false, reason: `阶段不存在：'${stageId}'`, opCount: 0, isCurrent: false, referencing: [] };
  }

  const opCount = stage.ops && typeof stage.ops === 'object' && !Array.isArray(stage.ops)
    ? Object.keys(stage.ops).length
    : 0;
  const isCurrent = this.data.pipeline.current.stage === stageId;

  // 引用者扫描：其余 stages 的 deps 命中该阶段者（REV-004）
  const target = parseStageId(stageId);
  const referencing: string[] = [];
  for (const [otherId, otherStage] of Object.entries(this.data.stages)) {
    if (otherId === stageId) {
      continue;
    }
    const deps = Array.isArray(otherStage.deps) ? otherStage.deps : [];
    const hit = deps.some((dep) => {
      if (dep === stageId) {
        return true;
      }
      const parsed = parseStageId(dep);
      return !!parsed && !!target && parsed.series === target.series && parsed.stageDir === target.stageDir;
    });
    if (hit) {
      referencing.push(otherId);
    }
  }

  if (!options.force) {
    // 错误路径：ops 非空（存在未归档操作方案）
    if (opCount > 0) {
      return { ok: false, reason: `阶段 '${stageId}' 仍有 ${opCount} 个未归档的 op；如需强制移除此阶段，请加 --force`, opCount, isCurrent, referencing };
    }
    // 错误路径：当前活跃阶段
    if (isCurrent) {
      return { ok: false, reason: `阶段 '${stageId}' 是当前活跃阶段；如需强制移除，请加 --force（将自动回退 current）`, opCount, isCurrent, referencing };
    }
    // 错误路径：被其它阶段 deps 引用（REV-004）
    if (referencing.length > 0) {
      return { ok: false, reason: `阶段 '${stageId}' 被其它阶段依赖：${referencing.join(', ')}；如需强制移除（将产生悬空依赖），请加 --force`, opCount, isCurrent, referencing };
    }
  }
  return { ok: true, opCount, isCurrent, referencing };
}

/**
 * 移除流水线阶段（仅注销 flow.json 注册；--purge 时同时删除 plan 目录）。
 *
 * 安全校验复用 checkRemovable：ops 非空 / 当前活跃阶段 / 被其它阶段 deps 引用，默认拒绝，--force 越过。
 * --force 移除时**不清理**引用者 deps 中的悬空项（deps 为声明式引用；保留原样 + 日志 referencing/snapshot 使失真可审计）。
 * 移除后 current 兜底：若 current 指向被删阶段，按 stages 插入序回退首个非 done；无则清空 current。
 */
removeStage(stageId: string, options: { force?: boolean; purge?: boolean } = {}): void {
  if (!this.data) {
    return;
  }
  const check = this.checkRemovable(stageId, { force: options.force });
  if (!check.ok) {
    throw new Error(check.reason ?? `无法移除阶段 '${stageId}'`);
  }

  // 阶段快照（REV-006）：误删后可从审计日志重建
  const stage = this.data.stages[stageId];
  const snapshot = {
    phase: stage.phase,
    status: stage.status,
    deps: Array.isArray(stage.deps) ? [...stage.deps] : [],
    opKeys: Object.keys(stage.ops ?? {}),
  };

  // ── 注销 flow.json 注册 ──
  delete this.data.stages[stageId];

  // ── current 兜底：不悬空 ──
  if (this.data.pipeline.current.stage === stageId) {
    const remaining = Object.keys(this.data.stages);
    const fallback = remaining.find((k) => this.data!.stages[k].phase !== 'done');
    if (fallback) {
      const pendingOp = Object.entries(this.data.stages[fallback].ops).find(
        ([, op]) => op.state === 'pending' || op.state === 'executing',
      );
      this.data.pipeline.current = { stage: fallback, op: pendingOp ? pendingOp[0] : '' };
    } else {
      this.data.pipeline.current = { stage: '', op: '' };
    }
  }

  // ── --purge：删除 plan/{series}/{stageDir}/ 目录 ──
  let purged = false;
  if (options.purge) {
    const parsed = parseStageId(stageId);
    if (parsed) {
      const dir = resolve(this.projectPath, '.openfeel', 'plan', parsed.series, parsed.stageDir);
      if (existsSync(dir)) {
        rmSync(dir, { recursive: true, force: true });
        purged = true;
      }
    }
  }

  // ── 审计日志（含引用者与阶段快照，REV-004 / REV-006） ──
  this.appendLog({
    time: '',
    agent: 'cli',
    action: 'remove_stage',
    detail: { stageId, purged, referencing: check.referencing, snapshot },
  });
}
```

### 改动 2：`src/commands/flow.ts` 新增 `flow stage remove`（置于 `stageCmd` 的 `add` 块 `:335-361` 之后、`flow advance` `:363` 之前）

```ts
// flow stage remove <stageId> [--force] [--dry-run] [--purge]
stageCmd
  .command('remove <stageId>')
  .description('移除流水线阶段（安全校验；默认仅注销 flow.json，不删目录）')
  .option('--force', '越过安全校验（ops 非空 / 当前活跃阶段 / 被其它阶段依赖）')
  .option('--dry-run', '仅预览，不写盘')
  .option('--purge', '同时删除 plan/{series}/{stageDir}/ 目录（非 TTY 须配 --force）')
  .action(async (stageId: string, options: { force?: boolean; dryRun?: boolean; purge?: boolean }) => {
    const lang = getCliLang(process.cwd());
    const mgr = createManager();
    if (!mgr.isLoaded()) {
      console.error(t('common.errorNoInit', lang));
      process.exit(1);
    }
    const data = mgr.getData();
    if (!data?.stages[stageId]) {
      console.error(t('flow.stage.remove.notFoundTmpl', lang, { stage: stageId }));
      process.exit(1);
    }

    // --dry-run：复用 checkRemovable 做安全校验，失败同样 exit 1（REV-005），并呈现引用者（REV-004）
    if (options.dryRun) {
      const info = mgr.checkRemovable(stageId, { force: options.force });
      console.log(t('flow.stage.remove.dryRunTitle', lang));
      console.log(`  ` + t('common.stage', lang) + `: ${stageId}`);
      console.log(`  ops: ${info.opCount}`);
      console.log(`  current: ${data.pipeline.current.stage}${info.isCurrent ? ' ←' : ''}`);
      console.log(`  ` + t('flow.stage.remove.dryRunReferencing', lang) + `: ` +
        (info.referencing.length > 0 ? info.referencing.join(', ') : t('common.none', lang)));
      if (!info.ok) {
        console.error(t('common.errorTmpl', lang, { msg: info.reason ?? '' }));
        process.exit(1);
      }
      console.log(t('flow.stage.remove.dryRunOk', lang));
      return;
    }

    // --purge 非 TTY 守卫
    if (options.purge && !options.force && !process.stdout.isTTY) {
      console.error(t('flow.stage.remove.purgeNeedForce', lang));
      process.exit(1);
    }

    try {
      // --purge TTY 二次确认（--force 跳过）
      if (options.purge && !options.force) {
        const { confirm } = await import('@inquirer/prompts');
        const ok = await confirm({ message: t('flow.stage.remove.purgeConfirm', lang), default: false });
        if (!ok) {
          console.log(t('common.cancelled', lang));
          return;
        }
      }
      mgr.removeStage(stageId, { force: options.force, purge: options.purge });
      mgr.save();
      console.log(t('flow.stage.remove.okTmpl', lang, { stage: stageId }));
      if (options.purge) {
        console.log(t('flow.stage.remove.purgedTmpl', lang));
      }
    } catch (err: unknown) {
      if (isFlowConcurrentError(err)) {
        console.error(`[并发冲突] flow.json 已被其它进程修改（期望 revision=${err.expectedRevision}，磁盘=${err.actualRevision}）。`);
        console.error('本次修改未写入。请重新执行该命令重试。');
        process.exit(2);
      }
      const msg = err instanceof Error ? err.message : String(err);
      console.error(t('common.errorTmpl', lang, { msg }));
      process.exit(1);
    }
  });
```

```
openfeel flow stage remove <stageId> [--force] [--dry-run] [--purge]
```

## 参数与校验规则（写死）

| 参数/条件 | 规则 |
|-----------|------|
| `<stageId>` | 必填；不存在 → `flow.stage.remove.notFoundTmpl` + exit 1 |
| 默认（无 flag） | 以下任一成立即拒绝（exit 1）：`ops` 非空；为 `pipeline.current.stage`；**被其它阶段 `deps` 引用** |
| `--force` | 越过上述**三项**安全校验；**不**替代 `--purge`；不绕过 `--dry-run`；**不清理**引用者悬空 deps（见决策 5） |
| `--dry-run` | 复用 `checkRemovable` 做安全校验；校验失败 → exit 1；成功则预览 stageId / ops 数 / current / 引用者；不写盘、不写日志、不删目录 |
| `--purge` | 额外删除 `plan/{series}/{stageDir}/`；TTY 交互二次确认；非 TTY 且无 `--force` → 拒绝（exit 1） |
| current 兜底 | 移除 current 阶段 → 回退首个非 done；无 → 清空 `{stage:'', op:''}` |
| 审计日志 | 成功移除后追加 `remove_stage`（`agent='cli'`，`detail = { stageId, purged, referencing, snapshot }`） |
| 并发冲突 | `save()` 冲突 → 提示 + exit 2（复用 `isFlowConcurrentError`，`flow.ts:26` 已导入） |

  - `removeStage('A', {force:true})` → 成功；`pipeline.current.stage` 回退到首个非 done（此处 B 为 done → 无 → 清空 `''`）；
  - 日志末条 `action==='remove_stage'` 且 `detail.stageId==='A'`。
- 构造 stage A（ops 空，current=A）+ stage B（ops 空，phase=exec_running）：
  - `removeStage('A')` → throws（当前活跃阶段）；
  - `removeStage('A', {force:true})` → current 回退到 B。
- 构造 A（非 current，ops 空）→ `removeStage('A')` 默认成功（无 current 变更）。
- `removeStage('nope')` → throws（阶段不存在）。
- **REV-004 deps 引用校验**：构造 A（ops 空、非 current）+ B（`deps=['A']`）：
  - `checkRemovable('A')` → `ok=false` 且 `referencing` 含 `'B'`、`reason` 含「被其它阶段依赖」；
  - `removeStage('A')` → throws；
  - `removeStage('A', {force:true})` → 成功，日志末条 `detail.referencing` 深等于 `['B']`。
  - 短名匹配：B（`deps=['stage-05']`）+ A 键 `v1.0.0-stage-05` → `checkRemovable('v1.0.0-stage-05').referencing` 含 `'B'`。
  - 存量守卫：构造一个**无 `deps` 字段**的 stage（如 `{ name, phase, status, ops }` 直接写入 fixture）→ `checkRemovable` 不抛错、`referencing` 为空。
- **REV-006 快照**：`removeStage('A', {force:true})` 后日志末条 `detail.snapshot` 深等于 `{ phase, status, deps, opKeys }`。
- `removeStage($stage, {purge:true})` → 断言 `plan/{series}/{stageDir}/` 目录被删除、日志 `detail.purged===true`；`purge:false` → 目录保留、`purged===false`。

**`test/commands/flow.test.ts`（扩展/新增）**
- `flow stage remove X --dry-run` → 不修改 flow.json（前后 `readFileSync` 内容一致）。
- `flow stage remove X --dry-run` 当 `X` 被 `Y.deps` 引用 → exit 1，且输出含引用者 `Y`（REV-004/005 联合）。
- 非 TTY（默认 vitest 环境）下 `flow stage remove X --purge`（无 `--force`）→ exit 1 且未删目录。

## 风险与回滚

| # | 风险 | 缓解/回滚 |
|---|------|-----------|
| 1 | `--purge` 误删计划产物 | 默认不删目录；`--purge` 显式 + TTY 二次确认 + 非 TTY 需 `--force`；文档注明先 `--dry-run`；回滚 = 从 git 恢复（`.openfeel/backup/` 为 migrate 专用，非常态备份） |
| 2 | current 悬空致后续 advance 失败 | 显式兜底（决策 4）+ 单测断言 |
| 3 | `--force` 移除被依赖阶段产生**悬空 deps** | 默认拒绝（REV-004）；`--force` 为显式破坏性意图，**不静默清理**引用者（决策 5），但日志记 `referencing` + `snapshot` 使失真可审计；未来可加 `--prune-refs` |
| 4 | 存量 stage 缺 `deps` 字段致扫描崩溃 | `Array.isArray(otherStage.deps)` 守卫（决策 5）+ 专项测试 |
| 5 | 短名 deps（`stage-05`）未被精确匹配漏检 | 归一化匹配 `(series, stageDir)`（决策 5）+ 测试 |
| 6 | 同文件并发（与 op-002 / op-001） | 本 op 置于 op-002、op-001 之后串行执行（deps.yaml 互斥组 `[001,002,003]`） |
| 7 | `--dry-run` 不校验安全条件致误导 | dry-run 复用 `checkRemovable`（REV-005），失败同样 exit 1 |
| 8 | 既有读取方 `archive/merge.ts:85`（`stage.deps.length`）对无 deps 存量 stage 存在潜在 undefined 访问 | **既有隐患，非本 op 引入**；记录为观察项，不在本阶段修（如需修另立 op/阶段） |
