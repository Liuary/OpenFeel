# op-002：setStatusField / parseStatusFields 正则兼容非粗体格式

## 目标

修复 `src/commands/stage.ts` 中 `parseStatusFields()` 和 `setStatusField()` 的正则表达式，使其同时兼容粗体（`- **状态**：value`）和非粗体（`- 状态：value`）两种 status.md 格式。

## 知识库参考

- kb/troubleshooting.md #"手动 edit status.md 频繁失败 — 格式匹配脆弱"：本 Bug 为此问题的延续——原有正则仅匹配粗体格式，手写/自动生成的 status.md 可能使用非粗体格式导致匹配失败

## 产出文件

- `src/commands/stage.ts`

## 实施步骤

### 步骤 1：修复 `parseStatusFields()` 正则（L76）

**当前代码**（`src/commands/stage.ts` L76）：
```typescript
const fieldRegex = /^-\s*\*\*(.+?)\*\*[：:]\s*(.*)$/gm;
```

**替换为**：
```typescript
const fieldRegex = /^-\s*(?:\*\*)?(.+?)(?:\*\*)?[：:]\s*(.*)$/gm;
```

- [x] 使用 `edit` 工具精确替换 L76 的正则表达式
- [x] 改动要点：`\*\*(.+?)\*\*` → `(?:\*\*)?(.+?)(?:\*\*)?`，粗体星号标记改为非捕获组并可选

### 步骤 2：修复 `setStatusField()` 正则（L204-207）

**当前代码**（`src/commands/stage.ts` L204-207）：
```typescript
const fieldRegex = new RegExp(
  `^(-\\s*\\*\\*${escapeRegex(key)}\\*\\*[：:]\\s*)(.*)$`,
  'gm',
);
```

**替换为**：
```typescript
const fieldRegex = new RegExp(
  `^(-\\s*(?:\\*\\*)?${escapeRegex(key)}(?:\\*\\*)?[：:]\\s*)(.*)$`,
  'gm',
);
```

- [x] 使用 `edit` 工具精确替换 L204-207 的正则模板字符串
- [x] 改动要点：`\\*\\*${escapeRegex(key)}\\*\\*` 改为 `(?:\\*\\*)?${escapeRegex(key)}(?:\\*\\*)?`
- [x] 注意：`escapeRegex(key)` 已处理特殊字符，`key` 值 `'状态'` 无需额外转义

### 注意事项

1. `parseStatusFields()` 使用正则字面量，`setStatusField()` 使用 `new RegExp()` 构造——模板字符串中需双反斜杠 `\\*\\*` 转义
2. 两处改动后的正则捕获组数量不变（捕获组1=键名、捕获组2=值），不影响后续逻辑
3. 两组改动后正则仍锚定行首 `- ` 模式，不会误匹配正文内容
