## 心得建议

1. **防御性类型守卫应在数据入口处实施**：Bug #1 的根本原因在于 flow.json 解析后未对 ops 字段类型做任何校验。任何从 JSON 反序列化得到的数据在遍历前都应添加类型守卫——`null` 在 JSON 中合法但在 JS 遍历中致命。

2. **静默异常处理是排查障碍**：`load()` 的 try-catch 仅设置 `this.data = null` 而不记录错误原因，使得 "flow.json 不存在" 的误导性错误难以追溯到真正的 null ops 崩溃。关键路径的错误处理应至少记录 `err.message` 到日志。

3. **同源崩溃点应全局排查**：发现一处 `Object.entries(stage.ops)` 崩溃后，应主动搜索全项目所有对 `stage.ops` 的遍历调用——本阶段在 load/summary/getSummary/overview 共 4 处修复了同源问题。
