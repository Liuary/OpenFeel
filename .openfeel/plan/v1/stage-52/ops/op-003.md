## 一、变更目标

落实反馈 09 的 F2（**无状态批量校正**）：新增 `flow health --fix`，以 **flow.json 为权威**，批量把 `status.md` 的「状态」字段回写为一致值（含 `--dry-run` 预览）；并完善 L7 的**文件孤儿**报告（当前 62 条只报告、无说明），按 A6 **不加清理入口**。

**为何选 `health --fix`（而非 `advance` 自动写 / 新增 `flow sync`）**——计划 §5.1 三选一裁定：
1. **覆盖面**：反馈场景是「11 个阶段批量校正」→ `--fix` 一次覆盖**存量**；`advance` 自动写只能覆盖未来推进。

3. **无冲突**：`--fix` 为**新增路径**，`advance` 与 `flow stage set` 语义/测试零影响。
4. **不新增 `flow sync`**：避免多命令面（`health --fix` 语义自洽）。

## 二、B2 / L7 子项清单

### B2-1（高）`reconcileStatusMd({ dryRun })`（core）

- **文件:行号**：`src/core/flow-manager.ts`（新增方法；参照既有 `healthCheck():2683+`、`repair():2275+`、`setStageDeps`（stage-51）等写盘范式）
- **现状**：`advanceStagePhase`（`:1245-1250` 附近）只更新 flow.json 的 `stage.status`/`current`，**从不写 `status.md`**；`status.md` 仅由 `flow stage set`（`src/commands/stage.ts:207`、`:428-429`）写 → 存在**批量不一致**且无 CLI 校正手段。
- **改后**：
  ```ts
  /** 单条差异 */
  export interface StatusReconcileItem {
    stage: string;              // 阶段 ID
    from: string;               // status.md 当前「状态」值（'' = 字段缺失）
    to: string;                 // flow.json 权威值（mapPhaseToStageStatus 派生）
    result: 'planned' | 'applied' | 'skipped-not-found';
  }

  /**
   * 以 flow.json 为权威，对账并回写各阶段 status.md 的「状态」字段。
   * 仅处理「状态」字段；绝不触碰执行模式/自动推进/当前任务/状态记录表。
   * @param options.dryRun true 时只计算差异、不写盘
   * @returns 差异清单（含 dry-run 预览结果）
   */
  reconcileStatusMd(options?: { dryRun?: boolean }): StatusReconcileItem[]
  ```
  实现要点：
  1. 遍历 `this.data.stages`（**跳过 `draft`**：见 op-005 窄兼容；`draft` 未发布不参与对账）；
  2. 权威值 = `mapPhaseToStageStatus(stage.phase, …)`（复用既有派生，**不另写映射**）；
  3. 读取 `status.md`（`findStatusPath`）→ 定位 `- **状态**：{value}` 行；**字段缺失** → 记为 `skipped-not-found`（**不新建字段**，避免扩大写入面）；
  4. `dryRun=false` 且值不同 → 写回（**原子写**）+ `appendLog({ action: 'status_reconcile', detail: { stage, from, to } })`；
  5. **只读探测 + 定向替换**：仅替换该字段行的值，其余字节**保持不变**（与 `commands/stage.ts:206-229` 的 `setStatusField` 语义一致）。
- **实现边界（防重复实现）**：core 内实现「状态字段定向写」的最小函数；**不重构** `commands/stage.ts:206-229`（该文件不在本 op 范围）。在 core 函数注释中标注「与 `commands/stage.ts:setStatusField` 同语义；后续可下沉合并」，并在 op-010 报告的**登记项**中记录合并建议。

- **现状**：`health` 仅只读检查（`--quick` 于 `:1233-1236`），**无 `--fix`**。
