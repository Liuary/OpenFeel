# op-003：四链路写入接入（setup、update、init、migrate 覆盖前备份）

- **阶段**：v1.1.2-stage-46
- **状态**：pending
- **前置**：`op-001`（**hard**：`backupFileBeforeWrite`/`BackupError`）、`op-002`（**hard**：`appendUpdateInfo('backed', …)` 与 `note` 字段）
- **负责 Agent**：openfeel-executor
- **最多重试**：3

## 变更目标

在四条部署链路（`setup` / `update` / `init` / `migrate`）的**全部覆盖写路径**接入「写前备份 + `backed` 条目」：① `writeManagedFile` 三条改写分支；② 全局 `opencode.jsonc` 三处直写；③ 项目 `.openfeel/config.yaml`（`writeDefaultConfig` 前）；④ 项目 `package.json`。`created`/`skipped`/`malformed` 不备份；**备份失败 → 跳过该文件写入 + `writeManagedFile` 返回 `'skipped'` + 记 `note='backup_failed'` 异常**。

**需求映射**：裁定 #3 + B3/B6/B7/B9 + REV-001/002/004。

## 关键裁定

1. **「备份后仍覆盖」——明确裁定（用户需求语义）**：用户指令是「**备份 + 提示**」，**不是「拒绝覆盖」**。故**备份成功后照常覆盖**；仅**备份失败**时才跳过该文件写入（B3）。`.openfeel/config.yaml` 亦同（**覆盖前备份，而非拒绝**）。
2. **BUG-002 关联（不重复开票；备份 = 缓解，非语义修复）**：`config/BUG-002`（`openfeel init` 无条件覆盖 `config.yaml`）的**期望行为**是「不再无条件覆盖用户已修改的 `config.yaml`（或覆盖前必须备份且提示）」。本 op ③ 落地的是**备份缓解**（可恢复 + 提示），**不改**覆盖语义本身 → 归档时**不得**视为 BUG-002 已语义修复（详见「BUG-002 关闭标准」）。
3. **锁不嵌套（kb #建议性文件锁模式）**：全局 `opencode.jsonc` 的写现有 `withFileLock(globalLockPath('global-opencode-jsonc'))`；备份须**在该锁之外（之前）**完成，避免与 `backup` 锁嵌套。
4. **`command` 显式透传**：`setup`→`'setup'`、`update`→`'update'`、`init`→`'init'`、`migrate`→`'migrate'`。
5. **失败动作值不扩**：`ManagedAction` 保持四值；备份失败返回既有 `'skipped'`（REV-004）。
6. **REV-007 ①（措辞修正，写死）**：flow.json 创建守卫的唯一归属为 **`FlowManager.initFlow`（`flow-manager.ts:2924-2932`，`existsSync` 守卫 `:2931-2932`）**；计划/REV-001 所写「`initFlow:2705-2706`」为**行号归属错误**（实测 `:2704-2707` 现为 `healthCheck` 的 status.md 一致性扫描，非守卫；「另一创建路径同款守卫」不成立）。**语义结论不变**：`flow.json` 不覆盖 → 不纳入备份。本 op 以注释/说明记录该更正，**不改 flow-manager**。
7. **REV-007 ②（profile.yaml 豁免显式记录）**：`~/.config/openfeel/profile.yaml`（`global-paths.ts:66-68`）存在同族覆盖风险，但 `writeProfile` 调用方仅 Feel 启动与 profile 写命令，**不在部署链路**（setup/update/init/migrate 零调用）→ **本阶段不纳入备份**（符合需求原文「部署覆盖前备份」）。记录于本 op「B9 补遗」+ op-004 manual。

## BUG-002 关闭标准（REV-009⑤，写死）

- **本阶段产出**：`init` 覆盖 `.openfeel/config.yaml` 前**备份原件** + 写 `backed` 条目 + TTY 提示 + 备份失败则不覆盖。属**缓解**（可恢复 + 可提示）。
- **`BUG-002` 的语义修复标准**（未达成，不因本阶段关闭）：`openfeel init` **不再无条件覆盖**用户已修改的 `config.yaml` —— 即采用「缺失时创建 / 存在时**合并**（保留用户 `defaults` 等）或**跳过**并提示」的语义；判定归属 `config` 模块后续立项（`config/BUG-002` 保持 `open`）。
- **关闭判定归属与时机**：由 **openfeel-feel-tester 在修复阶段验收**（非本阶段）；本阶段归档时须以「**缓解已落地**」记录，若 BUG-002 仍 `open` 则不得标注为已修复。
- **本阶段仅在 manual 记录**该缓解与残余风险（op-004）。

### 改动 4：`src/core/init.ts` `.openfeel/config.yaml`（`:174-182`，REV-001）

- 现状（`:175-182`）：
  ```ts
  const configPath = resolve(projectPath, '.openfeel', 'config.yaml');
  const configExisted = existsSync(configPath);
  writeDefaultConfig(projectPath, lang);       // 🔴 无条件整体覆盖
  if (configExisted) { updated.push('.openfeel/config.yaml'); } else { created.push(...); }
  ```
- **前置结构改动**（REV-009③ 口径统一）：`initWorkspaceCore`（`:163-166`）返回类型扩为 `{ created: string[]; updated: string[]; skipped: string[] }`（新增 `const skipped: string[] = []`）；`initWorkspaceOnly`（`:304-307`）同步扩型；`InitResult`（`:128-131`）增 `skipped: string[]`；`initProject`（`:259`）解构并透传（`return { created, updated, skipped }`）。与 `writeManagedFile` 备份失败返回 `'skipped'` 的口径一致。
- 改后（**备份 → 检查结果 → 覆盖写入**，单一路径；备份失败绝不覆盖）：
  ```ts
  const configPath = resolve(projectPath, '.openfeel', 'config.yaml');
  const configExisted = existsSync(configPath);
  if (configExisted) {
    // 覆盖前备份（REV-001 / 裁定 #3；BUG-002 缓解，非语义修复）——备份成功后仍覆盖（需求为备份+提示，非拒绝）
    try {
      const bk = backupFileBeforeWrite(configPath, { command: 'init', projectPath });
      if (bk) {
        appendUpdateInfo('backed', { projectRoot: projectPath, relativePath: '.openfeel/config.yaml', backupRel: bk.backupRel, command: 'init' });
        notifyBackupIfTTY(bk.backupRel);
      }
      // ✅ 仅备份成功后覆盖（同一 try 内，紧随备份；原件已留存于备份目录）
      writeDefaultConfig(projectPath, lang);
      updated.push('.openfeel/config.yaml');
    } catch (err) {
      if (err instanceof BackupError) {
        // 备份失败 → 绝不覆盖；记可区分异常 + 归类 skipped（与 writeManagedFile 口径一致）
        appendUpdateInfo('anomaly', { projectRoot: projectPath, relativePath: '.openfeel/config.yaml', note: 'backup_failed' });
        console.warn(`[init] ${err.message}；已跳过 config.yaml 覆盖以保护现有配置`);
        skipped.push('.openfeel/config.yaml (backup failed)');
      } else {
        throw err; // 非备份错误照旧上抛
      }
    }
  } else {
    // 目标不存在 → 无需备份，直接新建
    writeDefaultConfig(projectPath, lang);
    created.push('.openfeel/config.yaml');
  }
  ```
  > **控制流自洽说明（REV-008）**：`writeDefaultConfig` 仅出现**两处**——① `configExisted` 且**备份成功**的 `try` 内（紧随备份，原件已留存）；② `configExisted === false` 的 `else` 分支。**不存在**「备份失败 → 仍覆盖」路径；失败归类 `skipped`（与 `writeManagedFile` 返回 `'skipped'` 一致，REV-009③）。
  > 提示：`skipped` 需由调用方（`commands/init.ts`）汇总输出（可选打印 `[!]` 行；不打印亦不报错）。
- 目标为**项目资产** → `UpdateInfoTarget` 用 `{ projectRoot, relativePath }`。
