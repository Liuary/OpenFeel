## 一、缺陷与方案决策（困难点显式化）

### 1.1 缺陷（REV-80-019；方案期 CLI 实测复现原文）

b 项判据 = `versionOfStageId(stageId) ∈ archived_versions`（`src/core/flow-archive/archive-health.ts:57-71`）。`versionOfStageId` 经 `parseStageId` 把**短名归一为默认版本**（`DEFAULT_STAGE_VERSION = 'v1.0.0'`，`src/core/plan/path.ts:18,52-59`；`src/core/flow-archive/grouping.ts:39-49`），而 `plan stage add stage-NN` 的注册键 = `parsed.fullStageId`（`src/core/plan/stage.ts` 符号 `addStage`，`:215-224`）= `v1.0.0-stage-NN`。本仓迁移后 `v1.0.0` 已归档 → **任何以默认版本前缀新建的活跃阶段**立即被报「归档残留」warn（文案指向 restore 残留——对新阶段是误导性诊断），与 REV-80-001（短名归一化产物不得作已归档判据）内部口径不一致，与 R-80-3 / op-003 §5.4「迁移后零 warn」冲突。

**复现（方案期实测原文；隔离 temp 工程，未触本仓）**：`init` → 注入 `meta.archived_versions=['v1.0.0']` → `node bin/openfeel.js plan stage add stage-31`（键 = `v1.0.0-stage-31`）→ `node bin/openfeel.js flow health` 输出：

```
⚠️  归档一致性: 归档索引与文件不一致：索引有文件缺 [v1.0.0]；文件有索引缺 []
⚠️  归档残留: flow.json 仍含已归档版本阶段：v1.0.0-stage-31（可能由 checkpoint restore 带回或重复归档残留；须重新执行 flow archive <version> 收敛）
```

**真实归档面实测**：本仓 `.openfeel/flow-archive/v1.0.0.json` 的 stages 键 = `v1.0.0-stage-01..34`（**实含 stage-31**，89990 B）；9 组快照最大 `v1.1.2.json`（164023 B）。当前活跃集 `v1.2.0-*` 版本未归档 → 现网无候选（`flow health` 无「归档残留」项；改造后须保持）。当前实测 `flow health`：归档一致性 **pass（9 个版本）**、无「归档残留」。
