# REQ-068：版本号纠正 1.7.0→1.6.1 + 发布改走 CI 自动发布并登记规则

> 本文件为需求正文（人读副本，由 openfeel req 机械铺骨架）。**机读权威恒为 `.openfeel/flow.json` 的 `requirements` 条目**；两者不一致时以 flow.json 为准。下方状态为创建时快照，不追写实时状态。

## 状态

draft（创建时快照；以 flow.json 为准）

## 摘要

v1.7.0 的版本号定得过高（应为 1.6.1 补丁版），且发布流程假设了人工 `npm publish`。本项目实际流程是：远端 GitHub tag/release 触发 CI 自动发布 npm，不应手动发布。需要纠正全仓版本标注、改 release 脚本语义、并把 CI 发布规则写进开发规则文件，避免下次再按错误流程操作。

## 目标与验收

### 目标

把版本号从 1.7.0 纠正为 1.6.1（含文档/注释/计划），并把发布流程改成「push 到 master（版本变化）触发 CI 自动 npm publish」，不再手工发布；把两条规则（CI 发布 + 版本号分级）写进提示词、开发规则与模板。

### 验收

- A68.1 `package.json` / `dsh/package.json` 版本均为 1.6.1（requiresCli >=1.6.1）；`openfeel --version` = 1.6.1。
- A68.2 `CHANGELOG.md` 顶部版本段为 `## [1.6.1]`；`docs/VERSIONS.md`、`docs/releases/v1.6.1.md`、`docs/commands.md` 中不再出现 1.7.0。
- A68.3 源码注释/测试夹具中的 `v1.7.0` 版本标注统一为 `v1.6.1`：`grep -rn "1\.7\.0" src dsh docs scripts test package.json` 零命中（`.openfeel/**` 与 CHANGELOG 历史段除外；阶段 id `v1.7.0-stage-133` 是历史标识，保留不改）。
- A68.4 `scripts/release.mjs` 语义与 CI 对齐：默认只做版本校验+build；`--with-market` / `--commit-archive` / `--tag` / `--push` 分别控制市场索引、归档提交、打 tag、推送 commit；**推送 master 后由 CI 的 publish job 自动发布**（`ci.yml` 只在 `push` 到 master 且版本与 npm 不同时发布，tag/release 不触发）；`--publish` 仅作人工兜底。
- A68.5 `.openfeel/dev/dev_core.md` 新增动态规则（带日期）：**远端 push 到 master、版本变化时 CI 自动 npm publish；不要手动 `npm publish`**（tag/release 不触发，以 `ci.yml` 为准）；紧急兜底需显式 `--publish` 并记录原因；同时把该规则写进 `src/core/templates.ts` 的 DEV_CORE 模板，让新项目 init 自带。
- A68.6 全量 `npm test`、`npm run build`、dsh 四测（contract/verify/guard/integration）、`lint i18n` 全绿；`node scripts/release.mjs --dry-run --skip-build` exit 0。
- A68.7 提示词（`dsh/lib/surface/prompt.js` 及 4 份副本）写入**版本号分级规则**：默认按补丁（x.y.Z）推进；只有结构性/行为性变更才升 minor；破坏性变更才升 major；小改动不要升二级/一级。约束：**渲染态**（`renderFeelPrompt`）中英均 ≤1200 字符 / ≤25 行（当前 EN disabled 已 1143，余量约 57 字符，英文补句须 ≤50 字符），parity 5/5，并新增渲染态预算测试。
- A68.8 `docs/commands.md` 与 `CHANGELOG` 同步该分级规则与 CI 发布流程（push master→自动发布，无需手动 publish）。
