## 二、N2 子项清单

### N2-1（高）新增 `flow stage set <stageId> --deps <ids...>`

- **文件:行号**：`src/commands/flow.ts:388-420`（`stageCmd` 组，现有 `add`（:394）/`remove`（:423））；参照校验实现 `src/commands/plan.ts:37-44`（`--deps` 逗号/空格切分与校验）、`src/commands/flow.ts:376-381`（`validateStageId`/`normalizeStageId`）；`src/core/plan/path.ts:83`（`normalizeStageId`）
- **现状**：`--deps` 仅在**创建时**可设（`plan stage add --deps`），`flow stage` 组**无 `set`** → 改依赖只能手改 `flow.json`。
- **改后**：
  1. **core 新增**（`src/core/flow-manager.ts`）：
     ```ts
     /**
      * 覆盖写入某阶段的 deps 列表（含存在性/悬空校验）。
      * @param stageName 阶段 ID（简写或全称）
      * @param deps 依赖阶段 ID 列表
      * @throws Error 阶段不存在或存在悬空依赖时抛出（调用方决定退出码）
      */
     setStageDeps(stageName: string, deps: string[]): void
     ```
     实现：`normalizeStageId` 归一 → 校验阶段存在 → 逐项校验依赖阶段存在（**命令层强制**，核心层不静默）→ 写入 `stages[stage].deps` → `save()` + `appendLog({action:'stage_deps_set'})`。
  2. **命令层**：`flow stage set <stageId>` + `--deps <ids...>`（支持空格与逗号两种写法，解析逻辑与 `plan.ts:38` **共用/对齐**）。
     - **悬空依赖 → `exit 1` 且不写盘**（复用 stage-49 B2 的裁定：核心层 `checkDanglingDeps` 仅 `warn`，**强制校验在命令层**）。
     - 未指定 `--deps` → 视为「清空依赖」（`[]`），实施前以 `read` 复核既有 `flow stage add` 语义并对齐。
  3. **`--deps` 的 `--` 终止符注意**：commander 变长选项在最后位置的行为需实测（建议 `--deps a b` 置于命令末尾，文档注明）。

### N2-2（高）新增 `flow review update <revId>` / `flow review remove <revId>`

- **文件:行号**：`src/commands/flow.ts:742-834`（`reviewCmd` 组，现有 `add`（:748）/`resolve`（:805））；`src/core/flow-manager.ts:1927-1970`（`addReview`/`resolveReview` 旁）
- **现状**：审查条目**只能增**（`flow review add` / `view add`）与 `resolve`，**无 update/delete** → 误录条目无法纠正。
- **改后**：
  1. **core 新增**（`src/core/flow-manager.ts`）：
     ```ts
     /** 更新审查条目的可编辑字段（仅提供 patch 中的键进行覆盖） */
     updateReview(
       revId: string,
       patch: { priority?: 'high' | 'medium' | 'low'; title?: string; blocking?: boolean },
     ): boolean;

     /** 删除审查条目（留审计日志；返回是否命中） */
     removeReview(revId: string): boolean;
     ```
     二者均 `save()` + `appendLog`（`review_update` / `review_remove`，detail 含 patch 与标题）。
  2. **命令层**：
     - `flow review update <rev-id> [--priority <level>] [--title <text>] [--blocking <true|false>]`：
       - 至少提供一个字段，否则报错 + `exit 1`；
       - `--priority` 非法值 → `exit 1`（枚举校验：`high|medium|low`）；
       - `--blocking` 解析 `true/false`（非法 → `exit 1`）；
       - 未命中 → `exit 1`。
     - `flow review remove <rev-id>`：命中 → 成功输出被删条目 `id` + `title`（可追溯）；未命中 → `exit 1`。
  3. **不加额外保护门**（按计划口径：remove 直接生效 + 留日志 + 打印标题；如需保护由调用方审阅）。
