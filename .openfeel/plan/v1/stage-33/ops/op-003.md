## 目标

问题 3 的 Planner 侧边界说明，与 op-001/op-002 的「轻量决策」定义保持语义一致：对话式选型（不产出 plan.md）由 Feel 直接处理，仅产出正式计划文档或达规模阈值才唤起 Planner。涉及 planner.md 双层模板源各双语 + 部署实例，共 5 文件。

## 前置说明（两层模板源一致）

与 op-001 不同，planner.md 两层模板源**实测一致**（`git diff --no-index` 为空），部署实例 `.opencode/agents/planner.md` 与 `agents/zh-CN/planner.md` 也一致。故本 op 的编辑可**按节定点编辑**（推荐）或对内容一致的两层整节复制（可选）。但为规范统一，仍采用锚点定点编辑。

## 实施步骤

### 改动：新增「轻量决策边界」小节

锚点：节 `## 唤起条件`（zh）/ `## Invocation Conditions`（en）末尾（zh 在「- **Feel 兼任**（小规模）：< 5 个文件、≤ 30 行修改、补充已有计划、或 Bug 修复」之后；en 在「- **Feel handles concurrently** (small scale): < 5 files, ≤ 30 lines of changes, supplementing existing plans, or bug fixes」之后）与 `## 核心职责` / `## Core Responsibilities` 之间，**插入一个 `###` 小节**：

zh-CN：

```markdown
### 轻量决策边界

**轻量决策**（对话式选型：Feel 与用户通过 `question` 工具敲定技术方向或设计取舍，产出结论但不产出 plan.md）由 Feel 直接处理，不唤起 Planner。

仅当需要**产出正式计划文档**（plan.md，含阶段划分、任务表、约束表）或达到上方规模阈值时，Feel 才唤起 Planner。
```

en：

```markdown
### Lightweight Decision Boundary

**Lightweight decisions** (conversational selections: Feel and the user settle a technical direction or design trade-off via the `question` tool, producing a conclusion but no plan.md) are handled by Feel directly; Planner is not invoked.

Feel invokes Planner only when a **formal plan document** (plan.md, including stage division, task table, constraint table) is needed, or the scale thresholds above are reached.
```
