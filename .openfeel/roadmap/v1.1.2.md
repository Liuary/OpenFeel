# 分期大纲 v1.1.2

> **版本**：v1.1.2（W 级递增） | **创建日期**：2026-09-28 | **状态**：**已完成（2026-09-30 九阶段收官，`npm publish` 就绪）**
> **规划来源**：① Pantheogen《OpenFeel CLI 工具链体验反馈》（`godot/Pantheogen/docs/06-openfeel-tooling-feedback.md`），经 Feel 逐条核实后全量处理；② 追加需求「CLI 操作文档 skill 化」；③ 追加需求「权限模型修正」（`docs/phase-5/07-openfeel-permission-issue.md`）；④ 追加需求「平台强限定内容描述泛化」（用户指令）。
> **详细计划**：见 `.openfeel/plan/v1/v1.1.2/plan.md`。

## 目标

1. **可自描述**：CLI 关键操作不再迫使 Agent 翻包源码——补齐 phase 枚举与转移表、stageId 命名/目录映射约定的**机器可读入口**。
2. **可纠错**：补齐「移除阶段」「声明依赖」「冲突检测」，让「计划 → 流水线」落地环节可回退、可声明、可纠偏。
3. **状态与口径正确**：修复 `pipeline.phase` 在 `done` 时不置位的真缺陷，统一 `auto_advance` 配置口径并暴露「有效值 + 生效来源」，为关键 CLI 状态变更补齐 `flow.json` 审计日志。
4. **知识资产化**：将 CLI 操作文档沉淀为按需加载的 `openfeel-cli-usage` skill，根治反馈 #2/#3 痛点。
5. **权限可用**：修正 agent 模板权限模型，使「项目级全程自动审批」可用（补 `external_directory` + 文档化覆盖语义）。
6. **平台可移植**：将模板/规则/注释/文档/手册中「以 opencode 为唯一 harness」的描述泛化为无平台表述（零行为变更）。
7. **部署可回溯**：部署覆盖既有文件前自动备份原件（全局根 `~/.openfeel/backup/{ts}/`），并在全局状态文件中登记提示 Agent 检查。
8. **发布前无脏点**：集中清理测试/审查登记但未修的缺陷（含 `init` 覆盖用户 `config.yaml` 的 high 收口语义修复、`config effective` 来源偏差、模板泛化遗漏、`lint kb` 过期引用等），使版本收口前全绿。
9. **范围收口**：不引入新架构层，全部为命令层/核心层增量修复；版本号收口留到收尾阶段统一执行（完整载体清单见 `plan/v1/v1.1.2/plan.md` §3.1）。
10. **过程加固**：针对三大过程事件（审查官工具幻觉 / `npm test` 静默覆写真实环境 / 裸跑命中全局旧版）建立机制防线（模板纪律、CI 环境守卫与版本门禁、执行口径统一）；并清零既有遗留。
11. **全仓体检**：在发布后基线上对整个仓库做一次系统审查（8 单元 × 6 维度），形成可追溯的 REV 与修复流转清单。

> 说明：**用户决定继续 v1.1.2**（不新建版本）；stage-48/49 为 v1.1.2 的追加收尾阶段。

## 备注

- **经核实无需改动项**：反馈 #8（非 git 仓库噪声）已在 `src/core/flow-manager.ts:1099-1110` 用 `stdio:'pipe'` + catch 降级处理，输出「跳过自动 git commit」；`src/commands/flow.ts:511-525` 脏区检查亦被 try/catch 包裹。**本版本不修改该项**，计划与审查中显式记录以免误判遗漏。
- **经核实文档已存在项**：stageId 命名/目录映射规则已实现且有文档（`src/core/plan/path.ts`、`.openfeel/manual/core/plan-path.md:19-28`），本版本补齐的是**唯一性/冲突校验**与 **CLI 侧建议名**，非从零文档化。
- **需求纠正**：skill 权威源实际为**扁平单文件** `src/core/templates-data/opencode/skills/{name}/SKILL.md`（**无 `{lang}` 子目录**，skills 为中文单语），故新 skill 无需 zh-CN/en 双语同步；`NEW_SKILL_NAMES` 在现有代码中**不存在**。以上均见 plan.md 第五节。
- 阶段注册由 Feel 执行 `openfeel plan stage add`；本计划不修改 `flow.json`。
- **stage-44（权限模型）**：需求来源 `docs/phase-5/07-openfeel-permission-issue.md`。核实：9 agent 模板均**缺** `external_directory`；opencode `external_directory` 为合法 permission 键、默认 `ask`（本机 `opencode-ai@1.18.33` 二进制实测）。裁定 O1~O5 见 `plan/v1/stage-44/plan.md`；平台覆盖/合并语义标注「待实测」（op-000）。
- **stage-45（描述泛化）**：**仅描述泛化、零行为变更**；opencode 具体路径仅在适配器实现语境保留并标注。用户点名处 `AGENTS.md:82`。边界与盘点见 `plan/v1/stage-45/plan.md`。
- **串行约束**：stage-44 与 stage-45 均改 `src/core/templates-data/opencode/agents/**`，**必须串行（44 → 45）**；stage-45 与 stage-46 均改 `src/core/{init,setup,update}.ts` 与 `global-paths.ts`，**必须串行（45 → 46）**；stage-46 与 stage-47 均改 `src/core/init.ts` 与 `flow-manager.ts`，**必须串行（46 → 47）**；**stage-43 依赖 stage-47**（版本收口清单须以 41~47 全部落地后的实盘为准）。
- **stage-46（部署前备份）**：需求「部署时已有文件 → 备份原始文件 + 全局状态文件提示 agent 检查」。备份根 `~/.openfeel/backup/{ts}/`（保留层级 + `manifest.json`）；覆盖四链路（setup/update/init/migrate，含项目 `.openfeel/config.yaml`）；`update_infos.md` 新增「备份」类；`feel.md`（zh/en）检查规则扩展。裁定 B1~B9 见 `plan/v1/stage-46/plan.md`；**项目内备份不合并** `migrate`（B7）、**不做**还原命令（B8）。
- **stage-48（事件加固 + 遗留修复）**：三大事件（A 审查官工具幻觉 / B `npm test` 覆写真实环境 / C 裸跑命中全局旧版）机制加固（裁定 H1~H11 见 `plan/v1/stage-48/plan.md`）+ 13 项遗留清理。**继续 v1.1.2，不改版本号**。
- **stage-49（整仓全量审查）**：纯审查阶段（8 单元 × 6 维度），范围**不限 v1.1.2**；产出报告 + REV + 修复流转。默认**不改源码**。
