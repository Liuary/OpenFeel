## 目标

修复 `src/commands/project.ts` 中 `outputProjectOverview` 函数的入口路径节（🚪 入口路径），增加 `src/` 目录存在性判断；同时确认目录结构节（📁 目录结构）的存在性检查完整性。

## 设计决策

### 1. 入口路径门控策略（对应 REV-001）

**统一门控**：三条入口路径（CLI 入口 / 包入口 / 构建产物）以 `src/` 目录存在性为**统一门控**。

| 条件 | CLI 入口 (`src/cli/index.ts`) | 包入口 (`src/index.ts`) | 构建产物 (`dist/`) |
|------|------|------|------|
| `src/` **存在** | 正常输出路径值 | 正常输出路径值 | 正常输出 `dist/`（不做 dist/ 存在性检查） |
| `src/` **不存在** | 整节替换为统一提示 | ← 同上 | ← 同上 |

**`dist/` 不独立检查的决策理由**：
- `dist/` 是构建产物目录，`src/` 不存在时不可能有合法的 `dist/`
- `src/` 存在但 `dist/` 不存在 → 正常未构建状态，正常输出即可
- 与目录结构节的逻辑一致（目录结构中也不检查 `dist/`）

### 2. 入口路径节输出格式（对应 REV-001）

当 `src/` **存在**时（即现有正常行为，无需修改）：

```
🚪 入口路径
   CLI 入口:  src/cli/index.ts
   包入口:    src/index.ts
   构建产物:  dist/
```

当 `src/` **不存在**时，整节替换为：

```
🚪 入口路径
   （未检测到项目结构——缺少 src/ 目录）
```

> **决策**：整节替换而非逐行标注，因为三条路径都依赖 `src/`，逐行标注会产生三条相同提示，冗余且降低可读性。

### 3. 技术栈节处理策略（对应 REV-002）

**技术栈节（🔧 技术栈）保持现状不改。** 该节从 `package.json` 动态提取依赖版本号，属于通用技术栈信息，不依赖项目文件结构。"REV-004 修复"的范围仅限入口路径节和目录结构节的存在性判断，不涉及技术栈节。

### 4. 目录结构节一致性确认（对应 REV-004）

目录结构节（📁 目录结构）三个顶层目录的 existence check 当前状态：

| 目录 | 存在性检查 | 状态 |
|------|:--:|------|
| `src/` | `srcExists` → 分支输出 | ✅ 已完整 |
| `.opencode/` | `opencodeExists` → 分支输出 | ✅ 已完整 |
| `.openfeel/` | `openfeelExists` → 分支输出 | ✅ 已完整 |

**结论**：目录结构节的三个顶层目录均已有完整的 existence check，标注风格一致（「（目录不存在）」）。"补全一致性"实为"确认当前已一致"——本次修改无需调整目录结构节，仅确认现状即可。

> 原 plan.md 描述「当前已有部分存在性检查，需补全一致性」——经代码审查确认，三个顶层目录已全覆盖，无需额外补全。
