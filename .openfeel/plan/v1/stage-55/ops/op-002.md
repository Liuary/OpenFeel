## 一、变更目标

把全局部署资产刷到与当前模板一致（含 op-001 新增的「模块手册」节），**避免 op-003 删除项目级资产后降级运行**。命令裁定：**`node bin/openfeel.js setup`**（`src/core/setup.ts:29-110` `setupGlobalFramework`——**纯全局**：全局 `AGENTS.md` + 9 agent + 17 skill + 全局 `opencode.jsonc` 深度合并；走 `deployGlobalAsset`（受管区三态 + **写前备份**）；**幂等**）。**不用 `update`**（`src/core/update.ts:1572+` 会额外处理**项目侧** `.opencode/{agents,skills,instructions}` legacy 检测 → 与即将删除的项目资产交叠）。

## 二、F1 子项清单（**备份 → 刷新 → 判据**）

### F1-① 构建（保证 `dist` 与模板一致）

- **动作**：`npm run build`（`node bin/openfeel.js` 走 `dist`，须与 op-001 的模板改动一致）。
- **验收**：退出 0；重跑零 diff。

### F1-② **人工整目录备份**（在 CLI 写前备份之外的第二道保险）

- **动作**（PowerShell）：
  ```powershell
  $src = "$env:USERPROFILE\.config\opencode"
  $dst = "$env:TEMP\opencode\stage55-global-backup"
  if (Test-Path $dst) { Remove-Item -Recurse -Force $dst }
  Copy-Item -Recurse $src $dst        # 如需省时可先排除 node_modules（见下）
  # 可选（推荐）：生成清单哈希用于校验
  Get-ChildItem -Recurse -File $dst | Sort-Object FullName | Get-FileHash -Algorithm SHA256 |
    ForEach-Object { "$($_.Hash)  $($_.Path)" } | Set-Content "$dst\..\stage55-global-backup-hashes.txt"
  ```
- **备份范围**：`~/.config/opencode/` **全量**（含 `agents/`、`skills/`、`AGENTS.md`、`opencode.jsonc`、`openfeel/`、用户自定义文件）。
  - **可排除项（仅省时可选项）**：`node_modules/`（体积大、可重建）——**若排除须在报告中显式记录**「已排除 node_modules，恢复后需自行重装」。
- **备份位置与命名**：`$env:TEMP\opencode\stage55-global-backup`（**仓库外**，不入 git）+ 可选哈希清单 `stage55-global-backup-hashes.txt`。
- **校验方式**：`Test-Path $dst` 为真；`(Get-ChildItem -Recurse -File $dst | Measure-Object).Count` > 0；与源目录**顶层条目对照**（`agents`/`skills`/`AGENTS.md`/`opencode.jsonc` 均在）。
- **失败拦截**：备份未成功（路径不存在 / 计数为 0 / 顶层条目缺失）→ **立即停止，不得执行 F1-③**。

### F1-③ 执行刷新

- **动作**：`node bin/openfeel.js setup`（**幂等**，可重跑）。
- **执行前复核**：确认 op-001 已完成（`rg -c "模块手册" src/core/templates-data/agents-md/zh-CN.md` ≥1）且 F1-① 构建已完成。
- **执行后**：
  - 记录 `setup` 的 stdout（含备份路径提示，如 `~/.openfeel/backup/{ts}/`）；
  - **不触碰仓库文件**（`setup` 为纯全局）→ `git status --porcelain` 应无变化（**验证点**）。

### F1-④ **门 B 判据（逐条实测，5 条）**

| # | 判据 | 命令（只读） | 期望 |
|:--:|------|------|------|

  ```powershell

  ```
- **判据失败处置**：任一条不通过 → **回滚（F1-回滚）后停止**，**不得进入 op-003**；在报告中记录失败项与实际值。

### F1-回滚（失败或后续异常时）

1. **整目录恢复（首选）**：
   ```powershell
   Remove-Item -Recurse -Force "$env:USERPROFILE\.config\opencode"
   Copy-Item -Recurse "$env:TEMP\opencode\stage55-global-backup" "$env:USERPROFILE\.config\opencode"
   # 若备份时排除了 node_modules：进入该目录后 `npm install`（或由 opencode 自行重建）
   ```
2. **逐文件回滚（次选）**：`setup` 内置写前备份位于 `~/.openfeel/backup/{ts}/`（stage-46 机制），并按 `~/.openfeel/update_infos.md` 的「备份」条目定位；可逐文件复制回原位。
3. **校验**：恢复后复跑 **B1~B6**（B2 可能回到「不含模块手册」的旧态，属预期——**恢复的是操作前状态**）。
