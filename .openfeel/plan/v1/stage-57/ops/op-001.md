### 2.2 T32 拆分代码（**照此实现**，含 REV-001 前置断言）

```ts
  // T32：recent_projects 去重大小写/分隔符不敏感 —— 拆分为跨平台 + Windows 专属（stage-57 C1）

  it('T32：recent_projects 去重大小写不敏感（跨平台，绝对路径）', () => {
    mockHome.dir = join(tmpDir, 'home-t32');
    mkdirSync(join(mockHome.dir, '.config', 'openfeel'), { recursive: true });
    // 目标路径在 Windows/Linux 均为绝对路径；预置其「大写 + 正斜杠」变体
    // 仅大写受控 ASCII 尾段（proj/x → PROJ/X），避免 tmp 前缀含非 ASCII 用户名的 toUpperCase/toLowerCase 往返风险
    const target = resolve(tmpDir, 'proj', 'x');
    const preset = target.replace(/proj([\\/])x$/, 'PROJ$1X').replace(/\\/g, '/');
    // 防假绿：变体替换必须真实生效，否则本用例退化为「同串去重」而非「大小写不敏感去重」（REV-001）
    expect(preset).not.toBe(target);
    writeProfile({
      user: { name: 'U', lang: 'zh-CN' },
      preferences: { auto_advance: 'disabled', review_mode: 'full', communication: 'concise', confirm_threshold: 'medium' },
      history: { last_project: '', recent_projects: [preset] },
    });
    ensureProfileDefaults(target);
    const recent = readProfile().history.recent_projects;
    // 归一后视为同一条 → 只保留 1 条
    expect(recent).toHaveLength(1);
    expect(recent[0]).toBe(target);
    mockHome.dir = '';
  });

  // 盘符 + 反斜杠为 Windows 专属语义；POSIX 下 `C:\Proj\X` 非绝对路径，故跳过
  it.skipIf(process.platform !== 'win32')('T32win：recent_projects 去重（盘符大小写与分隔符，Windows 专属）', () => {
    mockHome.dir = join(tmpDir, 'home-t32win');
    mkdirSync(join(mockHome.dir, '.config', 'openfeel'), { recursive: true });
    writeProfile({
      user: { name: 'U', lang: 'zh-CN' },
      preferences: { auto_advance: 'disabled', review_mode: 'full', communication: 'concise', confirm_threshold: 'medium' },
      history: { last_project: '', recent_projects: ['c:/proj/x'] },
    });
    ensureProfileDefaults('C:\\Proj\\X');
    const recent = readProfile().history.recent_projects;
    expect(recent).toHaveLength(1);
    expect(recent[0]).toBe(resolve('C:\\Proj\\X'));
    mockHome.dir = '';
  });
```

### 2.3 双解析模拟片段（C1-4，用临时文件运行，**禁止经 shell 双引号内联**——避免 `$1` 插值污染）

```js
const path = require('node:path');
const norm = (p) => p.replace(/\\/g, '/').toLowerCase();
for (const [name, P, tmp] of [
  ['win32', path.win32, 'C:\\Users\\x\\Temp\\t-abc'],
  ['posix', path.posix, '/tmp/t-abc'],

  const target = P.resolve(tmp, 'proj', 'x');
  const preset = target.replace(/proj([\\/])x$/, 'PROJ$1X').replace(/\\/g, '/');
  console.log(name, norm(preset) === norm(target), 'variantApplied=' + (preset !== target));
}
// 期望：win32 true variantApplied=true / posix true variantApplied=true
```

> **本方案已实测**：`win32 true variantApplied=true`、`posix true variantApplied=true`。
> ⚠️ 含 `$1` 的正则验证必须写入临时 `.js` 文件再 `node <file>` 运行；经 PowerShell 双引号 `node -e "..."` 会被 `$1` 插值导致假 `false`（stage-57 REV 可信度声明已记录该取证缺陷）。

### 2.4 跨平台论证（**含 REV-001 措辞修正**）

1. 目标 `target = resolve(tmpDir,'proj','x')` 用测试内同一个 `node:path.resolve` 计算，**在两平台都是绝对路径**（win32 `C:\...\proj\x` / posix `/tmp/.../proj/x`）。
2. **【REV-001 修正】** 预置 `preset` 仅对**受控 ASCII 尾段** `proj\x`（或 `proj/x`）做**大写 + 反斜杠→正斜杠**变换；`tmpDir` 前缀的**大小写逐字符保持不变**，而前缀中的**路径分隔符**在 `.replace(/\\/g,'/')` 下被归一为 `/`——因 `normalizeKey` 本身也做 `\→/` 归一（`config.ts:307`），该前缀分隔符归一与 `normalizeKey` 幂等，**不影响相等性**（实测 `equal=true`）。
   > 原 plan §2.1 论证要点 2 写「tmpDir 前缀**逐字符**保持不变」**不准确**（win32 下 `\→/` 对前缀分隔符亦生效）；本 op 落地时须**同步修正 `plan.md:114` 该句措辞**（见 §五）。
3. `normalizeKey(p) = p.replace(/\\/g,'/').toLowerCase()`（`:307`）：`normalizeKey(target)` 与 `normalizeKey(preset)` 为同串（`PROJ/X`→`proj/x`、`\`→`/`）→ **恒等** → `filter` 命中 → 去重后 `toHaveLength(1)`；写入元素为 `normalizedPath = resolve(target) = target`。
4. 变体推导不依赖 `process.platform`，故无 Windows/Linux 分歧。

### 3.2 CI YAML 精确改法（替换 `ci.yml:43` 单行）

```yaml
      - name: Test
        run: |
          # 保退出码（pipefail）：tee 不得吞掉 npm test 失败码；日志落 $RUNNER_TEMP（不污染 Env guard 四路径）
          # REV-004：--no-color 关闭 vitest 3.x 在非 TTY 重定向下仍输出的 ANSI 色码（FORCE_COLOR=0 对该 reporter 无效）
          set -o pipefail
          npm test -- --reporter=verbose --no-color 2>&1 | tee "$RUNNER_TEMP/test.log"

      - name: Test failure annotations
        if: failure()
        run: |
          # 失败时把失败用例名转成可经 GitHub API 读取的注解（只读诊断；不改判定语义）
          LOG="$RUNNER_TEMP/test.log"
          if [ ! -f "$LOG" ]; then
            echo "::warning::未找到测试日志 $LOG，无法生成失败注解"
            exit 0
          fi
          # REV-004：首选 --no-color；此处再以 sed 剥 ANSI 色码兜底，防 vitest 未来版本行为漂移。
          # GNU sed 的 ESC 转义 \x1b 在 ubuntu-latest（GNU sed）可用；windows runner 不涉及（本 workflow 仅 ubuntu）。
          # 剥色后失败用例行形如 "× test/... > 用例名 Nms"，原 grep 模式命中。
          sed 's/\x1b\[[0-9;]*m//g' "$LOG" \
            | grep -E '^\s*(×|FAIL)|Failed Tests' \
            | head -n 20 \
            | while IFS= read -r line; do
                echo "::error::$line"
              done
          exit 0
```

> **说明**：注解步骤**未设** `pipefail`——`grep` 无命中（exit 1）时管道退出码取 `while`（0），不触发 `set -e`；`head -n 20` 限制注解条数。`if: failure()` + 结尾 `exit 0` 保证注解步骤**不改变 job 结论**。
> **REV-004 剥色表达式**：`sed 's/\x1b\[[0-9;]*m//g'`（等价于 `\x1b[` + CSI 参数 `[0-9;]*` + 终止 `m` 的全部 SGR 序列）。剥色后**最终匹配模式仍为** `^\s*(×|FAIL)|Failed Tests`（三条路径：`× 用例行`、`⎯ Failed Tests N ⎯` 分隔段、`FAIL 文件 > 用例` 详情行）。
> **双保险语义**：`--no-color` 为主（实测三条路径全命中）；sed 剥色为兜底（即使下游命令行为漂移仍可命中）。二者**幂等叠加**，不影响判定语义。

### 3.3 不变式（必须保持）

- 成功 run 不产生 `::error::` 注解；失败 run 的 job 结论仍为 `failure`。
- Env guard（`:46-62`）快照四路径**不受影响**（`test.log` 不在四路径内）。
- **不拆 job / 不换 runner / 不改 `publish` job**。
