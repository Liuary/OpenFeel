## 必查项（六维度）

1. **正确性**：
   - `writeManagedFile` **五分支**（`created` / `updated` / `adopt` / `appended` / `malformed`）语义与 `ManagedAction` 返回值一致性；**备份接入后**「备份失败返回 `'skipped'` + `anomaly(backup_failed)`」是否自洽（stage-46/47）；
   - `deployGlobalAsset` **破坏性签名**调用点完备（`setup.ts:40/47/56`、`update.ts:1466/1474/1483`、`migrate.ts:487/493/501`）与 `command` 透传（`setup`/`update`/`migrate`）；
   - `setup.ts` 全局部署时序（资产 → jsonc → state/hash）；
   - `migrate.ts` **事务边界**（备份 → 部署 → state 拆分重键 → 清理 → `finally` 回填 → `rollbackMigration` 可收敛）；
   - `backup.ts` 三步保护（判存 / 原子写 / manifest）与**锁作用域**（`withFileLock(globalLockPath('backup'))` 临界区，REV-005）；
   - `managed-region.ts` 四策略与三态（含 `SECTION_PREFIXES` 读侧短前缀匹配，stage-47）；
   - `update-state.ts` / `update-infos.ts` 双 state 路由（绝对/相对）与 `backed`/`anomaly`（含 `note='backup_failed'`）语义；
   - `fs/**`（`atomic-write` / `file-lock` / `sequence`）+ `utils/path.ts` 作为写入基础设施的正确性（temp 同目录、fsync、rename 容错、锁 TTL/退避/抢占、序号占号原子性）。
2. **一致性**：`init.ts` 的 `config.yaml` 语义（stage-47 BUG-002「不覆盖」）与 `manual/core/backup.md` 表述一致；`backup` 与既有 `flow.json.bak`/checkpoint/`migrate` 项目内备份的边界说明一致。
3. **文档-实现对齐**：`update.ts` 等注释声称 vs 实现（如 `writeManagedFile` 分支注释、`deployGlobalAsset` 等价关系注释）。
4. **边界与健壮性**：`malformed` 不写盘；`appended` 的去重与 `update_infos` 记录；`saveGlobalUpdateState` 时序；Windows `rename`/`unlink` 容错；`migrate` 中途失败可回滚；`backup` 备份失败 → **目标文件未写入**（stage-47 REV-011 A/B 分流：setup/update 跳过继续、migrate fail-fast）。
5. **安全面**：`backupFileBeforeWrite` 的 `projectPath`/`homedir` 相对化是否可越界（`..` 逃逸）；`migrate` 路径参数；`rmSync`/删除类操作边界；`update_infos`/`update_state` 写入是否全程加锁原子。
6. **过度设计**：`setup`/`update` 间是否存在重复部署逻辑可合并（但不因「可合并」即判缺陷，须给量化依据）；`fs/**` 三工具是否均有真实调用方。
