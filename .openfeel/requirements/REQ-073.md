# REQ-073：通用 config unset：补齐配置删除入口（含 models 迁移）

> 本文件为需求正文（人读副本，由 openfeel req 机械铺骨架）。**机读权威恒为 `.openfeel/flow.json` 的 `requirements` 条目**；两者不一致时以 flow.json 为准。下方状态为创建时快照，不追写实时状态。

## 状态

draft（创建时快照；以 flow.json 为准）

## 摘要

`openfeel config set` 存在但没有 unset：任何退役配置键（如旧项目 config.yaml 里的 `models:` 段）都无法通过 CLI 清理，agent 被 guard 挡在文件外、只能让人类手改。这是通用的 CLI 对称性缺口，不是 models 专用迁移。

## 目标与验收

### 目标

补齐 `openfeel config` 的对称缺口：`config set` 能写、但没有任何删除配置键的入口，导致旧项目里已退役的配置（如 `.openfeel/config.yaml` 的 `models:` 段）只能由人类手改。新增通用的 `openfeel config unset <key>`（不是 models 专用迁移），支持 `defaults.X` 与顶层段，保留注释与其它配置，并暴露为 `feel_verify action=config_unset`。

### 验收

- A73.1 `openfeel config unset <key>` 可删除 `defaults.X` 与顶层段（如 `models`）；写入走同一 YAML Document 路径，保留注释、键序（除被删键外）与其它配置。
- A73.2 键不存在时 exit 1 并给出明确提示；`--json` 输出 `{schemaVersion, key, removed, path}`（removed=false + 原因）。
- A73.3 `defaults.X` 删除后 `openfeel config effective X` 回落到 status.md/profile/builtin，并打印生效来源；不破坏 5 键 schema。
- A73.4 删除 `models` 后 `readConfig` 无该段、`openfeel lint`/`init` 等命令不受影响；当前仓库可用该命令清理旧 `models:` 段（作为首个验收样本）。
- A73.5 DSH 侧新增 `feel_verify action=config_unset`（参数 key），走同一 CLI；工具计数不变（仍是 15 个工具，action 扩展）。
- A73.6 测试：unset 幂等/不存在/defaults 回落/注释保留/`--json` 形态；`npm test`、`tsc`、`build`、dsh 四测、`lint i18n` 全绿。
- A73.7 版本 1.6.5（patch，root/dsh lockstep、`requiresCli >=1.6.5`），push master 后 CI 自动发布；不手动 publish。不改 guard 规则、不改 config 的「人类可手改」表述。
