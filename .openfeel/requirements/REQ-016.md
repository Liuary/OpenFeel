## 摘要

v1.5.5 加了 preflight 与「禁止 shell 写状态」的提示，但无法验证是否真的减少违规：没有 preflight 拒绝次数、`feel_next` 调用次数、主会话直接编辑/自审占比等代理指标。本需求只做**零运行时开销**的可观测项，为 1.5.7 判断闸门是否形式主义提供依据。

## 目标与验收

**目标**
1. `flow metrics` 人类输出追加「流程健康」块（`--json` 键集不变）：
   - 最近 N 条日志中 `advance_stage_phase` 的 resumed 比例；
   - `plan_pending → plan_review` 的平均停留时长（proxy：相邻 advance 时间差）；
   - 最近一次 preflight 时间与年龄（读 `.openfeel/dev/.preflight.json`）。
2. 适配器 `feel_status` / `feel_next` 返回 `observability`（preflight 年龄、`statusSync.due`、`stale` 的组合摘要），不新增工具/命令。
3. （可选，若成本低）`flow log --json` 保持契约；不新增写盘指标文件。

**验收**
- `flow metrics` 人类输出含「流程健康」三项；同命令 `--json` 键集与 1.5.5 完全一致。
- `feel_status.observability` 字段存在且为对象；缺失数据时降级为 null/0，不抛。
- 全量测试 / tsc / lint / dsh 通过；无 JSON 契约变更。
- 文档说明「token 无法直接测，用这些代理指标」及局限。
