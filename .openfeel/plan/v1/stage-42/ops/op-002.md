# op-002：`openfeel config effective`（有效值 + 生效来源）

- **阶段**：v1.1.2-stage-42
- **状态**：completed
- **前置**：op-001（**hard**：复用其 `buildCascadeConfig` 的 `profileDefaults`/优先级链，保证级联**单一权威**，避免再造第二套解析）
- **负责 Agent**：openfeel-executor
- **最多重试**：3

## 目标（含反馈条目）

新增 `openfeel config effective [key]`，输出四个配置键（`execution_mode`/`auto_advance`/`test_enabled`/`merge_mode`）的**有效值 + 生效来源**（`status.md` / `config.yaml` / `profile.yaml` / `builtin`），为 #5 的口径冲突提供**即时可验证出口**。

**对应反馈**：`docs/phase-5/06-openfeel-tooling-feedback.md` 问题 #5（中）「让 `openfeel config` 输出有效值 + 生效来源」。
**对应决策**：P9（采用**新子命令**而非改写 `config get`）。

> 参见 kb/patterns.md #CLI lint 子命令组扩展与 `--fix` 自动修复模式（父命令组追加子命令 + 子命令独立实现）、#i18n 键对称性校验模式、#CLI 国际化封装模式。

## 关键设计决策

1. **扩展现有命令还是新增子命令？→ 新增子命令（P9，裁定）**：
   - `config get` 语义 = **原始值读取**（项目模式 key 必填、全局模式读 profile）；`effective` 语义 = **级联解析结果**（值 + 来源）。二者语义不同，混入会使 `get` 输出契约变化并破坏既有测试（`test/commands/*` 与 `test/core/config.test.ts`）。
   - 遵循既有「父命令组追加子命令」惯例（`lint i18n`/`lint kb`、`config get-lang`/`set-lang`），零破坏、可独立演进。
2. **级联单一权威**：`resolveEffectiveConfig()` 放在 `FlowManager`，**内部复用 op-001 的 `buildCascadeConfig`**，不另写一套 config.yaml/profile 解析（避免制造新的「双源」——正是本版本要消除的问题）。
3. **来源判定（写死，优先级同 P2）**：`statusOverrides[key]` → `status.md`；否则 `configDefaults[key]` → `config.yaml`；否则 `profileDefaults[key]` → `profile.yaml`；否则 `DEFAULT_CONFIG[key]` → `builtin`。
4. **键集固定**：`execution_mode` / `auto_advance` / `test_enabled` / `merge_mode`（与 `DEFAULT_CONFIG` 一致）。值统一字符串化（`test_enabled` → `'true'`/`'false'`）。
5. **CLI 不依赖 flow.json**：`FlowManager` 未加载（无 flow.json）时 `buildCascadeConfig` 的 status 层为空，仍可输出 config/profile/builtin 结果。
6. **内置默认需可导入**：`DEFAULT_CONFIG`（`src/core/config.ts:123-128`）现为模块私有 `const`，须 `export`（供 `flow-manager` 取 `builtin` 值）。

### 改动 1：`src/core/config.ts` 导出 `DEFAULT_CONFIG`（`:123`）

### 改动 2：`src/core/flow-manager.ts` 新增公共方法 `resolveEffectiveConfig()`

置于 `verboseSummary`（`:1538` 附近）或 `getPhase` 之后的查询区；`DEFAULT_CONFIG` 与 `ConfigSource` 从 `./config.js` 导入。

```ts
import { readProfile, DEFAULT_CONFIG } from './config.js';

/** 配置生效来源枚举（P9） */
export type ConfigSource = 'status.md' | 'config.yaml' | 'profile.yaml' | 'builtin';

/** `openfeel config effective` 的四个受管键 */
const EFFECTIVE_CONFIG_KEYS = ['execution_mode', 'auto_advance', 'test_enabled', 'merge_mode'] as const;

/**
 * 解析四个受管配置键的「有效值 + 生效来源」。
 * 复用 buildCascadeConfig（单一权威），优先级：status.md > config.yaml > profile.yaml > builtin。
 */
resolveEffectiveConfig(): Record<string, { value: string; source: ConfigSource }> {
  const cascade = this.buildCascadeConfig();
  const result: Record<string, { value: string; source: ConfigSource }> = {};
  for (const key of EFFECTIVE_CONFIG_KEYS) {
    if (cascade.statusOverrides[key] !== undefined) {
      result[key] = { value: cascade.statusOverrides[key], source: 'status.md' };
    } else if (cascade.configDefaults[key] !== undefined) {
      result[key] = { value: cascade.configDefaults[key], source: 'config.yaml' };
    } else if (cascade.profileDefaults[key] !== undefined) {
      result[key] = { value: cascade.profileDefaults[key], source: 'profile.yaml' };
    } else {
      result[key] = { value: String(DEFAULT_CONFIG[key]), source: 'builtin' };
    }
  }
  return result;
}
```

### 改动 3：`src/commands/config.ts` 新增子命令（置于 `set` 块 `:227` 之后）

- 头部 import 增加：`import { FlowManager } from '../core/flow-manager.js';`
- 命令：
  ```ts
  // openfeel config effective [key] — 输出有效值 + 生效来源（P9）
  configCmd
    .command('effective [key]')
    .description(t('help.config.effective'))
    .action((key?: string) => {
      const lang = getCliLang(process.cwd());
      const mgr = new FlowManager(process.cwd());
      const resolved = mgr.resolveEffectiveConfig();
      const keys = Object.keys(resolved);

      if (key) {
        if (!resolved[key]) {
          console.error(t('config.effective.unknownKey', lang, { key, keys: keys.join(', ') }));
          process.exit(1);
        }
        const r = resolved[key];
        console.log(t('config.effective.row', lang, { key, value: r.value, source: r.source }));
        return;
      }

      console.log(t('config.effective.title', lang));
      for (const k of keys) {
        const r = resolved[k];
        console.log(t('config.effective.row', lang, { key: k, value: r.value, source: r.source }));
      }
    });
  ```

## 参数与校验规则

| 项 | 规则 |
|----|------|
| `[key]` 省略 | 输出四键表格（`execution_mode`/`auto_advance`/`test_enabled`/`merge_mode`） |
| `[key]` 提供且受管 | 输出单键 `{key}: {value}   [来源: {source}]` |
| `[key]` 提供但非受管 | `config.effective.unknownKey` + exit 1 |
| 来源判定 | `status.md` > `config.yaml` > `profile.yaml` > `builtin` |
| flow.json 缺失 | 正常输出（status 层为空），不报错 |
| 副作用 | 只读，不写盘 |
