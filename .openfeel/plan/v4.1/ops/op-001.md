# op-001：构建脚本三步管线改造

- **阶段**：v4.1-stage-01
- **前置**：无
- **负责 Agent**：Executor
- **最多重试**：3

## 目标

改造 `build.js`，使其在 TypeScript 编译前自动读取三类源文件（core.md / Agent / Skill），编码/转义后注入到 `src/core/templates.ts` 和 `src/core/update.ts` 的对应常量中，替代手动维护。

## 知识库参考

- kb/patterns.md #CLI 原子管理模式 — 构建脚本应作为可信的单步自动化入口
- kb/troubleshooting.md #流水线文件引用断裂连锁修复 — 路径+命令+配置三层引用应视为整体校验单元
- kb/setup.md #构建与测试 — 当前测试状态 225/227

## 实施步骤

- [ ] **步骤 1**：read 本方案文件完整内容
- [ ] **步骤 2**：改造 build.js 主流程 — 在 `rmSync` 清理 dist/ 之后、`npx tsc` 编译之前，插入三步管线调用：
  - `generateTemplateFromCoreMd()` — core.md → Base64 → 写入 templates.ts
  - `generateAgentDefinitions()` — agents/*.md → AGENT_DEFINITIONS → 写入 update.ts
  - `generateSkillDefinitions()` — skills/*/SKILL.md → SKILL_DEFINITIONS → 写入 update.ts
- [ ] **步骤 3**：在 `src/core/templates.ts` 中为 `CORE_INSTRUCTIONS_TEMPLATE_B64` 添加注入锚点：
  ```typescript
  // AUTO-GENERATED-BEGIN: CORE_INSTRUCTIONS_TEMPLATE_B64
  export const CORE_INSTRUCTIONS_TEMPLATE_B64 = "CURRENT_BASE64_VALUE";
  // AUTO-GENERATED-END: CORE_INSTRUCTIONS_TEMPLATE_B64
  ```
  注意：保持文件头部的 JSDoc 注释和其他导出（DEV_CORE_TEMPLATE、CURRENT_TEMPLATE）不变。
- [ ] **步骤 4**：在 `src/core/update.ts` 中为 `AGENT_DEFINITIONS` 和 `SKILL_DEFINITIONS` 添加注入锚点：
  ```typescript
  // AUTO-GENERATED-BEGIN: AGENT_DEFINITIONS
  const AGENT_DEFINITIONS: Record<string, string> = { ... 现有7个Agent ... };
  // AUTO-GENERATED-END: AGENT_DEFINITIONS

  // AUTO-GENERATED-BEGIN: SKILL_DEFINITIONS
  const SKILL_DEFINITIONS: Record<string, string> = { ... 现有8个Skill ... };
  // AUTO-GENERATED-END: SKILL_DEFINITIONS
  ```
  注意：保持文件头部 JSDoc、import 语句、ToolEntry/supportedTools/selectTools 等逻辑不变。
- [ ] **步骤 5**：实现 `generateTemplateFromCoreMd()` — 逻辑：
  1. `readFileSync('.opencode/instructions/core.md', 'utf-8')`
  2. `Buffer.from(content).toString('base64')`
  3. 读取 `src/core/templates.ts`，用正则匹配 `AUTO-GENERATED-BEGIN: CORE_INSTRUCTIONS_TEMPLATE_B64` 到 `AUTO-GENERATED-END: CORE_INSTRUCTIONS_TEMPLATE_B64` 之间的内容（含标记行），替换为：
     ```
     // AUTO-GENERATED-BEGIN: CORE_INSTRUCTIONS_TEMPLATE_B64
     export const CORE_INSTRUCTIONS_TEMPLATE_B64 = "{base64}";
     // AUTO-GENERATED-END: CORE_INSTRUCTIONS_TEMPLATE_B64
     ```
  4. `writeFileSync` 写回
- [ ] **步骤 6**：实现 `generateAgentDefinitions()` — 逻辑：
  1. `readdirSync('.opencode/agents/')` 过滤 `*.md`
  2. 对每个 .md 文件：`readFileSync` → 转义特殊字符（反引号→\\\`，`${`→`\${`，反斜杠→`\\`）
  3. 组装 `Record<string, string>` 对象字面量字符串（含 key 和模板字符串值）
  4. 替换 update.ts 中 `AUTO-GENERATED-BEGIN: AGENT_DEFINITIONS` 到 `AUTO-GENERATED-END: AGENT_DEFINITIONS` 之间的内容
- [ ] **步骤 7**：实现 `generateSkillDefinitions()` — 逻辑：
  1. 遍历 `.opencode/skills/*/SKILL.md`（glob 或 readdir + 检测子目录）
  2. 对每个 SKILL.md：`readFileSync` → 同样的转义处理
  3. 组装 `Record<string, string>` 对象字面量字符串
  4. 替换 update.ts 中 `AUTO-GENERATED-BEGIN: SKILL_DEFINITIONS` 到 `AUTO-GENERATED-END: SKILL_DEFINITIONS` 之间的内容
- [ ] **步骤 8**：在 build.js 中所有文件写入操作使用 `try-catch`，失败时输出明确错误信息并 `process.exit(1)`
- [ ] **步骤 9**：运行 `node build.js` 验证构建脚本自身可执行（注意：不依赖项目内部 TS 模块，仅用 Node.js 内置 fs/path 和 child_process）
- [ ] **步骤 10**：运行 `npm run build` 完整构建，确认：
  - build.js 执行无报错
  - templates.ts 中 Base64 值已更新
  - update.ts 中 AGENT_DEFINITIONS 和 SKILL_DEFINITIONS 已更新
- [ ] **步骤 11**：运行 `npm test` 确保 225+/227 测试通过，无新增失败

## 产出文件

- `build.js` — 重写，新增三步管线函数
- `src/core/templates.ts` — 添加 CORE_INSTRUCTIONS_TEMPLATE_B64 注入锚点（其余内容不变）
- `src/core/update.ts` — 添加 AGENT_DEFINITIONS / SKILL_DEFINITIONS 注入锚点（其余内容不变）
