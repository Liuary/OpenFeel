## 实施步骤

### T1 — `src/core/config.ts` 配置面（8 处改动 [REV-74-011 修订]）

1. **类型与值域**（置于 `ConfigDefaultsSchema` 定义之前，约 L25 上方）：

```ts
/** 工作流模式枚举值域（单一来源：schema / 类型 / 命令面值域派生均引用此处） */
export const WORKFLOW_MODES = ['full', 'fast'] as const;
/** 工作流模式：full=完整链路（含计划审查/方案/测试）；fast=快速迭代（跳过上述环节，保留审查单轮） */
export type WorkflowMode = (typeof WORKFLOW_MODES)[number];
```

2. **`ConfigDefaultsSchema`**（L26-30）：`merge_mode` 行后追加：

```ts
  workflow_mode: z.enum(WORKFLOW_MODES).optional().default('fast'),
```

   **第 8 处（[REV-74-011 修订] 补登记——实施期必要变更，openfeel-reviewer 复核确认「必要且正确」）**：`ConfigDefaultsSchema.auto_advance` 逐键 `.default()` 由 `'disabled'` **同步翻转 `'enabled'`**（与 `DEFAULT_CONFIG.auto_advance` 同键值 = 单一权威；源码注释「逐键 .default() 必须与 DEFAULT_CONFIG 同键值保持一致」即此约定固化）。原因：`resolveConfigDefaults` 缺失键路径经 `safeParse(undefined)` 取 **schema 逐键默认**——若不同步则取旧默认 `disabled`，F4/F6 断言（期望 `enabled`）必红，且同一默认值出现两处来源分叉。**代码动作已在实施期完成；本处为计划文档补登记（无新增代码动作）。**

3. **`DEFAULT_CONFIG`**（L164-168）：

```ts
/** 默认配置值（导出供 flow-manager 作为级联 builtin 层取值，保持单一权威） */
export const DEFAULT_CONFIG: Config = {
  execution_mode: 'manual',
  auto_advance: 'enabled',   // 裁定 E：部署级默认自动推进开启（与 workflow_mode 无关）
  merge_mode: 'manual',
  workflow_mode: 'fast',     // 裁定 B：新建默认 fast
};
```

4. **`Config` 接口**（L152-161）：嵌套 `defaults` 与扁平兼容字段各增 `workflow_mode?: 'full' | 'fast';`。

5. **`ResolvedConfigDefaults`**（L171-175）+ **`resolveConfigDefaults()`**（L193-219）：
   - 接口增 `workflow_mode: 'full' | 'fast';`，JSDoc「三键 → 四键」；
   - result 初始化增 `workflow_mode: DEFAULT_CONFIG.workflow_mode as ResolvedConfigDefaults['workflow_mode'],`；
   - L208 键数组扩为 `['execution_mode', 'auto_advance', 'merge_mode', 'workflow_mode'] as const`；
   - **不做级联**（只读 defaults、逐键失败回退 `DEFAULT_CONFIG` 的既有语义逐字保留）。

6. **`STAGE_FIELD_BY_CONFIG_KEY`**（L69-72）：追加 `workflow_mode: '工作流模式',`。

7. **`CONFIG_TEMPLATE_ZH`**（defaults 节 L431-442）`merge_mode` 块之后追加：

```
  # 工作流模式：full=完整链路（含计划审查/方案/测试）
  #            fast=快速迭代（跳过上述环节，保留审查单轮）

```

    **`CONFIG_TEMPLATE_EN`**（defaults 节 L484-495）同步追加：
