## 一、变更目标

## 二、B1 / B8 子项清单

> **执行纪律**：动手前以 `rg`/`read` 复核坐标（stage-51 已改 `commands/flow.ts`，行号可能漂移）。

### B1-1（高）`flow status --json`

- **文件:行号**：`src/commands/flow.ts:41`（`.command('status')`）
- **现状**：仅人类可读输出；无 `--json`。
- **改后**：增 `.option('--json', …i18n help 键…)`；`--json` 时：
  ```jsonc
  { "schemaVersion": 1, "pipeline": { "phase": "…", "current": { "stage": "…", "op": "…" } },
    "stages": [ { "id": "…", "phase": "…", "status": "…", "deps": [], "ops": { "op-001": "pending" } } ],
    "counts": { "total": 0, "done": 0, "active": 0 } }
  ```
  `--json` 分支**不得**打印标题/颜色/额外提示行（`return` 前不输出任何非 JSON 文本）。

### B1-2（高）`flow current --json` + B8 显示回退

- **文件:行号**：`src/commands/flow.ts:300`（`.command('current')`）；`src/core/flow-manager.ts:668-677`（`getCurrent()`，实测 `op` 为空时返回 `null`）
- **现状**：`getCurrent()` 在 `current.op === ''` 时返回 `null` → `flow current` 显示「阶段: (无)」，与 flow.json 的 `current.stage` 不一致（B8）。
- **改后**：
  1. **B8（命令层回退，不改 `getCurrent()` 返回契约）**：`current` 命令在 `getCurrent()` 为 `null` 时，改为读取 `mgr.getData()?.pipeline.current`，输出 `stage` + i18n 文案 `flow.current.noOpTmpl`（「{stage}（无 op）」）；若 `stage` 亦为空 → 保持既有「(无)」文案。
  2. **`--json`**：`{ "schemaVersion": 1, "stage": "…", "op": "", "phase": "…" }`（`op` 为空串而非 `null`，便于机器消费）。
- **注意**：`getCurrent()` 被其它消费者（如 `overview`）复用 → **本 op 不改其签名/返回**（仅命令层回退），避免连带翻转。

### B1-3（高）`flow health --json`

- **文件:行号**：`src/commands/flow.ts:1234`（`.command('health')`；现有 `--quick`）
- **改后**：增 `--json` → `{ "schemaVersion": 1, "ok": true, "items": [ { "name": "…", "status": "pass|warn|fail", "detail": "…" } ] }`。
  - 复用 `flow-manager.ts` 的 `healthCheck()` 结果（**新增只读访问器** `getHealthReport(quick?)` 或直接在命令层调用既有方法，取 `items` 数组）；
  - **退出码语义不变**（有 `fail` → 非 0；`warn` 不影响）。

### B1-4（中）`flow metrics --json`

- **文件:行号**：`src/commands/flow.ts:325`（`.command('metrics')`）；`src/core/metrics.ts`（`summary()`）
- **改后**：增 `--json` → `{ "schemaVersion": 1, ...metricsSummary }`（结构化指标对象，键名与 `summary()` 语义一致；**不**输出人类可读的表格文本）。
  - 若 `metrics.ts` 仅有 `summary()`（字符串）→ 在 `MetricsStore` 增 `getSummaryData()`（结构化访问器），**不改 `summary()` 既有签名/输出**（避免翻转既有断言）。

### B1-5（中）`flow overview --json`

- **文件:行号**：`src/commands/flow.ts:165`（`.command('overview')`）
- **改后**：增 `--json` → `{ "schemaVersion": 1, ...overviewData }`（阶段计数/health 统计/当前阶段等结构化字段）。命令层现有 `healthCheck(true)` 的 quick 统计（`:282-288`）改由结构化字段输出。

### B1-6（中）`flow phases --json` 追加 `schemaVersion`（**保持三键不动**）

- **文件:行号**：`src/commands/flow.ts:336`（`.command('phases')`；`:355-357` `JSON.stringify({ phases, transitions, advanceAccepted })`）
- **现状**：`--json` 输出 `{ phases, transitions, advanceAccepted }`（stage-41 起，stage-49 T19 追加 `transitionsDiff`）。
- **改后**：**仅追加** `schemaVersion: 1`（既有键**逐字保留**，含 `transitionsDiff`）；`--json` 描述文案更新。

### B1-7（中）i18n help 键

- 为 6 个命令的 `--json` 选项补 help 键（zh/en 对称）：`help.flow.status.json`、`help.flow.current.json`、`help.flow.health.json`、`help.flow.metrics.json`、`help.flow.overview.json`、`help.flow.phases.json`（命名以既有 `help.<path>.<opt>` 约定为准）；B8 文案 `flow.current.noOpTmpl`。

## 三、接口与签名变更

| 接口 | 变更 | 兼容 |
|------|------|------|
| `flow status\|current\|health\|metrics\|overview` | 增 `--json` | 纯新增；人类可读输出不变 |
| `flow phases --json` | 追加 `schemaVersion` | **向后兼容**（既有键保留） |
| `FlowManager.getHealthReport(quick?)` | **新增**（只读访问器，返回结构化 health） | 纯新增 |
| `MetricsStore.getSummaryData()` | **新增**（结构化指标） | 纯新增；`summary()` 不变 |
| `getCurrent()`（`flow-manager.ts:668-677`） | **不改**（B8 在命令层回退） | 契约不变 |

**`--json` 契约（统一口径，写死）**：
1. **纯 JSON 单文档**：`process.stdout` 仅输出一个 `JSON.parse` 可解析的文档；**无 ANSI 转义**、无标题行、无箭头提示；
2. 顶层对象**必须含** `schemaVersion: 1`；
3. 与人类可读输出**互斥**（`--json` 时不走人类可读分支）；
4. `--json` 与 `--quick`（health）等既有选项**可组合**。

## 八、风险与回滚

| # | 风险 | 缓解 / 回滚 |
|---|------|------|
| R1 | 某命令在 `--json` 前已打印提示行 → 破坏纯 JSON | 各命令 `--json` 分支**首行即 `return` 前 `console.log(JSON.stringify(...))`**，不做任何其它输出；验收 3~8 + 用例断言 |

| R4 | `schemaVersion` 命名/位置漂移 | 固定顶层键 `schemaVersion: 1`；未来变更须递增版本（写入注释） |
| R5 | i18n 键与并行 op 冲突 | `deps.yaml` 互斥声明；i18n 编辑串行 |
| **回滚** | — | `git revert`；`--json` 为新增选项（移除无副作用）；`phases` 增字段可单点回退 |
