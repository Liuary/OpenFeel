# op-002：agent 模板 `permission` 补 `external_directory` 并修正 `utility` `write`→`edit`

- **阶段**：v1.1.2-stage-44
- **状态**：completed
- **编号映射**：CLI `op-002` ↔ 计划编号 **`op-001`**
- **前置**：`op-001`（**hard**：实测结论决定值形式与 `utility` 是否改键）
- **负责 Agent**：openfeel-executor
- **最多重试**：3

## 变更目标

为 9 个 agent 权威源模板（zh-CN + en，共 **18 文件**）的 `permission:` 块末尾补 `external_directory: "allow"`；若 `op-001` 确认 `write` 非 schema 授权键，则将 `openfeel-utility.md` 的 `write: "allow"` 改为 `edit: "allow"`。

**需求映射**：`docs/phase-5/07-openfeel-permission-issue.md` **§四建议 1**（agent 模板补 `external_directory`）+ **§二.2**（白名单遗漏该键 → 回落 `ask`）；裁定 **O1**（保留内联块 + 补键）、**O2**（值取 `allow`）。**op-001 findings 结论为唯一落值依据**。

> 参见 kb/architecture.md #模板单源架构（**只改权威源 + `npm run build` 重生成；禁止手改生成段/构建产物**）、kb/patterns.md #跨平台行尾归一化模式。

## 关键设计决策

1. **只改权威源**：`src/core/templates-data/opencode/agents/{zh-CN,en}/*.md`。**禁改** `src/core/template-loader.ts` 生成段、`.opencode/agents/*.md`（构建产物）。
2. **值形式（数据驱动，依 op-001 场景 B）**：
   - 单值被接受 → `external_directory: "allow"`（**首选**，与同块其余键风格一致）；
   - 单值被拒/被忽略 → `external_directory: { "*": "allow" }`（对象形式，O2 备选）。
3. **插入位置**：该 agent `permission:` 块**最后一个键之后**（保持块内顺序稳定、diff 最小）。
4. **`utility` 改键条件（R3）**：**仅当** op-001 场景 E 确认 `write` 未被识别时，将 `write: "allow"` → `edit: "allow"`；否则保持 `write` 不动并在方案返回注明。
5. **不动其它字段**：`description`/`mode`/`model`/`color`/`reasoning_effort`/正文一律不变；不新增/删除其它键。
6. **双语一致**：zh 与 en 的 `permission` 键集必须一致（op-005 有断言）。

## 风险与回滚

| # | 风险 | 缓解/回滚 |
|---|------|-----------|
| 1 | 手改生成段/自举实例 | 只改权威源；`git diff --name-only` 核验；回滚 = `git checkout` 权威源 |
| 2 | 单值形式被拒致补键无效 | op-001 场景 B 数据驱动切对象形式（决策 2） |
| 3 | `write`→`edit` 误改（R3） | 仅当 op-001 明确「未识别」才改；`edit` 与内置默认 `*:allow` 一致，无实际放宽 |
| 4 | 双语不同步（R5） | op-005 键集一致性断言 |
| 5 | `feel-tester` 的 `webfetch: "deny"` 被误动 | 仅在其后**追加**一行，不改既有键（决策 5） |
| 6 | 插入位置错误致 YAML 结构破坏 | 插入于块末键之后、下一个 frontmatter 键之前；改后 `openfeel flow current`/`npx tsc --noEmit` 无异常；op-003 build 校验 |
