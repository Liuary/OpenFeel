## 精确改动点（文件:行号 → 现状 → 改后）

### 1. 遗留 #7：三个子 Schema 补 `.passthrough()`（`src/core/config.ts:57-74`）

- 现状：`ProfileUserSchema`（`:57-60`）/ `ProfilePreferencesSchema`（`:63-68`）/ `ProfileHistorySchema`（`:71-74`）均为普通 `z.object({…})`（**默认剥离**未知键）；仅顶层 `ProfileSchema`（`:77-81`）已 `.passthrough()`。
- 改后：
  ```ts
  export const ProfileUserSchema = z.object({ … }).passthrough();
  export const ProfilePreferencesSchema = z.object({ … }).passthrough();
  export const ProfileHistorySchema = z.object({ … }).passthrough();
  ```
- **依据**：使 `user.custom_ext` / `preferences.custom_pref` / `history.custom_hist` 在 `readProfile`→`writeProfile` 往返中**不被剥离**（与顶层 passthrough 语义一致）。
- **不影响语义**：`normalizeConfig`/默认值合并不变；仅保全序列化往返（R4）。

### 2. 遗留 #8：非法 YAML 不覆盖（`src/core/config.ts:181-206` + `:233-267`）

- **裁定（REV-48-007）**：`readProfile` 增**可选** `parseError?: string`（不破坏既有签名）；**解析/校验失败 → 不写回** + `console.warn` + 由调用方决策；**不引入** `config.ts → update-infos.ts` 依赖边（`ensureProfileDefaults` 触发于 Feel 会话流程而非 `update` 命令，写全局 `update_infos.md` 语义不恰当）。
- **改后（`readProfile`）**：
  ```ts
  export function readProfile(): Profile & { parseError?: string } {
    const profilePath = getProfilePath();
    if (!existsSync(profilePath)) { return { ...DEFAULT_PROFILE }; }
    try {
      const content = readFileSync(profilePath, 'utf-8');
      const raw = parseYaml(content) as Record<string, unknown> | null;
      if (!raw || typeof raw !== 'object') {
        // 错误路径：顶层非对象（含空文件/标量）—— 标记 parseError，供调用方跳过写回
        return { ...DEFAULT_PROFILE, parseError: `profile.yaml 顶层非对象：${profilePath}` };
      }
      const parsed = ProfileSchema.parse(raw) as Profile;
      return { …（既有深度合并不变）… };
    } catch (err) {
      // 错误路径：YAML 语法/Zod 校验失败 —— 标记 parseError（不写回），返回默认值保持可用性
      return { ...DEFAULT_PROFILE, parseError: `profile.yaml 解析失败（${err instanceof Error ? err.message : String(err)}）：${profilePath}` };
    }
  }
  ```
- **改后（`ensureProfileDefaults:233-237`）**：入口检查 parseError → 告警 + 直接返回（**跳过全部写回**）：
  ```ts
  const profile = readProfile();
  // 错误路径：profile.yaml 非法 → 不覆盖用户文件（遗留 #8；解析失败属用户可修复态，覆盖才是不可逆伤害）
  if (profile.parseError) {
    console.warn(`[profile] ${profile.parseError}；已跳过自动填充写回以保护现有文件`);
    return;
  }
  ```
- **`writeProfile` 调用方**（`src/commands/config.ts:197`，`config set --global`）：改为先 `const cur = readProfile(); if (cur.parseError) { console.error(...); process.exit(1); }`（**不覆盖**非法文件；提示用户修复），再执行既有 read→set→validate→write。
  - > 注意：`config.ts:236`（`ensureProfileDefaults`）已由上方处理；`commands/config.ts` 的 `set --global` 是本模块唯一的另一处写回入口。

## 风险与回滚

| # | 风险 | 缓解/回滚 |
|---|------|-----------|
| 1 | `.passthrough()` 使非法键流入后续逻辑（R4） | 仅保全序列化往返；读取语义（默认值合并）不变；单测覆盖 |
| 2 | 跳过写回使默认填充失效（用户改回文件后需再次触发） | 属**预期**：非法文件优先保护；告警提示用户修复；修复后下一会话正常 |
| 3 | `config set --global` 行为变更（exit 1） | 属改善（避免覆盖用户文件）；提示明确；文档记录 |
| 4 | 返回类型变更破坏调用方 | `parseError` 为**可选**字段 → 结构兼容；`tsc` 兜底 |
| 5 | 误引入依赖边（REV-48-007 禁止） | 验收 3 显式断言 `config.ts` 无 `update-infos` 引用 |
