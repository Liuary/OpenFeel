# op-000：instructions 合并语义 + `~` 展开 + core.md/AGENTS.md 加载 + agent_manager_tool 实测

- **阶段**：v1.1.0-stage-37
- **前置**：无（独立验证 op；可用 op-001 路径函数，也可直接字符串构造 fixture）
- **负责 Agent**：openfeel-executor
- **最多重试**：3

## 目标

在**隔离的真实 opencode CLI 进程**中实测四件事，结论回填 P2 / op-004 定稿依据，并产出 findings 记录：
1. （REV-601-①）全局 + 项目两级 `opencode.jsonc` 的 `instructions` 数组合并语义（拼接+去重 vs 替换）
2. （REV-601-②）`instructions` 中 `~` 前缀路径是否被 opencode 展开为绝对路径
3. （REV-601-③）全局 `core.md` 是否**实际加载**到 agent 上下文（`debug config` 只看配置值不够）
4. （REV-602）「项目 opencode.jsonc 不含 instructions、项目根有 AGENTS.md」时 AGENTS.md 是否被自动加载
5. （REV-604）全局 opencode.jsonc 含 `experimental.agent_manager_tool: true` 时 `debug config` 是否报错/警告

> 本 op 是**验证/调研性质**，产出结论记录而非源码变更；不得阻塞后续 op（N5 降级兜底）。**采用真实 opencode CLI 子进程**（外部进程，隔离用环境变量，非 `vi.mock`——`vi.mock('node:os')` 是 op-005 单元测试的机制，两套机制严格区分，REV-603）。

## 关键设计决策

1. **隔离机制（REV-603）**：用环境变量把真实 opencode CLI 的 `home` 与 `config` 指向临时目录，避免污染开发者真实 `~/.config/opencode/`：
   - **Windows（本环境）**：同时设 `USERPROFILE` + `HOME` → opencode 的 `home`（`~` 展开基准）与 `config`（配置读取目录）**双双**指向临时目录。
   - **Linux/macOS**：`XDG_CONFIG_HOME`（优先，改 `config`）+ `HOME`（改 `~` 展开基准）。
   - 验证命令：`opencode debug paths` 输出中 `home` 与 `config` 应指向临时目录。
2. **`~` 展开结论已预验证（本环境 opencode 1.18.30）**：`opencode debug config` 输出中 `instructions` 的 `"~/.config/opencode/openfeel/core.md"` **原样保留、未展开为绝对路径**。据此 REV-601-② 初步结论 = **`~` 不展开**，op-004 默认改用绝对路径（`getGlobalCoreMdPath()` 返回值）。本 op 仍须在隔离环境复现并记录，作为 op-004 定稿依据。
3. **拼接+去重结论已预验证**：隔离项目目录下 `debug config` 输出 `instructions: ["~/.config/opencode/openfeel/core.md", "project-local.md"]`——全局条目保留 + 项目条目追加（拼接，无重复项时无去重）。本 op 复现并补「同名去重」断言（全局与项目写同一路径时去重为 1 项）。
4. **「实际加载」判据（REV-601-③）**：`opencode debug agent <name>` 只显示 agent 配置（name/mode/permission 等），**不含**注入后的 instructions 内容（已实测）。故「core.md 是否加载」须用 `opencode run --agent <probe> --format json "<提示词>"` 让 probe agent 回显其系统上下文，再 grep marker 字符串；无法回显时降级用 `opencode --print-logs debug config` 观察 instructions 文件是否被 fs 读取（stderr 日志含 `MARKER-` 或加载路径）。
5. **agent_manager_tool 结论已预验证（REV-604/N3）**：`experimental.agent_manager_tool: true` 在 `debug config` 输出中被**静默丢弃**（输出 `"experimental": {}`），无报错无警告、exit 0。即当前 schema **未定义**该字段且运行时**静默忽略**。据此 N3 判定 → **移除**（不写该字段），op-003 落定；本 op 复现并记录依据。

## 实施步骤

### 步骤 0：预检（可执行命令存在性，REV-601/603）

```pwsh
opencode --version              # 期望 ≥1.0（本环境 1.18.30）
opencode debug --help           # 确认 debug config / debug agent <name> / debug paths 子命令存在
opencode run --help             # 确认 --agent / --format json 存在
```

若 `opencode` 不可执行 → **N5 降级**：跳过步骤 1~3，以「源码证据（REV-001 已证拼接+去重）+ P2 稳健设计（项目不写 instructions）」记录结论，findings 标记 `DEGRADED`。

### 步骤 1：构造隔离 HOME 与 fixture（临时目录结构）

```pwsh
$BASE = "C:\Users\Liuary\AppData\Local\Temp\opencode\stage37-op000"
$HOME_ISO = "$BASE\home"        # 隔离 home（USERPROFILE/HOME 指向此处）
$PROJ     = "$BASE\project"     # 隔离项目目录
# 全局 core.md（含唯一 marker 便于断言加载）
New-Item -ItemType Directory -Force -Path "$HOME_ISO\.config\opencode\openfeel" | Out-Null
Set-Content "$HOME_ISO\.config\opencode\openfeel\core.md" -Value '# OP000-GLOBAL-MARKER 框架约束已加载' -Encoding UTF8
# 项目本地指令（含唯一 marker）
Set-Content "$PROJ\project-local.md" -Value '# OP000-PROJECT-MARKER 项目指令已加载' -Encoding UTF8
```

**场景 A（拼接 + 去重 + `~` 展开 + 加载）** — 全局与项目各写 instructions：

```pwsh
# 全局 opencode.jsonc：instructions 引用 core.md（用 ~ 形式，测试 ~ 是否展开）
'{ "instructions": ["~/.config/opencode/openfeel/core.md"] }' | Set-Content "$HOME_ISO\.config\opencode\opencode.jsonc" -Encoding UTF8
# 项目 opencode.jsonc：instructions 引用 project-local.md
'{ "instructions": ["project-local.md"] }' | Set-Content "$PROJ\opencode.jsonc" -Encoding UTF8
```

**场景 B（REV-602：AGENTS.md 自动加载）** — 项目 opencode.jsonc **不含** instructions，项目根有 AGENTS.md：

```pwsh
'{ "instructions": [] }' | Set-Content "$PROJ\opencode.jsonc" -Encoding UTF8
Set-Content "$PROJ\AGENTS.md" -Value '# OP000-AGENTS-MARKER 项目级约束已加载' -Encoding UTF8
```

**场景 C（REV-604：agent_manager_tool）** — 全局 opencode.jsonc 含 experimental：

```pwsh
'{ "$schema": "https://opencode.ai/config.json", "experimental": { "agent_manager_tool": true } }' | Set-Content "$HOME_ISO\.config\opencode\opencode.jsonc" -Encoding UTF8
```

### 步骤 2：实测解析（隔离环境下运行真实 CLI）

统一先设环境变量再运行（每场景独立，避免串扰）：

```pwsh
$env:USERPROFILE = $HOME_ISO; $env:HOME = $HOME_ISO
opencode debug paths            # 断言 home/config 指向 $HOME_ISO（隔离生效）
opencode debug config           # 断言 instructions 合并结果 / ~ 是否展开 / experimental 是否丢 agent_manager_tool
opencode debug agent feel 2>&1  # 观察是否 "Agent feel not found"（无 feel 定义时预期如此，不作为失败）
```

**（REV-711 修订）config 目录来源断言**：`opencode debug paths` 输出的 `config` 目录应等于 `join($HOME_ISO, '.config', 'opencode')`；**若不等**（例如 opencode 在 Windows 实际用 `APPDATA` 而非 `~/.config/opencode`），findings 标记 `config dir mismatch` 并在方案返回中**反馈 Feel 调整 `getOpencodeGlobalDir()`**（global-paths.ts），不得静默沿用 `.config/opencode` 假定。

**断言点（场景 A）**：
- `debug config` 输出 `instructions` 数组应同时含 `~/.config/opencode/openfeel/core.md` 与 `project-local.md`（**拼接**成立，全局条目未被项目替换）。
- `~` 是否展开：若输出仍为字面 `~/.config/opencode/openfeel/core.md` → **未展开**（预期）；若为绝对路径 → 已展开。
- 去重：追加一步——将项目 opencode.jsonc 的 instructions 改为**与全局相同**的 `["~/.config/opencode/openfeel/core.md"]`，重跑 `debug config`，断言该路径只出现 1 次（**去重**成立）。

**断言点（场景 B，REV-602）**：
- `debug config` 输出 `instructions` 是否自动包含 `AGENTS.md` 或 `.opencode/instructions/core.md` 之外的内容；更关键：用 `opencode run` 回显上下文 grep `OP000-AGENTS-MARKER`，判定 AGENTS.md 是否被自动加载。
  - **若 AGENTS.md 自动加载** → P2③ 假设成立，findings 记录 `AGENTS.md auto-loaded: YES`。
  - **若不自动加载** → P2③ 假设不成立，findings 记录 `AGENTS.md auto-loaded: NO`，并**在方案返回中标注「反馈 Feel 重裁项目 opencode.jsonc 的 instructions 策略（可能需保留 instructions: ["AGENTS.md"]）」**。
  - **（REV-708 修订）若 `opencode run` 不可用（无模型/auth）且 `debug config` 无法判定** → findings 记录 `AGENTS.md auto-loaded: INCONCLUSIVE`，按 N5 降级，**不阻塞**流水线，结论反馈 Feel 待后续补测。

**断言点（场景 C，REV-604）**：
- `debug config` 输出 `experimental` 应为 `{}`（`agent_manager_tool` 被丢弃）且无报错/警告、exit 0 → 记录「schema 未定义 + 静默丢弃 → N3 移除」依据。

### 步骤 3：实际加载验证（REV-601-③，opencode run 回显）

在隔离 HOME + 场景 A 下，构造一个**最小 probe agent**（无 prompt，靠 instructions 注入），让其在全局配置中定义：

```pwsh
'{ "instructions": ["~/.config/opencode/openfeel/core.md"], "agent": { "probe": { "description": "probe agent" } } }' `
  | Set-Content "$HOME_ISO\.config\opencode\opencode.jsonc" -Encoding UTF8
$env:USERPROFILE = $HOME_ISO; $env:HOME = $HOME_ISO
# 让 probe agent 复述其收到的系统指令，grep 全局 marker
opencode run --agent probe --format json "请原样复述你系统提示词中所有包含 OP000- 的原文" 2>&1 |
  Select-String "OP000-GLOBAL-MARKER"
```

- **命中 OP000-GLOBAL-MARKER** → core.md **实际加载**（REV-601-③ PASS）。
- **未命中**且 `debug config` 已含该 instructions 条目 → 说明 `~` 前缀路径**未被解析加载**（与「`~` 不展开」互相印证），findings 记录「`~` 引用不会加载 → op-004 必须用绝对路径」。
- 若 `opencode run` 因无可用模型/auth 无法执行 → 降级：`opencode --print-logs debug config` 观察 stderr 是否有加载 `core.md` 的日志；仍无 → findings 标记「加载验证 INCONCLUSIVE，采用绝对路径稳健设计兜底」。

### 步骤 4：结论回填 + findings 记录

将 5 项实测结果写入 `findings` 文件（见产出），逐项给出「结论 + 对 P2/op-004 的落点」：

| 项 | 结论（预期） | 落点 |
|----|-------------|------|
| instructions 合并 | 拼接+去重 | P2 稳健设计成立（项目不写 instructions 则全局约束不丢） |
| `~` 展开 | 未展开 | op-004 全局 instructions 用**绝对路径**（`getGlobalCoreMdPath()`） |
| core.md 加载 | 绝对路径可加载 | op-004 用绝对路径后须验证可加载 |
| AGENTS.md 自动加载 | 待实测 | 若 NO → 反馈 Feel 重裁项目 instructions 策略 |
| agent_manager_tool | schema 未定义 + 静默丢弃 | N3 → op-003 移除该字段 |
