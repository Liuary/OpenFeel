## 摘要

`npx eslint src test dsh` 长期有 **33 errors / 53 warnings**，横跨 **21 个文件**，绝大多数是 `@typescript-eslint/no-unused-vars`（未使用的 import / 变量 / 类型）。v1.5.6 的门禁实际口径是「**新增行 0 错误**」，靠「新增行区间 × 错误行号」对撞来豁免既有债——这个口径有效但会掩盖「债在增长」的趋势，且新贡献者看到的是一条永远红的 eslint 命令。

分布（v1.5.6 实测）：`test/commands/req.test.ts` 4、`test/core/flow-manager.test.ts` 4、`src/core/flow-manager.ts` 3、`src/core/public-logger.ts` 2、`test/core/workspace/global-config.test.ts` 2、`src/commands/flow.ts` 2、`test/commands/flow.test.ts` 2，其余 14 个文件各 1。

## 目标与验收

**目标**
1. 33 个 error 全部清零（优先修 unused vars；确实需要保留的用 `// eslint-disable-next-line <rule> -- <理由>` 显式豁免，**不允许**改规则或降级 `eslint.config.js`）。
2. 53 个 warning 盘点一遍：能修则修，需保留的写理由。
3. 把门禁口径从「新增行 0」收紧为「**eslint 全绿**」，并写进阶段门禁模板。

**验收**
- `npx eslint src test dsh` exit 0（可接受仅剩 0 error / 少量带理由的 disable 注释）。
- `npx tsc --noEmit` 0；`npx vitest run` 全绿（清理 import 不得改变任何行为）。
- `npm run build` ×2 幂等，`dist` 产物无行为差异（可用对撞 `node bin/openfeel.js --version` 与关键命令输出）。
- 门禁模板/文档更新：把「新增行 0」的说明替换为「eslint 全绿」。

**风险提示**：删「未使用」的 import 前必须确认它没有副作用（如仅注册用的 import）；本仓 `src/core/i18n-data/*.ts` 的未使用 `I18nEntry` 类型属类型层，删除安全。
