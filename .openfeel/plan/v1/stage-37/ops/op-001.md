# op-001：全局路径模块 + 全局 opencode 配置基础（global-paths.ts / opencode-config.ts）

- **阶段**：v1.1.0-stage-37
- **前置**：无（先导 op；op-002/003/004 的 hard 基础）
- **负责 Agent**：openfeel-executor
- **最多重试**：3

## 目标

集中解析 opencode 全局路径（`global-paths.ts`）与全局 opencode 配置的内容/解析/深度合并/序列化（`opencode-config.ts`），作为 op-002（init 全局部署）与 op-003（update 深度合并）共用的路径与配置基础，消除 init/update 间框架内容重复。

> 参见 kb/patterns.md #全局跨项目用户画像 YAML 配置模式（`~/.config/{tool}/` 全局路径约定）；kb/architecture.md #opencode 全局/项目 agent 与 skill 合并语义（部署目标前提）；kb/patterns.md #向后兼容可选配置字段模式（深度合并保留用户字段）。

## 关键设计决策

1. **`global-paths.ts` 仅新增 opencode/全局 openfeel 路径，不收纳既有 4 处 `homedir()`**（D37-1 默认「否」）：`config.ts`（profile.yaml）、`identity.ts`（config.json）、`file-lock.ts`（locks）、`resolver.ts`（schemas）保持原样，避免扩大改动面（AGENTS.md 避免过度设计）。
2. **`homedir()` 仅 `global-paths.ts` 导入**（N4）：其余模块经 `global-paths` 取路径 → 测试只需 `vi.mock('node:os', { homedir })` 一处即隔离全部全局路径（op-005 落地）。
3. **新增 `opencode-config.ts`**：收拢「框架级全局 opencode.jsonc 内容对象 + 项目最小覆盖内容 + JSONC 解析/深度合并/序列化」。**本 op 一并产出深度合并逻辑**（虽 op-002 只用到「首次写入」、深度合并由 op-003 消费），使 op-002 与 op-003 均只 hard 依赖 op-001、可并行、无文件归属冲突。（相对计划 op-001「~2 文件」略有扩容到 ~4 文件，换取 op-002/003 并行与零重复，属刻意取舍。）
4. **序列化 = `JSON.stringify(obj, null, 2) + '\n'`**，注释不保留（与 v1.1 D3「JSONC 无标记、解析→深度合并→序列化」一致）；`parseJsonc` 从 update.ts 迁入本模块并导出（op-003 改造 update.ts 时改 import，删本地副本）。`parseJsonc` 仅去 `//` 行注释（既有能力），`/* */` 块注释未支持——框架受管的全局配置不含块注释，不作扩展（记录为已知边界）。
5. **深度合并语义（`deepMergeJsonc`）**：overlay=框架 覆盖 base=用户；逐字段规则见下表（向后兼容可选字段模式）。

| 字段 | 合并规则 |
|------|----------|
| `$schema` | 框架权威（`https://opencode.ai/config.json`）覆盖 |
| `default_agent` | 框架权威 `feel` 覆盖 |
| `instructions` | **拼接 + 去重**（框架 core.md 绝对路径在前，用户条目保留） |
| `agent` | 递归合并；框架模型默认（`openfeel-vision`/`openfeel-reviewer`）**仅在用户未设置时补入**，用户显式覆盖保留。（REV-703 修订：合并粒度为 **agent 级**——用户定义了该 agent key 即视为**完整自定义**，框架**不补 model**；框架仅对用户完全未出现的 agent key 补入整条 `{ model }`。与 stage-40 接口兼容：框架 agent 默认值只增补缺失 agent，不重写既有 agent 内字段） |
| `skills` | 框架**不写**（N6 自动发现）；用户已有 `skills` 保留不动 |
| `experimental` | 递归合并；`agent_manager_tool` 按 N3 处置（op-003 移除，故框架不写该键）；用户其它 experimental 键保留 |
| 其它未知字段 | passthrough 原样保留 |

/**
 * 全局路径模块
 * 集中解析 opencode 与 openfeel 的全局路径（基于用户主目录），
 * 作为 init/update 全局部署的路径基础。
 * 仅此模块 import node:os 的 homedir（N4）：测试 mock 一处即隔离全部全局路径。

import { join } from 'node:path';
import { homedir } from 'node:os';

/** 全局 opencode 配置根目录（~/.config/opencode） */
export function getOpencodeGlobalDir(): string {
  return join(homedir(), '.config', 'opencode');
}

/** 全局 opencode agents 目录 */
export function getGlobalAgentsDir(): string {
  return join(getOpencodeGlobalDir(), 'agents');
}

/** 全局 opencode skills 目录 */
export function getGlobalSkillsDir(): string {
  return join(getOpencodeGlobalDir(), 'skills');
}

/** 全局 opencode.jsonc 路径 */
export function getGlobalOpencodeJsoncPath(): string {
  return join(getOpencodeGlobalDir(), 'opencode.jsonc');
}

/** 全局框架约束 core.md 路径（~/.config/opencode/openfeel/core.md） */
export function getGlobalCoreMdPath(): string {
  return join(getOpencodeGlobalDir(), 'openfeel', 'core.md');

export function getGlobalUpdateStatePath(): string {
  return join(homedir(), '.openfeel', 'update_state.json');

### 步骤 2：新建 `src/core/opencode-config.ts`

```ts
/**
 * 全局 opencode 配置内容与合并逻辑
 * 提供框架级全局 opencode.jsonc 的内容对象、项目最小覆盖内容，
 * 以及 JSONC 解析 / 深度合并 / 序列化，供 init（首次写入）与 update（深度合并）共用。
 */
import { getGlobalCoreMdPath } from './global-paths.js';

/** 判断是否为纯对象（排除数组/null） */
function isPlainObject(v: unknown): v is Record<string, unknown> {
  return typeof v === 'object' && v !== null && !Array.isArray(v);
}

/** 框架级全局 opencode.jsonc 内容对象（N7；instructions 用绝对路径，见 op-000 结论） */
export function buildGlobalOpencodeFrameworkObj(): Record<string, unknown> {
  return {
    $schema: 'https://opencode.ai/config.json',
    default_agent: 'feel',
    instructions: [getGlobalCoreMdPath()],
    agent: {
      'openfeel-vision': { model: 'alibaba-cn/qwen3-vl-plus' },
      'openfeel-reviewer': { model: 'zhipuai/glm-5.2' },
    },
    // N3：experimental.agent_manager_tool 已被移除（op-000 实测 schema 未定义 + 静默丢弃），故不写
  };
}

/** 项目 opencode.jsonc 最小覆盖内容（N7：仅 $schema，不写 instructions/skills/default_agent） */
export function buildProjectOpencodeJsoncObj(): Record<string, unknown> {
  return { $schema: 'https://opencode.ai/config.json' };
}

/**
 * 解析 JSONC 文本为对象（去 // 行注释后 JSON.parse）。
 * 迁移自 update.ts 的 parseJsonc（op-003 删本地副本改 import 本函数）。
 */
export function parseJsonc(text: string): Record<string, unknown> {
  const normalized = text.replace(/\r/g, '');
  let result = '';
  let inString = false;
  let inEscape = false;
  let i = 0;
  while (i < normalized.length) {
    const ch = normalized[i];
    const next = normalized[i + 1];
    if (inEscape) { result += ch; inEscape = false; i++; continue; }
    if (ch === '\\' && inString) { result += ch; inEscape = true; i++; continue; }
    if (ch === '"') { inString = !inString; result += ch; i++; continue; }
    if (!inString && ch === '/' && next === '/') {
      i += 2;
      while (i < normalized.length && normalized[i] !== '\n') i++;
      if (i < normalized.length && normalized[i] === '\n') { result += '\n'; i++; }
      continue;
    }
    result += ch;
    i++;
  }
  return JSON.parse(result);
}

/**
 * 框架 agent 默认值合并（REV-703 修订：粒度为 agent 级）。
 * 仅在用户完全未定义该 agent key 时补入整条 { model }；用户定义了该 agent key
 * 即视为完整自定义，框架不补、不覆盖其内部任何字段（如 model）。
 * 与 stage-40 接口兼容：只增补缺失 agent，不重写既有 agent 内字段。
 */
function mergeAgentDefaults(
  baseVal: unknown,
  overlayVal: Record<string, unknown>,
): Record<string, unknown> {
  const base = isPlainObject(baseVal) ? baseVal : {};
  const result: Record<string, unknown> = { ...base };
  for (const [name, agentOverlay] of Object.entries(overlayVal)) {
    if (!(name in result)) result[name] = agentOverlay;
  }
  return result;
}

/**
 * 深度合并两个 opencode 配置对象（overlay=框架 覆盖 base=用户）。
 * 逐字段规则见 op-001 关键设计决策表；用户未知字段 passthrough 保留。
 */
export function deepMergeJsonc(
  base: Record<string, unknown>,
  overlay: Record<string, unknown>,
): Record<string, unknown> {
  const result: Record<string, unknown> = { ...base };
  for (const [key, overlayVal] of Object.entries(overlay)) {
    if (key === 'instructions' && Array.isArray(overlayVal)) {
      const baseVal = Array.isArray(base[key]) ? (base[key] as unknown[]) : [];
      result[key] = Array.from(new Set([...overlayVal, ...baseVal]));
    } else if (key === 'agent' && isPlainObject(overlayVal)) {
      result[key] = mergeAgentDefaults(base[key], overlayVal);
    } else if (key === 'skills') {
      // 框架不写 skills（N6），保留用户已有（result.skills 不动）
    } else if (isPlainObject(overlayVal) && isPlainObject(base[key])) {
      result[key] = deepMergeJsonc(base[key] as Record<string, unknown>, overlayVal as Record<string, unknown>);
    } else {
      result[key] = overlayVal;
    }
  }
  return result;
}

/** 合并全局 opencode.jsonc：解析→深度合并→序列化（保留用户字段，注释不保留） */
export function mergeGlobalOpencodeJsonc(raw: string): string {
  const base = parseJsonc(raw);
  const merged = deepMergeJsonc(base, buildGlobalOpencodeFrameworkObj());
  return JSON.stringify(merged, null, 2) + '\n';
}
```

## 风险与注意

- **D37-1 边界**：不收纳既有 4 处 `homedir()` 路径（config/identity/file-lock/resolver），避免过度设计与扩大改动面；如 Reviewer/Feel 判定统一收纳收益更大，再回退本 op 扩范围。
- **`parseJsonc` 块注释不支持**：既有能力边界，全局受管配置不含 `/* */`，记录即可；遇到块注释 parse 失败 → 降级为「跳过合并、保留原文件」并告警（op-003 落地）。
- **深度合并幂等性**：`instructions` 去重用 `Array.from(new Set(...))` 保证二次合并不产生重复；键序 = 框架键在前 + 用户键原序，`JSON.parse` 保序故稳定。
