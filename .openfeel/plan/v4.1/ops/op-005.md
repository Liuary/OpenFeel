# op-005：子 Agent 返回精简模式

- **阶段**：v4.1-stage-01
- **前置**：无
- **负责 Agent**：Executor
- **最多重试**：2
- **优先级**：P2（cache 命中率 95.5%，影响有限）

## 目标

子 Agent（Planner、Schemer、Executor、Reviewer、Feel Tester、Archiver）在完成任务后，向 Feel 返回精简摘要而非完整报告。完整报告写入对应私域日志（`.openfeel/users/{username}/log/`）。

## 知识库参考

- kb/architecture.md #Feel 调度 + openfeel CLI 推进模型 — 下游 Agent 仅在自己的职责边界内操作
- kb/patterns.md #Executor 强制第一步读方案 — 返回精简不影响执行纪律

## 实施步骤

- [ ] **步骤 1**：read 本方案文件完整内容
- [ ] **步骤 2**：在 `.opencode/agents/feel.md` 中新增「子 Agent 返回规范」小节，定义精简摘要格式：
  ```markdown
  ## 子 Agent 返回精简模式

  下游 Agent 完成任务后，向 Feel 返回精简摘要（≤ 10 行），格式：

  - **Agent**：{agent_name}
  - **状态**：{pass|fail|warning}
  - **摘要**：{一句话描述完成的工作}
  - **产出文件**：{关键文件列表，≤ 5 个}
  - **遗留问题**：{如有，列出 REV/BUG 编号；如无，写"无"}

  完整报告写入 `.openfeel/users/{username}/log/`，命名 `op-{op_id}-report-{date}.md`。
  Feel 在收到精简摘要后，检查状态决定下一步；需要详情时通过 `read` 工具加载完整报告。
  ```
