## 已闭环 REV

### REV-001 (high, closed): kb/index.md 概览表源文件数与实际不一致

**问题**：`kb/index.md`「项目快速概览」表格中「源文件」字段为 38，实际项目有 39 个 `.ts` 文件。与 `openfeel project overview` CLI 输出不一致。

**修复**：将 `38 个 .ts 文件（src/）` 改为 `39 个 .ts 文件（src/）`。

**教训**：包含动态指标（如文件计数）的静态概览表初始值必须与实际一致。Archiver 的索引维护逻辑（步骤 0）虽能在下次归档时修正，但初始值不应依赖修正机制。

### REV-002 (high, closed): plan 目录计数 glob 模式始终输出 0

**问题**：`src/commands/project.ts` 使用 `fg.sync(['plan/*/'])` 匹配子目录，fast-glob 默认仅返回文件，尾部斜杠不会激活目录匹配，导致始终输出 0。

**修复**：改为 `fg.sync(['plan/*'], { onlyDirectories: true })` 并移除尾部斜杠。

**教训**：fast-glob 的 `onlyDirectories` 选项必须显式声明才能匹配目录。尾部斜杠模式不具备自动激活效果。此坑位已沉淀至 kb/troubleshooting.md。

### REV-003 (medium, closed): Archiver 核心职责编号重复

**问题**：`.opencode/agents/archiver.md` 核心职责节中，新增的索引维护条目编号 `1.` 与原有操作记录归档编号 `1.` 重复（两个 `1.`）。

**修复**：重新编号为 1→操作记录归档、2→索引维护、3→知识提取、4→阶段总结。

**教训**：在编号列表中插入新条目时，需同步更新所有后续条目编号，避免编号冲突导致的歧义。

## 心得建议

1. **静态概览表 + 动态校验双保险**：op-001 的「项目快速概览」表包含可自动校验的指标（源文件数、Agent 数），Archiver 的步骤 0 应在每次归档时核对这些值，形成"申报 → 校验 → 纠正"的闭环。

2. **glob 库行为验证**：在使用 glob 库的非常规选项（如目录匹配、符号链接跟随）时，应在方案阶段通过实测验证行为，而非假设"应该可以"。REV-002 若在 op-002 实现前做一次 `fg.sync(['plan/*/'])` 测试即可提前发现。

3. **编号一致性**：在 Agent prompt 等结构化文档中插入新条目时，应全文检查编号序列，确保无重复或断裂。
