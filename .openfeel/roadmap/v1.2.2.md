## 目标

把 OpenFeel CLI 从「人类可读为主、决策散落在 Agent 提示词」升级为「**机器可读契约稳定、调度决策由 CLI 单一权威输出**」，让 DSH 适配器（及未来任何 harness 适配器）不再镜像领域逻辑、不再解析中文文本、不再依赖「有无堆栈」区分失败类型。

1. **JSON 输出契约基础设施**：冻结 `--json` 单文档契约（`schemaVersion` 恒为首键、数组元素字段不增删、可选字段用 `null`）；新增机器可读错误封装（稳定 `code` + `kind=refusal|internal`，**退出码 0/1/2 语义零改动、新增 3=internal**；legacy 载荷追加 `errorKind`；12 行 code→kind→exitCode 映射表）；`--version --json`；全局 `--project <path>`。
2. **调度决策权威**：新增 `flow next [--json]`，由 CLI 单点输出「当前阶段 + 相位 → 负责 Agent → 合法下一相位 → 建议命令 → 守卫 → 阻塞 REV」；`flow status --json` 的 `stages[]` 补齐 `workflowMode` / `requirementId` / `reviewTier` / `effectiveReviewTier` / `opsSummary`；`flow phases --json` 显式区分「展示档位」与「生效档位」。
3. **读命令 `--json` 补全**：10 组读命令（13 个命令面）全部支持 `--json`；`req list --json` 增 `linkedStages` / `progress`；`flow archive --dry-run --json` 暴露判据明细；`openfeel archive <stage> --json`。
4. **收口与适配器验收**：文档多载体（README×3 / GETTING_STARTED / commands / manual / cli-usage skill 快照 / 新增 JSON 契约文档）；CHANGELOG `[1.2.2]`；版本 1.2.2 全链路 A/B/C/D/E；用 OpenFeel-DSH 真实消费「既有 18 个 `--json` 出口 + 本版 11 项需求对应的全部新出口」做契约断言。
