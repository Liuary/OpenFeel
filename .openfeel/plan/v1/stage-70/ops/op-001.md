## 统一改写约定（4 skill 同构，R-1 零回归总纲）

1. **分节命名（严格字面）**：平台小节标题**一律**为 `### opencode 适配器` 与 `### Claude Code 适配器`（h3，含中文「适配器」三字与中间单空格）。
2. **正文能力名叙述**：skill 首节（或 `## 说明` 类首节）加一句：「正文以**能力名**叙述；平台差异见 `### opencode 适配器` / `### Claude Code 适配器` 两小节。」
3. **opencode 小节 = 原文搬家（零回归）**：
   - 原平台专有内容**整体迁入** `### opencode 适配器`；
   - 迁入块内**所有非标题行逐字保留**（字节不变，含代码块、行内 code、加粗、标点）；
   - **唯一允许的改动**：块的**标题行层级**由 `##`/`###` 降一级为 `###`/`####`（仅 `#` 数量变化，标题文本不变）；若原块无标题，则整块平移、不改一行。
4. **一个 skill 可含多对 `### opencode 适配器`/`### Claude Code 适配器`**（挂在各自能力名 `##` 小节下）；**标题文本须完全一致**。T4.1/T4.2 断言按 `toContain` 匹配（见 op-003）。
5. **Claude 小节内容**：仅写 Claude Code 侧真实事实；**不得**照抄 opencode 小节；不得引入未核实路径/字段（未定项写「由 Claude 侧决定」并标注本阶段边界）。
6. **`description` frontmatter**：**保留原触发词**（如 `Model not found`），仅**扩充**能力词（如「模型配置」「Claude Code 适配器」），不改 skill `name`。
7. **Feels 措辞（本 op 4 skill 内）**：正文中作为编排者角色的独立 `Feel` → 首现「主会话（Feel）」、其后「主会话」；**保留** `feel`（小写 agent 名/文件名）与「Feel 角色」「OpenFeel」。详见 T1.5。
