# op-006：迁移脚本 — `openfeel flow migrate` 旧版→新版自动转换
- **阶段**：v4.1-stage-03
- **前置**：op-001（PipelineSchema 类型定义）+ op-002（FlowManager 方法就绪）
- **负责 Agent**：Executor

## 目标

新增 `openfeel flow migrate` 子命令，将旧版（全局 phase）flow.json 自动转换为新版（阶段级 phase）格式。转换包含：备份旧文件、全局 phase 下沉到对应 stage、pipeline.phase 改为 MetaPhase。

- 参见 kb/patterns.md #CLI 原子管理模式 — migrate 命令遵循 save() 的安全写入模式（tmp + 校验 + rename）

## 迁移逻辑

**输入（旧格式）**：
```json
{ "pipeline": { "phase": "exec_running", "current": { "stage": "stage-03", "op": "op-001" }, "retry": 0 } }
```

**输出（新格式）**：
```json
{
  "pipeline": { "phase": "active", "current": { "stage": "stage-03", "op": "op-001" }, "retry": 0 },
  "stages": {
    "stage-03": { "phase": "exec_running", ... },
    "stage-02": { "phase": "done", ... }
  }
}
```

**推导规则**：
1. 旧 `pipeline.phase` 的值下沉到 `pipeline.current.stage` 对应的 stage → `stages[stageId].phase = oldPipelinePhase`
2. 若 `pipeline.current.stage` 为 `"-"` 或空，则旧 phase 下沉到第一个 stage
3. `stages` 中已有 phase 字段的 stage 保持不变（不覆盖）
4. `stages` 中无 phase 字段的 stage 默认设为 `"done"`（表示已完成），但 `current.stage` 对应的 stage 除外
5. 全局 `pipeline.phase` 改为 `"active"`（若旧 phase 为 `done` 则改为 `"done"`）

## 实施步骤

- [ ] 1. `read` 本方案文件完整内容（必做）
- [ ] 2. 在 `FlowManager` 中新增 `migrate()` 方法（约 80 行）：
  - **检测**：检查 `pipeline.phase` 是否为旧格式（值在 `PIPELINE_PHASES` 中且不在 `META_PHASES` 中）
  - 若已是新格式（`pipeline.phase` 在 `META_PHASES` 中），输出"已是新版格式，无需迁移"并返回
  - **备份**：将旧 `flow.json` 复制为 `flow.json.v4.0.bak`
  - **迁移阶段**：
    ```typescript
    const oldPhase = this.data.pipeline.phase; // 旧 PipelinePhase
    const currentStageId = this.data.pipeline.current.stage;
    
    for (const [stageId, stage] of Object.entries(this.data.stages)) {
      if (stage.phase !== undefined) continue; // 已有 phase，跳过
      if (stageId === currentStageId && currentStageId !== '-') {
        (stage as StageData).phase = oldPhase as PipelinePhase; // 下沉
      } else {
        (stage as StageData).phase = 'done'; // 已完成阶段
      }
    }
    ```
  - **更新全局 phase**：`this.data.pipeline.phase = (oldPhase === 'done') ? 'done' : 'active'`
  - 追加迁移日志：`appendLog({ action: 'migrate_v4.0_to_v4.1', ... })`
  - 调用 `save()` 持久化
- [ ] 3. 在 `src/commands/flow.ts` 中注册 `flow migrate` 子命令（约 25 行）：
  - 位置：放在 `flow repair` 命令之后
  - 描述：`将旧版 flow.json（v4.0 全局 phase）迁移到新版格式（v4.1 阶段级 phase）`
  - 参数：`--dry-run` 仅检测不执行（默认 false）；`--no-backup` 跳过备份（默认生成 .bak）
  - 执行流程：
    1. 创建 FlowManager 实例
    2. 检测是否已为新格式 → 是则输出提示并返回
    3. `--dry-run` 时输出迁移预览（哪些 stage 会被赋什么 phase）
    4. `--no-backup` 标记跳过备份
    5. 调用 `mgr.migrate()`
    6. `mgr.save()` 持久化
    7. 输出迁移成功摘要
- [ ] 4. 在 `FlowManager` 中新增辅助方法 `needsMigration(): boolean`（约 8 行）：
