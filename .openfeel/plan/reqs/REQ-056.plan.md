## 验收判据

判据沿用 `plan.md` §1.1，本需求对应 **A4 / A4b / A5 / A6**。必跑命令（仓库根）：

```bash
node bin/openfeel.js flow advance --stage v1.6.0-stage-NNN --to exec_running          # A4：缺计划 → STAGE_PLAN_GATE，revision 不变
node bin/openfeel.js flow advance --stage v1.6.0-stage-NNN --to exec_running --force   # A6：放行 + detail.gate_overrides=['plan']

npx vitest run test/core/flow-manager.test.ts test/commands/flow.test.ts
```

## 风险

- **门禁自锁**（`plan.md` R2）：T5 上线后本阶段若仍无写实 `plan.md` 就无法推进。规避——本文件与阶段 `plan.md` 在 T5 合并前落盘；确需推进时 `--force`（留痕，不静默）。
- **命令层镜像与核心层不同判据**：`--force` 在 `flow.ts:1134` 会跳过相位路径校验，只有 `advanceStagePhase` 是唯一写入口。规避——拦截只放核心层，命令层镜像只负责 `error.code`/`detail` 形状。
- **复位绕过**：`flow stage reset` 若不与 exec 门同口径，等于开一条免计划后门。规避——`resetStagePhase` 复检同一谓词，无 `--force` 拒绝且零写盘、不入 `reset_stage_phase` 日志。
