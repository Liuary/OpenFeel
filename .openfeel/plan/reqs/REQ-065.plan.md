## 目标

- **目标**：把「写实需求 + 计划」固化为测试工厂，避免每加一道门就打穿多套夹具；把空壳/缺计划/未盖章/dev 过期四类流程债汇总到 dashboard，从 advisory 变成可跟踪。
- **现状证据**：`test/fixtures/` 只有 `legacy-project/` 一个静态夹具目录与 `flow-writer.mjs`，**没有任何工厂/helper**；`dsh/test/` 也没有 `fixtures/` 子目录。v1.6.0 加正文门后 `dsh/test/verify.js` 首次运行 exit 1（夹具直接 `draft→in_progress`，REQ-065 摘要）；`lint fill` 恒 advisory（`src/commands/lint.ts:203` 注释「fill 是 advisory 清单」），dashboard（`src/commands/dashboard.ts:125` `runDashboard`）目前只聚合 `requirements/stages/blockingReviews`。
- **共享工厂设计（REV-P07）**：`dsh/package.json` 是 `"type": "module"`、零依赖，`dsh/test/verify.js` 用 `import`；根 `package.json` 同为 `"type": "module"`。因此共享层放在 `test/fixtures/req-input.js`（**纯 ESM、无 TS、无依赖**），两条栈同时 `import`：
  - `test/fixtures/factories.ts` → `import { makeFilledBodyInput, makeRequirementPlanInput } from './req-input.js'`
  - `dsh/test/verify.js` → `import { makeFilledBodyInput } from '../../test/fixtures/req-input.js'`（只读测试期依赖；`dsh` 发布物 `files` 不含 `test/`，不影响发布）
- **边界**：`lint fill` 退出码语义不变（恒 0）；dashboard 的聚合入口不改（唯一 `FlowManager`），只在 `collectDashboardData` 里加一段；不引入任何依赖。

## 风险

- **工厂与门禁口径分叉**：工厂若自己拼一段 40 字正文而不走 `filled.ts` 的判据，加门时又会打穿。规避——工厂只拼**已知能过门**的最小结构，`factories.test.ts` 直调 `isRequirementBodyFilled`/`isRequirementPlanFilled` 断言，判据仍单点。
- **「共享」退化回注释**（2026-11-24 新增，REV-P07）：只写「口径一致」注释、两栈各拼一份常量 → A65.1 实际未达成。规避——字段常量只在 `req-input.js` 里定义；reviewer `grep -rn "ReqBodyGate" test/fixtures dsh/test/verify.js` 与 `grep -n "req-input.js"` 双向取证；`factories.test.ts` 断言两栈产出逐字相等。
- **dashboard 第二份判定**：若在 `aggregate.ts` 里另写空壳规则，A65.3 同源断言必红。规避——`aggregate.ts` 只调 `lintRequirementBodies`。
- **advisory 被改成硬门**：把 `flowDebt` 接进退出码会让存量空壳直接红。规避——`lint fill` 与 dashboard 均不改退出码；`C16` 用例逐字保留。
- **`test/**` 写入门禁**：C8 若在 `review_passed` 相位直接写 `test/fixtures/**` 而被 guard 拒，会误判为「REQ-062 未生效」。规避——先验证 B3（`cd dsh && node test/guard.js` 的 `A62.1` 绿）再派 C8；否则在 `exec_running` 相位完成 C8。
