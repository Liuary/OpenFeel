# op-002：init 改造 — deployOpencode 全局部署 + 项目精简

- **阶段**：v1.1.0-stage-37
- **前置**：op-001（hard，路径与配置基础）
- **负责 Agent**：openfeel-executor
- **最多重试**：3

## 目标

`deployOpencode` 部署目标从项目 `.opencode/` 切换到全局 `~/.config/opencode/`；项目仅生成 `.openfeel/` + `AGENTS.md` + 项目 `opencode.jsonc`（最小覆盖）。全局 opencode.jsonc 首次写入采用「不存在则写、已存在则跳过」（REV-605，不做合并，合并统一归 op-003）。全局文件写入复用 stage-35 原子写 + 全局文件锁。

> 参见 kb/architecture.md #opencode 全局/项目 agent 与 skill 合并语义；kb/patterns.md #原子写模式 / #建议性文件锁模式（全局文件不裸写）；kb/patterns.md #init/update 重启提醒对称输出模式。

## 关键设计决策

1. **N1 边界**：只改 `deployOpencode` 部署目标，**不删除仓库自身 `.opencode/`**、不改 build.js 步骤 8（仓库自举实例保留，迁移属 stage-39）。
2. **REV-605 纪律**：全局 opencode.jsonc **首次写入 = 不存在则写框架级内容、已存在则跳过**（`writeGlobalFileIfMissing`），**不做合并**；深度合并逻辑只存在 op-003 的 `mergeGlobalOpencodeJsonc`。
3. **ADAPTER.md / `.gitignore` 停止部署**：`.opencode/` 不再写入项目，这两个「项目 `.opencode/` 布局说明/忽略规则」随之废弃（不迁移到全局）。
4. **全局文件写入用 `atomicWriteFileSync` + `withFileLock(globalLockPath('opencode-deploy'))`**，项目 opencode.jsonc 仍项目内原子写（`atomicWriteFileSync` 即可，无全局锁）。原 `writeTemplateIfMissing` 用 `writeFileSync`，全局化后须替换。
5. **项目 opencode.jsonc = 最小覆盖 `{ "$schema": "https://opencode.ai/config.json" }`**（N7），不写 `instructions`/`skills`/`default_agent`（P2 稳健设计 + N6 自动发现）。

### 步骤 2：新增全局文件写入助手（`writeTemplateIfMissing` 之后，约 L181）

```ts
/**
 * 全局文件写入：全局文件锁 + 原子写 + 已存在不覆盖
 * 与 writeTemplateIfMissing 同语义，但针对跨项目共享的全局路径（~/.config/opencode/）。
 */
function writeGlobalFileIfMissing(filePath: string, content: string): { created: boolean } {
  return withFileLock(globalLockPath('opencode-deploy'), () => {
    if (existsSync(filePath)) {
      return { created: false };
    }
    atomicWriteFileSync(filePath, content);
    return { created: true };
  });
}
```

### 步骤 3：重写 `deployOpencode`（L194-249 全函数替换）

```ts
/**
 * 部署 OpenCode 平台适配器到全局 ~/.config/opencode/（D1 全局化）
 * 全局文件遵循"已存在不覆盖"；项目仅写最小 opencode.jsonc 覆盖。
 * ⚠️ 不部署 package.json（REV-001）；不部署 ADAPTER/.gitignore（已随 .opencode/ 废弃）。
 */
export function deployOpencode(projectPath: string, lang: 'zh-CN' | 'en'): OpencodeDeployResult {
  let created = 0;
  let skipped = 0;
  const track = (result: { created: boolean }) => { if (result.created) created++; else skipped++; };

  // 1. Agent 定义（9 个）→ 全局 agents 目录
  const agentIds = listOpencodeAgentIds(lang);
  for (const agentId of agentIds) {
    track(writeGlobalFileIfMissing(
      join(getGlobalAgentsDir(), `${agentId}.md`),
      loadOpencodeAgentTemplate(lang, agentId),
    ));
  }

  // 2. Skill 定义（14 个）→ 全局 skills 目录
  const skillNames = listOpencodeSkillNames();
  for (const skillName of skillNames) {
    track(writeGlobalFileIfMissing(
      join(getGlobalSkillsDir(), skillName, 'SKILL.md'),
      loadOpencodeSkillTemplate(skillName),
    ));
  }

  // 3. 框架约束 core.md → 全局 ~/.config/opencode/openfeel/core.md
  track(writeGlobalFileIfMissing(
    getGlobalCoreMdPath(),
    loadOpencodeConfigTemplate(lang, 'instructions'),
  ));

  // 4. 全局 opencode.jsonc：不存在则写框架级内容（REV-605：已存在则跳过，合并归 op-003）
  //    （REV-710 修订）复用 op-001 mergeGlobalOpencodeJsonc('{}\n') 生成框架级内容，
  //    消除 JSON.stringify 序列化重复（parseJsonc('{}\n')={} → deepMergeJsonc({},框架)=框架 obj）。
  track(writeGlobalFileIfMissing(
    getGlobalOpencodeJsoncPath(),
    mergeGlobalOpencodeJsonc('{}\n'),
  ));

  // 5. 项目 opencode.jsonc：最小覆盖（仅 $schema），写入项目根（项目内原子写）
  const projectJsoncPath = resolve(projectPath, 'opencode.jsonc');
  let projectJsonc: { created: boolean };
  if (existsSync(projectJsoncPath)) {
    projectJsonc = { created: false };
  } else {
    atomicWriteFileSync(projectJsoncPath, JSON.stringify(buildProjectOpencodeJsoncObj(), null, 2) + '\n');
    projectJsonc = { created: true };
  }
  track(projectJsonc);

  return { created, skipped };
}
```

> 序列化统一走 op-001 `mergeGlobalOpencodeJsonc`（REV-710 修订）：全局 opencode.jsonc 用 `mergeGlobalOpencodeJsonc('{}\n')`，项目 jsonc 用 `JSON.stringify(buildProjectOpencodeJsoncObj(), null, 2) + '\n'`，二者最终序列化格式一致（`JSON.stringify(obj, null, 2) + '\n'`，注释不保留，D3 JSONC 解析→序列化）。

## 风险与注意

- **N1 自举边界**：本 op 不触碰仓库 `.opencode/`、不改 build.js 步骤 8；执行者不得顺手删除仓库自举实例。
- **真实全局污染**：开发期手工验证须用隔离 `USERPROFILE`/`HOME`（或临时 HOME）；单测 mock homedir（op-005）。
- **全局锁粒度（REV-706 修订）**：`writeGlobalFileIfMissing` 每次调用独立获取 `opencode-deploy` 锁（细粒度），26 个全局文件共 26 次锁获取/释放；因内容幂等（已存在不覆盖），并发竞争良性，可接受。
- **REV-605 严格**：op-002 不得实现任何「合并」逻辑，已存在即跳过，避免与 op-003 合并语义重复/冲突。
