## 方案期裁定（计划 §四 Q1/Q3/Q6 定稿）

- **Q1（`stage status` 字段命名）**：双给。`fields` 给 7 个规范化键（camelCase），`fields.raw` 给全部原始中文键值对（读侧宽容，不注入 flow.json）。规范化映射：`执行模式→execMode`、`自动推进→autoAdvance`、`状态→status`、`当前责任 Agent→reviewAgent`、`上一责任 Agent→previousReviewAgent`、`更新时间→updatedAt`、`工作模式→workflowMode`；缺失键值 `null`。
- **Q3（`project overview` 键名冻结）**：见下方 `ProjectOverviewData`。`dirs.*` 子项在目录不存在时为 `null`；`stats.*` 恒为 number（目录不存在 → 0，与人类输出一致）；`entries.cli/pkg/build` 恒为字符串 + `available` 布尔；`techStack.*` 为与人类逐字相同的展示字符串（不加第二套版本推导）。
- **Q6（no-init 语义）**：严格镜像各命令的人类退出码，不统一强加 `NO_INIT`：
  - `stage status` 无参：空列表 `{stages:[],count:0}` + exit 0（人类 noStages exit 0）；有参未找到 → `STAGE_NOT_FOUND` refusal 1。
  - `flow recover`：未初始化 → exit 0 + `initialized:false` + 空值。
  - `flow checkpoint list` / `flow log`：未初始化与空集合同形（`checkpoints:[]` / `entries:[]`）+ exit 0（人类 exit 0）。
  - `project overview`：不依赖 `.openfeel`，恒 exit 0；不引入 `initialized` 字段（T1 冻结字段集，无人类对等物）。
- **JSON 内部异常口径（对不变量 6 的细化）**：业务拒绝镜像人类 exit 1；JSON 模式下的内部异常走 stage-95 `INTERNAL_ERROR/internal/3`（`3` 为本版新增），人类模式保持既有 exit 1 文案逐字不变。该边界由 op-004 在契约 §13 登记。
