# REQ-074 计划：克制机制（版本纪律 + 范围收敛 + 反过度设计 + 反自由发挥）

> 依据：`.openfeel/plan/v1/stage-138/plan.md` §一（**A74.1—A74.7**）与 §二 **R3**（文档/版本归 R4）；本文件只做需求级拆解，**不改判据含义、不新增需求外任务**。边界：不实现 dashboard/metrics 采集、不做批次锁 `BATCH_LOCKED`、不做 `<24h` 硬门（A74.5 明确登记后续）；不扩 guard 白名单（`--bump/--reason/--confirm/--confirm-twice` 一律走 `npm run release -- ...`）；`--publish`/`--push` 保持既有语义（不加 `--confirm`）。

## 目标

- **做什么**：把「批次发布」从文档规则变成可执行机制——① 提示词加「版本纪律」检查点（含第 4 条「同批不连发 patch」）；② `scripts/release.mjs` 加 `--bump/--confirm/--confirm-twice/--reason`（`--confirm` 只约束 bump；publish/push 语义不变）、发布前打印**按版本过滤**的本批次清单、距上次发布 <24h 再发 patch 给 warn 且真实 bump 额外要 `--confirm-twice`；③ `dev_core`/`DEV_CORE` 加「版本与范围纪律」；④ reviewer 加「过度设计」5 判据与「计划外改动」（落 blocking REV），阶段/需求计划模板加 `## 不做清单` / `## 允许改动`；⑤ `docs/VERSIONS.md` 只写节奏与指标定义（采集/门禁登记后续）。
- **为什么**：1.6.0—1.6.4 = 5 版 / 17 REQ / 约 50.1h，其中 1.6.2 与 1.6.3 归档相隔 32 秒且同属「不预设模型」，本应 1 版（5 版 → 3 版）。根因三条：批次规则只在 `docs/VERSIONS.md:8-14`、未进提示词；版本在开发期写死；发布前无门禁。
- **预算事实（A74.1 的关键约束，2026-11-27 逐字量过）**：`renderFeelPrompt` 四组现状 zh/en × enabled/disabled = 776/893/1078/**1194** 字符（16/19/15/18 行，上限 1200/25），en-disabled 只剩 6 字符。目标值：zh 版本句 54→80 字符（「版本纪律」一行），正文 654→680（+26），渲染 **802/919**（16/19 行）；EN 四处同改——版本句 49→114（**+65**，含第 4 条 `no back-to-back patches` 与 `patch/minor/major` 三档）、checkpoint 1 209→173（**−36**）、checkpoint 2 135→109（**−26**）、checkpoint 3 166→155（**−11**），正文 855→847（**−8**），渲染 **1070 / 1186/1200**（15/18 行，余量 14）。此前「约 +73」是粗估，统一以上述实测为准；四份 `feel.md` 同步、`template-loader.ts` 只由 `npm run build` 生成。

## 验收判据

- **A74.1**：四组渲染态 ≤1200 字符 / ≤25 行（实测目标 zh 802/919、en 1070/1186，16/19/15/18 行），标题仍含「三个检查点 / Three checkpoints」，EN 含 `no back-to-back patches`；parity 5/5 sha256 一致；budget 测试绿，保留 `补丁/patch`、`minor`、`major`，并新增 `批次`/`backlog`、`back-to-back`（或 `连发`）断言。
- **A74.2**：`npm run release -- --dry-run --bump patch` 打印 `old → new` + 按版本过滤的本批次清单 + 24h warn 且零写盘、零 git；`--bump patch` 无 `--confirm` → exit 1 三文件哈希不变；重跑已 bump 的 `--bump patch` → 打印 `no-op: already 1.6.5`、exit 0、三文件哈希不变；`--bump minor` 无 `--reason` → exit 1；`--bump` 与 `--publish/--push/--notes-only` 互斥；`--publish`/`--push` **不需要 `--confirm`、也不会因缺省而失败**（`docs/VERSIONS:11` 兜底命令照旧）；<24h 再发 patch 有明确 warn 且真实 bump 需 `--confirm-twice`；批次清单在「17 条旧 done + 3 条本轮 done」夹具下只输出 REQ-072/073/074；既有 `STEPS`/`--json` 键序与 **20 个旧用例**不变。
- **A74.3**：`dev_core.md` 与 `DEV_CORE_TEMPLATE_ZH/EN` 均含「版本与范围纪律」五条；`test/core/templates.test.ts` 绿。
- **A74.4**：4 份 reviewer 模板（claude/opencode × zh-CN/en）含 5 判据 + 计划外改动，且计划外改动**落 blocking REV**（`review_add` + `auto_fix`）；4 份 planner 模板与 `plan-file.ts` 含 `## 不做清单`/`## 允许改动` 两节；`isRequirementPlanFilled` 仍只查三节（两节是占位不是写实判据）；C9 grep 覆盖 zh+en × planner+reviewer 各文件。
- **A74.5**：`docs/VERSIONS.md` 有 `releasesLast7d` / `medianIntervalHours` / `reqsPerVersion` / `patchPerMinor` / `outOfBatchRatio` 定义与公式，并写明本版不实现采集；R3 同批写 §发布节奏（同批不连发 patch）。
- **A74.6/A74.7**：release 文档段同步（`--bump/--confirm/--confirm-twice/--reason`）、1.6.5 一次性发布（REQ-072+073+074 同批、**版本字段 4 处 + 5 处文档引用**同批、发布后不再逐项升版）——取证归 R4 的 C10/C7。

## 风险

- **预算破 1200 / 同源分叉**：只能等义改写、不许抬上限或删检查点（尤其第 4 条 `back-to-back`）；改 `prompt.js` 必须同批改 4 份 `feel.md` 并 `npm run build`，手改 `template-loader.ts` 即分叉；目标余量 14 字符，改后逐组打印。
- **release.mjs 回归**：`--bump` 必须独立模式（否则 bump 后版本一致性三处比对立即失败）；`--confirm` **只加给 bump**，publish/push 与 `docs/VERSIONS:11` 兜底命令不动；目标从上次发布基线算，重跑 = no-op；写盘无事务，失败以 `git status` 兜底；`STEPS`/`--json` 既有键序 + **20 个旧用例**冻结。
- **批次清单混入旧 done/基线不可靠**：必须按 `target_version===当前发布版本` 或关联本版本阶段过滤（现有 17 条旧 done 全是 v1.2.2—v1.5.6）；按 semver 选归档基线（仓库有 `v1.7.0.json`），flow.json 不可读时降级 `null` 不阻断；<24h 判定只依赖 `.openfeel/release/last.json` 或 `archived_at`，拿不到就不 warn。
- **过度设计自证**：REQ-074 自身不新增 CLI/工具/JSON 出口、不做 dashboard/BATCH_LOCKED/硬门；reviewer 用本需求自己的 5 判据审本需求 diff。
