## 实施步骤

- [ ] 1. `guard.js` 导入 `existsSync`；新增 `isDocTarget(absolute)`：祖先目录含 `docs`（路径分段，大小写不敏感已在 Windows 归一）或扩展名 ∈ `{.md,.mdx,.txt,.rst,.adoc}`。
- [ ] 2. `parsePatchTargets` 保持现有导出与返回形状不变；新增 `parsePatchEntries(patch)` 返回 `[{path, kind:'add'|'update'|'delete'|'move'}]`（`*** Add File:` → add；`*** Update File:` / `--- a/` → update；`*** Delete File:` → delete；`*** Move to:` → move）。`guard.js` 内改用它；混合/无头仍保守拒绝。
- [ ] 3. bootstrap 例外：`!initialized && enforce==='always'` 时，若「全部目标不存在」且（apply_patch 则「全部 kind==='add'」）→ 放行；否则维持拒绝。放行时经 `process.stderr.write` 输出一次（按 cwd + reason 去重）补账本提示。
- [ ] 4. doc/note 放行：在「无活跃阶段」与「活跃阶段非 exec_running」两个拒绝点之前，若 `targets.every(isDocTarget)` → 放行；任一非 doc → 维持原拒绝（混合从严）。
- [ ] 5. `autoCommitOnDone`：先 `git rev-parse --is-inside-work-tree`；非 git 仓库 → `console.warn` 新 i18n 键（明确「无版本兜底」）+ 保留原跳过行；git 仓库但无变更 → 只打原跳过行。
- [ ] 6. i18n：新增 `flow.advance.gitCommitNoRepoWarnTmpl`（zh/en 成对），键序按文件既有分组追加。
- [ ] 7. `dsh/test/guard.js` 新增：bootstrap 新文件放行 / bootstrap 已存在文件拒绝 / 空仓 apply_patch Update 拒绝 / 空仓 apply_patch Add 放行 / done 阶段写 `docs/x.md` 放行 / done 阶段写根 `README.md` 放行 / plan 相位写 `docs/x.md` 放行 / plan 相位写 `src/x.ts` 拒绝 / doc+src 混合拒绝。
