## REV-002: plan 目录计数 glob 模式错误，始终输出 0
- **状态**：closed
- **优先级**：high
- **提出人**：Reviewer
- **提出时间**：2026-07-08 23:56

### 问题描述
`src/commands/project.ts` 第 108 行：
```typescript
const planDirEntries = fg.sync(['plan/*/'], { cwd: openfeelDir }).length;
```

fast-glob 默认不返回目录条目，`plan/*/` 尾部斜杠模式在无 `onlyDirectories: true` 选项时匹配结果为空数组。实际 `.openfeel/plan/` 下有 8 个子目录（v1, v2, v3, v3.1, v3.2, v4, v4.1, v4.2），但输出「0 个版本」。

而第 67 行的统计信息 `fg.sync(['.openfeel/plan/*/plan.md'])` 匹配的是文件所以正常返回 6。

### 修复建议
修改第 108 行为：
```typescript
const planDirEntries = fg.sync(['plan/*'], { cwd: openfeelDir, onlyDirectories: true }).length;
```

## REV-004: 非项目目录下入口路径和技术栈仍输出硬编码值
- **状态**：pending
- **优先级**：low
- **提出人**：Reviewer
- **提出时间**：2026-07-08 23:56

### 问题描述
当在非项目目录执行 `openfeel project overview` 时，src/ 等目录不存在，统计信息正确显示 0，但「入口路径」仍输出 `src/cli/index.ts` 等硬编码值，「技术栈」仍输出 `Commander 14+` 等默认值。这可能误导用户认为项目结构存在。

op-002 方案自测清单第 10 项仅要求"不会崩溃"，但更好的体验是在关键目录不存在时标注或省略。

### 修复建议
在入口路径和技术栈输出前，增加目录存在性判断。若 `src/` 不存在，入口路径节标注"（未检测到项目结构）"；技术栈节可保留默认值（因这些是通用技术栈信息，不依赖项目文件）。
