## 目标与范围

为 `openfeel setup` 新增**只读**主动诊断分支 `--check [--json]`：复用 stage-66 `checkGlobalDeployment()`，一致 → `exit 0`；不一致/缺失/不可判定 → `exit 1`；`--json` 输出稳定单文档（**纯 JSON**、含 `schemaVersion`）。**不新增顶层命令**（D-E）；**无 `--check` 时行为逐字不变**；`--check` 分支**不执行任何部署、零写盘**。

**精确文件/函数/行为**：

| 层 | 文件 | 变更 | 行为 |
|----|------|------|------|
| 命令 | `src/commands/setup.ts` | 注册 `--check`/`--json`；action 前置短路 | `--check` 分支：检测 → 文本/JSON 输出 → 设置退出码 → `return`（不部署） |
| i18n | `src/core/i18n-data/{zh-CN,en}.ts` | +6 键（`setup.check*` 4 + `help.setup.*` 2） | 文本文案 + 帮助文案 |
| test | `test/commands/setup.test.ts` | +T5.11~T5.15 | 三态退出码、`--json`、只读、无参回归 |

**不变量**：`setup` 无参/`--lang` 行为、输出、退出码**逐字不变**；既有命令 `--json` 契约不变。

  2. 在 `.option('--lang <lang>', ...)` 之后追加两个选项（描述走 help 键供 `applyHelpI18n` 替换）：
     ```ts

     .option('--json', t('help.setup.json', getCliLang(process.cwd())))
     ```
  3. action 签名改为：
     ```ts
     .action((options: { lang?: string; check?: boolean; json?: boolean }) => {
       const lang = getCliLang(process.cwd());
       // stage-67：--check 前置只读短路——不执行任何部署、零写盘（D-E / R-3）
       if (options?.check === true) {
         const result = checkGlobalDeployment();
         if (options.json === true) {
           // 纯 JSON 单文档；对齐既有 --json 约定（数值 schemaVersion）
           console.log(JSON.stringify({
             schemaVersion: 1,
             status: result.status,
             cliVersion: result.cliVersion,
             deployedVersion: result.deployedVersion,
           }, null, 2));
         } else if (result.status === 'ok') {
           console.log(t('setup.checkOkTmpl', lang, { deployed: result.deployedVersion ?? '?', cli: result.cliVersion }));
         } else if (result.status === 'mismatch') {
           console.log(t('setup.checkMismatchTmpl', lang, { deployed: result.deployedVersion ?? '?', cli: result.cliVersion }));
         } else if (result.status === 'missing') {
           console.log(t('setup.checkMissingTmpl', lang));
         } else {
           // unknown：显式命令下可报告（区别于被动静默）
           console.log(t('setup.checkUnknownTmpl', lang));
         }
         // 一致 → 0；不一致/缺失/不可判定 → 1（门禁可拦截）
         process.exitCode = result.status === 'ok' ? 0 : 1;
         return;
       }
       const deployLang = (options?.lang === 'en' || options?.lang === 'zh-CN') ? options.lang : 'zh-CN';
       const r = setupGlobalFramework(deployLang);
       // ...（以下原样保留，逐字不变）
     ```
  > **注意**：`--check` 分支必须在 `setupGlobalFramework(...)` **之前** `return`；无 `--check` 时 `lang`/`deployLang`/输出/`setup.complete`/重启提示**全部保持现状**。

## 困难点与决策
| # | 困难点 | 备选方案 | 采用 | 理由 |
|:-:|--------|----------|------|------|
| 1 | `--json` 的 `schemaVersion` 取值：阶段计划 T2 写 `'1.0'`（字符串），而全仓既有约定为数值 `1` | (a) 照计划用 `'1.0'`；(b) 对齐既有约定用数值 `1` | **(b) 数值 `1`** | KB `#CLI --json 结构化输出约定` 明确既有为数值 `1`（`flow status/current/phases` 等）；一致性为审查维度。**计划 T2 的 `'1.0'` 视为笔误**，已在验收 T5.13 固化 `schemaVersion: 1`。若 Feel/用户坚持 `'1.0'`，仅需改 action 与 T5.13 两处 |
| 2 | `unknown` 文本文案键缺失（阶段计划 §四只列 3 个 `setup.check*`，但 T2 要求 `unknown` 显式报告） | (a) 复用 `checkMissingTmpl`（语义不符）；(b) 新增 `setup.checkUnknownTmpl` | **(b)** | 语义准确；致 i18n 新基线由计划预估 **760 修正为 761**（+8）。已在 op-003 显式登记 761 |
| 3 | `--check` 与 `--lang` 组合 | (a) `--lang` 影响检测基准；(b) `--lang` 仅部署用，`--check` 忽略 | **(b)** | 检测是只读诊断，语言取 `getCliLang`（与被动提示一致）；不引入第二语言来源 |
| 4 | 退出码实现方式 | (a) `process.exit(1)`；(b) `process.exitCode = 1` | **(b)** | KB `#CLI 退出码语义`：防 stdout 截断；命令返回后进程自然以该码结束 |
