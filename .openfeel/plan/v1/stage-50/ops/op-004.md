## 一、变更目标

收口批次 D 的 5 条「i18n 泄漏 + 命令体验」欠账（T38~T42）：`--help` 的 `arguments` 描述在 en 下仍为中文、并发冲突文案 4+1 处硬编码重复、`flow wizard` 非 TTY 静默且失败 exit 0、REPL 被命令内 `process.exit` 杀死且 help 列表失真、`init`/`roadmap` 无 try-catch 且 `model set --build` 无超时、`stage create` 与 `flow stage add` 的 catch 块逐行复制。

## 二、T 编号化子项清单

> **执行纪律**：动手前 `rg`/`read` 复核坐标；行号漂移按语义定位。

### T38（medium）`applyHelpI18n` 不遍历 `arguments` + 并发冲突文案硬编码重复
- **文件:行号**：`src/cli/index.ts:78-109`（`walkCmd` 缺 `arguments` 遍历）、`:140-142`（并发冲突文案）；硬编码重复点 `commands/flow.ts:400-401/483-484/1317-1318`、`commands/stage.ts:432-433`
- **现状**：`walkCmd` 只处理 command 描述与 option 描述，**不遍历 `cmd.arguments`** → en 模式下 `stage create --help` 的参数（Arguments）行为中文；「并发冲突」提示在 4+1 处各自硬编码，文案漂移风险。
- **改后**：
  1. `walkCmd` 增 `cmd.arguments` 遍历：键约定 **`help.<commandPath>.arg<name>`**（`<name>` 取 `arg.name()`，命令路径与既有 option 键规则一致）；命中则 `arg.description(t(key, lang))`。
  2. 并发冲突文案**收敛到单点**：在 `handleCliError`（或 CLI 层既有错误统一出口）暴露统一处理，`commands/flow.ts:400-401/483-484/1317-1318`、`commands/stage.ts:432-433` 改为调用该单点；文案走 i18n 键 `common.concurrentConflict`（见 §四）。
- **注意 `parse` 时机**：`arguments` 描述设置必须在 `--help` 渲染前完成（现有 `applyHelpI18n` 调用点已满足，勿改调用时机）。
- **行为变更**：**是（en 输出改善）**；zh 输出保持等价（文案来源改为 i18n 键，文本一致）。

### T39（medium）`flow wizard` 非 TTY 不静默、渲染 ANSI、失败 exit 0
- **文件:行号**：`src/commands/flow.ts:1314-1325`（无 `isTTY` 守卫、catch 无 exit）；对照正确范式 `commands/stage.ts:414-417`、`commands/model.ts:71-75`
- **现状**：CI/脚本中运行 `flow wizard` 时渲染 ANSI 交互且失败仍 `exit 0` → 误判成功。
- **改后**：
  1. **非 TTY 守卫**：`if (!process.stdin.isTTY || !process.stdout.isTTY)` → 输出等价指引 `t('flow.wizard.nonTtyHint', lang)`（提示改用 `flow advance` 等非交互命令）并 `process.exitCode = 1`，**直接 return**。
  2. **catch 分类退出码**：捕获异常 → `console.error(t('common.errorTmpl', lang, {...}))` + `process.exitCode = 1`（沿用 stage/model 既有范式）。
- **行为变更**：**是**（非 TTY 由「渲染交互 + exit 0」变「提示 + exit 1」）；TTY 交互路径不变。

### T40（medium）REPL 被命令内 `process.exit` 终止 + 输出硬编码 + help 失真
- **文件:行号**：`src/cli/repl.ts:19`（exit 处理）、`:27/:41/:49`、`:58-80`（help 列表）
- **现状**：命令错误路径调用 `process.exit` → REPL 整体退出；输出硬编码中文；help 列表含**不存在**的命令、缺 7 个命令组。
- **改后**：
  1. 命令执行改为**不影响主进程退出**：捕获 `process.exit` 类终止（对可捕获路径改抛异常）或在 REPL 内以**独立 program 实例**执行（`new Command()` + 仅本地注册），避免命令内 `process.exit` 杀 REPL 主循环。
  2. 输出文案迁 i18n（`repl.*` 键，见 §四），不再硬编码中文。
  3. help 列表**动态生成**：由 program 的注册命令树生成（过滤不存在的条目，补齐 7 个命令组）。
- **行为变更**：**是**（错误命令不再终止 REPL；help 内容变化）。
- **测试**：`test/cli/repl.test.ts`（**新增 smoke**，见 §五 / R5）。

### T41（low）`init`/`roadmap` 无 try-catch + `model set --build` `execSync` 无 timeout
- **文件:行号**：`commands/init.ts:35-37`、`commands/roadmap.ts:21,31`、`commands/model.ts:96`
- **现状**：异常直接冒泡，堆栈外泄，与其余命令错误体验不一致；`execSync` 构建可无限挂起。
- **改后**：
  1. `init`/`roadmap` 的 action 补 `try/catch`：`catch (e) { console.error(t('common.errorTmpl', lang, { message: ... })); process.exitCode = 1; }`（复用既有 `common.errorTmpl`，**不新增键**）。
  2. `model.ts:96` 的 `execSync` 增 `{ timeout: 600000, stdio: 'inherit' }`（10 分钟），并捕获 `ETIMEDOUT` → 明确错误文案 + `exitCode = 1`。
- **耦合说明**：`roadmap.ts` 依赖 op-001 T10 已把 core 层 `process.exit` 改为 `throw`；本 op 的 try-catch 即该抛错的收口点（**顺序依赖 op-001**）。

### T42（low）`stage create` 与 `flow stage add` catch 块逐行复制
- **文件:行号**：`commands/stage.ts:429-444` vs `commands/flow.ts:397-412`（5+ 处拷贝）
- **现状**：同一「addStage 错误处理」逻辑复制多份，单点修改易漏。
- **改后**：随 T38 抽取私有 helper `handleAddStageError(err, lang, stageName)`（置于两命令共享位置，如 `src/commands/shared/` 或 CLI 错误出口），两处调用同一 helper。**行为不变**（文案与退出码等价）。
