## 关键设计决策

1. **隔离机制**：环境变量把 opencode 的 `home`（`~` 展开基准）与 `config`（配置读取目录）指向临时目录：
   - **Windows（本环境）**：`$env:USERPROFILE` + `$env:HOME` 双双指向隔离目录；
   - **Linux/macOS**：`XDG_CONFIG_HOME`（改 config）+ `HOME`；
   - 判据：`opencode debug paths` 的 `home`/`config` 均指向隔离目录；**不等则标记 `config dir mismatch` 并停止**（不得污染真实 `~/.config/opencode`）。
2. **观测手段**：
   - `opencode debug config`（在 `cwd=$PROJ` 下运行 → 含项目 `opencode.jsonc` 解析结果）；
   - `opencode debug agent <name>`（看该 agent 解析后的 `permission` ruleset）；
   - `opencode run --agent <probe>`（仅在需判定「是否实际询问/生效」时使用；无 auth 则降级）。
3. **数据驱动落值**：op-002 的 `external_directory` 值形式（单值 `"allow"` vs 对象 `{ "*": "allow" }`）与 `utility` 的 `write`→`edit` **以本 op 结论为准**（见「回填规则」）。
4. **不阻塞**：若 CLI 不可用/无法判定，按「降级规则」给出保守默认并标记 `DEGRADED`/`INCONCLUSIVE`，仍产出 findings。

## 实施步骤（脚本化，可执行）

### 步骤 0：预检

```pwsh
opencode --version                 # 期望 1.18.33（REV 实测环境）
opencode debug --help              # 确认 debug paths / config / agent 子命令存在
```

若不可执行 → 直接跳到「降级规则」，finding 标 `DEGRADED`。

### 步骤 1：构造隔离 HOME 与隔离项目

```pwsh
$BASE     = "$env:TEMP\opencode\stage44-op001"
$HOME_ISO = "$BASE\home"
$PROJ     = "$BASE\project"
Remove-Item -Recurse -Force $BASE -ErrorAction SilentlyContinue
New-Item -ItemType Directory -Force -Path "$HOME_ISO\.config\opencode\agents", "$HOME_ISO\.config\opencode", $PROJ | Out-Null

# 隔离生效
$env:USERPROFILE = $HOME_ISO; $env:HOME = $HOME_ISO
opencode debug paths
# 断言：输出 home == $HOME_ISO、config == "$HOME_ISO\.config\opencode"
#        不等 → 记录 `config dir mismatch` 并 STOP（不得继续，避免污染真实全局配置）
```

### 步骤 2：场景 A — 基线默认值（未声明任何 permission）

```pwsh
# 空全局配置（无 opencode.jsonc）；项目无 opencode.jsonc
Push-Location $PROJ
opencode debug config | Select-String "permission|external_directory"
opencode debug agent feel 2>&1 | Select-String "not found|permission"
Pop-Location
```

**观测**：(a1) 默认 `external_directory` 是否为 `ask`；(a2) 无 agent 定义时 `debug agent feel` 的表现。

### 步骤 3：场景 B — agent 内联 permission 的两种值形式（REV-001 补强点 3）

```pwsh
# B1：单值字符串形式
@'
---
description: probe single-value
mode: primary
permission:
  bash: "allow"
  external_directory: "allow"
---
probe
'@ | Set-Content "$HOME_ISO\.config\opencode\agents\probe-sv.md" -Encoding UTF8

# B2：对象形式
@'
---
description: probe object
mode: primary
permission:
  bash: "allow"
  external_directory:
    "*": "allow"
---
probe
'@ | Set-Content "$HOME_ISO\.config\opencode\agents\probe-obj.md" -Encoding UTF8

Push-Location $PROJ
opencode debug agent probe-sv  | Select-String "external_directory|allow|ask"
opencode debug agent probe-obj | Select-String "external_directory|allow|ask"
Pop-Location
```

**观测**：(a3，REV-001-③) 单值 `"allow"` 是否被 schema 接受并生效（与对象形式等价？报错？被忽略回落 `ask`？）。

### 步骤 4：场景 C — 顶层 `permission` vs agent 内联（覆盖 or 合并）

```pwsh
# 全局 opencode.jsonc：顶层 permission 全放行
'{ "$schema": "https://opencode.ai/config.json", "permission": "allow" }' |
  Set-Content "$HOME_ISO\.config\opencode\opencode.jsonc" -Encoding UTF8

# agent 仅声明 read deny，未声明 bash/glob（用于判定顶层是否被整体覆盖）
@'
---
description: probe override
mode: primary
permission:
  read: "deny"
---
probe
'@ | Set-Content "$HOME_ISO\.config\opencode\agents\probe-ov.md" -Encoding UTF8

Push-Location $PROJ
opencode debug agent probe-ov | Select-String "read|bash|glob|permission"
Pop-Location
```

**观测**：(b) 顶层 `"permission": "allow"` 是否对 `probe-ov` 生效，或**被 agent 内联块整体覆盖**（判据：`bash`/`glob` 的 effective 值是 `allow`(合并/继承) 还是 `deny/ask`(被覆盖)）。

### 步骤 5：场景 D — 自动追加 `allow` 逻辑是否真生效（§2.2 疑点 1）

```pwsh
# 移除全局顶层 permission，仅保留一个「未声明 external_directory」的 agent
Remove-Item "$HOME_ISO\.config\opencode\opencode.jsonc" -Force
@'
---
description: probe no-extdir
mode: primary
permission:
  bash: "allow"
---
probe
'@ | Set-Content "$HOME_ISO\.config\opencode\agents\probe-noext.md" -Encoding UTF8

Push-Location $PROJ
opencode debug agent probe-noext | Select-String "external_directory"
Pop-Location
```

**观测**：(c) 该 agent 的 effective `external_directory` = `ask`（默认）还是 `allow`（自动追加逻辑真生效）→ 决定 O2「补键」是「显式化」还是「改变行为」。

### 步骤 6：场景 E — `write` vs `edit` 键是否被识别（§2.2 疑点 2）

```pwsh
@'
---
description: probe write-key
mode: primary
permission:
  write: "deny"
---
probe
'@ | Set-Content "$HOME_ISO\.config\opencode\agents\probe-w.md" -Encoding UTF8
@'
---
description: probe edit-key
mode: primary
permission:
  edit: "deny"
---
probe
'@ | Set-Content "$HOME_ISO\.config\opencode\agents\probe-e.md" -Encoding UTF8

Push-Location $PROJ
opencode debug agent probe-w | Select-String "edit|write|permission"
opencode debug agent probe-e | Select-String "edit|write|permission"
Pop-Location
```

**观测**：(d) `write: deny` 是否在 effective 中出现（未识别 → 无该键/回落 allow）；`edit: deny` 是否出现（识别）。

### 步骤 7：场景 F — 项目 jsonc `agent.<name>.permission` vs frontmatter 优先级

```pwsh
# 项目 opencode.jsonc 覆盖 probe-e 的 edit
'{ "$schema": "https://opencode.ai/config.json", "agent": { "probe-e": { "permission": { "edit": "allow" } } } }' |
  Set-Content "$PROJ\opencode.jsonc" -Encoding UTF8
Push-Location $PROJ
opencode debug agent probe-e | Select-String "edit|permission"
Pop-Location
```

**观测**：(e) 项目 jsonc 的 `agent.<name>.permission` 是否覆盖/合并 frontmatter（`edit` 最终为 `allow` 还是仍 `deny`）。

### 步骤 8：清理与回填

```pwsh
Remove-Item -Recurse -Force $BASE -ErrorAction SilentlyContinue
Remove-Item Env:\USERPROFILE, Env:\HOME -ErrorAction SilentlyContinue
```

将 5 项结论写入 findings（见「产出文件」），并按下表回填：

| 项 | 结论落点 |
|----|----------|
| (a) 键合法性 + 默认值 + **单值形式是否接受** | op-002 值形式：接受 → `external_directory: "allow"`；不接受 → `external_directory: { "*": "allow" }` |
| (b) 覆盖 vs 合并 | op-004 文档表述（「agent 级覆盖/优先」是否需限定措辞） |
| (c) 自动追加 allow 是否生效 | O2 语义（补键 = 显式化 or 行为变更）；写进 findings 供审查 |
| (d) `write` 是否被识别 | **仅当确认未被识别** → op-002 将 `openfeel-utility.md`（zh/en `:12`）`write` 改 `edit`；否则保持 `write` 并标注 |
| (e) 项目 jsonc vs frontmatter 优先级 | op-004 文档「收紧入口」的准确性 |

## 降级规则（不阻塞）

- 某单项无法判定 → 标 `INCONCLUSIVE + 原因`，该项按上表「保守默认」处理，不阻塞。
- `opencode run` 需模型/auth 不可用 → 以 `debug agent`/`debug config` 的 effective ruleset 为准，findings 注明局限（与 plan §2.2「至少以 effective ruleset 为准」一致）。
