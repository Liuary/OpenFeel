## 目标

`npm run build` 重生成 `template-loader.ts` / `update.ts` 生成段；新增 build 步骤 8 从权威源重生成 `.opencode/` 自举实例并插入生成物标记（D36-3）；同步全部硬编码测试断言（区分「写入用新名」与「读取兼容保留旧名」两类 fixture，REV-306）；全量回归；输出自举重启提醒。

> 参见 kb/patterns.md #部署传播内容哈希比对模式；kb/patterns.md #update 增量部署哈希追踪 + 冲突标记三态模式（N3 标记须与 stage-38 控制区标记兼容）；kb/patterns.md #原子写模式（复用 `atomicWriteFileSync`）。

## 关键设计决策

1. **N4 步骤 8 位置（REV-308）**：置于 **`npx tsc` 之后**，用 `await import('./dist/core/fs/atomic-write.js')` 获取 `atomicWriteFileSync`（tsc 前 `dist/` 不存在无法 import）。保持 `npm run build` 单入口；若 Windows 下动态 import 异常，降级为独立 `npm run sync:opencode` 脚本（`package.json` scripts 新增，复用同一生成函数）。
2. **N3 生成物标记（REV-307 契约）**：标记 `<!-- openfeel:generated — 本文件由 npm run build 生成，请勿手工编辑 -->`。插入位置：
   - 有 YAML frontmatter 的 agent/skill `.md`：**frontmatter 闭合 `---` 之后**（第二个 `---` 下一行）。
   - 无 frontmatter 的 `ADAPTER.md` / `instructions/core.md`：首行。
   - 与 stage-38 `<!-- openfeel:begin/end -->` 控制区标记的**兼容契约**：`generated` 标记为**单行文件级信号**，位于文件顶部；控制区标记为**成对区域信号**，包裹正文受管内容。二者语法不冲突。约定：stage-38 的 managed-region 工具识别到 `openfeel:generated` 时，视整个文件为「受管产物」（跳过正文级区域探测，整体覆盖）；`openfeel:begin/end` 用于**非生成物**（用户可编辑文件）的局部受管区。本 op 仅落地 `generated` 标记，`begin/end` 归 stage-38。
3. **`.gitignore` 不重生成**：`.gitignore` 部署目标是项目根（`templates-data/opencode/.gitignore`），不在 `.opencode/` 自举实例内；故自举实例只生成 `agents/` + `skills/` + `instructions/core.md` + `ADAPTER.md`。
4. **自举实例语言**：取 `zh-CN`（本仓库规范语言，与现 `.opencode/` 一致）。生成前先对现 `.opencode/` 与权威源做一次 dry-run 比对，确认映射（`instructions/zh-CN.md` → `core.md`、`ADAPTER.zh-CN.md` → `ADAPTER.md`）无误后再写。
5. **测试 fixture 二分（REV-306）**：
   - **构造写入用新名**：测试里「创建 flow.json / 调 recordAttempt / 调 createReview / 调 archiveStage」等**产生写入**的 fixture，用 `openfeel-*` 新名，断言落盘内容为新名。
   - **读取兼容验证保留旧名**：专测 P5 兼容的 fixture，**保留旧名**（如 `assignee: 'planner'`），断言 `normalizeAgentName` / `flow status` 展示 `openfeel-planner`。
   - **禁止混用**：同一 fixture 不得既「写入旧名」又「断言新名落盘」（自相矛盾）。

### 步骤 2：build.js 新增步骤 8（`.opencode/` 自举重生成 + 标记，D36-3 / N4）

在 `build.js` 主流程 `npx tsc` 编译完成（`console.log('✓ TypeScript 编译完成')` L1163，REV-406 修订）之后、校验（`validateTemplates()` L1166）之前插入：

```js
async function regenerateOpencodeInstance() {
  console.log('⟳ 正在重生成 .opencode/ 自举实例（含生成物标记）...');
  const { atomicWriteFileSync } = await import('./dist/core/fs/atomic-write.js');
  const MARK = '<!-- openfeel:generated — 本文件由 npm run build 生成，请勿手工编辑 -->';
  const lang = 'zh-CN';

  // （REV-402 修订）先清除旧名残留，避免新旧并存；采用「清空目录 → 全量重写」策略
  // 使用 rmSync（node:fs）而非 git rm：build 脚本运行时无 git 依赖，删除后由 git add/status 自动识别；
  // git rm 仅适用于一次性迁移提交，不适用于 npm run build 每次运行时的自举重生成。
  // 1) 清空 .opencode/agents/*.md（删除旧名 8 文件，feel.md 保留由下方覆盖）
  const agentsOutDir = resolve(__dirname, '.opencode', 'agents');
  if (existsSync(agentsOutDir)) {
    for (const f of readdirSync(agentsOutDir).filter(f => f.endsWith('.md') && f !== 'feel.md')) {
      rmSync(join(agentsOutDir, f), { force: true });
    }
  }
  // 2) 清空 .opencode/skills/ 全部旧目录（递归删除 14 个旧名目录）
  const skillsOutDir = resolve(__dirname, '.opencode', 'skills');
  if (existsSync(skillsOutDir)) {
    for (const d of readdirSync(skillsOutDir, { withFileTypes: true }).filter(d => d.isDirectory())) {
      rmSync(join(skillsOutDir, d.name), { recursive: true, force: true });
    }
  }

  // agents：权威源 agents/{lang}/*.md → .opencode/agents/*.md（8 带前缀 + feel）
  const agentDir = resolve(TEMPLATE_OPENCODE_AGENTS_DIR, lang);
  for (const file of readdirSync(agentDir).filter(f => f.endsWith('.md'))) {
    let content = readFileSync(join(agentDir, file), 'utf-8').replace(/\r\n/g, '\n');
    content = insertGeneratedMark(content, MARK); // frontmatter 闭合 --- 之后
    atomicWriteFileSync(resolve(__dirname, '.opencode', 'agents', file), content);
  }

  // skills：权威源 skills/*/SKILL.md → .opencode/skills/*/SKILL.md（14 带前缀）
  for (const dir of readdirSync(TEMPLATE_OPENCODE_SKILLS_DIR, { withFileTypes: true }).filter(d => d.isDirectory())) {
    const src = join(TEMPLATE_OPENCODE_SKILLS_DIR, dir.name, 'SKILL.md');
    let content = readFileSync(src, 'utf-8').replace(/\r\n/g, '\n');
    content = insertGeneratedMark(content, MARK);
    // （REV-402 修订）清除后旧目录已删，先 mkdir 再写
    mkdirSync(resolve(__dirname, '.opencode', 'skills', dir.name), { recursive: true });
    atomicWriteFileSync(resolve(__dirname, '.opencode', 'skills', dir.name, 'SKILL.md'), content);
  }

  // instructions/core.md：权威源 instructions/{lang}.md → .opencode/instructions/core.md
  const instr = readFileSync(join(TEMPLATE_OPENCODE_INSTRUCTIONS_DIR, `${lang}.md`), 'utf-8').replace(/\r\n/g, '\n');
  atomicWriteFileSync(resolve(__dirname, '.opencode', 'instructions', 'core.md'), MARK + '\n' + instr);

  // ADAPTER.md：权威源 ADAPTER.{lang}.md → .opencode/ADAPTER.md
  const adapter = readFileSync(resolve(TEMPLATE_OPENCODE_DIR, `ADAPTER.${lang}.md`), 'utf-8').replace(/\r\n/g, '\n');
  atomicWriteFileSync(resolve(__dirname, '.opencode', 'ADAPTER.md'), MARK + '\n' + adapter);

  console.log('✓ .opencode/ 自举实例已重生成（25 文件，含生成物标记）');
}

/** 在 frontmatter 闭合 --- 之后插入生成物标记；无 frontmatter 则插首行 */
function insertGeneratedMark(content, mark) {
  const m = content.match(/^---\s*\n[\s\S]*?\n---\s*\n/);
  if (m) {
    return m[0] + mark + '\n' + content.slice(m[0].length);
  }
  return mark + '\n' + content;
}
```

**主流程调用（REV-406 修订）**：在 `build.js` 主流程 `npx tsc` 之后（`console.log('✓ TypeScript 编译完成')` L1163 下一行）、`validateTemplates()`（L1166）之前，插入：

```js
  // （REV-406 修订）步骤 8：重生成 .opencode/ 自举实例
  await regenerateOpencodeInstance();
```

> 说明：`regenerateOpencodeInstance()` 为 `async`（内部 `await import`），故调用处须 `await`。`build.js` 是 ESM（`import.meta.url`，L21 已证），支持**顶层 await**，主流程 `try` 块可直接 `await`，无需把主流程改造为 async IIFE。

> ⚠️ 若步骤 8 写入 `.opencode/` 异常（如 running session 句柄占用），`git checkout -- .opencode/` 可恢复；步骤 8 失败不应阻断 tsc 产物，但必须报错提示（`process.exit(1)` 保留原语义，或降级告警——Executor 按「失败即退出」处理，避免半生成状态提交）。

## 风险与注意

- **自举风险（高）**：`.opencode/` 是本仓库运行中会话的活跃配置，重生成 + 改名后**必须重启 opencode**；异常时 `git checkout -- .opencode/` 回滚。
- **N4 过度设计边界（R9）**：步骤 8 保持最小（仅生成 + 标记 + 校验），不引入独立 CLI/配置层；若动态 import 在 Windows 不稳定，降级 `npm run sync:opencode` 脚本（`package.json` 增 script，复用生成函数），不扩展 build.js。
- **标记破坏 frontmatter**：必须插在第二个 `---` 之后，插在之前会破坏 YAML 解析（REV-307）。
- **测试断言大范围误改（R5）**：逐文件核对 + 伪阳性清单 + 全量回归兜底；REV-306 二分纪律防 fixture 自相矛盾。
- **`.opencode/node_modules`**：非受管，不重生成、不标记、不提交。
