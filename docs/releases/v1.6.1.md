## 发布流程与版本号规则

- **版本号回落**：上一版版本号定得过高（按 minor 级），本版按**补丁版**纠正为 **1.6.1**（两个 `package.json` lockstep、`requiresCli >=1.6.1`）；历史阶段 ID（`v1.7.0-stage-133`）的归档与溯源引用保留不改。
- **发布走 CI（唯一标准路径）**：push 到 master 且 `package.json` 版本与 npm 已发版本不同 → CI 的 publish job（`.github/workflows/ci.yml`）自动 `npm publish`（`openfeel` + `openfeel-dsh`）；**tag / release 不触发**，**不需要手动 `npm publish`**，也不必打 tag。
- **本地入口**：`npm run release` 默认只做版本校验 + build；`--dry-run` 预检、`--push` 推送 commit（打了 tag 时一并推 tag）、`--publish` 仅 CI 失败时兜底并在提交信息 / 日志记录原因。
- **版本号分级**：版本号**默认按补丁 `x.y.Z` 推进**；**只有结构性 / 行为性变更才升 minor**；**破坏性变更才升 major**；小改动不要升二级 / 一级。
