# REQ-017：1.5.6：需求正文命令名校验（lint req：剥 openfeel 前缀 + 真实命令树解析 + 抑制标记）

> 本文件为需求正文（人读副本，由 openfeel req 机械铺骨架）。**机读权威恒为 `.openfeel/flow.json` 的 `requirements` 条目**；两者不一致时以 flow.json 为准。下方状态为创建时快照，不追写实时状态。

## 摘要

REQ-015 暴露的流程漏洞：写需求正文的人（含 Agent）凭意图写命令名，不与 CLI 注册面核对，导致 `stage deps` / `stage reset` / `op create` / `archive create` 这类**根本不存在**的命令进了需求，到执行期才被发现，靠人工补一张差异表兜底——下次还会犯。本需求把「命令名存在性」变成机器可校验的事实：新增 `openfeel lint req`。<!-- 本行按定义要引用「根本不存在」的命令名作为 bug 例证，引用即目的 --><!-- lint-req:ignore -->

## 目标与验收

**目标 1：新增 `lint req`**

- 与 `lint i18n` / `lint kb` 并列（`src/commands/lint.ts`）；`--json` 输出沿用既有形状 `{schemaVersion, target, ok, issues:[{path,message}]}`，`target='req'`。
- 扫描 `.openfeel/requirements/*.md` 全部正文，不区分需求状态。

**目标 2：判定规则（已用 16 份真实正文实测，零误报）**

1. **候选**：行内反引号 span，1–4 个 token，每 token 匹配 `^[a-z][a-z0-9_-]*$`（**允许下划线**：`flow review_add` 这类真实缺陷形态必须入候选）。含点 / 斜杠 / 大写开头 / `-` 或 `<` 开头等形态在**首个不匹配 token 处停止扩展**，对已收集的**前导 token 串**判定（不得「整 span 含不合形态 token 就跳过」，否则 `flow stats --json` 永远免检）。`flow.json` / `docs/**` / `--json` / `<stageId>` 不构成候选；`plan_review` / `stage-114` / `op-001` 是**单 token 非根名**而静默（不是形态排除）。<!-- 本行按定义要引用错误命令名作为判定示例（bug 例证），引用即目的 --><!-- lint-req:ignore -->
2. **剥前缀**：首 token 为 `openfeel` 时剥掉再解析（`openfeel config get` 属合法写法）。
3. **解析**：从 `program.commands`（`src/cli/index.ts` 已导出 `program`）构建**真实命令树**，逐 token 贪心下降，每个 token 必须是上一级的已注册子命令。**不得维护第二份命令清单**（会与注册面漂移）。**参数起点**：当前节点声明了位置参数（commander `registeredArguments.length > 0`）时，后续 token 视为参数、解析到此结束——参数值命中命令名 → 降级 B 类（`archive create`），否则通过（`stage set stage-01` / `config get workflow_mode`）。<!-- 参数起点歧义的判定示例（archive create）按定义要引用错误命令名，故本行免检 --><!-- lint-req:ignore -->
4. **A 类（计入失败）**：首 token 是根命令，但逐词解析在某处断掉，**且断点父命令未声明位置参数** → issue（「无法解析为命令路径（断在 X）」）。
5. **B 类（低置信，不改变退出码）**：① 首 token 不是根命令、span ≥2 token 且**尾 token 是任一已注册命令名** → issue（「疑似未知命令组」）；② **参数起点歧义**（父命令声明位置参数、该 token 又命中命令名）→ issue（「疑似把参数写成命令名」）。两类都只提示、不阻塞。
6. **解析到已注册命令即通过**：`plan scheme`、`stage`、`flow review` 这类「停在父命令」的写法合法，不得因「还有更深子命令」而报错。

**目标 3：抑制机制（两档）**

- 行内：`<!-- lint-req:ignore -->` → 跳过该行全部候选。
- 区间：`<!-- lint-req:ignore-start -->` … `<!-- lint-req:ignore-end -->` → 跳过区间内全部候选。
- 用途：正文按定义需要引用「错误命令名」的场合。REQ-015 的差异表已按区间标记自举。

**目标 4：退出码**

- 有 A 类 → exit 1；仅 B 类或无 issue → exit 0（与 `lint i18n` / `lint kb` 的「发现问题非 0」口径一致）。

**验收**
