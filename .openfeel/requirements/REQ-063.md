# REQ-063：需求审查相位 + req 命令 JSON 错误码

> 本文件为需求正文（人读副本，由 openfeel req 机械铺骨架）。**机读权威恒为 `.openfeel/flow.json` 的 `requirements` 条目**；两者不一致时以 flow.json 为准。下方状态为创建时快照，不追写实时状态。

## 状态

draft（创建时快照；以 flow.json 为准）

## 摘要

需求只有 review/verify 的「记录」，没有「待审」相位：偏差门只能挂 `→done`，审查时机不可控；且 `req claim/advance/complete` 没有 `--json`，三条 gate 码（REQ_BODY_GATE/REQ_PLAN_GATE/REQ_PLAN_DEVIATION）只能靠 human 文案 + exit 1 取证，自动化无法区分拒绝原因，这是 v1.6.0 明确登记的技术债。

## 目标与验收

### 目标

给需求生命周期加一个真正的审查窗口（`in_progress → review_pending → done`），让「先审后完成」有相位可挂；同时给 `req claim/advance/complete` 补 `--json` 与错误码，消灭「gate 码只能靠 human 文案取证」的妥协。

### 验收

- A63.1 需求状态域新增 `review_pending`：`in_progress → review_pending → done` 合法，`review_pending → in_progress` 可回退；`in_progress → done` 直连移除（`--force` 可跳但留痕）。
- A63.2 `review_pending` 下 `req advance --to done` 要求 review+verify pass；缺失时 exit 1 且 `--json` 返回稳定 `error.code`（`REQ_REVIEW_REQUIRED` / `REQ_VERIFY_REQUIRED`）。
- A63.3 `req claim/advance/complete` 支持 `--json`；`REQ_BODY_GATE`/`REQ_PLAN_GATE`/`REQ_PLAN_DEVIATION` 三码进入 `errors.ts` 与 error-envelope 契约表。
- A63.4 既有 done 门三态与 flow-manager done 门穷举用例语义不变；`dashboard`/`lint req`/`req board` 的 JSON 形状向后兼容（旧分组键保留或新增不替换）；出口计数文档与测试同批更新。
