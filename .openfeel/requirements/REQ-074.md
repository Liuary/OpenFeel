# REQ-074：克制机制：版本纪律 + 范围收敛 + 反过度设计 + 反自由发挥

## 状态

draft（创建时快照；以 flow.json 为准）

## 摘要

本次会话把同一段工作拆成 1.6.0~1.6.5 六个补丁版本：每个需求一升版、一发布，4 个 patch 号被浪费；docs/VERSIONS 里已有的「批次发布、禁止做完一个小功能就发一版」规则没有进入提示词，也没有任何门禁或检查，导致 AI 按「完成即发布」的惯性推进。需要把克制做成机制：版本只在发布时动、一次发布一个批次、发散需求进 backlog、审查检查过度设计与计划外改动。

## 目标与验收

### 目标

建立可执行的「克制」机制：版本号只在发布时推进、一次发布=一个批次（同批需求拆阶段不拆版本）、新想法进 backlog 不进当前批次、reviewer 增加过度设计与计划外改动检查；写入 feel_mode 提示词、dev_core/模板与 release 脚本，并记录可观察指标定义。

### 验收

- A74.1 feel_mode 提示词新增「版本纪律」检查点（中文 ≤120 字符；英文压缩既有句子腾预算，渲染态 ≤1200/≤25 行）：版本只在发布时定；一次发布=一个批次；新想法进 backlog；同批不连发 patch。parity 5/5、budget 测试绿（同步调整旧的 patch/minor/major 断言）。
- A74.2 `scripts/release.mjs`：新增 `--bump patch|minor|major`（发布时才改版本；minor/major 需 `--reason`；开发阶段不改版本）；真正发布前打印本批次清单（自上个版本以来 done 的 REQ/阶段/改动文件数）；真实发布需 `--confirm`；距上次发布 <24h 再发 patch 时给明确 warn 并要求再次确认；`--dry-run` 零写盘、零 git。
- A74.3 `.openfeel/dev/dev_core.md` 与 `src/core/templates.ts` DEV_CORE 模板新增「版本与范围纪律」：版本是发布信号不是开发里程碑；一批次一版本；同批需求拆阶段；新想法进 backlog（draft + 下一版本 target）；小改动不单独发版。
- A74.4 reviewer 清单与计划模板：reviewer 增加「过度设计」5 条判据（不必要抽象/新依赖/兼容层/IO 分支/REQ 外公开契约）与「计划外改动」（未在 plan/REQ 内的文件直接打回）；阶段/需求计划模板加 `## 不做清单` 与 `## 允许改动` 两节，计划评审检查 scope creep。
- A74.5 指标定义写入 `docs/VERSIONS.md`（releasesLast7d / medianIntervalHours / reqsPerVersion / patchPerMinor / outOfBatchRatio）；dashboard/metrics 实现、批次锁、<24h 硬门登记为后续需求（避免本版过度设计），本版不实现。
- A74.6 文档：`docs/commands.md` 的 release 段同步 `--bump/--confirm/--reason`；`CHANGELOG`、`docs/VERSIONS`、`docs/releases/v1.6.5.md`。
- A74.7 版本 1.6.5 **一次性**发布：本批次含 REQ-072 + REQ-073 + REQ-074；发布后本会话不再逐项升版。
