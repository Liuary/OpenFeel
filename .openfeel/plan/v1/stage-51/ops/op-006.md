## 一、变更目标

修复 op 文件名不可靠问题（反馈二问题 11）：`createScheme` 以 `safeTitle`（仅替换空白）拼文件名，标题含 `/` 时 `reserveSequence` 的 `openSync(path,'wx')` 因路径多一级抛 **ENOENT（创建直接失败）**；且命名不统一导致归档/审查引用断链。改为**固定 `op-NNN.md`**（标题写入文件内容，模板已含 `# {opId}：{title}`），读取端兼容历史命名。

## 二、N8 子项清单

### N8-1（中/低）`createScheme` 文件名固定为 `op-NNN.md`

- **文件:行号**：`src/core/plan/scheme.ts:191-196`（实测 `:191` `const safeTitle = title.replace(/\s+/g, '_')`；`:196` `candidate: (seq) => \`${opIdOf(seq)}_${safeTitle}.md\``）；`src/core/fs/sequence.ts:98`（`openSync(path,'wx')` 抛 ENOENT 的根因）
- **现状**：文件名 = `op-NNN_{safeTitle}.md`；`safeTitle` **仅替换空白**，**未过滤 `/` `\` `:` 等路径字符** → 标题含 `/` 时创建失败（ENOENT）；本仓 ops 实为手工 `op-NNN.md`（**与生成规则不一致**）。
- **改后**：
  1. `candidate` 改为 `${opIdOf(seq)}.md`（**去掉 `_${safeTitle}`**）；
  2. **删除** `safeTitle` 变量（及其 `replace` 逻辑）——标题不再参与命名；
  3. `parse` 回调（`:197-200`，`/^op-(\d+)/`）**保持不变**（新旧命名均可解析序号：`op-003.md` 与 `op-003_标题.md` 均匹配 `^op-(\d+)`）→ **序号分配不受影响**（关键：避免与历史文件撞号）。
  4. 标题写入内容：`generateSchemeTemplate(opIdOf(reserved.seq), parsed.fullStageId, title)` 已含标题行（**现状已满足**，无需改模板）；模板内 `# {opId}：{title}` 为标题权威来源。
- **行为变更**：**是**（**新建文件命名变更**：`op-NNN.md`）。
- **兼容影响**：既有 `op-NNN_title.md` 的历史文件**不迁移、不改名**（A5）；引用它们的归档/审查文档由**读取端兼容回退**（N8-2）保证仍可读；**不做迁移命令**（A5 明确）。

### N8-2（中/低）`extractTitle` 兼容回退（新旧命名双读）

- **文件:行号**：`src/core/plan/scheme.ts:71-75`（`extractTitle(fileName)`）；消费点 `:314`（`listSchemes` → `title: extractTitle(fileName)`）与 `getScheme`（`:218-`）相关读取路径
- **现状**：`extractTitle` 仅从**文件名**解析标题（`op-NNN_title.md` 形式）→ 新命名 `op-NNN.md` 无标题可解（恒空/`op-NNN`）。
- **改后**：
  1. 签名调整为**以路径为准**（需要读内容）：
     ```ts
     /**
      * 读取 op 标题（兼容两种命名）。
      * - 新命名 op-NNN.md：读文件内容首行的 `# {opId}：{title}`（缺则回退空串）
      * - 历史命名 op-NNN_title.md：沿用文件名解析（原行为）
      * @param filePath op 文件的绝对路径
      * @param fileName 文件名（用于历史命名回退）
      */
     function extractTitle(filePath: string, fileName: string): string
     ```
     判定顺序：① 文件名含 `_`（`^op-\d+_(.+)\.md$`）→ **走历史解析**（原行为，零变化）；② 否则 → 读文件内容，匹配首個 `^#\s*op-\d+[：:]\s*(.+)$`；命中 → 标题；未命中 → 回退文件名去扩展（`op-NNN`）。
  2. 内容读取失败（IO）→ 回退文件名，**不抛错**（列表命令需健壮）。
  3. `listSchemes` / `getScheme` / 任何其它调用点统一改用新签名（`rg -n "extractTitle"` 全量核对，确保无遗漏调用）。
- **行为变更**：**是**（新命名可读出标题；历史命名行为不变）。

### N8-3（低）迁移说明与文档移交（**不做迁移命令**）

- **改后**：
  1. **代码侧**：在 `createScheme` 处补中文注释说明命名约定（`op-NNN.md`，标题在内容首行）+ 历史兼容（读取端回退），供后续维护者理解（**A5 要求「给出迁移说明」**）。
  2. **文档侧（归归档官）**：`.openfeel/manual/cli/commands.md`（op 创建/命名小节）与 `.openfeel/kb/patterns.md`（「op 文件命名规范」条目）的正文更新**移交归档官**——本 op **不写**文档正文（遵循既有「文档类归归档官」裁定），但须在 op-009 报告的**文档同步清单**中登记该两项（含「新旧命名共存 + 不做迁移」说明要点）。
  3. **CHANGELOG**：命名变更记入 `Changed`（由 op-006→op-009 收口时统一登记，见 op-009）。
- **明确不做**：不提供 `openfeel plan scheme rename` / 批量重命名脚本 / 历史回改（A5）。
