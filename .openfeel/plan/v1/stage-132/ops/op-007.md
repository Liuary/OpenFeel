## 回滚/风险
- **回滚（REV-011 可执行路径）**：T11 是纯新增文件，`git clean -fd docs/research/` 即回退；T12 正文写入前**先做只读备份**——`mkdir -p .openfeel/tmp/stage-132/body-backup && cp .openfeel/requirements/REQ-05{5,6,7,8,9}.md .openfeel/requirements/REQ-060.md .openfeel/tmp/stage-132/body-backup/`（只读方向，不写受保护路径），回滚时用**同一通道**回填：`feel_req action=body id=REQ-0NN section=摘要 file=.openfeel/tmp/stage-132/body-backup/REQ-0NN.md --replace`（`## 目标与验收` 同法各一次），再 `git diff --stat .openfeel/requirements/` 归零；若该文件已入库，可等价的 `feel_req action=body ... --replace --text "$(git show HEAD~1:.openfeel/requirements/REQ-0NN.md)"`。T13 单独提交可整体 `git revert`。
- **风险（R1 改源码不生效）**：`feel_*` 走全局安装的 openfeel，T12 与 A7/A9 取证会失真 → T13 显式记录所用 CLI 路径（`openfeel.command` 或 `npm i -g .` 后的版本号）。
- **风险（T12 越权写受保护路径）**：`.openfeel/requirements/*.md` 被 guard 保护，工具直写与 shell 跑 openfeel 写命令都会被拒 → 只能走 `feel_req action=body`（op-001/006 已提供通道）。
- **风险（T12 反守卫冲突）**：`test/commands/req.test.ts:110-113` 的 afterEach 比对真实正文快照 → T12 **不得**在测试中执行（§7.3）。
- **风险（A12 只改计数不改叙述）**：只对齐 `docs/json-contract.md` 三行会让 §8.1 要求的口径缺失 → 以五处 `grep` 与人工对照双证。
- **风险（误动冻结文档）**：`dsh/docs/compat/*.md` 六份是 v1.2.1 逆向规格，改动即失真 → `git status` 断言为空。
