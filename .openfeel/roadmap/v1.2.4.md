## 目标

本版是**补丁版本**，范围已锁定，不新增功能、不扩项。目标只有两类：

1. **收口 `dsh/ACTION-GUIDE.md` 的 A1~A5 全部待办**：
   - **A1（P1，数据安全）**：`archive <stage>` 已有归档时拒绝覆盖（`ARCHIVE_EXISTS`/refusal/1，零写盘）；新增 `--force` 显式覆盖；

2. **版本 1.2.4 全链路收口**：A/B/C/D/E 载体、CHANGELOG `[1.2.4]`、README×3 / GETTING_STARTED / commands / `docs/json-contract.md` / `.openfeel/manual/**` / `openfeel-cli-usage` skill 快照 / `docs/dsh-cli-requirements-supplement-1.2.3.md` 增量到 v1.2.4；`--version` = **1.2.4**。

## 关键裁定

| 议题 | 裁定 |
|------|------|
| **版本号** | **v1.2.4**（补丁版本；三段 semver） |
| **工作流模式** | **fast**（单阶段；fast 仍必经 openfeel-reviewer **单轮计划审查**，不得跳过） |
| **阶段划分** | **单阶段** `v1.2.4-stage-100`；无阶段间依赖 |
| **范围红线** | 只做 A1~A5 + 版本收口；不修改 `dsh/`、不新增依赖、不改 phase 枚举/转移表、不镜像 Agent 编制、不为 JSON 分支复制第二套业务判定 |
| **A1 方案** | **拒绝覆盖 + `--force`**（ACTION-GUIDE 推荐序第 1 项）：目标归档文件已存在且未显式 `--force` → `ARCHIVE_EXISTS`/refusal/1，**零写盘**（主判据：归档文件内容哈希（SHA-256）+ flow.json revision + `log[]` 长度 + KB 条目数；mtime 仅辅助）；`--force` 仅绕过归档文件覆盖保护，不改变知识提取/日志写盘语义 |
| **A1 保护范围** | 保护为**归档文件级**（非阶段级）：`archive v1.2.0-stage-78` → `archive-v1.2.0-stage-78.md`，`archive stage-78` → `archive-stage-78.md`，互不触发；行为零改动，登记为已知边界 |
| **A2 数据源** | JSON 以 **flow.json 注册阶段**为调度视图（`id/phase/status/deps/workflowMode/opsTotal/opsDone`）；人类输出保持**计划目录清单**不变（两者视图不同，非同一输出双实现） |
| **A3 派生** | `provider`/`model` 按生效值首个 `/` 切分；`source` = 生效层（解析链 **default > project > global**，同 REV-1606）；`scope` 回显 `--scope`，未指定为 `null` |
| **A4 lint** | `lint kb` / `lint i18n` 共用同一文档形态 `{schemaVersion,target,ok,issues[]}`；`ok:false` 仍输出成功文档并保持既有 **exit 1** 门禁语义；人类输出逐字不变 |
| **A4 roadmap** | 里程碑表按表头驱动解析（兼容 3 列/4 列历史格式）；元素键固定 `title,theme,stage,deliverable`；不传版本 → `version:null,milestones:[]` |
| **A5 形态** | `{schemaVersion,scope:"project",defaults:{...}}`（取自 `resolveConfigDefaults` 四键）；**不用 `values`**——项目 `defaults` 与全局 profile `values` 键域不同，避免消费端误判同形 |
| **计数（核验后锁定）** | **40 个成功 JSON 出口 / 41 个注册 `--json` 选项**。较任务预估 39/40 **+1**：`lint kb` 与 `lint i18n` 是两个独立 Commander 子命令，冻结计数测试按命令树遍历，二者各需注册 `--json`（详见计划 §三） |
| **版本收口时点** | 版本号写入与文档收口为**最终任务组**；版本写入后不再引入业务代码改动 |
| **发布** | 完成后由 Feel commit/push；本计划不代 push；是否 `npm publish` 由用户决定；**不直写 flow.json** |
| **外部项** | OUT-1：DSH 适配器侧消费 v1.2.4 新出口（`cli.text()` → `cli.json()`、`requiresCli` 升级）由 DSH 侧执行，**不纳入本仓文件清单** |

- **不代 push**：推送由 Feel/用户执行；本计划不执行 `git push`。
