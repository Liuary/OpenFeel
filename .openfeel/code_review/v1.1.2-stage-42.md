## 心得建议

1. **「文档 vs 实现」不一致要当事实缺陷处理**：模板宣称「优先取全局画像」而实现从未接入 `readProfile()`，任何依赖该口径的验收都会自我矛盾；修正必须文案与实现同批，并 `rg` 残留引用。
2. **值正确 ≠ 口径正确**：「来源标注」也是交付契约的一部分。仅断言 `value` 的单测（`flow-manager.test.ts:2783`）会让来源偏差（`config/BUG-003`）在 652 全绿下漏网——单测必须覆盖 `source` 维度。
3. **验收命令本身可能破坏被验收对象**：`npm run build && npm test` 会真实覆盖仓库配置，说明「测试隔离」是流水线级前置条件而非测试细节；反向守卫让每次跑测即回归。
4. **隔离类修复必须有致败实验**：只证明「改完是绿的」不足；移除修复后缺陷须真实复发且被守卫精确捕获，才证明守卫有效（本阶段 REV-011 验收范式，建议推广）。
5. **幽灵引用要留痕**：幻觉会话造成的编号断裂/状态矛盾，归档时如实保留并标注「待重验」，比静默清理更利于审计追溯。
