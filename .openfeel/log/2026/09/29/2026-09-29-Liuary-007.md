# 2026-09-29  feel-tester：BUG-002（high）上报——`openfeel init` 无条件覆盖已存在的 `.openfeel/config.yaml`

> 提出人：openfeel-feel-tester | 类型：Bug 上报（正式测试 / 归档期间定位）
> **优先级：high ｜ 阻塞：否（不阻塞 stage-41 归档，已归入 stage-46 REV-001 同一根因）**
> 完整条目见私域 `.openfeel/users/Liuary/bugs/config/BUG-002_init无条件覆盖config.yaml静默丢失用户配置.md`。

## 结论

`openfeel init` 经 `writeDefaultConfig`（`src/core/config.ts:420-425`）对**已存在**的 `.openfeel/config.yaml` **无条件整体覆盖**，无提示、无备份、无人工提交记录，静默丢失用户配置。

唯一写入点（两处）：

- `src/core/init.ts:174-182` `initWorkspaceCore`：`existsSync` 仅用于 created/updated 分类，**不阻止写入** → `writeDefaultConfig` 仍会执行。
- `src/core/init.ts:371-376` `initDemo`：`if (!existsSync(configPath))` 守卫，安全。

## 事件证据（三方互证）

1. 本会话期间 `.openfeel/config.yaml` 的 `defaults` 由用户设定值 `execution_mode: auto / auto_advance: enabled / test_enabled: true` 被重置为模板默认 `manual / disabled / false`。
2. `git diff -- .openfeel/config.yaml` 为空 → 文件内容 == HEAD 内容；HEAD 值恰为 `DEFAULT_CONFIG`（`src/core/config.ts:123-128`）= 一次 `writeDefaultConfig` 模板覆盖后的结果。
3. `git log --oneline -- .openfeel/config.yaml` 最后一次提交为 `db0913d`（2026-09-26 v1.1.1-stage-01 归档），该提交实际**只改了 `meta.version: 1.1.0→1.1.1`**，从未记录本会话的 `auto/enabled/true` 改动。
4. 观测记录：`.openfeel/log/2026/09/28/2026-09-28-Liuary-003.md` 记载用户把 `execution_mode=auto / auto_advance=enabled / test_enabled=true` 写入 `.openfeel/config.yaml`；`42-REV-001` 复核时确认当时值为 auto/enabled/true。

## 影响

- 触发条件：任何对**既有项目**（已有 `.openfeel/config.yaml`）重复执行 `openfeel init`（含 `initDemo` 之外的主链路）。
- 影响面：用户可编辑的配置文件被静默重置，执行模式/自动推进/测试开关等偏好丢失。
- 关联：与 stage-46 REV-001（high, blocking）为**同一根因**——计划声称「`.openfeel/**` 走 writeTemplateIfMissing 不覆盖」与实测不符。

## 建议修复方向

1. `writeDefaultConfig` 补 `existsSync` 守卫（不存在才写），或在覆盖前调用 `backupFileBeforeWrite`（command='init'）+ `backed` 条目（对齐 stage-46 REV-001 的修正要求）；
2. `initWorkspaceCore` 的 created/updated 分类与写入行为对齐，避免「分类为 updated 却整体覆盖」的语义错位。
