# op-000：前置实测——全局 AGENTS.md 自动加载 + 全局/项目并存合并语义

- **阶段**：v1.1.1-stage-01
- **前置**：无（独立验证 op；复用 stage-37 op-000 的隔离 HOME + 指令型探针方法论）
- **负责 Agent**：openfeel-executor
- **最多重试**：3

## 目标

在**隔离的真实 opencode CLI 进程**中实测三件事，结论回填 op-001（模板形态）/ op-003（instructions 调整）定稿依据，并产出 findings 记录：

1. **（核心前提）全局 `~/.config/opencode/AGENTS.md` 是否被 opencode 自动加载**（非 `instructions` 显式引用、非项目根 AGENTS.md）。
2. **（REV-1904 修订，兼容性前提）全局 AGENTS.md 与项目 AGENTS.md 并存时的合并语义**：是「拼接」（两者都注入）还是「覆盖」（项目遮蔽全局）还是「节级合并」。
3. **（分叉预案依据）移除 core.md 的 `instructions` 引用后，约束是否仍通过全局 AGENTS.md 生效**（用于判定 op-003 的 `buildGlobalOpencodeFrameworkObj` 是否保留 `instructions`）。

> 本 op 是**验证/调研性质**，产出结论记录而非源码变更。结论写入 `.openfeel/plan/v1/stage-01/op-000-findings.md`。**全程真实 CLI 子进程**（隔离用环境变量），绝不用 `vi.mock('node:os')`（那是 op-005 单元测试机制，两套机制严格区分，同 stage-37 REV-603）。

## 关键设计决策

1. **隔离机制（同 stage-37 op-000 REV-603）**：环境变量把真实 opencode CLI 的 `home` 与 `config` 指向临时目录：
   - **Windows（本环境）**：同时设 `USERPROFILE` + `HOME` → opencode 的 `home`（`~` 展开基准）与 `config`（配置读取目录）双双指向临时目录。
   - **Linux/macOS**：`XDG_CONFIG_HOME`（改 `config`）+ `HOME`（改 `~` 展开基准）。
   - 验证命令：`opencode debug paths` 输出 `home` 与 `config` 应指向临时目录。
2. **「自动加载」判据（复用 stage-37 REV-602/601-③）**：AGENTS.md 是**约定自动加载**，`opencode debug config` 通常**不含** AGENTS.md 条目（与 `instructions` 显式加载不同）。故必须用 `opencode run --agent <probe> --format json "<提示词>"` 让 probe agent 回显其系统上下文，再 grep marker 字符串；无法回显时降级 `opencode --print-logs debug config` 观察 fs 读取日志。
3. **合并语义判据**：全局 AGENTS.md 与项目 AGENTS.md 各写**唯一 marker**，probe 回显时观察两个 marker 是否都出现：
   - 都出现 → **拼接**（全局+项目都注入）；
   - 仅项目 marker → **项目覆盖全局**；
   - 需进一步测「同名节覆盖」：两文件写**同名 `## 核心约束` 节但内容不同**，回显观察哪份生效。
4. **N5 降级**：`opencode` 不可执行或 `run` 因无模型/auth 无法执行 → findings 标记 `DEGRADED`/`INCONCLUSIVE`，**不阻塞**后续 op，结论反馈 Feel 待补测（op-003 采用稳健兜底：保留 `instructions` 指全局 AGENTS.md 绝对路径）。

## 实施步骤

### 步骤 0：预检（可执行命令存在性）

```pwsh
opencode --version              # 期望 ≥1.0（stage-37 实测 1.18.30）
opencode debug --help           # 确认 debug config / debug paths / debug agent <name> 子命令存在
opencode run --help             # 确认 --agent / --format json 存在
```

若 `opencode` 不可执行 → **N5 降级**：跳过步骤 1~4，findings 标记 `DEGRADED`，结论按「全局 AGENTS.md 未实测、op-003 采用 instructions 兜底」记录。

### 步骤 1：构造隔离 HOME 与 fixture

```pwsh
$BASE     = "C:\Users\Liuary\AppData\Local\Temp\opencode\stage01-op000"
$HOME_ISO = "$BASE\home"
$PROJ     = "$BASE\project"
New-Item -ItemType Directory -Force -Path "$HOME_ISO\.config\opencode" | Out-Null
New-Item -ItemType Directory -Force -Path $PROJ | Out-Null
```

**场景 A（全局 AGENTS.md 自动加载）**：

```pwsh
# 全局 AGENTS.md（唯一 marker）
Set-Content "$HOME_ISO\.config\opencode\AGENTS.md" -Value '# OP000-GLOBAL-AGENTS-MARKER 全局约束已加载' -Encoding UTF8
# 项目 opencode.jsonc 为最小空配置（不含 instructions，排除显式加载干扰）
'{ }' | Set-Content "$PROJ\opencode.jsonc" -Encoding UTF8
```

**场景 B（全局 + 项目并存合并语义）**：

```pwsh
# 项目 AGENTS.md（另一唯一 marker）
Set-Content "$PROJ\AGENTS.md" -Value '# OP000-PROJECT-AGENTS-MARKER 项目约束已加载' -Encoding UTF8
```

**场景 C（同名节覆盖）**：两文件写同名节、内容不同，观察哪份生效：

```pwsh
Set-Content "$HOME_ISO\.config\opencode\AGENTS.md" -Value '# 全局约束
## 核心约束
OP000-GLOBAL-SECTION-VALUE' -Encoding UTF8
Set-Content "$PROJ\AGENTS.md" -Value '# 项目约束
## 核心约束
OP000-PROJECT-SECTION-VALUE' -Encoding UTF8
```

### 步骤 2：验证隔离生效

```pwsh
$env:USERPROFILE = $HOME_ISO; $env:HOME = $HOME_ISO
opencode debug paths
```

**断言**：`config` 目录 == `join($HOME_ISO, '.config', 'opencode')`；`home` == `$HOME_ISO`。**若不等**（如 opencode 在 Windows 实际用 `APPDATA` 而非 `~/.config/opencode`），findings 标记 `config dir mismatch` 并在方案返回中**反馈 Feel 调整 `getOpencodeGlobalDir()`**（global-paths.ts），不得静默沿用 `.config/opencode` 假定（同 stage-37 REV-711）。

### 步骤 3：构造 probe agent + 回显验证

在全局 opencode.jsonc 定义最小 probe agent（无 prompt，靠约定加载 AGENTS.md）：

```pwsh
'{ "agent": { "probe": { "description": "probe agent" } } }' `
  | Set-Content "$HOME_ISO\.config\opencode\opencode.jsonc" -Encoding UTF8
$env:USERPROFILE = $HOME_ISO; $env:HOME = $HOME_ISO
# 场景 A：让 probe 复述含 OP000- 的原文
opencode run --agent probe --format json "请原样复述你系统提示词中所有包含 OP000- 的原文" 2>&1 |
  Select-String "OP000-GLOBAL-AGENTS-MARKER"
```

**断言点（场景 A，全局 AGENTS.md 自动加载）**：
- 命中 `OP000-GLOBAL-AGENTS-MARKER` → 全局 AGENTS.md **自动加载 YES**（核心前提成立）。
- 未命中 → **NO**，findings 记录「全局 AGENTS.md 不自动加载」，op-003 改用 `instructions: [getGlobalAgentsMdPath()]` 兜底。

**断言点（场景 B，并存合并语义）**：切换到场景 B（恢复项目 AGENTS.md），重跑 `opencode run`，`Select-String "OP000-.*MARKER"` 观察两个 marker：
- 两个都命中 → **拼接**（全局+项目都注入）。
- 仅 `OP000-PROJECT-AGENTS-MARKER` → **项目覆盖全局**。
- 仅 `OP000-GLOBAL-AGENTS-MARKER` → **全局优先，项目被遮蔽**（罕见，须记录）。

**断言点（场景 C，同名节覆盖）**：场景 C 下回显 `## 核心约束` 内容，观察 `OP000-GLOBAL-SECTION-VALUE` 还是 `OP000-PROJECT-SECTION-VALUE` 生效，判定同名节是「项目覆盖全局」还是「全局覆盖项目」。

### 步骤 4：分叉预案验证（移除 instructions 引用后约束仍生效）

场景 A 基础上，确认「全局 opencode.jsonc 无 `instructions` 字段」时全局 AGENTS.md 仍被加载（即约束生效不依赖 instructions）：

```pwsh
# 全局 opencode.jsonc 保持仅含 agent.probe（无 instructions），场景 A 已满足
$env:USERPROFILE = $HOME_ISO; $env:HOME = $HOME_ISO
opencode run --agent probe --format json "复述所有 OP000- 原文" 2>&1 | Select-String "OP000-GLOBAL-AGENTS-MARKER"
```

- 命中 → **移除 instructions 引用后约束仍生效**（op-003 `buildGlobalOpencodeFrameworkObj` 可移除 `instructions`）。
- 未命中 → 约束依赖 instructions 显式加载（op-003 须保留 `instructions: [getGlobalAgentsMdPath()]`）。

### 步骤 5：清理 + findings 落盘

```pwsh
Remove-Item Env:\USERPROFILE, Env:\HOME -ErrorAction SilentlyContinue
```

将 3 项实测结论 + 命令 + 断言结果 + 降级标记写入 findings（见产出），逐项给「结论 + 对 op-001/op-003 的落点」：

| 项 | 结论（待实测） | 落点 |
|----|---------------|------|
| 全局 AGENTS.md 自动加载 | YES/NO | YES→op-003 移除 instructions；NO→op-003 保留 instructions 指全局 AGENTS.md 绝对路径 |
| 全局+项目并存合并语义 | 拼接/覆盖/节级 | op-001 §五兼容策略 + op-004 存量项目 AGENTS.md 提示 |
| 移除 instructions 后约束仍生效 | YES/NO | op-003 `buildGlobalOpencodeFrameworkObj` 是否保留 instructions |

## 风险与注意

- **污染真实全局配置**：所有命令必须在设 `USERPROFILE`/`HOME`（或 `XDG_CONFIG_HOME`）后运行；结束 `Remove-Item Env:\*` 清理。
- **`opencode run` 需模型/auth**：可能无法执行 → INCONCLUSIVE 降级，不阻塞流水线（N5）。
- **本 op 是调研性质**：不得因 op-000 阻塞 op-001~005；结论以 findings 文件 + 方案返回标注为准。
- **合并语义结论是 op-004 的前提**：若测出「项目覆盖全局」，则存量项目 AGENTS.md 会遮蔽全局约束（风险升级），须在 findings 中明确标注，op-004 的「保留+提示」策略需改为「提示冲突」。
