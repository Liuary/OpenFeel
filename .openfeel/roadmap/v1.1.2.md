# 分期大纲 v1.1.2

> **版本**：v1.1.2（W 级递增） | **创建日期**：2026-09-28 | **状态**：**已完成（2026-10-01：十三阶段（41~53）全部归档；发布就绪，`npm publish` 时机待用户决定）**
> **规划来源**：① Pantheogen《OpenFeel CLI 工具链体验反馈》（`godot/Pantheogen/docs/06-openfeel-tooling-feedback.md`），经 Feel 逐条核实后全量处理；② 追加需求「CLI 操作文档 skill 化」；③ 追加需求「权限模型修正」（`docs/phase-5/07-openfeel-permission-issue.md`）；④ 追加需求「平台强限定内容描述泛化」（用户指令）。
> **详细计划**：见 `.openfeel/plan/v1/v1.1.2/plan.md`。

## 目标

1. **可自描述**：CLI 关键操作不再迫使 Agent 翻包源码——补齐 phase 枚举与转移表、stageId 命名/目录映射约定的**机器可读入口**。
2. **可纠错**：补齐「移除阶段」「声明依赖」「冲突检测」，让「计划 → 流水线」落地环节可回退、可声明、可纠偏。
3. **状态与口径正确**：修复 `pipeline.phase` 在 `done` 时不置位的真缺陷，统一 `auto_advance` 配置口径并暴露「有效值 + 生效来源」，为关键 CLI 状态变更补齐 `flow.json` 审计日志。
4. **知识资产化**：将 CLI 操作文档沉淀为按需加载的 `openfeel-cli-usage` skill，根治反馈 #2/#3 痛点。
5. **权限可用**：修正 agent 模板权限模型，使「项目级全程自动审批」可用（补 `external_directory` + 文档化覆盖语义）。
6. **平台可移植**：将模板/规则/注释/文档/手册中「以 opencode 为唯一 harness」的描述泛化为无平台表述（零行为变更）。
7. **部署可回溯**：部署覆盖既有文件前自动备份原件（全局根 `~/.openfeel/backup/{ts}/`），并在全局状态文件中登记提示 Agent 检查。
8. **发布前无脏点**：集中清理测试/审查登记但未修的缺陷（含 `init` 覆盖用户 `config.yaml` 的 high 收口语义修复、`config effective` 来源偏差、模板泛化遗漏、`lint kb` 过期引用等），使版本收口前全绿。
9. **范围收口**：不引入新架构层，全部为命令层/核心层增量修复；版本号收口留到收尾阶段统一执行（完整载体清单见 `plan/v1/v1.1.2/plan.md` §3.1）。
10. **过程加固**：针对三大过程事件（审查官工具幻觉 / `npm test` 静默覆写真实环境 / 裸跑命中全局旧版）建立机制防线（模板纪律、CI 环境守卫与版本门禁、执行口径统一）；并清零既有遗留。
11. **全仓体检**：在发布后基线上对整个仓库做一次系统审查（8 单元 × 6 维度），形成可追溯的 REV 与修复流转清单。

> 说明：**用户决定继续 v1.1.2**（不新建版本）；stage-48/49 为 v1.1.2 的追加收尾阶段。
