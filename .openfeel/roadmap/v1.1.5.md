## 目标

用户执行 `npm i -g openfeel@X` 升级 CLI 后，**全局资产**（`~/.config/opencode/AGENTS.md`、agents、skills、`opencode.jsonc`）**不会自动刷新**，须重跑 `openfeel setup` 并重启 harness 才生效；而框架当前**完全不检测、不提示**，普通用户无从知晓，会持续加载旧全局资产。

本版本以**最小命令面**补齐这一缺口：

1. **可靠的事实源**：把 `~/.openfeel/update_state.json.openfeel_version` 从「只写不读、且仅首次创建时写入」改造为「**每次全局部署刷新 + 被读取比较**」，使其语义 = 「当前已部署全局资产的版本」。
2. **被动检测与提示**：任意 CLI 命令运行时（TTY 交互、非 `--json`/`--quiet`、非 CI）对比「CLI 版本 vs 已部署版本」，不一致或全局部署缺失时向 **stderr** 提示「运行 `openfeel setup` 并重启 harness」。仅读全局 `~/.openfeel/`，**不写盘、不改退出码**。
3. **主动诊断命令**：新增 `openfeel setup --check [--json]`（只读、可机器消费），显示已部署版本 vs CLI 版本与部署状态；一致退出 0，否则退出 1。
4. **升级流程文档化**：README（zh/en）、`docs/GETTING_STARTED.md`、`docs/commands.md`、`manual/core/setup.md`、`openfeel-cli-usage` skill 权威源统一说明「升级后须重跑 `openfeel setup` + 重启」。
