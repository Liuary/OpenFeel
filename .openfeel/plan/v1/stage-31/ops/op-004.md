## 目标

为 `flow advance` 命令新增 `--dry-run` 选项，推进前先验证合法性并输出预览信息，不实际修改 flow.json。

- kb/patterns.md #CLI 原子管理模式：`--dry-run` 遵循不可变原则，在 `save()` 前截断

## 实施步骤

### 步骤 1：在 flow advance 命令定义中添加 `--dry-run` 选项

**当前代码**（`src/commands/flow.ts` L363-364）：
```typescript
    .option('--stage <id>', '阶段 ID（如 stage-03），必须指定')
    .option('--force', '强制执行（跳过非法 phase 校验和阶段跳跃检查，但不可绕过 REV 阻塞检查）')
```

**修改为**（在 `--force` 后追加 `--dry-run`）：
```typescript
    .option('--stage <id>', '阶段 ID（如 stage-03），必须指定')
    .option('--force', '强制执行（跳过非法 phase 校验和阶段跳跃检查，但不可绕过 REV 阻塞检查）')
    .option('--dry-run', '仅验证不执行修改（预览输出）。与 --force 组合时跳过校验但仍不执行修改')
```

- [ ] 使用 `edit` 工具在 L364 之后插入 `--dry-run` 选项声明

> **REV-003 回应**：`--dry-run` 描述明确注明与 `--force` 组合行为——"跳过校验但仍不执行修改"。

### 步骤 2：在 action 中更新 options 类型签名 [FIX] REV-002

**修改为**：

- [ ] 使用 `edit` 工具更新类型签名，新增 `dryRun?: boolean` 字段

> **REV-002 回应**：Commander 自动将 `--dry-run` 转为 camelCase `dryRun`。类型签名显式声明 `dryRun?: boolean` 确保 TypeScript 严格模式下类型检查通过，同时作为文档注释告知后续维护者该选项存在。

### 步骤 3：在 advanceStagePhase() 执行前插入 dry-run 判断

**插入位置**：`src/commands/flow.ts`，在 L459 `let archived = false;` 之前。

**插入代码**：
```typescript
      // --dry-run：仅验证合法性，不实际修改 flow.json
      if (options.dryRun) {
        const data = mgr.getData();
        const fromPhase = data?.stages[options.stage!]?.phase ?? t('common.unknown', lang);
        const toPhase = options.to;

        if (options.force) {
          console.warn(t('flow.advance.dryRunForceWarn', lang));
        }
        console.log(t('flow.advance.dryRunTitle', lang));
        console.log(`  ` + t('common.stage', lang) + `: ${options.stage}`);
        console.log(`  ` + t('flow.advance.dryRunFrom', lang) + `: ${fromPhase}`);
        console.log(`  ` + t('flow.advance.dryRunTo', lang) + `: ${toPhase}`);
        console.log('');
        console.log(t('flow.advance.dryRunOk', lang));
        return;
      }
```

- [ ] 使用 `edit` 工具在 L459 之前插入 dry-run 代码块

> **REV-003 回应**：当 `--force` 和 `--dry-run` 同时指定时，先输出 `dryRunForceWarn` 警告（告知用户 `--force` 跳过部分校验），然后输出预览信息。`return` 确保无论是否 `--force`，均不执行 `advanceStagePhase()` + `save()`。

> **关键设计**：dry-run 判断在所有前置校验（格式 P0、非法 phase P1、阶段跳跃保护、REV 阻塞）**之后**、`advanceStagePhase()` **之前**。这意味着 dry-run 必须通过所有校验才能到达此处——如果前置校验失败，dry-run 也会报错退出，这与"预览真实性"原则一致。

## 风险说明

| 风险 | 概率 | 缓解 |
|------|------|------|
| `--dry-run` + `--force` 跳过校验后预览不准确 | 低 | `--force` 跳过 P1 和阶段跳跃保护是预期行为——用户想看"强制执行"的预览；dryRunForceWarn 警告已提示 |
| dry-run 插入位置在 autoRepair 之后 | 低 | autoRepair 仅在检测到不一致时触发且极少发生；若触发则会 save()，之后 dry-run 声明"未修改"可能有轻微偏差。autoRepair 的非侵入性（仅修正 phase/status 不一致）使此偏差可接受 |
| dry-run 后用户忘记去掉 --dry-run | 低 | 预览输出明确提示 "去掉 --dry-run 后正式执行"，降低操作失误概率 |
