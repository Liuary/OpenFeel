## 目标

将 `feel-tester.md` 从 72 行扩充到 90–110 行，细化快速验收的自主判断逻辑，标准化 Bug 条目格式（含优先级判据），明确回归验证的最小集合定义。

## 实施步骤

- [ ] 1. 读取当前 `.opencode/agents/feel-tester.md` 完整内容（72 行）
- [ ] 2. 重写 `## 快速验收` 节，明确 Tester 的快速验收**独立判断**（不依赖 Reviewer 的 FAST-PASS 标记）：
  - 三要素与 Reviewer 对齐：代码量 < 200 行、Executor 自测全部通过、覆盖率 ≥ 80%
  - Tester 自行从 Executor 自测报告和 git diff 中获取数据，**不依赖 flow.json 的 reviews 字段**
  - 判定逻辑：三要素全部满足 → 快速验收；任一不满足 → 完整验收
  - 快速验收行为：运行 `npm test` 一次确认通过 + 检查自测报告完整性 → 通过即推进
- [ ] 3. 在 `## 快速验收` 之后新增 `## 完整验收流程` 节：
  - 逐项验收操作方案中的每条自测清单
  - 运行全量测试套件 `npm test`
  - 运行验收测试（如有独立验收用例）
  - 手动验证产出文件存在性和内容正确性
  - 验证方案一致性回写记录
- [ ] 4. 重写 `## Bug 管理` 为 `## Bug 模板规范`，标准化 BUG 条目格式：
  - YAML frontmatter 格式：
    ```yaml
    status: open | fixing | resolved | closed
    priority: high | medium | low
    module: {模块名}
    author: Tester
    created: YYYY-MM-DD HH:MM
    ```
  - 正文含：复现步骤、期望行为、实际行为、影响范围
  - 优先级判据（明确场景化）：
    - **high**：功能完全不可用、数据丢失/损坏、流水线阻塞（无法推进）
    - **medium**：功能可用但行为不符预期、非核心功能异常、边界情况未处理
    - **low**：UI/文案问题、非关键路径的边缘场景、性能微降（< 10%）
- [ ] 5. 在 `## Bug 模板规范` 之后新增 `## 回归验证流程` 节：
  - **最小回归集合**（每次 Bug 修复后必须执行）：
    1. 原始 Bug 复现步骤（确认已修复）
    2. 关联模块的冒烟测试（`npm test` 中对应模块的测试用例）
    3. 修复涉及的函数/模块的单元测试
  - **扩展回归**（high 优先级 Bug 修复后推荐执行）：全量测试套件
  - 回归验证结果写入 Bug 文件的「验收记录」表
- [ ] 6. 删除过时的 `## 快速验收` 中引用 `FAST-PASS` 标记的旧描述（替换为 Tester 独立判断逻辑）
- [ ] 7. 最终检查：`wc -l` 确认行数在 90–110 范围内
