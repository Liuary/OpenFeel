## 经验与建议

- job 级 `concurrency` 是消除「同一 ref 多 run 并发副作用」的标准手段；对**发布类不可逆副作用**应取 `cancel-in-progress: false`（排队而非取消进行中的发布）。
- **串行化 ≠ registry 状态同步**：npm registry 的 staged→finalize 存在分钟级延迟窗口，跨 run 的「版本是否已变」判断仍可能误判；彻底方案需幂等/重试语义（本轮按用户裁定不做）。
- 可选后续（非本次要求）：publish 步骤后置重试、或改用 provenance/oidc 语义化发布流程，或接受手动重跑。
