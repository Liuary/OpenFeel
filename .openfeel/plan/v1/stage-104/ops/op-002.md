# op-002：审查挂载点与返工边：review add 免 op 挂 stage + review_passed→exec_running（P0-2/P0-3）

- **阶段**：v1.3.3-stage-104
- **状态**：pending
- **前置**：无（与 op-001 文件集不重叠）
- **负责 Agent**：openfeel-executor
- **最多重试**：3
- **对应问题**：P0-2（fast 无 op → 审查无法登记）、P0-3（审查通过后无返工边）

## 目标

让「审查」这一通用行为不再依赖 `full` 才有的 op：`flow review add` 支持 `--stage <id>` 挂阶段级 REV；同时给 fast 表补 `review_passed → exec_running` 返工边（可带 `--reason` 整改原因），并消除由此产生的路径多义与归档归属错误。

## 涉及文件

- `src/commands/flow.ts`（review add 选项 / 分支；advance 的 `--reason`）
- `src/core/view/entry.ts`（`AddReviewOptions` / 校验 / `ReviewItem.stage`）
- `src/core/flow-manager.ts`（`FAST_TRANSITIONS`、`ReviewItem.stage`、`reviewStageOf`、`listStageBlockingOpenReviews`、`findPhasePath` tie-break）
- `src/core/archive/merge.ts`（REV 归属改用 `reviewStageOf`）
- `src/core/i18n-data/{zh-CN,en}.ts`（新键成对）
- `test/commands/flow.test.ts`、`test/core/view/entry.test.ts`、`test/core/flow-manager.test.ts`、`test/core/archive/merge.test.ts`

## 实施步骤

- [ ] 1. `flow review add`：`--op` 由 `requiredOption` 改为 `option`；新增 `--stage <id>`；action 分支：`--op` 优先走既有路径；否则 `--stage` 或 `pipeline.current.stage` 解析 stage；两者皆无 → `INVALID_ARGUMENT`（明确「--op 或 --stage 二选一」）。`--auto-fix` 无 `--op` → `INVALID_ARGUMENT`（`AUTO_FIX_REQUIRES_OP`）。
- [ ] 2. `entry.ts`：`AddReviewOptions` 增 `stageId?: string`、`opId?: string`；**`--stage` 路径必须绕过 `lastIndexOf('.')` 的 op 解析**（stage id 自身含点，`v0.0.1-stage-01` 会被切成 `v0.0.1-stage-0` / `1`）——先按 `normalizeStageId + 双键回退` 直接查 stage，命中即以 `op = stageId`、`stage = stageId` 建 REV；未命中才走既有 op 解析。`autoFixDetail` 在无 op 时拒绝。
- [ ] 3. `ReviewItem` 增可选 `stage?: string`（向后兼容，旧数据缺省 undefined）；新增单点 `reviewStageOf(review)`：`review.stage` 优先，其次 `op` 精确命中 stages 键（stage 级），最后 `lastIndexOf('.')` 前缀（op 级）。`listStageBlockingOpenReviews` 与 `archive/merge.ts:89-99` 统一改为消费它（修 B3：否则 stage 级 REV 在归档摘要中丢失）。
- [ ] 4. fast 表：`review_passed: ['archiving', 'exec_running']`（顺序保持 archiving 在前，既有展示稳定）；同步 `FAST_TRANSITIONS` 顶部注释。
- [ ] 5. `flow advance` 增 `--reason <text>`（可选）：传入且目标为 `exec_running` 时写入日志 detail（`rework_reason`），其它情况忽略并向 stderr 提示一次。
- [ ] 6. `findPhasePath` 同深度歧义 tie-break（**必须**，否则回归）：`start === 'review_pending' && to === 'exec_running'` 且命中两条路径时，优先首跳为 `review_failed` 的路径（保持修复前唯一路径行为）；其余歧义维持 `ambiguous`。
- [ ] 7. 测试：
  - fast 0-op 阶段 `review add --stage <id>` 成功；`flow status --json` 可见；`listStageBlockingOpenReviews` 命中；`archive <stage>` 摘要含该 REV。
  - 无 `--op`/`--stage` → exit 1；`--auto-fix` 无 `--op` → exit 1。
  - fast `review_passed → exec_running` 合法；`review_pending → exec_running` 仍走 `review_failed`（tie-break）；`review_passed → exec_running` 可带 `--reason` 且日志含 `rework_reason`。
  - full 表不变（`review_passed` 仅 `test_pending`）。
- [ ] 8. `npx vitest run test/commands/flow.test.ts test/core/view/entry.test.ts test/core/flow-manager.test.ts test/core/archive/merge.test.ts` 全绿；`npx tsc --noEmit` 0。
- [ ] 9. `dsh/ADAPTER.md`：在「写入门禁 / 审查」相关节注明「stage 级 REV（`op = stageId`）用于无 op 场景，不参与 `flow attempt` / `flow retry`」；`flow review add --help` 的 `--op`/`--stage` 文案同步。
- [ ] 10. **补登计划审查 REV 留痕**（P0-2 修好后立即）：`flow review add --op v1.3.3-stage-104.op-002 --title "计划审查 P01~P04 吸收记录" --blocking false`，随后 `flow review resolve <REV>`（closed）；PR 描述里引用 plan §七。
