# op-001：双层模板源收敛为单源（`templates-data/opencode/`）

- **阶段**：v1.1.0-stage-36
- **前置**：无（先导 op，产出单一权威源 + 收敛后的 build.js）
- **负责 Agent**：Executor
- **最多重试**：3

## 目标

将三对双层模板源（agent / instruction / skill）逐文件取较新合并到唯一权威树 `templates-data/opencode/`，删除冗余树 `templates-data/agents/` 与 `templates-data/core-instructions/`；build.js 全部源路径改指权威树；skill 行尾归一 LF；新增 `.gitattributes`；build 新增「三对注入对象键集与内容一致」断言。D36-5 reviewer 模型只读核对（保持 `glm-5.2`，无改动）。

> 参见 kb/troubleshooting.md #双层模板源发散（本阶段首要收敛对象）；kb/architecture.md #多语言模板数据管线；kb/patterns.md #构建脚本多语言循环生成模式（build.js 语言循环注入结构）；kb/patterns.md #跨平台行尾归一化模式（CRLF 泄漏进模板串的隐患）。

## 关键设计决策

1. **D36-4 定夺：两套 skill/agent 定义不合并，保留两个注入对象 + 单源 + 一致性断言**（N2 落地）。理由：`SKILL_DEFINITIONS`（`update.ts`）与 `OPENCODE_SKILL_DEFINITIONS`（`template-loader.ts`）消费方不同（update 命令 vs init 部署），合并会牵连调用方大改；且 build 已具备「同源读取 + 断言键集/内容一致」能力，合并无净收益、徒增改动面。故**保留两个对象，仅改源路径 + 加断言**。agent 同理（`AGENT_TEMPLATES` ↔ `OPENCODE_AGENT_TEMPLATES`）、instruction 同理（`CORE_INSTRUCTIONS_TEMPLATES` ↔ `OPENCODE_CONFIG_TEMPLATES[*].instructions`）。
2. **合并方向（取较新，不选整树）**：agent 侧 `templates-data/agents/` 的 `feel.md` 多「## 冲突检测」节（21 行），须逐文件 diff 后把该节并入 `opencode/agents/*/feel.md`；instruction 侧 `opencode/instructions/` 已含 Vision（较新），保留其为权威，仅核对 `core-instructions/` 是否另有独有内容（已知无）。skill 侧两侧 git 内容一致，仅行尾差异，取 `opencode/skills/` 为权威 + 归一 LF。
3. **删除顺序纪律**：先合并 → 逐文件 `diff` 校验无信息丢失 → 再删除冗余树 → 独立 git commit（可 `git revert`）。破坏性删除不得与合并同 commit 混合。
4. **行尾归一位置**：在注入函数内 `content.replace(/\r\n/g, '\n')`（与 core-instructions 步骤 1 一致），而非依赖 `.gitattributes` 单项；`.gitattributes` 作第二道保险（规范后续检出）。
5. **build 源常量处置**：`SKILLS_DIR`（L35）改指 `templates-data/opencode/skills`（仍被步骤 4 + validateSkillDefinitions 使用，**重指不删**）；`CORE_MD_PATH`（L33）、`AGENTS_DIR`（L34）、`TEMPLATE_CORE_MD_PATH`（L28）、`TEMPLATE_AGENTS_MD_PATH`（L29）为**死常量**（全文件无引用），删除。（REV-403 修订）另补删两个**改向后才成为死常量**的源目录常量：`TEMPLATE_AGENTS_DIR`（L27）与 `TEMPLATE_CORE_INSTRUCTIONS_DIR`（L30）——原被 `generateAgentDefinitions`/`validateAgentDefinitions`（L140/145/152/747/769）与 `generateTemplateFromCoreMd`/`validateCoreInstruction`（L105/110/115/496）引用，改向 `TEMPLATE_OPENCODE_AGENTS_DIR`/`TEMPLATE_OPENCODE_INSTRUCTIONS_DIR` 后全文件再无引用，须一并删除；`TEMPLATE_AGENTS_MD_DIR`（L31）仍被 `generateAgentsMdTemplate`（L184）使用，**保留不删**。

### 步骤 7：三对注入对象一致性断言（N2）

在 `validateTemplates()`（L814）与 `validateOpencodeTemplates()`（L1105）之后新增一个 `validateSingleSourceConsistency()`，断言三对对象键集与归一化内容一致：

```js
function assertConsistent(nameA, nameB, entriesA, entriesB) {
  const keysA = Object.keys(entriesA);
  const keysB = Object.keys(entriesB);
  const errors = [];
  if (JSON.stringify(keysA) !== JSON.stringify(keysB)) {
    errors.push(`${nameA} 键集(${keysA.join(',')}) ≠ ${nameB} 键集(${keysB.join(',')})`);
  }
  for (const k of keysA) {
    const a = (entriesA[k] || '').replace(/\r\n/g, '\n');
    const b = (entriesB[k] || '').replace(/\r\n/g, '\n');
    if (a !== b) errors.push(`${nameA}.${k} 内容 ≠ ${nameB}.${k}`);
  }
  return errors;
}

/**
 * 从 template-loader.ts 提取 agent 模板对象并 flatten 为 Record<`${lang}.${agentId}`, content>
 * （REV-407 修订：复用 matchBraces L422 + matchBraceAt L669 + extractTemplatePairs L593，
 *   整体结构仿 validateAgentDefinitions L710）
 */
function extractAllAgentEntries(anchorName) {
  const section = extractBetweenAnchors(TEMPLATE_LOADER_PATH, anchorName);
  const objText = matchBraces(section);
  if (!objText) return {};
  const flat = {};
  const langRegex = /(?:[\s,])(?:(['"])([a-zA-Z_][\w-]*)\1|([a-zA-Z_$][a-zA-Z0-9_$]*))\s*:\s*\{/g;
  let langMatch;
  while ((langMatch = langRegex.exec(objText)) !== null) {
    const langKey = langMatch[2] || langMatch[3];
    const innerStart = objText.indexOf('{', langMatch.index);
    const innerEnd = matchBraceAt(objText, innerStart);
    if (innerStart === -1 || innerEnd === -1) continue;
    const innerObj = objText.slice(innerStart, innerEnd + 1);
    const pairs = extractTemplatePairs(innerObj);
    for (const [agentId, content] of Object.entries(pairs)) {
      flat[`${langKey}.${agentId}`] = content;
    }
    langRegex.lastIndex = innerEnd + 1;
  }
  return flat;
}

/**
 * 断言 instructions 双源一致（REV-407 修订）：
 * CORE_INSTRUCTIONS_TEMPLATES（Record<lang, B64>）与 OPENCODE_CONFIG_TEMPLATES[lang].instructions（B64）
 * 逐语言解码后归一化比对。
 * 复用 extractBetweenAnchors（L405）+ matchBraces（L422）+ extractOpencodeConfigLangEntries（L968），
 * langRegex 模式同 validateCoreInstruction（L489）。
 */
function assertInstructionsConsistent() {
  const errors = [];
  // 1) 提取 CORE_INSTRUCTIONS_TEMPLATES：锚点段 → matchBraces → langRegex 提取 lang→B64
  const coreSection = extractBetweenAnchors(TEMPLATE_LOADER_PATH, 'CORE_INSTRUCTIONS_TEMPLATES');
  const coreObjText = matchBraces(coreSection);
  if (!coreObjText) return ['无法提取 CORE_INSTRUCTIONS_TEMPLATES 对象'];
  const coreB64ByLang = {};
  const langRegex = /(?:[\s,])(?:(['"])([a-zA-Z_][\w-]*)\1|([a-zA-Z_$][a-zA-Z0-9_$]*))\s*:\s*'([^']+)'/g;
  let m;
  while ((m = langRegex.exec(coreObjText)) !== null) {
    coreB64ByLang[m[2] || m[3]] = m[4];
  }
  // 2) 提取 OPENCODE_CONFIG_TEMPLATES：锚点段 → matchBraces
  const configSection = extractBetweenAnchors(TEMPLATE_LOADER_PATH, 'OPENCODE_CONFIG_TEMPLATES');
  const configObjText = matchBraces(configSection);
  if (!configObjText) return ['无法提取 OPENCODE_CONFIG_TEMPLATES 对象'];
  // 3) 逐语言解码比对（B64 → utf-8 → CRLF 归一 LF）
  const norm = (s) => Buffer.from(s, 'base64').toString('utf-8').replace(/\r\n/g, '\n').replace(/\r/g, '\n');
  for (const lang of Object.keys(coreB64ByLang)) {
    const configEntries = extractOpencodeConfigLangEntries(configObjText, lang);
    if (!configEntries || configEntries.instructions === undefined) {
      errors.push(`[${lang}] OPENCODE_CONFIG_TEMPLATES 缺少 instructions 键`);
      continue;
    }
    if (norm(coreB64ByLang[lang]) !== norm(configEntries.instructions)) {
      errors.push(`[${lang}] CORE_INSTRUCTIONS_TEMPLATES ≠ OPENCODE_CONFIG_TEMPLATES[${lang}].instructions`);
    }
  }
  return errors;
}

function validateSingleSourceConsistency() {
  const errors = [];
  // 三对：agent / skill / instructions
  errors.push(...assertConsistent('AGENT_TEMPLATES', 'OPENCODE_AGENT_TEMPLATES',
    extractAllAgentEntries('AGENT_TEMPLATES'), extractAllAgentEntries('OPENCODE_AGENT_TEMPLATES')));
  errors.push(...assertConsistent('SKILL_DEFINITIONS', 'OPENCODE_SKILL_DEFINITIONS',
    extractTemplatePairs(matchBraces(extractBetweenAnchors(UPDATE_PATH, 'SKILL_DEFINITIONS'))),
    extractTemplatePairs(matchBraces(extractBetweenAnchors(TEMPLATE_LOADER_PATH, 'OPENCODE_SKILL_DEFINITIONS')))));
  // instructions：CORE_INSTRUCTIONS_TEMPLATES（B64） vs OPENCODE_CONFIG_TEMPLATES[*].instructions（B64）
  // （REV-407 修订）复用 assertInstructionsConsistent()，逐语言解码比对，见下
  errors.push(...assertInstructionsConsistent());
  // 另断言「不存在同名双源文件」：templates-data/agents、templates-data/core-instructions 已不存在
  if (existsSync(resolve(TEMPLATES_DATA_DIR, 'agents')) || existsSync(resolve(TEMPLATES_DATA_DIR, 'core-instructions'))) {
    errors.push('冗余模板树仍存在：templates-data/agents 或 core-instructions 未删除');
  }
  if (errors.length) {
    console.error('  ✗ 单源一致性校验失败');
    for (const e of errors) console.error(`      ${e}`);
    process.exit(1);
  }
  console.log('  ✓ 单源一致性校验通过（三对对象键集与内容一致）');
}
```

> `extractAllAgentEntries(anchor)` 与 `assertInstructionsConsistent()` 完整实现已内联于上方代码块（REV-407 修订）：前者复用 `matchBraces`（L422）+ `matchBraceAt`（L669）+ `extractTemplatePairs`（L593）提取 `Record<lang, Record<agentId, content>>` 并 flatten 为 `Record<lang.agentId, content>`；后者复用 `extractBetweenAnchors`（L405）+ `matchBraces` + `extractOpencodeConfigLangEntries`（L968）逐语言解码 B64 比对。
