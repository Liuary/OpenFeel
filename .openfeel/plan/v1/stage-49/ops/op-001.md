## 必查项（六维度）

1. **正确性**：`advanceStagePhase` **全路径**（含 `pipeline.phase` 全量 done 判定、`targetPhase==='done'` 归档标记返回、`autoRepairInconsistency` 与组合条件 `|` 路径不互相干扰）；`plan/stage.ts` 的 deps 落点（`overview.md` + `flow.json.stages[].deps`）与 stageId 归一化；`plan/scheme.ts` 的 op 编号/兜底注册冲突检测；`archive/merge.ts` + `utils/kb-dedup.ts` 归档去重链路。
2. **一致性**：`validate`/`hasTransition`/`getValidTargets` 三者数据源一致（均取运行时 `pipelineConfig`）；`PIPELINE_PHASES`（`pipeline-schema.ts`）与 `flow phases`/`advance` 口径（stage-47 方案 B 后应显式差异而非静默不一致）。
3. **文档-实现对齐**：`flow-manager.ts` 注释声称的语义 vs 实际代码（如 `pipeline.phase` done 判定、`current` 不回退的既有裁定）。
4. **边界与健壮性**：存量数据缺 `meta`/`deps`/`stats`/`pipeline.current`；空 `stages`；`meta.revision` 缺失（乐观并发 `FlowConcurrentModificationError`）；`.bak`/checkpoint 生命周期（`CHECKPOINT_MAX_KEEP`、Windows rename 容错）。
5. **安全面**：任何以 `projectPath`/`stageId` 拼接的路径是否可越界（`resolve` 后是否校验落在 `.openfeel/` 内）；`rmSync`/删除类操作的边界；`execSync git` 的注入面（`autoCommitOnDone` 的 stageName 拼接）。
6. **过度设计**：`artifact-graph/**`（6 文件）是否有实际消费方（`rg` 引用面）；是否有无复用需求的抽象层/包装。
