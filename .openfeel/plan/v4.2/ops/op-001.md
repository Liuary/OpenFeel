# op-001：增强 kb/index.md 项目快速概览节

- **阶段**：v4.2-stage-01
- **前置**：无（可并行执行 op-002）
- **负责 Agent**：Executor
- **最多重试**：3

## 目标

在 `kb/index.md` 顶部新增"项目快速概览"节，并更新 Archiver prompt 使其在归档时自动维护该节内容。

## 背景

参考 `.openfeel/plan/v4.2/plan.md` 方案 A：在现有 `kb/index.md` 顶部增加一个项目快速概览表格（项目定位、模块职责、技术栈），通过 `check-kb` skill 加载时 Feel 可直接获取项目全貌，零新增文件。

## 实施步骤

- [ ] 1. 读取 `.openfeel/kb/index.md` 完整内容，理解当前结构
- [ ] 2. 在 `# 知识库索引` 标题行之后、"## 分类概览" 之前，插入"## 项目快速概览"节，内容如下：

```markdown
## 项目快速概览

| 维度 | 内容 |
|------|------|
| 定位 | AI Agent 开发流程治理 CLI 工具 |
| 语言 | TypeScript (Node.js ≥20) |
| 核心依赖 | Commander, Zod, YAML, fast-glob |
| 源文件 | 38 个 .ts 文件（src/） |
| Agent 数 | 8 个（feel/planner/schemer/executor/reviewer/tester/archiver/事务官） |
| 模块入口 | src/index.ts → src/cli/index.ts |
| 关键目录 | src/core/（流水线核心）、src/commands/（CLI 命令）、.opencode/agents/（Agent 定义） |
| 最近更新 | YYYY-MM-DD（归档时自动更新此字段） |
```

> 注："最近更新"日期使用实施当天日期（2026-07-08）；后续由 Archiver 在归档时更新此字段。

- [ ] 3. 读取 `.opencode/agents/archiver.md` 完整内容
- [ ] 4. 在 Archiver prompt 的「核心职责」节末尾（第 1 条之后）追加一条职责。定位到 `1. **操作记录归档**` 所在行，在其后（第 2 条之前）插入：

```markdown
1. **索引维护**：归档完成后检查 `.openfeel/kb/index.md`「项目快速概览」节，若以下任一条件满足则更新对应字段：
   - 源文件数（"源文件"行）：`glob src/**/*.ts` 数量与记录值不一致 → 更新
   - Agent 数（"Agent 数"行）：`glob .opencode/agents/*.md` 数量与记录值不一致 → 更新
   - 最近更新（"最近更新"行）：归档日期与记录值不一致 → 更新为当前日期
```

- [ ] 5. 在 Archiver prompt 的「归档流程」节中，在各步骤编号之间插入索引更新步骤。定位到 `### 步骤 1：提取知识条目` 之前，插入：

```markdown
### 步骤 0：更新项目快速概览
  归档开始前，读取 `.openfeel/kb/index.md` 的「项目快速概览」节，检查源文件数、Agent 数、最近更新日期是否与当前项目状态一致。不一致时更新对应字段。
  使用 `glob src/**/*.ts` 统计源文件数，使用 `glob .opencode/agents/*.md` 统计 Agent 数。
```

并将原有步骤重新编号：
- 原「步骤 1：提取知识条目」→「步骤 1」（不变）
- 原「步骤 4（NEW）：推进流水线状态」→ 保持原编号，但确保未因上述插入而冲突

> 注：Archiver prompt 中的步骤编号本身已不连续（步骤 1→4 + 2/3/4a/4b），仅需确保新增步骤不与其他步骤编号冲突。若步骤 0 已在 prompt 中存在，追加到步骤 1 之前即可。

- [ ] 6. 自测验证（见下方自测清单）
