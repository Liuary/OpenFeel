## 目标

- **目标**：让需求级计划与正文写入不再靠手建/多次调用——`req plan` 生成并校验四节计划骨架，`req body --from` 一次性导入整份正文，`lint fill --fix-plan` 批量补齐缺失计划骨架；并修掉 `--text` 多行截断（正文 A64.4），adapter 侧改走临时文件安全通道。
- **现状证据**：`src/commands/req.ts` 有 18 个子命令（`add :193` … `body :1595`），**没有 `plan`**；`req body` 只有 `--text`/`--file`（`:1598-1599`），一个需求要 4 次调用（6 需求 24 次，REQ-064 摘要）；`lint fill`（`src/commands/lint.ts:179`）只列清单、无修复动作；需求级计划现状是 **planner 手写**（`.openfeel/plan/reqs/` 现有 REQ-055~060 六份手写文件）。
- **A64.4 的两处已知裁剪点**：引擎侧 `const body = raw.trim()`（`src/core/req/body-file.ts:250`）会裁掉首尾空行/缩进；adapter 侧 `optionalArg`（`dsh/lib/tools/shared.js:304`）同样 `.trim()`，且 `feel_req` 的 body 分支把整段正文塞进 argv（`dsh/lib/tools/index.js:1178` 的 `pushOption(argv,'--text',text)`）——多行文本走命令行参数是截断/转义风险面。
- **边界**：写实判据只认 `src/core/plan/filled.ts` 的 `isRequirementPlanFilled`（禁第二份四节/字数规则）；`lint fill` 的 advisory 退出码语义不变（恒 exit 0）；`release`/CLI 出口编号口径见阶段计划 §1.2（`req plan` = #50）。

- **A64.1**：`path` 恒为 `.openfeel/plan/reqs/REQ-NNN.plan.md`（POSIX 相对路径，不随阶段/版本漂移）；生成内容含四节且 `isRequirementPlanFilled(content) === true`（复用 `filled.ts`，单测直调）；已存在 → exit 1、文案含 `--force`、**字节级零写盘**；`--force` → exit 0 且 `replaced:true`。
- **A64.2**：一次调用写多小节（`sections` 长度 ≥2、`calls:1`）；`## 状态`/`## 预估版本`/`## 父需求`/`## 变更记录` 等元信息小节**不被覆盖**（`PROTECTED_BODY_SECTIONS` 拒写或跳过并报告）；每个写入小节在 `## 变更记录` 各追加 1 条；`--from missing.md` → exit 1 且零写盘。
- **A64.3**：`--fix-plan` 只为「计划文件不存在」的需求建骨架；已有计划（含空壳）进 `skipped[]`、字节不变；`--json` 含 `created[]`/`skipped[]`；重复执行 → `created[]` 为空（幂等）；`lint fill` **仍恒 exit 0**（`C16` 逐字保留）。
- **A64.4**：写入文件字节与输入**逐字相等**（含空行、`###` 子标题、行首 `- `/`1. `、`---`）；CRLF 输入不被归一；`lines` 与 `body.split(/\r?\n/).length` 一致；`--text` 全空白 → `empty_text` exit 1 零写盘；adapter 侧 `grep -n "pushOption(argv, '--text'" dsh/lib/tools/index.js` **零命中**（正文改走 `--file`），临时文件不残留。
- **A64.5**：三命令各有单测（幂等 / 保护小节 / 缺文件），`npx vitest run` 三文件全绿；既有 `req body`/`req add`/`lint` 用例零失败。

## 风险

- **两套判据**：`plan-skeleton.ts` 若自带一套「四节是否齐全/字数够不够」判定，会与计划门分叉。规避——只 import `isRequirementPlanFilled`；reviewer 用 `grep -rn "isRequirementPlanFilled" src/` 断言命中 ≤2 处。
- **覆盖已写实计划**：`--force` 会冲掉 planner 手写内容。规避——缺省拒绝且**零写盘**（字节级），文案给出两条出路（改名/`--force`）；单测断言拒绝路径 `flow.json` revision 不变。
- **`--from` 与 `--text/--file` 的互斥面扩大**：参数三选一易漏。规避——沿用既有 argument-shape 守卫（`req.ts:1631-1651`）风格，新增 `--from` 与其余两者互斥的同类校验。
- **`--fix-plan` 变成批量覆盖**：可能把「已存在但空壳」的计划当缺失重建。规避——`--fix-plan` 只处理 `missingPlan`（文件不存在），空壳走 `--force` 单独通道；`fixed[]`/`created[]` 只含新建 id。
- **`--text` 修复变静默降级**（2026-11-24 新增，REV-P01）：修完仍把多行塞进 argv，或用例只做「包含」断言。规避——用例做**字节级相等**；adapter 侧 `finally` 清理临时文件；reviewer `grep` 断言 `--text` 在 adapter 侧零命中；`--file` 与 `--text` 互斥校验保留。
