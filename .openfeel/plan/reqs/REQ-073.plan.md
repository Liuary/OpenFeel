# REQ-073 计划：通用 config unset（补齐配置删除入口 + feel_verify）

> 依据：`.openfeel/plan/v1/stage-138/plan.md` §一（**A73.1—A73.7**）与 §二 **R1**（文档面归 R3、版本归 R4）；本文件只做需求级拆解，**不改判据含义、不新增需求外任务**。边界：不做 models 专用迁移（通用删除入口）；不改 guard 规则；不改 config「人类可手改」表述（A73.7）。

## 目标

- **做什么**：新增通用的 `openfeel config unset <key>`：支持 `defaults.X`（X 为单段键名，**不限 schema** —— `test_enabled` 这类退役键也要能删）与顶层段（如 `models`、`meta`、passthrough 键），走同一 YAML Document 路径（`hasIn` → `deleteIn` → `atomicWriteFileSync`），保留注释与其它键序；键不存在 exit 1；`--json` 输出 `{schemaVersion,key,removed,path}`（不存在时 `removed=false` + `reason`）。DSH 侧暴露 `feel_verify action=config_unset`（参数 key，走同一 CLI，工具数仍 15）。当前仓库 `models:` 段作为首个真实清理样本。
- **为什么**：`config set` 能写但**没有任何删除入口** —— `.openfeel/config.yaml` 又是 guard 保护路径（`dsh/lib/guard.js:773`），agent 的 write/edit 直写被拒，退役键（旧项目 `models:` 段）只能让人类手改。这是 CLI 对称性缺口，不是 models 专用问题。
- **事实与契约**：`setConfigValue`（`src/core/config.ts:664-690`）是写盘单点范式；`ConfigSchema` 三层全 `optional`(:112-116，删空不破 schema)、`resolveConfigDefaults`(:223+) 逐键回退 `DEFAULT_CONFIG`；`config set` 无 `--json`（`docs/commands.md:973`）—— unset **故意例外**，因为需要 `removed` 机读位；`--json` 是进程级预扫描（`src/commands/shared/json-output.ts:119-173`），子命令必须显式 `.option('--json')`。工具面 `dsh/test/contract.js:127` 固定 15 个工具、`:447-454` 只断言 action 枚举包含项 → **只扩 action**。**生效时机**：`dsh/lib/tools/index.js` 由宿主启动加载，`config_unset` 在当前会话要重启后才可用；验收以新进程测试（`dsh/test/verify.js`）为准。

## 风险

- **删配置打穿 schema / 删错段**：`ConfigSchema` 三层全 optional + 删后 `safeParse` 复验 + 只删 `doc.hasIn` 命中路径；`test_enabled`（`.openfeel/config.yaml:26`，非 schema 的 passthrough 键）不得被误伤（用例覆盖）；仓库样本删前 `git status` 干净，异常可 `git checkout -- .openfeel/config.yaml` 回退。
- **`--json` 退出码与管道**：不存在时只能置 `process.exitCode=1` 后 return（`process.exit` 会在 Windows 管道截断 stdout，参照 `failCli` 口径）；JSON 与人类两路文案都要有，且人类路径逐字可断言。
- **工具面误伤**：只扩 `action` 枚举、**不新增工具**（15 个不动）、不动 `config_get/config_set/config_effective` 的 argv 组装；工具改动当前会话不生效（宿主 `loaded_hash`），验收走 `dsh/test/verify.js` 新进程。
