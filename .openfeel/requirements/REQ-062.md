# REQ-062：文档类变更写白名单 + 统一 GateOverride 审计

> 本文件为需求正文（人读副本，由 openfeel req 机械铺骨架）。**机读权威恒为 `.openfeel/flow.json` 的 `requirements` 条目**；两者不一致时以 flow.json 为准。下方状态为创建时快照，不追写实时状态。

## 状态

draft（创建时快照；以 flow.json 为准）

## 摘要

v1.6.0 执行期为修文档被迫两次 `review_passed → exec_running --force`：guard 只在 exec_running 放行源码/文档写入，而文档修正恰恰发生在 review 之后。同时 `--force` 有两套语义（`allowGateOverride` 留痕放行 vs `force` 跳相位），`flow stage reset --to <后置相> --force` 仍是无审计路径，审计字段不统一。

## 目标与验收

### 目标

把「只改文档/注释/测试夹具」定义为可在 `review_passed`/`test_passed` 写入的变更类型，避免为了改一句文档被迫 force 回退 `exec_running`；并把 `--force`/`allowGateOverride`/`reset --force` 收敛为同一个 GateOverride 审计 schema。

### 验收

- A62.1 `review_passed` 相位下允许写 `docs/**`、根 `*.md`（README/CHANGELOG 等）与 `test/**` 夹具；写 `src/**` 仍被 guard 拒绝（两态用例）。
- A62.2 `flow advance --force`、`flow stage reset --force` 与各门 `allowGateOverride` 统一写 `flow.json.log`：`gate_overrides[]` + `reason` + `by` + `from/to`。
- A62.3 `flow stage reset --to <后置相> --force` 不再是无审计路径（构造用例断言 log 有 override 条目）。
- A62.4 `GateOverride` 有类型定义与单测；既有 done 门 / blocking REV 判据不变。
