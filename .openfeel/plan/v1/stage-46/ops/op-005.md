## 精确改动点（测试文件与断言点）

### ① NEW `test/core/backup.test.ts`

隔离：`vi.mock('node:os', homedir→tmpHome)`；`beforeEach` `resetBackupSetCache()`。

| 断言 | 期望 |
|------|------|
| 目标不存在 | `backupFileBeforeWrite` 返回 `null`；不创建 `backup/` 下目录 |
| 目标存在（全局） | 返回 `{backupRel, ts}`；`backupRel` 以 `global/` 开头；备份文件内容 == 源；`manifest.json` 含 `source → {backupRel, hash, command, time}` |
| 目标存在（项目） | `backupRel` 以 `project/<basename>-<hash8>/` 开头 |
| ts 复用 | 同进程连续两次 → 同 `ts`；`resetBackupSetCache()` 后 → 新 `ts` |
| 撞名 | 预置同 `ts` 目录（无法直接控时间 → 断言 `while` 逻辑：两次不同 `reset` + 毫秒不同 → 不同目录）；以「已存在同名目录则 `-2`」的单测（可用 mock `Date` 或直接断言目录唯一性） |
| 绝不覆盖 | 预置目标备份文件内容 → 再次备份不修改既有文件（不同 `ts` 目录） |
| 备份失败 | 目标为不可读/注入 `atomicWriteFileSync` 抛错 → 抛 `BackupError`，`err.filePath` 为源路径 |
| 并发（REV-005） | 两进程（`spawnSync` 子进程脚本，参照 `test/core/fs/file-lock.test.ts:109` 模式）同时备份同一源 → 各自独立 `{ts}` 目录，两份 manifest 均完整，无覆盖 |
