## 目标

- **做什么**：删掉 v1.6.3 遗留的三项小债——① i18n 的 `model.get.inconsistent` / `model.get.shadowed` 死文案、`src/commands/model.ts` 三段不可达分支（`:76-78` / `:85-87` / `:88-92`），并同步 `dsh/docs/compat/commands.md:304` 的过期表述（「never fires / retained but unreachable」→「两分支已在 v1.6.4 删除，`inconsistent`/`byScope` 字段保留以稳定 JSON」）；② `dsh/ADAPTER.md:291-302`「验证」段的 v1.6.0 计数快照（四套，53/129/180/10）更新为实测 **五套**（contract 54 / verify 136 / guard 193 / preflight 10 / integration 跳过）+ `2026-11-26` 快照；同源旧值 `dsh/README.md:306/:310-313/:319`、`dsh/ACTION-GUIDE.md:79`（现行半句）同批修正；③ 文档补「旧项目 `.openfeel/config.yaml` 的 `models:` 段可整段删、不生效、受 guard 保护只能人工改、删后重启会话」迁移提示。
- **为什么**：模型两层化后 `inconsistent` 恒 `false`、`byScope.default` 恒 `null`，旧文案（「以 frontmatter 为准」「用 --scope default」）会误导恢复 default 层；ADAPTER 计数停在 1.6.0（且 README/ACTION-GUIDE 仍是更旧的 53/129/180/191）会让读者误判验证规模；1.6.2 起 `init` 不再生成 `models:` 段，但存量项目的旧段既无生效语义也无清理指引。
- **契约底线（A71.2 的真实形状）**：`model get --json` 键序 `schemaVersion,scope,agent,provider,model,source`（`json-contract.test.ts:1098-1128` 锁定）与 `model list --json` 键序 `schemaVersion,scope,agents`（条目 `agent,provider,model,source`）不变；`get --scope default --json` 仍 `model:null,source:null`,exit 0；内部 `GetModelResult` 的 `byScope.default`（恒 `null`）与 `inconsistent`（恒 `false`）字段保留（`model-config.test.ts:101-113` / `:157-167` 锁定）。本需求只删 CLI 打印分支，不删字段。**范围外（登记不改）**：`toJsonModel` 的 default 兜底判定、`src/core/config.ts` 的 ModelsSchema / 只读兼容、`docs/commands.md:1122`「人类输出不变」、根 `README×2`；**范围内**：`dsh/docs/compat/commands.md:304` 一行（T1）与三文件同源计数（T2）。
