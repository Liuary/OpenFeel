## 目标

把 OpenFeel 从「一切皆流水线」改造为「**以需求为核心、非流水线优先、Agent 自治调度**」：以需求发布/接取为主工作模式、流水线与版本解绑（仅发布时推进版本号）；执行者/探索者作为通用工作者可被任意 Agent 按需调度；鼓励拆分需求并行执行；并据此提速、瘦身提示词、简化通用任务、新增三模式。

1. **需求接取制度（主题一）**：feel 发布需求 → Agent 接取（认领）→ 完成即通知 feel 发布下一步；**拆分＝一等动作**（并行接取缩短端到端）；流水线与版本解绑（版本号仅在发布时推进）。**机制层由常驻 feel 中介**（只有 feel 常驻）。
2. **通用工作者直接调度（主题二）**：执行者/探索者可被**任意 agent 直接调度**（**直接派发，不经 feel 转介**——与需求接取制度是**两套**机制）。落地双口径：opencode 嵌套 task（隔离实测 go/no-go）/ Claude 侧 Handoff 直发（平台不支持嵌套 Task）；规则放宽「subagent 不调用 Task」。
3. **探索者与执行者（主题三）**：新增 `openfeel-explorer`（**只读**：Bash/Read/Glob/Grep）替代对内置 Explore/general 的依赖；执行者（读写）承接任意 agent 的活；**先探后执行**；路由表更新。
4. **提示词瘦身（主题四）**：现代模型能力强 → 提示词不写繁琐内容；**必要的操作流程一律转 skill**；agent 提示词**只列 skill 索引**（名称 + 一行用途）；CLI 可校验的约束移出提示词；引入上下文治理策略（compact / 工具结果 / 按需加载）。验收方向值：feel.md ≤ 现状 50%（31036B → ≤15.5KB）。
5. **三模式架构（主题五）**：规划 / 快速 / 通用；**需求规模驱动**（有一定规模默认快速；用户要求或设置 → 完整/规划）；`general → fast/full` 可升级、不自动降级；**需求级模式属性**（流水线模式是需求级属性）+ 模式解析单点（含 supersede「需求层正交边界」）。
6. **可观测性改造（主题六）**：接线 `recordRun`（现死代码）；CLI 日志补 `duration_ms`/`project`/`session_id`（+ done 行必写加固）；op 级 phase 埋点；活跃/闲置语义显式标注（替代 >20min 启发式）。
7. **并行提速（主题七）**：审查关合并/抽样（免审/快线/全量三档）；并行化独立子任务（拆分需求并行执行）；减少人工等待；归档轻量化（机械步骤下沉）；会话卫生核验。

## 关键裁定

| 议题 | 裁定 |
|------|------|
| **执行顺序** | **86→87→88→89→90→91→92→93 严格串行**（可观测性前置 → 需求接取 → 调度机制 → 通用工作者 → 三模式 → 提示词瘦身〔收编〕→ 提速 → 收官） |
| 本仓自举 | v1.2.1 八阶段以 **full** 运行（架构级变更需完整审计链） |
| 模式值域 | `WORKFLOW_MODES` 扩展 **3 值 `full / fast / general`**（保留既有字面量零回归）；展示命名 规划 / 快速 / 通用 |
| 需求级模式 | `RequirementData.workflow_mode?` 可选；解析链 `status.md 显式 > 需求级 > config > profile > builtin`；**supersede**「需求层正交边界」（6 禁止串断言显式改写，禁删除） |
| 默认与流转 | 需求默认走快速；用户要求/设置 → full；`general → fast/full` 可升级，**不自动降级** |
| 拆分模型 | 拆分＝一等动作（`req split` + `parent_id?` 可选）；**不做**需求树状态聚合（父子仅溯源） |
| 接取制（机制层） | feel 发布 → 各 Agent 认领（占用校验在位）→ 完成 Handoff 通知 feel → 发布下一步；并行接取＝独立子需求并行 claim；常驻 feel 中介 |
| 调度机制（双口径） | opencode = 直接嵌套 task（先隔离实测）；Claude = Handoff 直发 + feel 即到即派；**降级红线**：实测不可行则两 harness 统一 Handoff 并留痕 |
| 探索者 | 只读 4 工具（`Bash/Read/Glob/Grep`，不加 Skill）；opencode permission 对标 reviewer 只读块 |
| 瘦身口径 | agent 提示词＝「skill 索引壳 + 最小约束」；**单写者纪律**（88~90 最小落文，91 统一收编）；验收方向值 feel.md ≤ 50% |
| 审查档位 | 三档「免审 / 快线 / 全量」按模式与规模；转移表层实现；不破坏 blocking REV 门 / 审计 / `--dry-run` |
| 并行 | 仅限独立子任务（无依赖）；组合转移 `\|` 复用（v0.5.3 既有） |
| 版本解绑 | 需求不绑版本；版本号仅发布时推进；`requirements` **维持不归档**（v1.2.0 裁定 W） |
| 可观测性 | 不建 dashboard / 不改 phase 枚举；埋点字段可选 + 读侧宽容（存量零注入） |
| 不做 | 需求树聚合 / requirements 随版本归档 / TTL 抢占 / 改 phase 枚举 / 第三方依赖 / dashboard / Claude 嵌套 Task 强求 / 会话卫生虚构实现 |

## 发布

- **不代 push / 不 `npm publish`**：推送与发布由 Feel/用户执行（与 v1.1.x / v1.2.0 口径一致）。
- v1.2.1 为**功能主题版（Z 级）**：命令面增量（`req split` + `req/--workflow-mode`）；Agent 体系结构变更（新增 `openfeel-explorer`，agent 9→10）；流水线语义增量（三模式 / 审查档位）；可观测性字段增量。需同步 `openfeel-cli-usage` skill 与 docs/manual/README。
- **不新增第三方依赖**；CI 无改动；**既有 full/fast 行为零回归**（字面量保留、转移表仅有意变更且登记）；埋点字段一律可选 + 读侧宽容（存量 flow.json 零注入）。
- 向后兼容承诺：既有命令**零报错**；`requirements` 归档口径不变；supersede 仅涉及 `src/core/req/**` 与 workflow_mode 的断言改写（kb supersede 记录）。
