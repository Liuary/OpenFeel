# v1.6.4 发布说明

- **来源阶段**：v1.6.4-stage-137
- **需求**：REQ-071

## 变更摘要

- **model 死文案 / 死分支清理（A71.1）**：`src/core/i18n-data/{zh-CN,en}.ts` 删除 `model.get.inconsistent` / `model.get.shadowed`（中英各 2 行）；`src/commands/model.ts` 删除三段不可达分支（`scope=default` 的 inconsistent、未指定 scope 的 inconsistent、shadowed）；`dsh/docs/compat/commands.md` 的 `model` 小节改为「两分支已在 v1.6.4 删除（`inconsistent` / `byScope` 字段保留以稳定 JSON）」。
- **JSON 契约不变（A71.2）**：`GetModelResult` 的 `inconsistent`（恒 `false`）与 `byScope.default`（恒 `null`）字段保留；`model get --json` 六键序、`model list --json` 顶层/条目键序、`get --scope default --json` 的 `model:null,source:null`（exit 0）均不变。
- **验证计数刷新（A71.3）**：`dsh/ADAPTER.md` 验证段改五套（contract 54 / verify 136 / guard 193 / preflight 10 / integration 跳过，2026-11-26 实测）；`dsh/README.md` 与 `dsh/ACTION-GUIDE.md` 的同源旧值（53/129/180/191/四套）同步修正。
- **旧项目 config 迁移提示（A71.4）**：`docs/GETTING_STARTED.md` 新增说明——旧项目 `.openfeel/config.yaml` 的 `models:` 段不生效，可整段手动删除（受 guard 保护、agent 不可写），删除后重启会话；`openfeel init` 新项目已无该段。
- **版本**：两包 lockstep 1.6.4、`openfeel.requiresCli >=1.6.4`；`dsh/ADAPTER.md` 新增 `## v1.6.4` 小节。

## 语义

本版**零命令行为变更**：不删 JSON 键、不改生效链、不动 guard 与 flow 状态机；只清理不可达代码 / 文案、刷新文档计数与补迁移提示。

## 升级与验证

- **升级**：`npm i -g openfeel@v1.6.4`（本地开发：`npm run build` 后用 `node bin/openfeel.js`）
- **验证**：`npx tsc --noEmit` → `npm test` → `npm run build`（两遍幂等）→ `cd dsh && node test/contract.js && node test/verify.js && node test/guard.js && node test/preflight.js && node test/integration.js` → `node bin/openfeel.js lint i18n` → `node scripts/release.mjs --dry-run --skip-build`

## 发布流程

- 发布走 CI 自动发布（唯一标准路径）：push 到 master 且 `package.json` 版本与 npm 已发版本不同 → CI 的 publish job 自动 `npm publish`（`openfeel` + `openfeel-dsh`）；不需要手动 `npm publish`，也不必打 tag。
- 版本号 lockstep：`package.json` / `dsh/package.json` = 1.6.4、`openfeel.requiresCli` = `>=1.6.4`。
