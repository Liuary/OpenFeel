# op-002：CLI config --global 标志
- **阶段**：v5.0
- **前置**：op-001（依赖 readProfile / writeProfile 方法）
- **负责 Agent**：Executor
- **最多重试**：3

## 目标

为现有 `config get/set` 子命令添加 `--global` 选项，支持对 `~/.config/openfeel/profile.yaml` 的读写操作。

## 背景

v4.6-stage-02 实现了项目级 `config get <key>` / `config set <key> <value>` 命令，操作 `.openfeel/config.yaml` 的 `defaults` 块。v5.0 需要扩展为同时支持全局 profile 操作。参见 kb/patterns.md #CLI 原子管理模式、kb/patterns.md #i18n 域扩展与 config 命令组模式。

## 实施步骤

### 步骤 1：添加 --global 选项到 get/set 子命令

- [ ] 1.1 为 `config get <key>` 添加 `.option('-g, --global', '操作全局 profile（~/.config/openfeel/profile.yaml）')`
- [ ] 1.2 为 `config set <key> <value>` 添加相同 `.option('-g, --global', ...)`
- [ ] 1.3 在 action 回调中通过 `this.opts().global` 判断是否全局模式

### 步骤 2：实现 `config get --global` 逻辑

- [ ] 2.1 `config get --global`（无 key）：从 `readProfile()` 读取完整 Profile，以可读格式输出（YAML 或结构化 key=value 列表）
- [ ] 2.2 `config get --global <key>`（有 key）：支持**点分隔嵌套键**（如 `user.name`、`user.lang`、`preferences.auto_advance`、`preferences.review_mode` 等），从 Profile 对象中深层取值并输出
- [ ] 2.3 嵌套取值实现：实现 `getNestedValue(obj, 'user.name')` 辅助函数，按 `.` 分割路径逐层查找。路径不存在时输出友好提示（如 `"user.name：未设置"`）
- [ ] 2.4 保留 `config get <key>`（无 `--global`）的现有行为——操作项目级 config.yaml 的 `defaults` 块

### 步骤 3：实现 `config set --global` 逻辑

- [ ] 3.1 定义全局 key **白名单**（与项目级不同，全局支持更丰富的 key）：
  - `user.name`（string）
  - `user.lang`（`zh-CN` | `en`）
  - `preferences.auto_advance`（`enabled` | `disabled`）
  - `preferences.review_mode`（`full` | `skip_small_changes`）
  - `preferences.communication`（`concise` | `detailed`）
  - `preferences.confirm_threshold`（`low` | `medium` | `high`）
- [ ] 3.2 白名单校验：非白名单 key 时输出错误信息（列出支持的 key）并 `process.exit(1)`
- [ ] 3.3 value 校验：按各 key 的合法值集合校验（如 `user.lang` 仅接受 `zh-CN`/`en`），非法值输出友好提示
- [ ] 3.4 实现 `setNestedValue(obj, 'user.lang', 'en')` 辅助函数：按 `.` 分割路径，逐层创建中间对象，设置末层值
- [ ] 3.5 写入流程：`readProfile()` → `setNestedValue` 修改 → 用 Zod ProfileSchema 全量校验 → `writeProfile()` 写回
- [ ] 3.6 设置成功后输出确认信息（含 key 和实际写入的值）
- [ ] 3.7 保留 `config set <key> <value>`（无 `--global`）的现有行为——操作项目级 config.yaml

### 步骤 4：i18n 文本补充

- [ ] 4.1 在 `src/core/i18n-data/zh-CN.ts` 和 `en.ts` 的 `config` 域中新增以下键（双语言对称）：
  - `config.get.globalProfileNotFound` / `config.get.globalKeyNotFound` / `config.get.globalResult`
  - `config.set.globalInvalidKey` / `config.set.globalInvalidValue` / `config.set.globalValueOk`
  - `config.set.globalAllowedKeys`（动态模板，含 `{keys}` 变量）
- [ ] 4.2 在 `regenerateI18nTypes()` 中确认新键被识别

## 困难点

| 困难点 | 方案 | 优劣分析 |
|--------|------|----------|
| Commander `this.opts()` 在 action 中使用箭头函数时 `this` 丢失 | **方案 A**：将 action 从箭头函数改为 `function()` 声明 | 优：Commander 原生支持，代码改动小；劣：需修改现有 action 风格（当前为箭头函数） |
| | **方案 B**：使用 `.hook('preAction')` 中获取 opts | 优：不改动箭头函数风格；劣：opts 传递链路复杂 |
| | **选 A**。箭头函数改 function 声明是最小改动，且 Commander 官方推荐此模式访问 opts |
