# op-003：实现 git commit 自动提交机制
- **阶段**：v4.4-stage-02
- **前置**：op-001（soft）、op-002（soft，共享 flow.ts 文件）
- **负责 Agent**：Executor
- **最多重试**：3
- **参考**：kb/patterns.md #CLI 原子管理模式、kb/architecture.md #多语言模板数据管线（模板同步策略）、kb/patterns.md #构建脚本多语言循环生成模式（中英文模板对称原则）

## 目标

通过双重保障实现 Executor 完成后自动提交：Agent prompt 强化（主，在 executor.md 中强制要求 `git add -A && git commit`）+ 流水线安全网钩子（辅，在 `flow advance` 命令中检查 git 脏区并警告）。

## 设计决策

> **git commit 优先级：Agent 自律 > 流水线强制**（参见 plan.md 关键设计决策）。主要依赖 executor.md prompt 强化。流水线钩子 (`git status --porcelain`) 仅作为安全网警告，不自动提交（避免误提交敏感文件）。

  ```typescript
  // git 脏区检查（安全网）：Executor 未提交时输出醒目警告
  try {
    const { execSync } = await import('node:child_process');
    const gitStatus = execSync('git status --porcelain', {
      cwd: process.cwd(),
      encoding: 'utf-8',
      timeout: 5000,
    }).trim();
    if (gitStatus) {
      console.warn('[!] ╔════════════════════════════════════════╗');
      console.warn('[!] ║  ⚠ Git 脏区警告：存在未提交的变更     ║');
      console.warn('[!] ║  请确认 Executor 已完成 git commit    ║');
      console.warn('[!] ╚════════════════════════════════════════╝');
    }
  } catch {
    // git 不可用（无 .git 目录或 git 未安装）时静默跳过
  }
  ```

## 困难点

1. **flow advance 中的 async/await 问题**：现有 action 函数不是 async 的（`.action((options) => {...})`）。若需要 `await import('node:child_process')`，有两个方案：
   - **方案 A（推荐）**：使用同步 `execSync`，通过顶层 `import { execSync } from 'node:child_process'` 导入。优点：无需改为 async；缺点：少量阻塞（可接受，git status 通常 <100ms）。
   - **方案 B**：将 action 改为 async。需检查 Commander 对 async action 的兼容性（Commander 12+ 默认支持）。
   - **选定方案 A**：顶层同步 import，代码更简洁。

2. **构建后模板更新**：executor.md 修改后需运行 `npm run build` 将 .md 文件重新内联到 `template-loader.ts` 的 `AGENT_TEMPLATES` 常量中，确保 `openfeel update` 时部署最新模板。
