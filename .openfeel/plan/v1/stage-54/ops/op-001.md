## 一、变更目标

修 `cli/BUG-005`：空模板检测当前用**纯子串** `content.includes('- [ ] 待补充')` → **正文行内引用该字面**（如文档里写「仍含 `- [ ] 待补充`」）也会被判 `empty` → 触发 **`publish` 误拒 + `health`/`ops list` 误报**。改为**整行锚定**判定（容错缩进 / CRLF / 行尾空白），并让 `publishScheme` 复用同一判定（保住「单一来源」）；同时按 **A9** 将 E1-补 的 `null → filled` 语义**登记为已知边界**（**不改 `detectFillState` 契约 / `--json` 契约**）+ 注释 + manual + 断言。

**实测复现（本阶段）**：`flow health` → `⚠️ 空模板: 1 个操作方案模板未填充：v1.1.2-stage-52.op-005`（该 op 已 `done`、文件完整）；`flow ops list` → `v1.1.2-stage-52.op-005 [done] (empty)` + warning —— 均为**误报**（op-005.md 含 9 处「待补充」，其中多为**行内引用**）。

## 二、E1 子项清单

### E1-① `isTemplateEmpty` 改整行锚定（根因）

- **文件:行号**：`src/core/flow-manager.ts:3751`（`EMPTY_TEMPLATE_MARKER`）、`:3753-3756`（`isTemplateEmpty`）、`:3747-3750`（注释「单一来源」）
- **现状**：
  ```ts
  export const EMPTY_TEMPLATE_MARKER = '- [ ] 待补充';
  /** 模板是否仍含空模板标记（未填充） */
  export function isTemplateEmpty(content: string): boolean {
    return content.includes(EMPTY_TEMPLATE_MARKER);      // ← 纯子串（根因）
  }
  ```
- **改后**：
  ```ts
  export const EMPTY_TEMPLATE_MARKER = '- [ ] 待补充';

  /**
   * 空模板标记的**整行锚定**正则（单一来源）：
   * 行首可含缩进（[ \t]*）、`-` 与 `[ ]` 之间允许空白、行尾允许空白并容忍 CRLF；
   * 仅当标记**独占一行**（含缩进）时判为未填充——避免正文**行内引用**该字面导致误报（BUG-005）。
   * **已知边界**：代码围栏（```）内的独占行仍判为 empty（不引入围栏解析，见 stage-54 A1）。
   */
  const EMPTY_TEMPLATE_LINE_RE = /(?:^|\n)[ \t]*-\s*\[\s*\]\s*待补充[ \t]*(?=\r?\n|$)/;

  /** 模板是否仍含空模板标记（未填充；**整行锚定**，非子串） */
  export function isTemplateEmpty(content: string): boolean {
    return EMPTY_TEMPLATE_LINE_RE.test(content);
  }
  ```
- **注释同步**（`:3747-3750`）：补「**整行锚定**」语义与「代码围栏内独占行 = 已知边界」说明，并指向 `cli/BUG-005` 与 stage-54 E1。
- **预验证（本官实测，可复跑）**：
  | 输入 | 旧子串 | 新整行锚定 |
  |------|:--:|:--:|
  | `v1.1.2-stage-52/ops/op-005.md`（含 9 处行内引用） | `true`（**误报**） | **`false`** ✅ |
  | 模板独占行 `- [ ] 待补充\n` | `true` | **`true`** ✅ |
  | 模板 CRLF `- [ ] 待补充\r\n` | `true` | **`true`** ✅（CRLF 容错） |
  | 行内引用 `` 引用：仍含 `- [ ] 待补充`； `` | `true` | **`false`** ✅ |
  | 缩进独占行 `  - [ ] 待补充  \n` | `true` | **`true`** ✅ |
  > 复跑命令：`node -e "const fs=require('fs');const re=/(?:^|\n)[ \t]*-\s*\[\s*\]\s*待补充[ \t]*(?=\r?\n|$)/;const c=fs.readFileSync('.openfeel/plan/v1/stage-52/ops/op-005.md','utf8');console.log(re.test(c), c.includes('- [ ] 待补充'))"` → 期望 `false true`。

### E1-② `detectFillState` 复核（`empty` 自动复用；`partial` 是否收紧）

- **文件:行号**：`src/core/flow-manager.ts:3758-3772`（`detectFillState`）
- **现状**：`empty` 分支调 `isTemplateEmpty`（自动受益）；`partial` 用 `/(?:^|\n)\s*-\s*\[ \]/`（**已整行锚定**，但行首为 `\s*`，会把**行内引用**行（未在行首）排除；需复核缩进/CRLF 行为）。
- **改后（复核裁定）**：
  1. `empty` 分支**不改**（复用 `isTemplateEmpty` → 自动整行锚定）；
  2. `partial` 分支**统一为同一锚定口径**（避免 `empty`/`partial` 两套语义）：`/(?:^|\n)[ \t]*-\s*\[\s*\]/`（行首仅允许空格/Tab，**不含 `\r`**，避免把 CRLF 的 `\r` 吞进行首判定）；
  3. 若复核发现 `partial` 收紧会改变既有语义边界（如「行首无缩进的裸 `- [ ]`」），以 **测试为准** 并在方案修正记录中留痕——**不得**为此改变 `fill` 返回域（仍为 `'empty'|'partial'|'filled'`）。
- **验收**：行内引用（非行首）→ 不进 `partial`；行首 `- [ ]`（任意缩进）→ `partial`。

### E1-③ `publishScheme` 复用 `isTemplateEmpty`（消除重复子串判断）

- **文件:行号**：`src/core/plan/scheme.ts:8`（import）、`:449-457`（空模板校验）
- **现状**：
  ```ts
  import { FlowManager, isFlowConcurrentError, EMPTY_TEMPLATE_MARKER, … } from '../flow-manager.js';   // :8
  …
  if (content.includes(EMPTY_TEMPLATE_MARKER)) {          // ← :455 第二处子串判断
    return { published: false, reason: 'empty-template' };
  }
  ```
- **改后**：
  ```ts
  import { FlowManager, isFlowConcurrentError, isTemplateEmpty, EMPTY_TEMPLATE_MARKER, … } from '../flow-manager.js';  // 新增 isTemplateEmpty
  …
  if (isTemplateEmpty(content)) {                          // 复用单一来源
    return { published: false, reason: 'empty-template' };
  }
  ```
  - `EMPTY_TEMPLATE_MARKER` **仍保留**（`:46/:52` 模板骨架生成需要）→ **不得**删除该 import。
  - 返回契约不变（`{ published: false, reason: 'empty-template' }`）。

### E1-④ 注释 + manual 登记（E1-补 / A9）

- **文件:行号**：`src/commands/flow.ts:935-937`（`ops list` 的 `null → filled` 兜底）
- **现状**：`// 填充度：复用 flow-manager 的单一标记判定；无文件视为 filled（无法检测）` + `const fill = content === null ? 'filled' : detectFillState(content);`
- **改后**：注释补「**已知边界（stage-54 E1-补 / A9）**：`null`（op 文件缺失 / 命名不含前缀 / 目录不可读）视为 `filled` —— 与 `health` 的「null 跳过不报」为**同向漏检**（非分叉）；现行数据短名命中故不可复现；**不扩展** `detectFillState` 返回域与 `--json` 契约」。
- **manual 登记**：`.openfeel/manual/cli/commands.md` 的 `ops list` 节补一行边界说明（**正文归归档官**；本 op 提供要点并在 op-003 登记文档同步清单）。
- **不改**：`detectFillState` 签名/返回域、`--json` 的 `fill` 字段取值集合。
