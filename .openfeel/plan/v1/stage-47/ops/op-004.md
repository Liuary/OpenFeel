- **阶段**：v1.1.2-stage-47

## 变更目标

修 `REV-v1.1.2-stage-41 REV-009`（`--purge` 先于 `save()` 的中间态：目录已删但注册未落盘）与 `REV-v1.1.2-stage-46 REV-011`（jsonc 直写备份失败 fail-fast 与 B3 不一致）。

**需求映射**：plan §二 第 8/9 项裁定；kb/patterns.md #原子写模式 / #建议性文件锁模式 / #回滚边界模式。

## 关键裁定

1. **REV-009 事务顺序（写死）**：`removeStage` **不再执行目录删除**，改为**返回** `purgeTarget?: string`；命令层顺序 = `removeStage(...)` → `save()` 成功 → `rmSync(purgeTarget)`。消除「save 失败但目录已删」的中间态。
2. **REV-011 混合裁定**：`setup`/`update` → **A**（补 `try/catch` → `anomaly(backup_failed)` + 跳过 jsonc 写 + 继续，对齐 B3 幂等语义）；`migrate` → **B**（**保留 fail-fast**，不改代码，manual 文档化：可回滚事务下 abort 更干净）。

    // 计算待删目录（不在此处删除 —— 须 save() 成功后再删，REV-009 事务顺序）
    let purgeTarget: string | undefined;
    if (options.purge) {

### 2. `src/commands/flow.ts:459-465` 命令层顺序（REV-009）

- 现状：
  ```ts
  mgr.removeStage(stageId, { force: options.force, purge: options.purge });
  mgr.save();
  console.log(t('flow.stage.remove.okTmpl', lang, { stage: stageId }));
  if (options.purge) { console.log(t('flow.stage.remove.purgedTmpl', lang)); }
  ```
- 改后：
  ```ts
  const { purgeTarget } = mgr.removeStage(stageId, { force: options.force, purge: options.purge });
  mgr.save();                                     // 先落盘注册变更
  if (purgeTarget) {                              // 再删目录（save 失败则不会到达此处）
    const { rmSync } = await import('node:fs');
    rmSync(purgeTarget, { recursive: true, force: true });
    console.log(t('flow.stage.remove.purgedTmpl', lang));
  }
  console.log(t('flow.stage.remove.okTmpl', lang, { stage: stageId }));
  ```
  - import：`rmSync` 可用顶部静态 import（`node:fs`）或动态（如上）；以项目既有风格（顶部 `import { … } from 'node:fs'`）为准。
