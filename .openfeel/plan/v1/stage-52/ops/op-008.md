## 一、变更目标

修复 L8（**严重**）：`src/utils/kb-dedup.ts` 读取 kb 分类文件后**未归一化 CRLF**，导致条目行头正则在**含 `\r` 的行尾不匹配** → 条目被**静默跳过**；使 stage-51 新增的 `openfeel knowledge dedup` 对实际 kb 文件几乎完全失效（实测 `patterns.md` 严格解析 **2** 条 vs 去 CR **105** 条；`troubleshooting.md` **0** vs **31**）。

---

## 二、L8 子项清单

### L8-1（高）读取后统一归一化行结束符

- **文件:行号**：`src/utils/kb-dedup.ts:53-54`（实测 `:54` `const lines = content.split('\n');`，其前为 `readFileSync(filePath, 'utf-8')`）
- **现状**：直接 `split('\n')` → Windows 换行 `\r\n` 残留 `\r` 于行尾；`:62` 的行头正则 `^##\s+\[([+-])\]\s+(.+?)\s+\((\d{4}-\d{2}-\d{2})\)$` 的 `$` 因 `\r` **不匹配** → 条目被跳过（**静默**，无告警）。
- **改后**：
  ```ts
  // 归一化行结束符（CRLF/CR → LF），避免行尾 \r 致行头正则不匹配（L8）
  const content = readFileSync(filePath, 'utf-8').replace(/\r\n?/g, '\n');
  const lines = content.split('\n');
  ```
  1. **单一修正点**（读取处归一化，**不在正则上加 `\r?`**——避免多点修补与二次漂移）；
  2. 归一化对**已有 LF 文件**为恒等变换（零影响）；
  3. 补中文注释说明根因与量化影响（2→105 / 0→31）。

### L8-2（高）连带核对：正则与分词器在归一化后的行为

- **文件:行号**：`src/utils/kb-dedup.ts:62`（行头正则）、`:106-115`（`tokenize`，实测 `:109` 字符类含 `\s`）
- **改后（核对结论，不盲目改）**：
  1. `:62` 正则**保持不变**（归一化后 `$` 正确匹配；避免双重修补）；
  2. `tokenize`（`:109` 的字符类含 `\s`）→ `\r` 本属 `\s`，归一化前后**分词结果一致**（核对确认，无需改）；
  3. 若实测发现其它依赖 `\r` 的路径（如 `mergeEntry` 拼接）→ 一并归一化并记录（`rg -n "\\\\r" src/utils/kb-dedup.ts` 复核）。

### L8-3（中）阈值噪声连带评估（A5 明确要求）

- **文件:行号**：`src/utils/kb-dedup.ts:31`（`const SIMILARITY_THRESHOLD = 0.8;`）、`:199-201`（`shouldUpdate`）
- **现状**：解析量极小（2/0）→ 阈值问题被掩盖；修复后解析量升至 105/31 → **相似条目数可能显著上升**（噪声）。
- **改后（**默认阈值不变**，显式评估 + 文档）**：
  1. **不改默认值 `0.8`**（改阈值属语义变更，A5 未授权；`knowledge dedup` 已提供 `--threshold` 覆盖）；
  2. **量化评估**（执行时实测并写入报告）：
     - 以本仓 `patterns.md` + `troubleshooting.md` 为样本，统计 `knowledge dedup` 在**默认阈值**下的输出条数（top-N）；
     - 记录「相似度 > 0.8 的条目数」与「0.5~0.8 之间的条目数」作为噪声基线；
  3. **结论处置**：
     - 若默认阈值下输出**可人工消化**（如 ≤ 20 条）→ 维持默认，仅补文档说明；
     - 若**噪声明显**（如 > 50 条）→ **不改默认**，但在 manual 中给出推荐用法（`--threshold 0.85`）并在 op-010 报告登记「后续评估阈值默认值」为登记项；
  4. **文档要点移交归档官**：`.openfeel/manual/**`（去重说明：解析量上升是**修复目的**；建议用法与阈值）；
  5. **`openfeel knowledge dedup` 代码不改**（stage-51 已实现；本 op 仅修内部解析）。
