落实反馈 09 的 F4（**中断后无恢复检测**）：① **B3** 新增 `flow ops list [--stage]`，展示每个 op 的 `state` + **模板填充度**（`- [ ] 待补充` 残留检测）+ 空模板 warning，使「中断/未填充」可观测；② **B4** 引入 `draft` 两阶段（`plan scheme create --draft` → `plan scheme publish`），并在**窄兼容**约束下避免影响既有 70+ op。

## 二、B3 / B4 子项清单

### B3-1（中）`flow ops list [--stage]`（含填充度与空模板 warning）

- **文件:行号**：`src/commands/flow.ts`（新增子命令，置于 `advance`/`attempt` 附近同组；参照 `plan scheme list`（`src/commands/plan.ts:126-143`，实测只打印 stage/opId/title）与 `listSchemes`（含 `content`））
- **现状**：无 `flow ops` 命令；`plan scheme list` 只打印 `[stage] opId — title`，**不显示 state、不检测空模板**（`src/core/plan/scheme.ts:46,49,52` 空模板固定 `- [ ] 待补充`）。
- **改后**：
  ```
  openfeel flow ops list [--stage <id>] [--json]
  ```
  1. 数据来源：`flow.json` 的 `stages[].ops`（state/attempts/title）+ `listSchemes()` 的 `content`（模板首行/填充度）；
  2. **填充度**判定：扫描 op 文件内容，检测 `- [ ] 待补充` 残留（沿用 `core/plan/scheme.ts` 的空模板标记；**单一来源**，不另立标记常量——如已存在导出常量则复用，否则抽 `EMPTY_TEMPLATE_MARKER` 常量并供 B4 `publish` 校验共用）；
     - `empty`：仍含 `- [ ] 待补充`；
     - `partial`：已删除该标记但存在其它 `- [ ]` 未勾选项；
     - `filled`：无未完成标记；
  3. **空模板 warning**：`empty` 的 op 输出 warning 行（i18n），提示「该 op 模板未填充」；
  4. **draft 单独分组**（A1 窄兼容第 3 条）：`draft` op 归入「未发布（draft）」分组展示；
  5. `--json`：复用 op-001 口径 → `{ schemaVersion: 1, ops: [ { stage, opId, title, state, fill, warning? } ] }`；
  6. 只读命令（**不写盘**）。

### B4-1（中）`createScheme(..., { draft })`（core）

- **文件:行号**：`src/core/plan/scheme.ts:180-194`（实测 `createScheme` 直接注册 `state:'pending'`）、`:46,49,52`（空模板标记）
- **现状**：`createScheme` 无 draft 概念；创建即 `pending`（可被 `advance`/统计计入）。
- **改后**：
  ```ts
  /**
   * 创建操作方案。
   * @param options.draft true → 以 draft（未发布）状态注册；false/缺省 → pending（现行为）
   */
  export function createScheme(
    projectPath: string, stageName: string, title: string,
    options?: { draft?: boolean; onImplicitRegister?: (info: { stage: string; skeletonCreated: boolean }) => void },
  ): string
  ```
  - `draft: true` → `stages[].ops[opId].state = 'draft'`；`appendLog({ action: 'scheme_create', detail: { draft: true } })`；
  - **缺省行为不变**（`pending`）→ 零破坏。

### B4-2（中）`publishScheme(projectPath, stageName, opId)`（core）

- **文件:行号**：`src/core/plan/scheme.ts`（新增，与 `removeScheme`（stage-51）同区）
- **改后**：
  ```ts
  /**
   * 将 draft op 发布为 pending（校验模板已填充）。
   * @returns 结果（成功/原因码）
   */
  export function publishScheme(projectPath: string, stageName: string, opId: string): {
    published: boolean;
    reason?: 'not-found' | 'not-draft' | 'empty-template';
  }
  ```
  1. 校验：op 存在且 `state === 'draft'`（否则 `not-draft`）；模板**不含** `- [ ] 待补充` 残留（否则 `empty-template`，**exit 1 并提示**）；
  2. 成功 → `state = 'pending'` + `appendLog({ action: 'scheme_publish' })`；
  3. 空模板检测**复用 B3-1 的同一标记/判定函数**（**单一实现**）。

### B4-3（中）命令层：`plan scheme create --draft` 与 `plan scheme publish`

- **文件:行号**：`src/commands/plan.ts:108-124`（`scheme create`，实测 `:109`）、`:126-143`（`scheme list`）、`:145-190`（`scheme remove`）；新增 `publish` 子命令（与 `remove` 同组）
- **改后**：
  1. `scheme create <stage> <title>` 增 `--draft`（透传 `createScheme` 的 `options`）；
  2. 新增 `scheme publish <stage> <opId>`：成功 → 输出「已发布 {opId}（draft → pending）」；`empty-template` → stderr 报错 + `exit 1`（提示先填充模板）；`not-found`/`not-draft` → 报错 + `exit 1`；
  3. `scheme list` 输出增补 `state`（便于识别 draft；**保持既有字段顺序**，仅在行尾追加标记，尽量不破坏既有断言）。

### B4-5（中，**REV-52-002/A1 第 5 条**）`flow attempt` 对 draft op 的**双层守卫**

- **文件:行号**：**命令层** `src/commands/flow.ts:743`（`.command('attempt')`，action 内、调用 `recordAttempt` 之前）；**核心层** `src/core/flow-manager.ts:1791-1859`（`recordAttempt`）
- **现状**：`recordAttempt` 只改 `op.attempts`/`op.state`（stage-51 N4 已入 `syncCurrentOp`），**不校验 state 是否 draft**。
- **改后**：
  1. **命令层守卫**：`attempt` 取 op 后若 `state === 'draft'` → `console.error(t('flow.attempt.draftRefusedTmpl', lang, { stage, opId }))` + `process.exitCode = 1`，**直接 return**（不调用 `recordAttempt`）；
  2. **核心层兜底**：`recordAttempt` 开头 `if (op.state === 'draft') { return { shouldRetry: false, shouldReplan: false }; }`（或抛显式错误，**以不改返回契约优先** → 返回 `{shouldRetry:false, shouldReplan:false}` 并 `appendLog({ action:'attempt_refused_draft' })`）；**注释说明**双层理由（API 调用方亦被拦截）；
  3. 提示文案含**可执行指引**：`openfeel plan scheme publish <stage> <opId>`。
