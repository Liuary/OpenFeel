> 依据：`.openfeel/plan/v1/stage-133/plan.md` §一（正文原编号 **A61.1–A61.4**）与 §二 R1（步 A1/A2）+ 收口步 E13。本文件只做需求级拆解，**不改判据、不新增需求外任务**。
> **2026-11-24 修订（REV-P04 / REV-P05 / REV-P09）**：判据按正文原编号重排（A61.1=六步链、A61.2=whoami 早停/`--publish`、A61.3=CHANGELOG 草稿/`--notes-only`、A61.4=归档产物白名单）；删除「无 `--dry-run` 即 whoami 再 publish」与 `--yes-publish`/`--confirm` 口径，改为正文的「默认不真发、真实发布只认 `--publish`」；`release` **不登记 CLI `--json` 出口**。

## 目标

- **目标**：把「版本一致性校验 → build → 双包 publish → `market:index` → 归档产物提交 → tag/push」收敛为 `npm run release` 一条命令；**默认不真发**（真实发布只认 `--publish` 且 `npm whoami` 认证通过）；`npm whoami` 失败时早停并打印 `npm login` 指引（**不打印 token**）；`--dry-run` 本地演练；`--notes-only` 生成 CHANGELOG 草稿、人工确认才写入。
- **现状证据**：`package.json` 的 `scripts` 只有 `build`/`test`/`test:coverage`/`dev`/`market:index`/`market:index:check`——**没有** `release`；发布步骤散在人工对话里（REQ-061 摘要：v1.6.0 卡在 npm token 失效，whoami 401 / publish 404）。
- **相关锚点**：`scripts/build-market-index.mjs`（`main` `:401`、`--check` `:50`、`runCheck` `:506`）可复用；归档产物落点 `.openfeel/log/archive-<stage>.md` 与 `docs/releases/<version>.md`（`src/core/archive/merge.ts:342-343`、`:439-441`）；版本三源＝根 `package.json`（1.6.0）/`dsh/package.json`（1.6.0）/`CHANGELOG.md` 首段/`docs/VERSIONS.md`。
- **边界**：`release` 是 `package.json` 启动的独立脚本，**不是 CLI 子命令**，因此不占 `docs/json-contract.md` 的出口编号（REV-P09）；真实 publish/push 由人类在发版窗口执行。

## 验收判据

判据沿用**需求正文原编号**（只增不改），本需求对应 **A61.1 / A61.2 / A61.3 / A61.4**。必跑命令（仓库根）：

```bash
npm run release -- --dry-run --json              # A61.1/A61.4：六步全 ok；干净工作树零写盘；archive-commit.paths 三类齐
npm run release -- --publish --json              # A61.2：whoami 失败 → exit 1 早停 + npm login 指引 + 无 token
npm run release -- 1.7.0 --notes-only --json     # A61.3：只产草稿，CHANGELOG.md 字节不变
npx vitest run test/scripts/release.test.ts      # A61.1—A61.4：顺序/失败早停/默认不真发/确认写盘
node bin/openfeel.js lint i18n                   # E13 收口
npm test && npm run build                        # E13 收口
```

- **A61.1**：`steps.map(s=>s.id)` 逐字等于 `['version','build','publish','market','archive-commit','tag']`；六步 `status:'ok'`；`git status --porcelain` 前后均为空；注入 `version`/`build` 失败 → `exitCode:1` 且 `publish`/`market`/`archive-commit`/`tag` 全 `skipped`。
- **A61.2**：无 `--publish` → 零**真实** publish（`exec` 记录里「不带 `--dry-run` 的 `npm publish`」计数为 0；既无 `--dry-run` 又无 `--publish` 时 publish 步骤 `skipped`）；`--publish` + `whoami` 失败 → exit 1、`publish` 及后续 `skipped`、文案含 `npm login`、stdout/stderr 无 `/\b_[A-Za-z0-9]{20,}\b/` 与 `/npm_[A-Za-z0-9]{20,}/` 命中；`--publish` + 认证通过才真发。
- **A61.3**：草稿含 `## [1.7.0]`、REQ 标题、REV 结论；`--notes-only` 后 `CHANGELOG.md` sha256 不变；**只有** `--write-changelog` 才写真实文件（单测断言「无确认开关 → 零写盘」）。
- **A61.4**：`steps['archive-commit'].paths` ⊇ `.openfeel/log/archive-*.md`、`.openfeel/flow-archive/`、`.openfeel/checkpoints/`、`docs/releases/<version>.md`、`CHANGELOG.md`、`docs/VERSIONS.md`；`ARCHIVE_ARTIFACTS` 单点定义（`grep -c` = 1）。
- **不纳入本阶段**：真实 `npm publish` 与 `git push`（发版窗口由人类执行，见下「风险」第 2 条）。

## 风险

- **越权 commit**：`git commit` 的 guard 相位白名单为 `['exec_running','review_passed','test_passed','archiving']`（`dsh/lib/guard.js:2292`），`done` 相位被拒——脚本必须由人类在外部终端跑；agent 只交付脚本 + `--dry-run`/`--notes-only` 证据，**不新增任何 commit 放行路径**。
- **误发版**：唯一真实发布开关是 `--publish`（正文 A61.2），且必须先过 `npm whoami`；`--dry-run` 与 `--publish` 互斥（同时给 → `INVALID_ARGUMENT` exit 1）；单测钉死「无 `--publish` → 零**真实** `npm publish`（不带 `--dry-run` 的调用为 0）」。**不设 `--yes-publish`/`--confirm` 等自造开关**（2026-11-24 修订，REV-P04）。
- **token 泄漏**：whoami 失败文案只给 `npm login` 指引；断言输出无 token 形态（含 `_…` 与 `npm_…` 两类）。
- **版本三源漂移**：`CHANGELOG.md` 首段、`docs/VERSIONS.md`、两个 `package.json` 任一不一致即 `VERSION_MISMATCH` exit 1；校验函数与 `test/core/release-metadata.test.ts` 共用，禁第二份规则。
- **归档清单漏项**：`ARCHIVE_ARTIFACTS` 是单点常量；reviewer 用 `grep -n "ARCHIVE_ARTIFACTS" scripts/release.mjs` 确认只有一份定义。
- **出口计数误登记**：`release --json` **不进** CLI 出口表（REV-P09）；若有人把它登记成 #51，`test/cli/json-contract.test.ts` 会红——按 50/51 口径修正。
