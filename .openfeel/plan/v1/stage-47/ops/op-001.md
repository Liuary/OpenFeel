## 精确改动点（文件:行号 → 现状 → 改后）

### 1. `src/commands/flow.ts:334-360`（`phases` command）

- 现状：action 内 `const phases = mgr.getPipelinePhases();`（`:340`）；`--json` 输出 `{ phases, transitions }`（`:343-346` 附近）；人类可读输出含 phase 列表 + 转移表 + `flow.phases.hint`。
- 改后（两处）：
  ```ts
  // ① 人类可读：当存在 PIPELINE_PHASES 之外的运行时 phase 时，追加边界说明
  const customPhases = phases.filter((p) => !(PIPELINE_PHASES as readonly string[]).includes(p));
  if (customPhases.length > 0) {
    console.log(t('flow.phases.customPhaseNote', lang, { phases: customPhases.join(', ') }));
  }

  // ② --json：增 advanceAccepted（= 内置 15 phase；advance 的推进白名单）
  console.log(JSON.stringify({ phases, transitions, advanceAccepted: [...PIPELINE_PHASES] }, null, 2));
  ```
- **依据**：`flow phases` = **存在视图**（运行时 `pipelineConfig.phases`，可含自定义如 `gate`）；`flow advance` 的 phase 校验用 `PIPELINE_PHASES`（内置 15，`commands/flow.ts:534` 亦如此打印）。方案 B 把差异**显式化且可编程消费**，不收敛 advance 校验（避免波及 `PipelinePhase` 类型与模糊修正）。

### 2. `src/core/flow-manager.ts` 新增导出错误类 + 两处抛出改造

- **新增**（类声明区，与 `FlowConcurrentModificationError`（`:111-122`）同级）：
  ```ts
  /** 阶段目录冲突：两个不同 stageId 映射同一 (series, stageDir)（cli/BUG-002） */
  export class StageDirConflictError extends Error {
    readonly stage: string;
    readonly other: string;
    constructor(stage: string, other: string) {
      super(`阶段目录冲突：'${stage}' 与 '${other}' 映射同一 (series, stageDir)，请改用其它 stage-NN`);
      this.name = 'StageDirConflictError';
      this.stage = stage;
      this.other = other;
    }
  }
  ```
- `registerStage`（`:727`，抛出 `:737`）：
  - 现状：`throw new Error(\`阶段目录冲突：'${stageName}' 与 '${conflict}' …\`)`
  - 改后：`throw new StageDirConflictError(stageName, conflict);`
- `addStage`（`:1152`，抛出 `:1162`）：同上，`throw new StageDirConflictError(stageId, conflict);`
