## 设计裁定（方案期定稿，随 op 落文）

### 裁定 1（Q4-schema 定稿，承大计划 §十 Q4）：`reason` **不入** `RequirementData`（v1.2.0 范围）

- **裁定**：`RequirementData` 字段表 = **10 字段**（`id` / `title` / `status` / `target_version?` / `priority?` / `owner?` / `claimed_at?` / `created_at` / `updated_at` / `body_path?`）；**不含 `reason`**；**不含 `source`**（REV-81-005 已删）；**字段计数勘正（REV-81-010）**：实数 **10**（原计数有误——含 `id`）。
- **理由**：① 本阶段（引擎面）无该字段消费方——与 REV-81-005 删 `source?` 同判据「无消费方的字段不入 schema」；② `blocked` 事由承载面已足：人读走 REQ 正文（变更记录节），机读走 `log[]` 审计条目（`requirement_status` 的 detail；stage-82 落地 `req set --status blocked` 时如需携事由，入 detail 即可，**无需 schema 变更**）；③ 未来增补 `reason?: string` 为纯增量可选字段（读侧宽容 + 缺省回落已成为本版纪律），零迁移成本；反之 v1.2.0 首发即冻结 reason 的完整语义（清空规则 / 仅 blocked 约束 / 展示口径）成本高且无需求依据；④ 与裁定 N（边界「不做」清单）及「减法优先」方向一致。
- **登记**：写入 op-003 自测报告「Q4-schema 定稿」节 + `ops/deps.yaml` `scheme_decisions`，供 stage-82/83 消费。

### 裁定 2：`requirements` 读侧宽容（不 load 补齐）

- **读取**：`getRequirements(data)` 派生 `data.requirements ?? []`（op-002 落地）；**写入**：`addRequirement` 内先 `data.requirements ??= []` 再 push（写路径兜底）。
- **不采纳** `load()` 补齐（方案 (b) 已否）：对齐 REV-78-015 方向（stage-79 已移除 `meta.archived_versions` 的 load 补齐，语义由 `getArchivedVersions` 自防御承担）。

### 步骤 1：`src/core/req/types.ts`（新建）

- [ ] 1.1 文件头中文注释：职责 = 需求层类型与常量**单一来源**；正交声明 = 零 import（叶子模块；**不依赖归档层 / 不引用工作流模式字段**）——注释措辞**不得含禁用串字面量**（禁用串出现即 op-003 T5.6 静态断言假红；REV-81-009）。
- [ ] 1.2 常量与类型（**类型由常量派生，防两处枚举漂移**）：
  ```ts
  /** 需求状态值域（7 值，裁定 B；单一来源——stage-82 命令层校验须从此派生，禁硬编码） */
  export const REQ_STATUSES = ['draft', 'scheduled', 'in_progress', 'done', 'blocked', 'cancelled', 'rejected'] as const;
  /** 需求状态联合类型（自 REQ_STATUSES 派生，唯一权威） */
  export type RequirementStatus = (typeof REQ_STATUSES)[number];

  /** 需求优先级值域（三档；单一来源） */
  export const REQ_PRIORITIES = ['P0', 'P1', 'P2'] as const;
  /** 需求优先级类型（自 REQ_PRIORITIES 派生） */
  export type RequirementPriority = (typeof REQ_PRIORITIES)[number];

  /** 需求 ID 格式（REQ-NNN 三位起补零；**含数字捕获组**；**非全局标志**，防 lastIndex 状态污染） */
  export const REQ_ID_PATTERN = /^REQ-(\d{3,})$/;   // 含数字捕获组（m[1] 供 nextRequirementId 解析）；非全局标志
  ```
- [ ] 1.3 `RequirementData` 接口（逐字段中文 JSDoc；字段表逐字，顺序如下）：
  ```
  id: string                  // REQ-NNN（max+1 不回收；REQ_ID_PATTERN）
  title: string               // 需求标题（人读简明描述）
  status: RequirementStatus   // 显式粗粒度状态；新建恒 'draft'（REV-81-005）
  target_version?: string     // 预估版本（如 v1.3.0；可选）
  priority?: RequirementPriority // 优先级 P0/P1/P2（可选）
  owner?: string              // 认领人（claim 写入；未认领缺省）
  claimed_at?: string         // 认领时间 ISO 8601（与 owner 同批写入/清除）
  created_at: string          // 创建时间 ISO 8601
  updated_at: string          // 最近更新时间 ISO 8601（仅实际变更时刷新）
  body_path?: string          // 正文相对路径（POSIX 分隔符，如 .openfeel/requirements/REQ-001.md）
  ```
