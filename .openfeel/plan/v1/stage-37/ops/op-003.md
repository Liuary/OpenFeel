# op-003：update 改造 — 全局部署 + 深度合并 + skills/$schema/agent_manager_tool 修正 + update_state 全局化

- **阶段**：v1.1.0-stage-37
- **前置**：op-001（hard，路径与配置基础）
- **负责 Agent**：openfeel-executor
- **最多重试**：3

## 目标

`updateProject` 部署目标改全局；全局 opencode.jsonc「解析→深度合并→序列化」保留用户字段（复用 op-001 `mergeGlobalOpencodeJsonc`）；移除非法 `skills` `{name:path}` 生成、修正 `$schema` URL、按 N3 移除 `agent_manager_tool`；update_state 按全局/项目拆分（N2）；识别 legacy 布局并提示（N8）。

> 参见 kb/patterns.md #update 增量部署哈希追踪 + 冲突标记三态模式；kb/troubleshooting.md #update_state.json 降级风险排查（全局 state 首次加载降级防全量覆盖）；kb/patterns.md #向后兼容可选配置字段模式；kb/architecture.md #opencode 全局/项目 agent 与 skill 合并语义。

## 关键设计决策

1. **全局 opencode.jsonc 深度合并 = `parseJsonc` → `deepMergeJsonc` → `JSON.stringify`**（op-001 已实现 `mergeGlobalOpencodeJsonc`），保留用户字段、注释不保留；**合并语义统一在 op-001，op-003 只调用不重写**（与 REV-605 呼应：合并只此一处）。
2. **项目 opencode.jsonc 不再由 update 写 instructions/skills/default_agent**：不存在 → 写最小 `{ $schema }`；已存在 → 保留不动（旧非法字段清理属 stage-39 migrate）。`buildUpdatedJsonc`/`formatJsonc`/`replaceSkillsFieldInJsonc`/`buildJsoncFromObject`/`NEW_SKILL_NAMES` 随之删除。
3. **N3 agent_manager_tool = 移除**（op-000 实测：schema 未定义 + `debug config` 静默丢弃为 `"experimental": {}`）。同步删模板 `templates-data/opencode/opencode.jsonc` 的 `experimental` 块（D37-2）与 `buildJsoncFromObject` 的 experimental 保留逻辑（后者随函数删除）。
4. **update_state 拆分（N2/REV-607）**：新增 `loadGlobalUpdateState`/`saveGlobalUpdateState`/`createGlobalUpdateState`（复用 `UpdateStateSchema`，不改现有 `projectPath` 签名）；全局资产 hash 走 `~/.openfeel/update_state.json`，项目资产（AGENTS.md + 项目 opencode.jsonc）走项目 `.openfeel/update_state.json`。全局 state key 用**绝对路径**（机器本地 state，无歧义）。**首次全局 state 加载失败（null）→ 降级为「全量写入 + 重建 state」，不得因降级静默覆盖用户全局配置**（kb troubleshooting 已知坑）。
5. **legacy 识别（N8）**：检测项目内遗留 `.opencode/agents|skills|instructions` 时输出「请运行 `openfeel migrate`（stage-39 提供）」提示，**不静默迁移/删除**。
6. **全局文件写入复用 stage-35 工具**：`atomicWriteFileSync` + `withFileLock(globalLockPath(...))`；全局 opencode.jsonc 深度合并后的写盘用全局锁 `global-opencode-jsonc`。

`saveUpdateState`（L99）之后新增三个函数（**不改动** `loadUpdateState`/`saveUpdateState`/`createUpdateState` 的 `projectPath` 签名）：

```ts
/**
 * 读取全局 update_state.json（~/.openfeel/update_state.json）
 * 复用 UpdateStateSchema；不存在/校验失败 → null（降级为全量覆盖+重建，调用方防全量覆盖）
 */
export function loadGlobalUpdateState(): UpdateState | null {
  const statePath = getGlobalUpdateStatePath();
  if (!existsSync(statePath)) {
    return null;
  }
  try {
    const raw = readFileSync(statePath, 'utf-8');
    const data = JSON.parse(raw);
    const result = UpdateStateSchema.safeParse(data);
    if (!result.success) {
      console.warn(`[update] 全局 update_state.json schema 不匹配，视为首次更新: ${result.error.message}`);
      return null;
    }
    return result.data;
  } catch {
    return null;
  }
}

/** 写入全局 update_state.json（跨项目共享 → 加锁 + 原子写） */
export function saveGlobalUpdateState(state: UpdateState): void {
  const statePath = getGlobalUpdateStatePath();
  withFileLock(globalLockPath('global-update-state'), () => {
    atomicWriteFileSync(statePath, JSON.stringify(state, null, 2) + '\n');
  });
}

/**
 * 首次全局 update 创建初始全局 state。
 * 全局资产 key 用绝对路径（机器本地 state，无歧义）。
 */
export function createGlobalUpdateState(files: Record<string, string>): UpdateState {
  const fileEntries: Record<string, FileState> = {};
  for (const [path, content] of Object.entries(files)) {
    fileEntries[path] = { hash: hashContent(content), status: 'clean' };
  }
  // （REV-707 修订）移除冗余 mkdirSync：saveGlobalUpdateState → atomicWriteFileSync 已自动建目录，
  // 与 createUpdateState 语义对称（本函数只组装 state，不触碰文件系统）。
  return {
    version: '1.0',
    last_update: new Date().toISOString(),
    openfeel_version: getOpenfeelVersion(),
    files: fileEntries,
  };
}
```

### 步骤 5：`getIncomingContent` 改全局路径匹配（L1783-1819）

将 `relativePath` 匹配从项目 `.opencode/` 前缀改为**绝对全局路径**（`relativePath` 现在就是绝对路径）：

```ts
function getIncomingContent(projectPath: string, relativePath: string, lang: 'zh-CN' | 'en'): string {
  // 全局 core.md
  if (relativePath === getGlobalCoreMdPath()) {
    return loadTemplate(lang, 'core-instructions');
  }
  // 全局 agent：路径末段 {name}.md 且位于 getGlobalAgentsDir() 下
  if (relativePath.startsWith(getGlobalAgentsDir())) {
    const name = basename(relativePath, '.md');
    return loadAgentTemplate(lang, name);
  }
  // 全局 skill：{name}/SKILL.md 且位于 getGlobalSkillsDir() 下
  // （REV-701 修订）用跨平台 basename 匹配，避免硬编码 '/' 在 Windows（join 产出 '\'）下永远 false
  if (relativePath.startsWith(getGlobalSkillsDir()) && basename(relativePath) === 'SKILL.md') {
    const name = basename(dirname(relativePath));
    return SKILL_DEFINITIONS[name] ?? '';
  }
  // 项目 opencode.jsonc / AGENTS.md（仍项目级）
  if (relativePath === 'opencode.jsonc') {
    return JSON.stringify(buildProjectOpencodeJsoncObj(), null, 2) + '\n';
  }
  if (relativePath === 'AGENTS.md') {
    return loadTemplate(lang, 'agents-md');
  }
  return '';
}
```

## 风险与注意

- **`writeWithMergeDetection` 复用**：现有函数已接受「绝对 filePath + state key」，全局资产直接传绝对路径即可，无需新写冲突检测逻辑（避免重复）。
- **全局 state 降级防全量覆盖**：`loadGlobalUpdateState` 返回 null 时，`createGlobalUpdateState({})` 空 files → 全局资产走「不存在→created / 存在但无记录→降级安全覆盖」，须确保「安全覆盖」不抹除用户对全局文件的合法改动——全局 opencode.jsonc 走 merge（保留用户字段），agents/skills/core.md 走 hash 比对（无记录时降级覆盖，与既有项目语义一致）。
- **agent_manager_tool 移除依据**：op-000 findings 已记录「schema 未定义 + 静默丢弃」，删除依据回填 REV-004（大计划）；若 Feel 裁定「保留」，则本 op 步骤 7 反向操作并在 findings 记录依据。
- **`$schema` 残留**：`buildUpdatedJsonc`/`buildJsoncFromObject` 删除后，`grep opencode.openfeel src/` 应零命中（模板 `opencode.jsonc` 与 template-loader 生成段本已正确）。
- **改动面大**：update.ts 删除 5 函数 + 重写 updateProject，独立 commit，便于 `git revert`。
