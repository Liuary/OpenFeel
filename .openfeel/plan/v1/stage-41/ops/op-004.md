## 目标（含反馈条目）

在 `openfeel plan stage add <name>` 暴露 `--deps` 参数，透传至核心 `addStage(projectPath, name, deps)`，使依赖落 `overview.md`「## 依赖」与 `flow.json.stages[].deps`。

**对应反馈**：`docs/phase-5/06-openfeel-tooling-feedback.md` 问题 #4（中）「`plan stage add` 不支持声明依赖（deps）；核心函数已支持但 CLI 未暴露」。
**对应决策**：P12（依赖落点确认为 `flow.json`，**不引入 `deps.yaml` 读取**——该文件不被 flow 引擎消费属既有设计）。

> 参见 kb/patterns.md #stageId 三格式解析（deps 为引用，不强制校验）。

## 关键设计决策

1. **参数形态兼容两种写法**：`--deps a b`（空格分隔，commander 变参）与 `--deps a,b`（逗号分隔，反馈建议写法）**均支持**——命令层对每个条目按 `,` 再切分、`trim`、去空。这样既满足 commander `<ids...>` 惯用法，也满足反馈与验收标准中的 `--deps a,b`。
2. **不校验 deps 格式**：依赖可能指向尚未注册的未来阶段，属正常用法；本 op 不做 `validateStageId` 校验（避免过度设计）。
3. **不引入 `deps.yaml`**：明确不实现（P12）。
4. **幂等语义沿用现状**：`plan/stage.ts` 的 `addStage` 在目录已存在时**不覆盖** `overview.md`，故重复执行 `plan stage add` 时 deps **不会**被改写（既有行为，保持不变）。
5. **deps 为「真实数据」——与 op-003 的交互（REV-004）**：`flow.json.stages[].deps`（类型 `string[]`，`flow-manager.ts:95`；写入路径 `registerStage :704/:715`、`addStage :1128`、`plan/stage.ts:103`）自本 op 起由 CLI 写入，成为**数据完整性校验的输入**：op-003 的 `FlowManager.checkRemovable` 会扫描 `stages[].deps`，默认阻止「被其它阶段依赖的阶段被移除」。**deps 以原始字符串透传、不做规范化**（决策 2），故**消费方须自行归一化比较**——op-003 采用「精确相等 **或** 经 `parseStageId` 解析后 `(series, stageDir)` 相同」的匹配，兼容 `--deps stage-05` 短名。本 op **不引入** deps 校验，也**不改变** `deps` 存储格式。

## 精确改动点（文件:行号 → 现状 → 改后）

### 改动 1：`src/commands/plan.ts:20-30` `plan stage add` 新增选项并透传

- 现状：
  ```ts
  stageCmd
    .command('add')
    .description('添加工作阶段')
    .argument('<name>', '阶段 ID（如 stage-01 或 v1.0.0-stage-01）')
    .action((name: string) => {
      const projectPath = process.cwd();
      const lang = getCliLang(projectPath);
      addStage(projectPath, name);
      console.log(t('plan.stage.createdTmpl', lang, { name }));
    });
  ```
- 改后：
  ```ts
  stageCmd
    .command('add')
    .description('添加工作阶段（完整入口：建目录 + overview/status + 注册 flow.json）')
    .argument('<name>', '阶段 ID（如 stage-01 或 v1.0.0-stage-01）')
    .option('--deps <ids...>', '依赖阶段 ID 列表（空格或逗号分隔，如 --deps a b 或 --deps a,b）')
    .action((name: string, options: { deps?: string[] }) => {
      const projectPath = process.cwd();
      const lang = getCliLang(projectPath);
      // 兼容 --deps a,b 与 --deps a b：逐项按逗号再切分、去空
      const deps = (options.deps ?? [])
        .flatMap((d) => d.split(','))
        .map((s) => s.trim())
        .filter(Boolean);
      addStage(projectPath, name, deps.length > 0 ? deps : undefined);
      console.log(t('plan.stage.createdTmpl', lang, { name }));
    });
  ```
  - `description` 文案调整见 op-005（三入口分层）；本 op 可先按现状保留，op-005 统一收口，避免重复改动同一行。**建议**：本 op 只加 `.option(...)` 与 action 签名，`description` 留给 op-005。

## 参数与校验规则

| 参数 | 规则 |
|------|------|
| `<name>` | 阶段 ID；沿用 op-002 的 `validateStageId`（三入口统一校验） |
| `--deps <ids...>` | 可选；变参。每个条目按 `,` 再切分、`trim`、过滤空串 → 最终 `string[]` |
| 空 deps | 不传 或 解析后为空 → 传 `undefined` → `overview.md` 显示「无」、`flow.json.deps = []` |
| deps 格式 | **不校验**（可引用未来阶段） |
| 落点 | `overview.md`「## 依赖」+ `flow.json.stages[fullStageId].deps` |
| 幂等 | 目录已存在时不改写 overview（既有行为） |
