# op-004：status.md CLI 管理命令

- **阶段**：v4-stage-04
- **前置**：无（批次内独立 op）
- **负责 Agent**：Executor

## 目标

新增 `openfeel stage` 命令组，通过 CLI 原子操作管理 status.md 的读写，替代 Agent 手动 `edit` 工具，消除格式匹配脆弱性问题。

> 参见 kb/troubleshooting.md「手动 edit status.md 频繁失败 — 格式匹配脆弱」— CLI 原子操作是根治方案。

## 实施步骤

- [x] 步骤1：`read` 本方案文件完整内容
- [x] 步骤2：阅读 `src/commands/flow.ts` 了解现有命令结构和注册模式
- [x] 步骤3：阅读项目 CLI 入口文件（`src/cli/index.ts`），确认如何注册新命令组
- [x] 步骤4：新建 `src/commands/stage.ts`，实现以下子命令：
  - `openfeel stage status [<stageId>]` — 读取 status.md 显示阶段状态（执行模式、当前任务、阻塞原因）
  - `openfeel stage set <stageId> --status <value>` — 设置阶段状态字段（原子更新，非全量重写）
  - `openfeel stage task <stageId> <taskNo> --done|--undone` — 勾选/取消任务 checkbox
- [x] 步骤5：CLI 实现细节：
  - 使用 `readFileSync` + 正则解析 status.md 的当前结构和任务列表
  - `set` 操作：定位 `**状态**：` 行，替换其后值（保留 Markdown 格式其余部分不变）
  - `task` 操作：定位 `- [ ] 任务{N}` 行，切换为 `- [x]`（或反向）
  - 所有写操作前备份 status.md 到 `.openfeel/tmp/status.{stageId}.bak`
- [x] 步骤6：在 CLI 入口注册 `stage` 命令组（与 `flow` / `plan` 同级）
- [x] 步骤7：同步更新相关 Agent prompt：在 Feel、Schemer、Executor、Reviewer 的 prompt 中注明「状态更新须通过 `openfeel stage` 命令，禁止直接 edit status.md」
