# op-005：测试改造 — 隔离 HOME + 全局路径断言 + schema/合并/legacy 断言

- **阶段**：v1.1.0-stage-37
- **前置**：op-002 / op-003 / op-004（hard，断言其全局路径行为）
- **负责 Agent**：openfeel-executor

## 目标

init/update 测试改隔离 HOME（`vi.mock('node:os', { homedir })`）；断言全局路径 + 项目精简 + 不写 instructions；新增 schema / 合并保留 / legacy 提示断言；确保**全部涉及全局的测试在 mock homedir 下运行，不污染真实 `~/.config/opencode/` 与 `~/.openfeel/`**。

> 参见 kb/patterns.md #全局跨项目用户画像 YAML 配置模式（mock homedir 隔离先例）；kb/patterns.md #update 增量部署哈希追踪 + 冲突标记三态模式。

## 关键设计决策

1. **mock homedir 机制 = `vi.mock('node:os', ...)`（REV-603）**，与 op-000 的「真实 CLI 子进程 + 环境变量」严格区分。两套成熟先例：
   - `test/core/workspace/global-config.test.ts` L10-14：`let mockHomeDir` + `vi.mock('node:os', async () => ({ ...actual, homedir: () => mockHomeDir }))`（REV-606 引用点 L11）。
   - `test/core/config.test.ts` L11-16：`vi.hoisted` + `vi.mock('node:os', ...)`（更稳健，REV-606 引用点 L13）。
   - 本 op 统一采用 `vi.hoisted` 变体（避免模块加载顺序问题）。
2. **init.test.ts / update.test.ts 当前未 mock homedir** → `initProject` 的 `ensureGlobalConfig`、`updateProject` 的 `recordProjectLang` 会读写真实 `~/.openfeel/config.json`（**既有污染缺陷**，本 op 一并修复）。
3. **opencode-instance.test.ts（仓库自举实例）不受影响**（N1，本 op 不碰）。
4. **断言二分纪律（REV-306 沿用）**：构造写入用新路径；读取兼容 fixture 保留旧名；禁止同一 fixture 既写旧名又断言新名落盘。

## 风险与注意

- **mock 顺序**：`vi.mock` 须在 import 被测模块（init.js/update.js）之前声明，否则 `homedir` 已绑定真实实现；用 `vi.hoisted` + 顶层 `vi.mock` 保证提升。
- **既有污染缺陷**：init.test/update.test 原未 mock，本次修复后 `ensureGlobalConfig`/`recordProjectLang` 不再写真实 `~/.openfeel/config.json`。
- **计数断言脆弱**：`created/skipped` 精确数随文件清单变化，执行时以实际返回值为准调整，勿照抄旧 27/26 硬编码。
- **冲突目录路径**：全局冲突文件写 `~/.openfeel/update_conflicts/`（op-003 已改），测试断言路径须同步，勿沿用项目 `.openfeel/update_conflicts/`。
