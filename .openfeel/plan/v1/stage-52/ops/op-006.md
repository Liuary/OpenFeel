## 二、B6 子项清单

### B6-1（中）`renameScheme(projectPath, stageName, opId, title)`（core）

- **文件:行号**：`src/core/plan/scheme.ts`（新增；与 `removeScheme`（stage-51）、`publishScheme`（op-005）同区）；参照 `extractTitle`（stage-51 后 `:77-95`，读内容首行/文件名回退）与 `createScheme:180-194`
- **现状**：`plan scheme` 仅 `create`（`src/commands/plan.ts:109`）/`list`（`:127`）/`remove`（`:147`）→ **标题创建后不可改**（仅能删了重建，损失 opId 连续性）。
- **改后**：
  ```ts
  /** 重命名结果 */
  export interface RenameSchemeResult {
    renamed: boolean;
    /** 未重命名原因 */
    reason?: 'not-found' | 'title-unchanged' | 'file-missing';
    /** 旧标题（用于输出与审计） */
    previousTitle?: string;
  }

  /**
   * 更新 op 标题：同步 flow.json 的 ops[opId].title 与 op 文件内容首行的 `# {opId}：{title}`。
   * 文件名为 op-NNN.md（不含标题）→ 无需重命名文件。
   * @param title 新标题（非空；首尾空白折叠）
   */
  export function renameScheme(
    projectPath: string, stageName: string, opId: string, title: string,
  ): RenameSchemeResult
  ```
  实现要点：
  1. 定位阶段与 op（`normalizeStageId` 归一；未命中 → `not-found`）；
  2. 新标题 `trim()` 后**不得为空**（空 → `not-found` 外的独立报错，由命令层校验）；
  3. 读 op 文件（`opsDir/op-NNN.md`；若不存在 → `file-missing`）；
  4. **写 flow.json**：`stages[stage].ops[opId].title = title`（经 `FlowManager` 加锁 + `save()`）；
  5. **写文件首行**：把**首个** `^#\s*op-\d+[：:]\s*.*$` 行替换为 `# {opId}：{title}`（**原子写**）；若首行无该模式 → **在文件头部插入**该标题行（保持其余内容不变）；
  6. 标题未变（与旧值相同）→ `title-unchanged`（命令层 no-op 成功提示）；
  7. `appendLog({ action: 'scheme_rename', detail: { opId, from: previousTitle, to: title } })`。

### B6-2（中）命令层 `plan scheme rename <stage> <opId> --title "…"`

- **文件:行号**：`src/commands/plan.ts`（`schemeCmd` 组，与 `remove`（`:145-190`）同区）
- **改后**：
  1. `schemeCmd.command('rename <stage> <opId>').requiredOption('--title <text>', …)`；
  2. `--title` 为空/全空白 → stderr 报错 + `exit 1`；
  3. 结果分支：`renamed` → 输出「已重命名 {opId}：{from} → {to}」；`title-unchanged` → no-op 成功 + 提示；`not-found` / `file-missing` → 报错 + `exit 1`；
  4. **与 `remove` 的交互**：不改 `remove`（stage-51 保护语义保持）。

## 八、风险与回滚

| # | 风险 | 缓解 / 回滚 |
|---|------|------|
| R1 | flow.json 与文件首行**不一致**（一半成功一半失败） | **先写文件后写 flow.json**（或反之）须明确顺序 + 失败时输出明确「部分成功」提示；建议：**先校验（存在/非空/文件可读）→ 写文件 → 写 flow.json**，并把失败点写入错误文案；`file-missing` 时**不写 flow.json**（原子性尽量前移） |
| R2 | 首行替换误伤（文件含多个 `# ` 标题） | **仅替换首个匹配行**；不匹配则**插入**头部，不动其它行 |
| R3 | 历史命名文件被误改文件名 | 明确**不改文件名**（A5）；用例覆盖 |
| R4 | 与 `remove`/`publish` 并发（同 stage） | 同一 CLI 进程内串行；`FlowManager.save()` 有锁 |
| R5 | i18n 与并行 op 冲突 | `deps.yaml` 互斥声明 |
| **回滚** | — | `git revert`；标题可再次 `rename` 回原值（幂等可逆）；文件首行可手工恢复 |
