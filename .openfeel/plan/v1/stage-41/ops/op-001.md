# op-001：`flow phases` 子命令（phase 枚举 + 运行时转移表 + `--json`）

- **阶段**：v1.1.2-stage-41
- **状态**：completed
- **前置**：无（hard 无；soft 无）
- **负责 Agent**：openfeel-executor
- **最多重试**：3

## 目标（含反馈条目）

新增 `openfeel flow phases` 子命令，自描述**全部 15 个合法 phase** 与**运行时实际生效的转移表**，并支持 `--json` 供自动化解析；同时把 `flow advance --to` 的帮助文本指向该命令。

**对应反馈**：`docs/phase-5/06-openfeel-tooling-feedback.md` 问题 #2（高）「`--help` 不自描述 phase 枚举与合法转移，迫使 Agent 翻包源码」。
**对应决策**：版本级计划 P10（`--json` 结构 `{ phases, transitions }`）、P13（转移表**必须来自运行时 `pipelineConfig`**，禁止直引 `PIPELINE_PHASES` 硬编码）。

> 参见 kb/patterns.md #CLI 错误诊断增强模式（自描述沿用「原因 + 当前状态 + 可用操作」三层思路）、#CLI lint 子命令组扩展与 `--fix` 自动修复模式（父命令追加子命令惯例）、#i18n 键对称性校验模式。

## 关键设计决策

1. **数据源唯一性（P13，硬性）**：`flow phases` 的 phase 列表与转移表**只能**来自 `FlowManager` 暴露的运行时访问器（其底层为 `this.pipelineConfig`，缺省回退 `getDefaultPipelineConfig()`）。**不得**在命令层 `import { PIPELINE_PHASES }` 作为输出源——`flow.ts:27` 虽已导入 `PIPELINE_PHASES`（供 `advance` 校验使用），但本命令输出禁用该常量。
2. **命令自身不依赖 flow.json**：访问器只读 `pipelineConfig`（`loadPipelineConfig()` 在构造时已尝试加载，失败回退默认），故 `flow phases` 在未初始化项目亦可输出默认表；**不**调用 `mgr.isLoaded()` 拦截。
3. **组合 key 原样展示**：`transitions` 的 key 可能含 `|`（如默认配置 `review_passed|test_passed`），默认输出原样展示该 key，不做拆分，避免丢失「多源任一触发」语义。
4. **零副作用**：命令只读，不 `save()`、不写 `flow.json`、不 `appendLog`。

## 精确改动点（文件:行号 → 现状 → 改后）

### 改动 1：`src/core/flow-manager.ts` 新增公共访问器

在 `getAvailablePhases()`（现 `:1270-1280`）之后、`resolveCurrentPhase()`（现 `:1282`）之前插入两个公共方法：

```ts
/**
 * 获取运行时生效的 phase 列表（供 flow phases 自描述）。
 * 数据源 = this.pipelineConfig（构造时经 loadPipelineConfig 加载 .openfeel/pipeline.yaml）；
 * 缺省/解析失败时回退内置默认配置。返回副本，避免调用方修改内部状态。
 */
getPipelinePhases(): string[] {
  const phases = this.pipelineConfig?.phases ?? this.getDefaultPipelineConfig().phases;
  return [...phases];
}

/**
 * 获取运行时生效的 phase 转移表（key 可含 '|' 组合条件）。
 * 缺省/解析失败时回退内置默认配置。返回浅拷贝。
 */
getPipelineTransitions(): Record<string, string[]> {
  const transitions = this.pipelineConfig?.transitions ?? this.getDefaultPipelineConfig().transitions;
  return Object.fromEntries(Object.entries(transitions).map(([k, v]) => [k, [...v]]));
}
```

- 现状：`FlowManager` 仅有私有 `pipelineConfig: PipelineConfig | null`（`:267`）与私有 `getDefaultPipelineConfig()`（`:2749-2792`），无对外只读访问器；命令层拿不到转移表。
- 改后：新增上述两个 `public` 方法（不破坏既有 API）。
- **行号说明**：以上行号为制定时快照，执行时以 `grep -n "getAvailablePhases" src/core/flow-manager.ts` 定位为准。

### 改动 2：`src/commands/flow.ts` 新增 `flow phases` 子命令

在 `flow metrics`（现 `:318-327`）之后、`const stageCmd = flow.command('stage')`（现 `:329-332`）之前插入：

```ts
// flow phases — 自描述：列出全部合法 phase 与运行时转移表
flow
  .command('phases')
  .description('列出全部合法 phase 及其流转映射（自描述）')
  .option('--json', '以 JSON 输出 { phases, transitions }')
  .action((options: { json?: boolean }) => {
    const lang = getCliLang(process.cwd());
    const mgr = createManager();
    const phases = mgr.getPipelinePhases();
    const transitions = mgr.getPipelineTransitions();

    if (options.json) {
      console.log(JSON.stringify({ phases, transitions }, null, 2));
      return;
    }

    console.log(t('flow.phases.title', lang));
    console.log(t('flow.phases.listLabel', lang) + `: ${phases.length}`);
    for (const p of phases) {
      console.log(`  - ${p}`);
    }
    console.log('');
    console.log(t('flow.phases.transitionsLabel', lang) + ':');
    for (const [key, targets] of Object.entries(transitions)) {
      console.log(`  ${key} → [${targets.join(', ')}]`);
    }
    console.log('');
    console.log(t('flow.phases.hint', lang));
  });
```

- 现状：`flow` 命令组无 `phases` 子命令。
- 改后：新增只读子命令，默认人类可读、`--json` 机器可读。
- 若 `mgr.getPipelinePhases()` 返回空数组（理论上不会，缺省回退默认 15 项），仍照常输出空列表，不报错。

## 新增/修改的命令签名

```
openfeel flow phases [--json]
```

- 位置参数：无
- 选项：`--json`（布尔）——输出 `{ phases: string[], transitions: Record<string,string[]> }`

## 参数与校验规则

| 项 | 规则 |
|----|------|
| 前置校验 | 无（不依赖 `flow.json` 是否存在） |
| `--json` | 纯布尔；`true` 时输出 `JSON.stringify({ phases, transitions }, null, 2)`，可被 `JSON.parse` |
| 默认输出 | 标题 + `phases.length` + 逐行 `- <phase>` + 转移表 `key → [t1, t2, ...]`（组合 key 原样含 `\|`）+ 提示行 |
| 数据源 | `FlowManager.getPipelinePhases()` / `getPipelineTransitions()`（运行时 `pipelineConfig`，缺省回退默认） |
| 副作用 | 无（不写盘、不改 `flow.json`、不写日志） |
