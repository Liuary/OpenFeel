## 心得建议

1. **描述泛化须先立「判定原则」再动手**：断言「平台 = opencode」→ 泛化；说明 opencode 具体用法/路径/命令 → 保留并标注。没有这条原则，`glob .opencode/agents/*.md` 这类**操作指令**会被误伤而失真。
2. **「零行为变更」需要独立证据链，不能只靠「测试全绿」**：diff 逐行归因（改动行 = 注释行）+ build 幂等（build 后零 diff）+ 命令输出对比（worktree 逐字比对）三条互证，其中 build 幂等同时证明「生成物非手改」。
3. **双源同句是审计盲区**：`templates-data/agents-md/*`（部署源）与仓库根 `AGENTS.md`（手工维护）语义同句但无单一源约束，改一处不会触发任何失败——本阶段因此漏改 `agents-md:112`（BUG-002），且 `templates/BUG-001` 已发生过一次。
4. **盘点是有限的，漫游检查必须兜底**：A 类清单按行号盘点，但「同语义句的其它副本」不会自动进入清单；改动文案类任务应显式增加「关键句全仓 rg 遍历」作为收尾步骤。
5. **不适用的审查条目应显式 closed 并留理由**（REV-001 以「复核即验收」标注），避免 low 项无人认领。
