## 设计裁定（方案期定稿，随 op 落文）

### 裁定 3：状态流转**单点表**（`advanceRequirement` 与 `updateRequirement({status})` 共用，零第二套）

| 当前 status | 允许的显式目标 | 备注 |
|---|---|---|
| `draft` | `scheduled` / `blocked` / `cancelled` / `rejected` | 裁定 M |
| `scheduled` | `in_progress` / `blocked` / `cancelled` / `rejected` | 裁定 M |
| `in_progress` | `done`（**门**：`allLinkedStagesDone`）/ `blocked` / `cancelled` / `rejected` | done 门见裁定 4 |
| `blocked` | `scheduled` / `in_progress` / `cancelled` / `rejected` | 解除路径（承大计划 Q4：`req set --status`） |
| `done` / `cancelled` / `rejected` | （终态，无可显式流转） | done 的自动回退由 stage-83 聚合回写承担 |
| 同值（X → X） | 幂等 no-op（`{ok:true, changed:false}`） | 幂等写入模式（kb） |

表外组合（如 `draft → in_progress`、`draft → done`、`scheduled → done`、`scheduled → draft`、终态再流转）→ `invalid_status`。**`done` 的唯一自动写路径 = stage-83 聚合回写；显式路径仅此表**。

### 裁定 4：`done` 门 = `allLinkedStagesDone(data, requirementId)`（导出谓词，单一口径）

- 判据：`Object.values(data.stages)` 中 `(stage.requirement_id ?? null) === requirementId` 的集合**非空** ∧ 全部 `phase === 'done'`。**零关联 → false**（空集守卫，裁定 H；防 vacuous truth）。
- stage-83 的 `computeRequirementAggregate` 与聚合回写须与本谓词**语义等价**——允许 stage-83 重构让本谓词委托聚合函数（**禁第二套判定**）；本谓词为 advance→done 门的当前实现。

### 裁定 5：`releaseRequirement` 无占用者 = **no-op 成功语义**（Q3 定稿）

- `{ok:true, changed:false}`：不修改任何字段、不刷新 `updated_at`、不写审计（幂等友好；命令层可提示「未认领，无变更」）。
- `release` **不设状态门**（终态需求亦可释放）；占用者存在 → 清除 `owner` + `claimed_at`（`delete`），刷新 `updated_at`，审计 `requirement_release`。

### 裁定 6：正文骨架定稿（裁定 K 七章节 + 覆写策略 + 快照形态）

- **章节**（H1 标题 + 6 个 H2）：标题 / 状态 / 摘要 / 目标与验收 / 预估版本 / 关联阶段 / 变更记录。
- **覆写策略**：目标文件**已存在 → no-op 不覆盖**（保留人工补充内容）；**无 `overwrite` 参数**（减法优先）。no-op 时仍保证 `body_path` 赋值（见裁定 7）。
- **快照形态**（承 stage-81 plan 开放问题 4）：写入**创建时状态快照**（恒为 `draft`）+ 文件头注记「机读权威恒为 flow.json；两者不一致以 flow.json 为准；状态为创建时快照，不追写实时状态」。
- **模板逐字**（`{...}` 为插值位；`{target_version}` 缺省渲染为 `（未指定）`）：
  ```md
  # {id}：{title}

  > 本文件为需求正文（人读副本，由 req add 机械铺骨架）。**机读权威恒为 `.openfeel/flow.json` 的 `requirements` 条目**；两者不一致时以 flow.json 为准。下方状态为创建时快照，不追写实时状态。

  ## 状态

  {status}（创建时快照；以 flow.json 为准）

  ## 摘要

  （待补充）

  ## 目标与验收

  （待补充）

  ## 预估版本

  {target_version}

  ## 关联阶段

  （以 flow.json 的 `stages[*].requirement_id` 为准；此处可人工补充说明）

  ## 变更记录
  ```

### 裁定 7：`body_path` 写入单点 = `writeRequirementBodySkeleton`；相对路径恒 POSIX 分隔符

- 骨架函数负责把 `req.body_path = '.openfeel/requirements/{id}.md'`（**正斜杠硬编码**；Windows 下 `path.join` 会产反斜杠，禁用于存储路径）写入**传入对象本体**（须为 `addRequirement` 返回的本体），保证「文件存在 ↔ body_path 已设」由构造一致；返回绝对路径。
- 存储路径与文件系统路径分离：`getRequirementBodyRelPath(id)`（存储用，POSIX）vs `getRequirementBodyPath(projectPath, id)`（FS 访问用，`join` 原生分隔符）。

### 裁定 8：查询 API 返回**浅副本**（数组 + 元素）；变更 API 返回结果

- `getRequirements` / `listRequirements`：`[...]` 数组副本 + 元素 `{...r}` 浅副本（较 `getReviewItems`（@ `:977-985`）的数组级副本更强一级——需求对象为高频可变实体，防调用方直改内部内存态；理由登记）；`getRequirement`：命中返回 `{...r}`、未命中 `null`。
- `addRequirement` 返回**新建对象本体**（变更 API；调用方需继续设置 `body_path`）；其余写原语返回 `RequirementOpResult`。

### 裁定 9：错误码与审计 action（冻结）

```ts
export type RequirementErrorCode =
  | 'not_found'        // 需求不存在
  | 'stage_not_found'  // 阶段不存在（link 专用）
  | 'already_claimed'  // 已被他人占用（claim）
  | 'already_linked'   // 阶段已属其它需求（link 重绑；须先解绑）
  | 'invalid_status'   // 状态门拒绝（claim 终态 / 非法流转 / patch.status 非法值 / link 终态需求）
  | 'invalid_field';   // 字段门拒绝（白名单外键 / 非法值 / owner 空串 / title 空串）
export type RequirementOpResult = { ok: true; changed: boolean } | { ok: false; code: RequirementErrorCode };
```

- **抛错 vs 错误码不对称（显式登记，REV-81-015）**：`addRequirement` 为**唯一抛错原语**——`title` 空 / `priority` 非法属**构造期入参校验**（调用方契约违反，无业务冲突与状态机语义，故不经错误码）；其余写原语恒经 `RequirementOpResult` 错误码（**业务冲突**：`not_found` / `stage_not_found` / `already_claimed` / `already_linked` / `invalid_status` / `invalid_field`——可恢复、须命令层 exit 映射）。**命令层统一出口（stage-82）**：`addRequirement` 的 throw 捕获后按 `invalid_field` 语义提示 + exit 非 0 零写盘。

| 原语 | 审计 action | detail | 写入条件 |
|---|---|---|---|
| `addRequirement` | `requirement_add` | `{ id, title }` | 恒（新建必发生） |
| `claimRequirement` | `requirement_claim` | `{ id, owner }` | 仅实际认领（changed） |
| `releaseRequirement` | `requirement_release` | `{ id, owner }`（owner = 释放前占用者） | 仅实际释放 |
| `updateRequirement`（状态维度） | `requirement_status` | `{ id, from, to }` | 仅状态实际变更 |
| `updateRequirement`（字段维度） | `requirement_update` | `{ id, fields: [...] }` | 仅字段实际变更 |
| `advanceRequirement` | `requirement_status` | `{ id, from, to }` | 委托 update（同路径，零第二套） |
| `linkRequirement` | `requirement_link` | `{ stage, requirementId }`（解绑 = `null`） | 仅实际变更 |

  ```ts
    data: FlowData,
    input: { title: string; target_version?: string; priority?: RequirementPriority },
  ): RequirementData {
    const title = typeof input?.title === 'string' ? input.title.trim() : '';
    if (title === '') { throw new Error('需求标题不能为空'); }        // 非法入参：编程错误抛错（非业务冲突）
    if (input.priority !== undefined && !(REQ_PRIORITIES as readonly string[]).includes(input.priority)) {
      throw new Error(`需求优先级非法：${String(input.priority)}`);    // 值域单点 = REQ_PRIORITIES

    if (input.target_version !== undefined && String(input.target_version).trim() === '') { throw new Error('预估版本不能为空串'); }
    data.requirements ??= [];                                        // 写路径兜底（REV-81-003）
    const now = new Date().toISOString();
    const req: RequirementData = {
      id: nextRequirementId(data),                                   // 须在 push 之前分配
      title,
      status: 'draft',                                               // 新建即 draft（REV-81-005）

      updated_at: now,

    if (input.priority !== undefined) { req.priority = input.priority; }
  ```

  ```ts
  export function claimRequirement(data: FlowData, id: string, owner: string): RequirementOpResult {
    const name = typeof owner === 'string' ? owner.trim() : '';
    if (name === '') { return { ok: false, code: 'invalid_field' }; }
    const req = (Array.isArray(data.requirements) ? data.requirements : []).find((r) => r?.id === id);
    if (!req) { return { ok: false, code: 'not_found' }; }
    if (isTerminalRequirementStatus(req.status)) { return { ok: false, code: 'invalid_status' }; }
    if (req.owner && req.owner !== name) { return { ok: false, code: 'already_claimed' }; }  // 数据零变更
    if (req.owner === name) { return { ok: true, changed: false }; }                          // 同 owner 幂等
    req.owner = name;
    req.claimed_at = new Date().toISOString();
    req.updated_at = req.claimed_at;
    appendRequirementLog(data, 'requirement_claim', { id, owner: name });
    return { ok: true, changed: true };
  }
  ```

  ```ts
  /** 显式流转表（裁定 3；终态不再流转） */
  const ALLOWED_TRANSITIONS: Record<RequirementStatus, RequirementStatus[]> = {
    draft: ['scheduled', 'blocked', 'cancelled', 'rejected'],
    scheduled: ['in_progress', 'blocked', 'cancelled', 'rejected'],
    in_progress: ['done', 'blocked', 'cancelled', 'rejected'],
    blocked: ['scheduled', 'in_progress', 'cancelled', 'rejected'],
    done: [], cancelled: [], rejected: [],
  };
  /** 状态变更应用（唯一实现）：返回 false = invalid_status（含 done 门不满足） */
  function applyStatusChange(data: FlowData, req: RequirementData, to: RequirementStatus): boolean {
    if (!(REQ_STATUSES as readonly string[]).includes(to)) { return false; }
    if (to === req.status) { return false; }                       // 同值由调用方按幂等 no-op 处理
    if (!ALLOWED_TRANSITIONS[req.status].includes(to)) { return false; }
    if (to === 'done' && !allLinkedStagesDone(data, req.id)) { return false; }  // 裁定 4（零关联拒绝）
    const from = req.status;
    req.status = to;
    req.updated_at = new Date().toISOString();                      // 状态维度刷新（字段维度由 update 收尾；两维度并存不重复赋值——单次赋值纪律，REV-81-013）
    appendRequirementLog(data, 'requirement_status', { id: req.id, from, to });
    return true;
  }
  ```

  - ⑤ **全部维度先校验、后落地**（校验失败 → 整 patch 零变更）；⑥ `status` 提供且 ≠ 当前 → 走 `applyStatusChange`（false → `invalid_status`）；= 当前 → 该维度无变更；
  - ⑦ 字段维度逐字段比较后**对 raw 本体赋值**（仅实际不同才赋值；赋值对象恒为 `data.requirements` 内同一引用，非副本）；⑧ `updated_at` **单次赋值纪律**（REV-81-013）：**状态维度由 `applyStatusChange` 刷新**（本函数不重复赋值）；**字段维度由 update 收尾刷新**一次（仅字段维度有实际变更时）；**两维度并存时不重复赋值**（以 `applyStatusChange` 的刷新为准）；⑨ 审计分条：状态变更的 `requirement_status` 由 `applyStatusChange` 内写（**勿重复**）；字段维度实际变更 → `requirement_update` `{ id, fields: [实际变更键...] }`；⑩ 返回 `{ok:true, changed: 任一维度实际变更}`。
- [ ] 2.6 `advanceRequirement`（零第二套：委托 update 的状态路径）：
  ```ts
  /** 显式人工推进（裁定 M）；语义与 update({status}) 完全一致（同表同门同审计） */
  export function advanceRequirement(data: FlowData, id: string, to: RequirementStatus): RequirementOpResult {
  ```

- [ ] 3.4 `writeRequirementBodySkeleton`（裁定 6/7）：
  ```ts
  /**
   * 机械铺需求正文骨架（人读副本）。
   * - mkdir 幂等；atomicWriteFileSync（backup 缺省 false）
   * - 目标文件已存在 → **no-op 不覆盖**（保留人工补充内容）
   * - 恒将 req.body_path 设为本函数单点派生的 POSIX 相对路径（传入须为 addRequirement 返回的本体）
   * @returns 目标文件的绝对路径
   */
  export function writeRequirementBodySkeleton(projectPath: string, req: RequirementData): string {
    const dir = getRequirementsDir(projectPath);
    mkdirSync(dir, { recursive: true });                       // 幂等
    const filePath = getRequirementBodyPath(projectPath, req.id);
    req.body_path = getRequirementBodyRelPath(req.id);         // 单点赋值（no-op 路径亦保证一致）
    if (existsSync(filePath)) { return filePath; }             // 已存在 → 不覆盖
    atomicWriteFileSync(filePath, renderRequirementBodySkeleton(req));
    return filePath;
  }
  ```
