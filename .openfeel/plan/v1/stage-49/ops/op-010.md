## B1 精确改动点

### 1. `src/core/flow-manager.ts:2458-2482` `autoRepairInconsistency` 增「预览」模式

- 现状：签名 `autoRepairInconsistency(stageName: string): { fixed: boolean; detail: string }`；两处修复分支**直接赋值**（`:2470 stage.phase = 'done'` / `:2477 stage.status = 'done'`）。
- 改后（增可选 `options`，`dryRun` 时不赋值，仅返回等价结果）：
  ```ts
  autoRepairInconsistency(stageName: string, options: { dryRun?: boolean } = {}): { fixed: boolean; detail: string } {
    if (!this.data) { return { fixed: false, detail: 'flow.json 未加载' }; }
    const stage = this.data.stages[stageName];
    if (!stage) { return { fixed: false, detail: `阶段 '${stageName}' 不存在` }; }

    // 修复: status=done 而 phase≠done → 同步 phase 为 done（dryRun 时仅报告，不写内存）
    if (stage.status === 'done' && stage.phase !== 'done') {
      const detail = `phase ${stage.phase} → done (与 status 同步)`;
      if (!options.dryRun) { stage.phase = 'done' as PipelinePhase; }
      return { fixed: true, detail };
    }
    // 修复: phase=done 而 status≠done → 同步 status 为 done（dryRun 时仅报告）
    if (stage.phase === 'done' && stage.status !== 'done') {
      const detail = `status ${stage.status} → done (与 phase 同步)`;
      if (!options.dryRun) { stage.status = 'done'; }
      return { fixed: true, detail };
    }
    return { fixed: false, detail: '未检测到不一致' };
  }
  ```
- 兼容性：新增参数**可选**，既有调用方（如有）行为不变。

### 2. `src/commands/flow.ts:516-523`（`advance` 的 autoRepair 段）

- 现状：
  ```ts
  if (options.stage) {
    const repairResult = mgr.autoRepairInconsistency(options.stage);
    if (repairResult.fixed) {
      console.log(t('flow.advance.autoRepaired', lang) + `: ${repairResult.detail}`);
      mgr.save();                       // 🔴 dry-run 也会写盘
    }
  }
  ```
- 改后（**REV-007②：dry-run 用「预览专用键」，不复用「已自动修复」**）：
  ```ts
  if (options.stage) {
    // B1 修复：dry-run 走预览模式（不写内存/不写盘），仅在非 dry-run 时 save()
    const repairResult = mgr.autoRepairInconsistency(options.stage, { dryRun: options.dryRun });
    if (repairResult.fixed) {
      console.log(
        options.dryRun
          ? t('flow.advance.autoRepairPreview', lang) + `: ${repairResult.detail}`
          : t('flow.advance.autoRepaired', lang) + `: ${repairResult.detail}`,
      );
      if (!options.dryRun) { mgr.save(); }
    }
  }
  ```
- **措辞理由**：既有关键 `flow.advance.autoRepaired` 文案为「已自动修复」，与 dry-run 的「未写盘」拼读别扭；故 dry-run 独立用 `flow.advance.autoRepairPreview`（「正式执行**将**自动修复」），语义自洽。
- **dry-run 分支（`:607-623`）保持不变**（仍在其后）；因 autoRepair 在 dry-run 下不再改写内存，`dry-run` 输出的 `fromPhase`/校验结果反映**实际磁盘态**（与真实执行前的磁盘态一致），符合「预览」语义。

  // B2 修复：校验 deps ⊆ 已注册 stages（短名/完整名按 normalizeStageId 归一化比较）
  if (deps.length > 0) {

### 5. `src/core/flow-manager.ts` `healthCheck` 增「悬空依赖」检测（存量防御）

- 现状：`healthCheck`（`:2608-2641`）依次 `checkFlowJson` / `checkCrossFileConsistency` / `checkZombieStates` / `checkConfigYaml` / `checkPipelineYaml` / `checkDepsYaml`（后 4 项 `!quick`）。
- 改后：新增 `// ── 7. 悬空依赖检测 ──`（**仅 `!quick`**）并实现私有方法：
  ```ts
  /** 7. 悬空依赖检测：stages[].deps 是否均指向已注册阶段（B2 存量防御） */
  private checkDanglingDeps(items: HealthCheckItem[]): void {
    if (!this.data) { return; }
    const known = new Set(Object.keys(this.data.stages).map((k) => normalizeStageId(k) ?? k));
    const dangling: string[] = [];
    for (const [stageId, stage] of Object.entries(this.data.stages)) {
      const deps = Array.isArray(stage.deps) ? stage.deps : [];
      for (const d of deps) {
        if (!known.has(normalizeStageId(d) ?? d)) { dangling.push(`${stageId} → ${d}`); }
      }
    }
    if (dangling.length > 0) {
      items.push({ section: '悬空依赖', status: 'warn', message: `检出 ${dangling.length} 条悬空依赖：${dangling.slice(0, 5).join('; ')}${dangling.length > 5 ? ' …' : ''}` });
    } else {
      items.push({ section: '悬空依赖', status: 'pass', message: '未检测到悬空依赖' });
    }
  }
  ```
  - **REV-007① 更正（事实）**：`flow-manager.ts` **未导入 `normalizeStageId`**（实测该符号在 `flow-manager.ts` 零引用；仅 `findStageStatusPath` / `findStageDirConflict` / `parseStageId` 自 `./plan/path.js` 导入，见 `:31`）→ 本 op **须在 `flow-manager.ts` 新增 import**：`import { …, normalizeStageId } from './plan/path.js';`（并入既有同一行）。
  - **核心层仍保持宽松兜底**：`checkDanglingDeps` 仅 **`warn`**（数据卫生提示），不做阻断；**校验的强制点在命令层 `commands/plan.ts`**（B2 主修），核心层不因悬空 deps 抛错。
  - 判定为 **`warn`**（非 `fail`）：悬空依赖不影响流水线运行，仅数据卫生；`ok` 判定只看 `fail`，故不阻塞 `flow health` 退出码。
