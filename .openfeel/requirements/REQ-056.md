# REQ-056：执行前必须有计划：需求级计划门禁与偏差回写

> 本文件为需求正文（人读副本，由 openfeel req 机械铺骨架）。**机读权威恒为 `.openfeel/flow.json` 的 `requirements` 条目**；两者不一致时以 flow.json 为准。下方状态为创建时快照，不追写实时状态。

## 状态

in_progress（创建时快照；以 flow.json 为准）

## 摘要

「计划」只有阶段级 `plan.md`，可缺失、可占位，且没有任何门禁检查它：`plan_pending → plan_passed` 只看相位，`exec_running` 可以零计划开始。执行完全依赖主会话的临时决定，上下文一清就没人知道原本打算怎么做；计划与执行偏离后也无人回写。

## 目标与验收

**目标**：执行前必须有计划，计划按需求拆解；偏差必须回写且可机检。

- A4 无 `plan.md` 或占位时 `advance --to exec_running` 被拒（`STAGE_PLAN_GATE`，`detail` 列出缺失/空壳）。
- A4b 需求级计划 `.openfeel/plan/reqs/REQ-NNN.plan.md` 缺失或占位同样拒绝。
- A5 计划变更未回写 `## 偏差与回写` → `advance --to done` 返回 `plan_deviation`；补齐后放行。
- A6 阶段计划门放行时为每个在办需求盖章 `{path, sha256, recorded_at}`；`--force` 放行并写 `gate_overrides` 审计。
- 存量未盖章需求放行但 warn 并标记 `plan_unstamped`，不阻塞归档。

## 问题

1. 阶段 `plan.md` 由人写、CLI 不创建也不校验；117 个阶段目录中 9 个根本没有 `plan.md`。
2. 没有「按需求拆解」的计划载体：需求与计划断裂，审查无基准。
3. 偏差回写靠口头约定，无可机检证据。
4. 小改动没有轻量档，容易退化为「不写计划直接干」。

## 初步规划

1. `src/core/plan/path.ts`：`findStagePlanPath` / `findRequirementPlanPath`（全局 `plan/reqs/`）。
2. `flow-manager.ts`：`describeStagePlanGate` + `advanceStagePhase` 门（核心层，防 `--force` 路径绕过）+ `resetStagePhase` 复检。
3. `requirement-ops.ts`：`→done` 前 sha256 偏差门 + 回写小节判据。
4. `req.ts` / `flow.ts` 文案与 `--force` 透传；i18n 中英同批。
5. 测试覆盖缺计划/占位/齐全/force/存量五态。
