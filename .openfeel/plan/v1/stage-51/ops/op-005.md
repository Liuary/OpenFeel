## 二、N5 / N6 / N7 子项清单

### N5-1（中）`setStatusField` 返回三态，区分「字段缺失」与「值未变」

- **文件:行号**：`src/commands/stage.ts:205-229`（`setStatusField`，实测 `:222-224` 以「内容是否变化」判定字段缺失）
- **现状**：同值写入 → 内容未变 → 被判定为「字段未找到」→ **误报错**（幂等脚本失败）；文案见 `src/core/i18n-data/zh-CN.ts:356`（`stage.set.errorFieldNotFoundTmpl` 一类）。
- **改后**：
  1. 新增**纯读探测**（不写盘）：
     ```ts
     /**
      * 探测字段写入结果（不写盘）。
      * @returns 'not-found' 字段缺失 / 'unchanged' 值已相同 / 'will-change' 将发生变更
      */
     function probeStatusField(statusPath: string, field: string, value: string): 'not-found' | 'unchanged' | 'will-change'
     ```
     实现：读 `status.md` → 精确匹配字段行（文档既有格式）；未命中字段名 → `not-found`；命中且值**逐字符相同** → `unchanged`；否则 `will-change`。
  2. `setStatusField(...)` 保留为写入函数（返回 `boolean`），**行为不变**（仍执行替换 + 原子写）。
  3. `stage set` action 据探测结果分支（下一子项）。

### N5-2（中）`stage set` 备份后置 + 同值 no-op 成功

- **文件:行号**：`src/commands/stage.ts:337-354`（`stage set` action；实测 `:345` **无条件** `backupStatus(statusPath, stageId)`，`:347` 调用 `setStatusField`，`:349-351` 失败报错）
- **现状**：① 每次都生成 `.bak` → 累积；② 同值 → 误报错（见 N5-1）。
- **改后**：
  1. **先探测后写**：
     | 探测结果 | 行为 | 退出码 | `.bak` |
     |------|------|:--:|:--:|
     | `not-found` | 报错（既有 `errorFieldNotFoundTmpl`） | 1 | 不生成 |
     | `unchanged` | **no-op 成功** + 提示 `stage.set.noopTmpl`（「字段 {field} 已是目标值，未做变更」） | **0** | **不生成** |
     | `will-change` | **`backupStatus` → `setStatusField` → 成功输出** | 0 | 生成 |
  2. 失败路径（写盘异常）保持既有错误输出 + `exit 1`。
- **行为变更**：**是**（同值由「报错」→「成功」；`.bak` 由「无条件」→「仅变更时」）——**A3 用户已裁定采纳**。
- **兼容影响**：依赖「同值报错」探测的脚本会失去该信号（改由 exit 0 + no-op 文案表达）；`.bak` 减少为期望方向。

### N7-1（中/低）`stage set` 字段扩展（白名单）

- **文件:行号**：`src/commands/stage.ts:327-354`（`stage set` 选项定义与 action）
- **现状**：`stage set` 仅有 `--status` → 「执行模式/自动推进/责任 Agent」无 CLI（只能手改 `status.md`）。
- **改后**：新增三个选项 + 字段白名单校验（**A4 裁定**）：
  | 选项 | 目标字段（status.md） | 取值校验 | 非法值 |
  |------|------|------|------|
  | `--status <v>`（既有） | `状态` | 既有允许集（以实测 `:347` 上下文为准） | `exit 1` |
  | `--exec-mode <manual\|auto>` | `执行模式` | 枚举 `manual` / `auto` | `exit 1`（`stage.set.invalidValueTmpl`） |
  | `--auto-advance <enabled\|disabled>` | `自动推进` | 枚举 `enabled` / `disabled` | `exit 1` |
  | `--review-agent <agent>` | `当前责任 Agent` | **非空**字符串（agent 名，允许 `-`/`.`），并规范化（trim） | `exit 1` |
  - **字段白名单（A4）**：`状态` / `执行模式` / `自动推进` / `当前责任 Agent` / `上一责任 Agent`。白名单外的字段名**不接受**（内部复用；`上一责任 Agent` 由流转逻辑写入，本 op 不新增直接选项）。
  - **多个选项同时提供**：按**固定顺序**依次探测/写入（`状态` → `执行模式` → `自动推进` → `当前责任 Agent`），任一失败即 `exit 1`（已写入的部分保留并在输出中注明）。
  - 全部走 N5 的「先探测后写」路径（同值 no-op、备份后置）。

### N6-1（中）`stage task <id> --add "描述"`

- **文件:行号**：`src/commands/stage.ts:356-399`（`stage task` 组，实测 `:361-362` 为 `<stageId>`/`<taskNo>` 位置参数）
- **现状**：无 `--add` → 任务行只能手改 `status.md`（违反纪律）；`stage task <id> 1 --done` 在无任务行时报「未找到任务 1」。
- **改后**：
  1. 位置参数 `<taskNo>` → **`[taskNo]`（可选）**（`--add` 模式下不需要编号；既有 `stage task <id> <no>` 调用**不受影响**）；action 内校验：既未提供 `taskNo` 也未提供 `--add` → 报错 + `exit 1`。
  2. 新增 `--add <desc>`（与 `--done`/`--undo` **互斥**，同时提供 → `exit 1`）。
  3. 追加逻辑（core 抽公共函数）：
     ```ts
     /**
      * 向 status.md 追加一条任务行（编号 = 既有任务数 + 1）。
      * @returns 新任务的编号
      */
     export function appendStatusTask(projectPath: string, stageId: string, desc: string): number
     ```
     - 任务行范式：`- [ ] 任务{N}：{desc}`（与既有解析一致，见 `commands/stage.ts` 的 `taskNo` 解析）；
     - 插入位置：`## 当前任务`（或实测小节名）末尾；若小节不存在 → 报错 `exit 1`（提示用 `plan stage add` 生成骨架）；
     - 写盘经原子写；`desc` 去掉首尾空白，含换行 → 折叠为空格（防结构破坏）。
  4. **编号连续性**：`N` 由既有任务行最大编号 + 1 计算（避免删除后重号）。

### N6-2（中）`plan stage add <name> --tasks "t1" "t2"`

  1. `plan stage add` 增 `--tasks <items...>`（空格/逗号两种写法，解析逻辑与 `--deps` 对齐）。

  3. 无 `--tasks` 时保持现状（`> 待补充`）→ **零破坏**。
