## 一、变更目标

消除 `plan scheme create` 的「**半注册**」阶段状态：当阶段未在 `flow.json` 注册而触发**隐式注册**时，除写 `flow.json` 条目外，**一并补齐 `overview.md` / `status.md` 骨架**（复用既有骨架生成逻辑，幂等），并输出明确提示。使 `plan/…/{stage}/` 目录结构与「创建侧」语义一致，避免后续 `advance` 报错误导。

## 二、N3 子项清单

### N3-1（高）隐式注册分支补建阶段骨架

- **文件:行号**：`src/core/plan/scheme.ts:107-132`（`syncToFlowJson` 内的隐式注册分支，实测 `:107` 判定 + `:125-131` 写入 stage 条目）；复用来源 `src/core/plan/stage.ts:26`（`addStage(projectPath, name, deps?)` —— 实测 `:42-60` 生成 `overview.md`、`:63-` 生成 `status.md`，均为「不存在才写」的**幂等**行为）
- **现状**：隐式注册只写 `flowData.stages[stageName] = { name, phase: 'plan_pending', status: 'planned', deps: [], ops: {} }`，**不建 `overview.md`/`status.md`** → 形成「半注册」阶段（`plan/…/{stage}/` 缺骨架），`advance` 时报错信息误导。
- **改后**：
  1. **抽取公共函数**（`src/core/plan/stage.ts`）：
     ```ts
     /**
      * 确保阶段目录与 overview.md / status.md 骨架存在（幂等：已存在不覆盖）。
      * 从 addStage 抽出，供 addStage 与 plan scheme create 的隐式注册共用。
      * @param projectPath 项目根路径
      * @param name 阶段 ID（简写或全称）
      * @returns 是否发生了创建（true = 补建了骨架/目录）
      */
     export function ensureStageSkeleton(projectPath: string, name: string): boolean
     ```
     `addStage(...)` 改为**复用**该函数（保持行为与文案完全一致，避免双实现）；`scheme.ts` 只调用该函数，**不复制骨架文本**。
  2. **`scheme.ts` 隐式注册分支**：在 `flowData.stages[stageName] = {...}`（`:125-131`）之后调用 `ensureStageSkeleton(projectPath, stageName)`；返回 `true`（补建发生）时置一个本地标记，供命令层输出提示（见 N3-2）。
  3. **异常处理**：骨架创建失败（权限/IO）→ **告警但不中止**（`op` 文件与 `flow.json` 条目已写），告警文案含路径与原因（`console.warn`，与 `:113`/`:119` 既有告警风格一致）。
  4. **既有跳过分支保持不变**：`:110-124` 的「非法 stageId / (series,stageDir) 冲突 → 告警并 `return`（跳过注册）」逻辑**不动**；该分支**不得**建骨架（与「跳过注册」语义一致）。

### N3-2（低）隐式注册补齐提示

- **文件:行号**：`src/core/plan/scheme.ts:208`（`syncToFlowJson` 调用点）；`src/commands/plan.ts:103-115`（`plan scheme create` action）
- **现状**：静默隐式注册，用户不知阶段被自动创建。
- **改后**：`createScheme` 的返回值/副带信息需让命令层知晓「发生了隐式注册 + 是否补建骨架」（**不改变既有返回类型 `string`** 为兼容前提 → 采用可选第二返回值/回调或导出查询函数，实施时择最简；推荐新增可选参数 `options?: { onImplicitRegister?: (info: { stage: string; skeletonCreated: boolean }) => void }`）。
  - 命令层收到回调 → 输出 `plan.scheme.implicitRegisterTmpl`（「阶段 {stage} 未注册，已按注册语义补齐阶段骨架」）。
- **行为变更**：**是（新增提示）**；零破坏（仅多一行 stdout）。

### N3-3 二选一裁定与理由（**要求 4**）

| 方案 | 内容 | 裁定 |
|:--:|------|:--:|
| ① | **不隐式注册**：`scheme create` 遇阶段未注册时拒绝并提示「请先 `plan stage add`」 | **不采用** |
| ② | **隐式注册时补建 `overview.md`/`status.md` 骨架**（复用 `addStage` 骨架生成，幂等；输出补齐提示） | **采用**（与 A1 用户裁定一致） |

**采用②的理由**：
1. **零破坏**：隐式注册是**既有行为**（`:107-132` 已在生产生效）；方案①会把「自动注册」改为「拒绝执行」→ **破坏既有下游调用**（凡依赖 `plan scheme create` 自动注册的脚本/流水线会立即失败），属破坏性变更。
2. **治本**：缺陷本质是「注册不完整（半注册）」，而非「注册本身不该发生」——补骨架即消除根因，成本仅 2 个幂等写。
3. **复用而非新增**：骨架生成已在 `core/plan/stage.ts` 存在（`addStage`），抽公共函数即可，符合「大框架面向扩展、细节简洁」。
4. **一致性**：`plan stage add`（完整入口）本就产出骨架；`scheme create` 隐式注册补齐后，两条路径产出的阶段目录结构**一致**，符合本阶段「单一语义」主题。

**对既有下游工作流的影响评估**：
- **调用行为不变**：既有 `plan scheme create` 调用（含本仓 stage-41~51 的流水线用法）**无需改动**；仅多出 `overview.md`/`status.md` 两个骨架文件（若原本已有则不覆盖）。
- **存量「半注册」项目**：下次对同一阶段执行 `scheme create` 时会**补建骨架**（期望方向，幂等安全）；**不提供**批量历史补齐命令（与 A5/A7「不做迁移命令」口径一致）。
- **失败模式**：骨架创建失败仅告警，不影响 op 创建与 flow.json 注册（保留既有容错）。
- **验收口径变化**：`plan scheme create` 的产物由「op 文件 + flow.json 条目」扩展为「**+ 阶段骨架**」；`docs`/`manual` 由归档官同步说明（本 op 不改文档正文）。
