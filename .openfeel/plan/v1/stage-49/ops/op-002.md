## 必查项（六维度）

1. **正确性**：全部子命令 help 文案 vs 实际行为（含本版本新增 `flow phases` / `flow stage remove` / `config effective` / `plan stage add --deps`）；`applyHelpI18n` 注入链（i18n 键为真正文案源、命令层硬编码为 fallback，两者是否一致）。
2. **一致性**：退出码约定（0 成功 / 1 通用错误 / 2 并发冲突）全命令覆盖；`--dry-run` / `--force` 在各状态变更命令的语义一致性；三入口（`plan stage add` / `flow stage add` / `stage create`）职责与 deprecated 口径；**i18n 键 zh/en 对称**（`lint i18n` 实测）。
3. **文档-实现对齐**：命令 description/option 文案 vs `docs/commands.md` 与 `.openfeel/manual/cli/**`（交 U6 交叉核对，本单元先记录差异）。
4. **边界与健壮性**：非法参数/缺参/未知子命令的提示；`process.exit` 与 `exitOverride` 交互；非 TTY 下交互式命令（`flow wizard`、`stage create` deprecated 提示）的静默行为。
5. **安全面**：命令层拼接路径（`project.ts` 探测、`migrate` 路径参数）是否可越界；`execSync`/子进程调用；`--purge` 类删除命令的确认与 `save()` 顺序。
6. **过度设计 / 冗余**：**中文硬编码残留**（应走 i18n）——`rg -n "[一-龥]" src/commands/*.ts` 抽样判定；`src/index.ts:10 export const VERSION = '0.1.0'` 全仓零引用且与 `package.json.version`(1.1.2) 漂移 → **记录并交 U7 交叉核对**。
