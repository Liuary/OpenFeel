# op-002: 修复 CLI 校验过严导致 Feel 绕过它手动编辑 flow.json

## 目标

解决测试项目日志反复出现的"openfeel flow CLI 失效，手动编辑 flow.json 推进"问题。根因是当 `stage.phase` 与 `stage.status` 不一致时（如 `phase: plan_pending` 但 `status: done`），`validate()` 返回 errors 而非 warnings，CLI 拒绝一切推进，导致 Feel 只能手动编辑。

## 实施步骤

- [x] 步骤1: 在前置校验通过后，创建本方案文件 op-002.md
- [x] 步骤2: 修改 `flow-manager.ts` — 在 `validate()` 中区分"阻塞错误"和"非阻塞警告"，将 `phase/status` 不一致从 errors 移到 warnings
- [x] 步骤3: 修改 `flow-manager.ts` — 新增 `autoRepairInconsistency()` 方法，自动修复 `phase` 与 `status` 不一致
- [x] 步骤4: 修改 `flow.ts` — 在 `flow advance` 的 action 中，`validate()` 前增加自动修复逻辑
- [x] 步骤5: 修改 `flow-manager.ts` — 增强 `save()` 方法，增加错误日志输出
- [x] 步骤6: 为新增消息添加中英文 i18n key（`flow.advance.autoRepaired`、`flow.advance.saveError`）

- [x] 步骤8: 完成自测报告
