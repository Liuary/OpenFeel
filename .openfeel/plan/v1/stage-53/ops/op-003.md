### D6-1（中）`DEV_SUB_DIRS` 增 `current_archive`

- **文件:行号（实测）**：`src/core/workspace/structure.ts:32`（`const DEV_SUB_DIRS = ['note'];`）；消费点 `:56-64`（`createWorkspace` 循环 `mkdirSync` + `created.push(`.openfeel/dev/${subDir}/`)`）
- **现状**：`dev/` 下仅自动创建 `note/`。
- **改后**：`const DEV_SUB_DIRS = ['note', 'current_archive'];`
  - `createWorkspace` **无需改动**（循环自动覆盖）→ 新建项目自动获得 `.openfeel/dev/current_archive/`；
  - 补中文注释说明该目录用途（**公共域**，纳入版本管理；承载 `current.md` 轮换出的旧记录）。
- **注意**：**`init.ts:220-224` 不改**（目录由 `createWorkspace` 统一创建；确认 init 链路调用它 —— `rg -n "createWorkspace" src/core/init.ts` 复核）。

### D6-2（中）**不新增**用户私域 `dev_last/` 目录常量（裁定）

- **裁定**：**不加**源码常量。理由：
  1. `WORKSPACE_DIRS`/`DEV_SUB_DIRS` 的语义是「**项目级公共目录**清单」（`.openfeel/` 与 `.openfeel/dev/` 下）；
  2. `dev_last/` 位于 `users/{username}/`（**私域**、随用户而异），无「创建项目工作区时统一建」的场景；
  3. 其创建由 **D5-1 的 workspace skill**（会话启动自检步骤 mkdir）覆盖 —— 与既有 `log/`、`note/`、`bugs/` 等同为「随用随建」；
  4. 新增常量会扩大语义并引入「为单一场景造抽象」的过度设计（全局约束 2）。
- **回退条件**：若后续出现「需要 CLI 统一初始化用户私域目录」的需求（如 `openfeel user init`），再评估纳入常量。
- **验收**：`rg -n "dev_last" src/core/` **零命中**（源码不含该常量/路径）。

### D6-3（低）`.gitignore` **不改**（登记）

- **改后**：确认 `.gitignore` 已忽略 `.openfeel/users/` 与 `.openfeel/tmp/` → `dev_last/` **天然不入库**；`current_archive/`（公共域）**未被忽略** → 入库。
