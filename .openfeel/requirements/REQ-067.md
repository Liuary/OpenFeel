# REQ-067：guard wrapper 加固：脚本内容静态分类

> 本文件为需求正文（人读副本，由 openfeel req 机械铺骨架）。**机读权威恒为 `.openfeel/flow.json` 的 `requirements` 条目**；两者不一致时以 flow.json 为准。下方状态为创建时快照，不追写实时状态。

## 状态

draft（创建时快照；以 flow.json 为准）

## 摘要

v1.6.0 收口时为了写 6 份需求正文，用 `pwsh -File .ps1` 包装脚本调用官方 CLI，guard 因「不可判定」只 warn 放行 —— 同类 `.cmd`、`bash -c`、`node -e` 都能绕开 shell gate，等于 shell 写入门禁对包装执行形同虚设。

## 目标与验收

### 目标

封掉 guard 的 wrapper 绕过面：`pwsh -File`、`cmd /c`、`bash -c`、`node -e` 等包装执行时，静态读取脚本内容并按其内容分类（openfeel 写动词 / 受保护路径），不可判定也留审计。

### 验收

- A67.1 wrapper（`pwsh -File x.ps1`、`cmd /c x.cmd`、`bash -c "…"`、`node -e "…"`）内容命中 openfeel 写动词或受保护路径 → 按 class 1/2 拒绝并审计。
- A67.2 普通 wrapper（无 openfeel 写、无受保护路径）不受影响（回归用例）。
- A67.3 无法读取脚本内容时记 class 4 warn + 审计包含 `wrapper` 与目标路径。
- A67.4 新增 ≥6 条 guard 用例（.ps1/.cmd/bash -c/node -e/编码混淆/普通脚本）。
