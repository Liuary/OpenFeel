## 翻译纪律

1. **不翻译**：代码标识符、CLI 命令（如 `openfeel flow advance`）、文件路径（如 `.openfeel/flow.json`）、frontmatter 键、YAML 值中 `mode`/`model`/`color`/`permission` 的值
2. **必须翻译**：frontmatter `description` 字段值、正文全部内容、标题、表格表头
3. **思维语言切换**：feel.md 行为准则中的"以中文思维思考"→"think in English"；英文模板→英文思维
4. **术语一致**：全文统一使用术语表中的英文称谓；首次出现可附带中文注释如 `Orchestrator (总统领)`
5. **语义对等**：不添加/删除/改写原文语义，仅做语言转换

### Part D：build.js 多语言 Agent 注入

- [ ] D1. 修改 `build.js` 的 `generateAgentDefinitions()` 函数（当前约第 113 行）：
  - 当前：硬编码读取 `templates-data/agents/zh-CN/`，生成 `Record<string, Record<string, string>>` 仅含 `'zh-CN'` 键
  - 改为：迭代 `templates-data/agents/` 下的所有子目录（`onlyDirectories: true`），每个子目录作为一个语言键
  - 对每个语言目录，读取其中的 `.md` 文件，构建嵌套 Record
  - 示例结构：`{ 'zh-CN': {...}, 'en': {...} }`
  - 注意：使用 `readdirSync` 时需要 `{ withFileTypes: true }` 过滤目录
  - 参见 kb/troubleshooting.md #fast-glob 目录匹配需显式声明 onlyDirectories（此处用 `readdirSync` 的 `withFileTypes`）

- [ ] D2. 同时修改 `TEMPLATE_AGENTS_DIR` 常量（当前约第 27 行）：从 `resolve(TEMPLATES_DATA_DIR, 'agents', 'zh-CN')` 改为 `resolve(TEMPLATES_DATA_DIR, 'agents')`（指向语言目录的父目录）

- [ ] D3. [FIX] **REV-003**：修改 `validateAgentDefinitions()`（当前约第 426 行）适配多语言结构：
  - 当前：`extractTemplatePairs()` 从 `AGENT_TEMPLATES` 对象文本中匹配**最内层**的 `key: \`...\`` 模式，只能提取到 `zh-CN` 内层内容
  - 多语言化后数据结构为 `{ 'zh-CN': { archiver: ..., ... }, 'en': { archiver: ..., ... } }`
  - 修正步骤：
    1. 从 section 中提取顶层语言键（正则或 `matchBraces` + 手动解析）
    2. 对每个语言键，提取其内层对象文本
    3. 将内层对象文本传给 `extractTemplatePairs` 提取 Agent 条目
    4. 读取对应语言目录（如 `agents/en/`）下的源文件
    5. 逐语言调用 `compareTemplatePairs` 校验模板与源文件一致性
  - 若某语言目录不存在但模板中有该语言键 → 标记为错误
  - 若语言目录有 `.md` 但模板缺少 → 标记为错误（与现有逻辑一致）
