# AI_Prompt v3.0 发展方向研究

> Obsidian + Claudian + Hermes + 向量化记忆 + RAG —— 从工具型 Agent 到环境型 Agent 的范式跃迁

---

## 一、研究背景

AI_Prompt v2.0 已完成全部五个阶段的建设，成功构建了一套跨 AI 工具的 Agent 开发治理框架：三层约束体系、九大 Agent 角色、十四状态机、双轨（人工/自动）工作流、多工具适配器部署。项目在"AI Agent 该怎么做事"这个维度上已经形成了完整的解决方案。

然而，2025-2026 年间，AI Agent 生态发生了几个重要变化：

1. **记忆成为瓶颈**：Mem0（57.6k stars）等通用记忆层的爆发表明，Agent 的持久化、可检索记忆是当前最大的能力缺口
2. **知识管理工具与 AI 融合**：Obsidian 社区涌现出"Claudian"概念——将 Claude（Claude Code）深度嵌入 Obsidian 知识管理系统
3. **开源模型能力追平**：Nous Research 的 Hermes 系列模型在函数调用和结构化输出方面已达到可用水平，本地部署成为可行选项
4. **向量化检索成为标配**：RAG 从实验技术变为生产基础设施，语义检索 + 关键词 + 实体链接的混合检索成为主流方案

这些变化共同指向一个方向：**AI Agent 正从"你调用的工具"演变为"驻留在你工作环境中的智能伙伴"**。本报告分析这四股力量的含义，并提出 AI_Prompt 的 v3.0 发展方向。

---

## 二、四个概念深度解析

### 2.1 Obsidian：本地优先的知识管理基础设施

Obsidian 是一款基于本地 Markdown 文件的知识管理工具，截至 2026 年拥有数千万用户。其核心设计原则：

| 原则 | 说明 | 对 AI Agent 的启示 |
|------|------|-------------------|
| **数据属于你** | 所有数据存储在本地，开放格式，不被锁定 | AI 记忆不应绑定特定服务提供商 |
| **耐久性** | 纯文本 Markdown，可被任何工具读取，未来 50 年仍可访问 | AI 产出应优先使用开放格式 |
| **隐私** | 数据在本地设备，端到端加密 | AI 治理框架应支持完全本地运行 |
| **可塑性** | 500+ 社区插件，高度可定制 | AI 工作流应可扩展、可定制 |
| **独立** | 100% 用户支持，无投资者压力 | AI 治理标准应由社区驱动 |

Obsidian 的核心技术创新是**双向链接**（`[[wikilink]]`）和**知识图谱**——笔记之间形成可导航的语义网络，而非平面列表。这与 AI_Prompt 当前 `.ai/kb/` 的线性索引形成鲜明对比。

### 2.2 Claudian：AI 嵌入知识工作环境

"Claudian"是 Obsidian 社区中涌现的一个概念标签，特指**将 Claude（Claude Code）的能力深度嵌入 Obsidian 知识管理系统**。截至 2026 年 6 月，GitHub 上有 7 个使用 `claudian` 标签的公开项目，涵盖以下场景：

| 项目 | 场景 | 核心思路 |
|------|------|---------|
| `obsidian-ai-second-brain` | 个人知识库搭建 | 基于 Karpathy LLM Wiki 方法论，用 Claude 自动化知识整理 |
| `local-domain-expert-vault` | 学术研究 | Obsidian + Zotero + Claude，本地领域专家知识库 |
| `obsidian-llm-wiki` | 审阅门控研究 Wiki | Claude 辅助论文审阅和知识抽取 |
| `leah` | 双语知识库模板 | 中英文 Obsidian vault 模板，Claude 友好的规则和提示词 |
| `claudian` (插件) | IDE 集成 | 将 AI 编码 Agent 嵌入 Obsidian 侧边栏 |

**Claudian 的核心思想**：AI 不应该只是"你打开终端调用一下"的工具，而应该**驻留在你的知识工作环境中**——理解你的笔记结构、知道你的知识图谱、在你的 vault 中读写 Markdown 文件。这是一种"环境型 Agent"的理念。

对 AI_Prompt 的启示：当前 AI_Prompt 的治理体系部署在项目目录中，Agent 通过读写 `.ai/` 下的 Markdown 文件来维持状态。这天然兼容 Obsidian 的 vault 架构——`.ai/` 工作区本身就是一个结构化的 Markdown 知识库，可以被 Obsidian 打开、浏览、双向链接。

### 2.3 Hermes：开源本地模型的能力突围

Hermes 是 Nous Research 发布的开源大语言模型系列，专为**函数调用（Function Calling）和结构化输出（JSON Mode）**而训练：

| 版本 | 基座模型 | 核心能力 | 意义 |
|------|---------|---------|------|
| Hermes-2-Pro | Llama-3-8B | 函数调用、ChatML 格式 | 首个达到实用水平的开源函数调用模型 |
| Hermes-3 | Llama-3.1-70B | GOAP 推理框架、工具使用 | 引入结构化推理（Scratchpad），提升多步规划能力 |

Hermes 的关键技术特征：
- **ChatML 提示词格式**：结构化的多轮对话格式，支持 system/user/assistant/tool 四种角色
- **Function Calling 原生支持**：通过 `<tool_call>` XML 标签生成结构化函数调用，而非自然语言描述
- **JSON Mode / Structured Outputs**：严格按照提供的 JSON Schema 生成输出
- **Scratchpad 推理**（Hermes-3）：Goal → Actions → Observation → Reflection 的结构化推理链

对 AI_Prompt 的启示：
1. **模型后端解耦**：当前 Agent 角色定义绑定特定工具（Kilo/Claude Code）的模型后端。未来应支持配置不同的 LLM 后端，包括本地 Hermes 模型
2. **Function Calling 标准化**：AI_Prompt 的 Agent 角色定义可以与 Hermes 的 function calling 格式对齐，让 Agent 角色成为可被任何兼容模型"加载"的技能定义
3. **隐私项目支持**：金融、医疗等敏感行业可以在完全本地环境下运行 AI_Prompt + Hermes，数据不出设备

### 2.4 向量化记忆 + RAG：Agent 记忆的工程化

Mem0 是这个领域的典型代表（57.6k stars，Y Combinator S24 项目），它定义了 AI Agent 的通用记忆层：

**Mem0 的架构层次**：
```
┌────────────────────────────────────────┐
│          AI Agent / 应用层              │
│  (ChatGPT、客服机器人、个人助手...)      │
├────────────────────────────────────────┤
│           Mem0 记忆层                   │
│  ┌──────────────────────────────────┐  │
│  │  多级记忆 (User/Session/Agent)    │  │
│  ├──────────────────────────────────┤  │
│  │  混合检索 (语义+BM25+实体链接)     │  │
│  ├──────────────────────────────────┤  │
│  │  时间推理 (Temporal Reasoning)    │  │
│  ├──────────────────────────────────┤  │
│  │  ADD-only 增量写入 (不覆盖)        │  │
│  └──────────────────────────────────┘  │
├────────────────────────────────────────┤
│           向量数据库 / 嵌入模型          │
└────────────────────────────────────────┘
```

**2026 年 4 月新算法的关键突破**：

| 基准 | 旧算法 | 新算法 | 提升 |
|------|--------|--------|------|
| LoCoMo | 71.4 | **91.6** | +20.2 |
| LongMemEval | 67.8 | **94.8** | +27.0 |
| BEAM (1M tokens) | — | **64.1** | 新增 |

核心技术变化：
- **ADD-only 提取**：单次 LLM 调用，只增不改不删，记忆累积而非覆盖
- **Agent 生成事实一等公民**：Agent 确认的操作结果与用户输入同等权重存储
- **实体链接**：实体被提取、嵌入并在多条记忆间链接，用于检索增强
- **多信号融合检索**：语义 + BM25 关键词 + 实体匹配并行打分后融合

**对 AI_Prompt 的关键启示**：
- 当前 `.ai/kb/` 的文件系统记忆方案是可靠的 single source of truth，但检索效率低（grep/文件名匹配）
- 可增加**可选的向量化索引层**：文件系统仍是主存储，向量索引是加速检索的缓存，可随时从 Markdown 文件重建
- Agent 生成的操作结果（状态变更、决策记录、审查结论）应被索引为与用户输入同等权重的一等记忆

## 三、概念间的内在联系

这四个概念并非孤立，它们共同描绘了 AI Agent 的下一个演进方向：

```
                     ┌─────────────────────────┐
                     │     AI 驻留环境           │
                     │                         │
  ┌──────────┐       │  ┌──────────┐           │
  │ Obsidian │───────┼──│ VS Code  │           │
  │ 知识管理  │  双向  │  │  编码    │           │
  └────┬─────┘  链接  │  └────┬─────┘           │
       │               │       │                 │
       │    ┌──────────┴───────┴─────┐           │
       │    │   AI_Prompt 治理层      │           │
       │    │  (约束/角色/状态机)      │ ← 当前    │
       │    └──────────┬─────────────┘           │
       │               │                         │
       │    ┌──────────┼──────────┐              │
       │    ▼          ▼          ▼              │
       │ ┌──────┐ ┌────────┐ ┌────────┐         │
       └─│ 向量 │ │ 知识   │ │ 本地   │         │
         │ 记忆 │ │ 图谱   │ │ 模型   │         │
         └──────┘ └────────┘ └────────┘         │
              ▲          ▲          ▲           │
              │          │          │           │
         Mem0/RAG   Obsidian   Hermes          │
              │      wikilink   Ollama          │
              └──────────┼──────────┘           │
                         │                      │
                    "环境型 Agent"               │
                    新范式                       │
                     └─────────────────────────┘
```

### 3.1 从"工具型 Agent"到"环境型 Agent"

| 维度 | 工具型 Agent（当前） | 环境型 Agent（未来） |
|------|---------------------|---------------------|
| **触发方式** | 用户主动调用 CLI/IDE | 驻留在工作环境中，主动感知上下文 |
| **记忆方式** | 文件系统线性索引 | 向量化 + 知识图谱混合检索 |
| **知识组织** | 分类目录 + 文件名 | 双向链接 + 语义网络 |
| **模型选择** | 绑定特定工具/API | 多后端可配置（云端/本地） |
| **用户界面** | 终端/对话框 | 嵌入知识管理工具（Obsidian/VS Code） |
| **数据主权** | 依赖工具提供商 | 本地优先，开放格式 |

### 3.2 AI_Prompt 在这个图景中的位置

AI_Prompt 的独特价值在于它不只是一个"Agent 框架"或"记忆库"，而是一个**治理层**——它定义 Agent 怎么做事。在环境型 Agent 的新范式中，治理层的位置更加关键：

- **向下**：对接记忆层（向量化检索、知识图谱）和模型层（多后端）
- **向上**：对接用户环境（Obsidian、VS Code、终端）
- **核心**：保持三层约束体系、状态机、审查闭环等治理能力不变

AI_Prompt 有机会成为连接"能力基础设施"（Mem0/Hermes）和"工作环境"（Obsidian/VS Code）的**治理中间件**。

## 四、AI_Prompt v3.0 发展方向

基于以上分析，提出四个新阶段，按优先级排序：

### 阶段六：向量化知识库（优先级：🥇 最高）

**目标**：在现有 `.ai/kb/` 文件系统基础上增加可选的语义检索层

**核心原则**：文件系统是 single source of truth，向量索引是加速缓存层，可随时从 MD 文件重建

**具体内容**：
- **轻量级嵌入索引**：使用本地嵌入模型（如 bge-small）对 `.ai/kb/*.md` 中的所有条目生成向量索引，存储在 `.ai/tmp/vectors/`（不纳入版本管理）
- **会话启动自动更新**：每次 Agent 会话启动时，对比文件哈希判断是否需要增量重建索引
- **混合检索接口**：语义相似度 + 文件名/标题精确匹配 + 最近更新时间衰减，融合打分
- **可选依赖**：向量化能力作为可选增强，不影响不安装依赖的基础使用

**对标参考**：Mem0 的 ADD-only 增量写入、多信号融合检索

**验证方式**：在已有知识库的项目中部署向量化索引，对比 Agent 使用前后检索相关知识库条目的速度（时间）和覆盖率（语义匹配命中数 vs grep 命中数）

---

### 阶段七：知识图谱化记忆（优先级：🥈 高）

**目标**：让知识条目之间形成可遍历的关联网络，受 Obsidian 双向链接启发

**具体内容**：
- **Wikilink 支持**：在 `.ai/kb/` 的所有 Markdown 文件中引入 `[[条目名]]` 式双向引用
- **自动关联建议**：Agent 在写入知识库条目时，自动分析已有条目，建议可能的链接
- **图谱遍历检索**：当 Agent 查询某个知识条目时，不仅能返回该条目，还能沿链接图返回一度/二度关联条目
- **知识图谱可视化**（远期）：可选的 Mermaid/Graphviz 导出，在 Obsidian 中可视化

**验证方式**：在 `.ai/kb/` 中创建 5+ 个相互有关联的知识条目，Agent 查询时能够沿链接图返回相关条目，准确率 > 80%

---

### 阶段八：多模型后端解耦（优先级：🥉 中高）

**目标**：将 Agent 能力描述与具体模型后端解耦，支持云端 API 和本地模型

**具体内容**：
- **模型配置文件**：`.ai/config.yaml` 中增加 `model` 配置节，支持 `provider`（openai/anthropic/ollama）、`model_name`、`base_url`
- **Agent 角色标准化**：将 Agent 角色定义从工具特定格式（`.kilo/agents/`、`adapters/claude-code/`）中提取出工具无关的核心描述，存储在 `.ai/agents/` 下
- **Function Calling 对齐**：Agent 的工具调用格式对齐 OpenAI/Hermes function calling 标准
- **Hermes 本地支持**：提供 Hermes 模型的 Ollama 部署配置模板，验证 Agent 角色在本地 Hermes 模型上的可用性

**验证方式**：在同一项目中分别使用云端 API（Claude）和本地模型（Hermes via Ollama）运行同一个 Agent 角色，对比输出质量和一致性

---

### 阶段九：AI 驻留能力 — Claudian 方向（优先级：🏅 持续）

**目标**：让 AI_Prompt 治理体系不仅存在于项目目录，而是嵌入开发者日常工具

**具体内容**：
- **Obsidian 集成**：
  - 将 `.ai/` 工作区映射为 Obsidian vault，知识库条目之间自动形成双向链接图
  - Agent 可以直接在 Obsidian 中创建/编辑知识库条目
  - 利用 Obsidian 的 Dataview 插件生成计划仪表盘（状态总览、审查条目、Bug 列表）
- **VS Code 深度集成**：
  - 侧边栏面板实时显示当前计划状态、审查条目数量、Bug 数量
  - CLI 工具补充：`ai-status`、`ai-review`、`ai-bugs`、`ai-log`
- **统一入口**：无论通过 Obsidian、VS Code 还是 CLI 调用 AI，都遵循同一套约束和记忆体系

**验证方式**：在本地 Obsidian vault 中打开 `.ai/` 目录，验证双向链接自动生成、Agent 可读写知识库条目、Dataview 仪表盘正常显示

## 六、风险与机遇

### 6.1 机遇

| 机遇 | 说明 | 时间窗口 |
|------|------|---------|
| **记忆层标准化空白** | 尚无 AI Agent 记忆的开放标准，AI_Prompt 有机会定义 `.ai/kb/` + 向量索引的标准格式 | 2026-2027 |
| **Obsidian 生态增长** | Obsidian 用户基数持续增长，Claudian 概念刚刚萌芽，AI_Prompt 可成为连接 AI 治理与知识管理的桥梁 | 2026 Q3-Q4 |
| **本地模型拐点** | Hermes-3 + Ollama 的组合已可满足 Agent 函数调用需求，隐私敏感行业的需求即将爆发 | 2027+ |
| **GitHub 正定义 AGENTS.md** | GitHub Copilot 官方支持 AGENTS.md，AI_Prompt 作为最早系统化该格式的项目，有机会参与标准制定 | 现在 |

### 6.2 风险

| 风险 | 说明 | 应对 |
|------|------|------|
| **复杂度膨胀** | 新增向量索引、知识图谱、多模型支持可能使部署和维护变复杂 | 保持"可选依赖"原则，核心功能不依赖额外组件 |
| **工具厂商自建** | Obsidian/VS Code 可能自建类似的治理体系 | 保持跨工具兼容的优势，不与单一工具深度绑定 |
| **本地模型质量** | Hermes 等模型在复杂任务上的能力与 Claude/GPT 仍有差距 | 阶段八定位为"可选支持"，不替代现有 API 方案 |
| **维护成本** | 四个新阶段带来持续的格式适配和依赖管理成本 | 采用适配器模式，核心与适配层解耦 |

## 七、核心理念延续

v3.0 不改变 AI_Prompt 的以下核心理念：

1. **约束优先于赋能**：向量化记忆和知识图谱是"让 Agent 更高效地找到约束"，而非"给 Agent 更多能力"
2. **文件系统是 single source of truth**：向量索引永远可从 Markdown 文件重建，不存在"索引与源文件不一致"的状态
3. **人工控制点不丢失**：记忆检索和知识图谱是辅助决策，最终审批仍保留在人工流程中
4. **声明式优于程序式**：新增的配置（模型后端、索引参数）以 YAML/Markdown 声明式文件驱动

---

## 八、结论

AI_Prompt 的 v3.0 方向可以概括为：**从"治理 Agent 行为"扩展到"治理 Agent 的记忆与知识"**——在保持约束体系、角色分工、状态机等治理能力的同时，为 Agent 引入更高效的记忆检索（向量化）、更结构化的知识组织（知识图谱）、更多样的运行环境（本地模型）和更自然的驻留方式（Obsidian/VS Code 集成）。

这四个方向——Obsidian 的双向链接、Claudian 的环境驻留、Hermes 的本地能力、Mem0 的向量化记忆——共同指向一个愿景：**AI Agent 不再是需要被"管理"的外部工具，而是可以被"治理"的工作环境的一部分**。
