## 关键设计决策

1. **REV-907 测试边界**：会话启动修复**只做** `resolveUpdateInfo` / `loadUpdateInfos` / `clearUpdateInfos` 函数单测 + feel.md/core-instructions **模板静态断言**（读源文件断言含关键文案），**不做行为级 E2E**（不模拟 Feel 启动→读→修复→重启全链路），记录为已知覆盖空白（Feel 启动行为由 op-003 模板语义保证，不在单测范围）。注意 REV-1003：`resolveUpdateInfo`/`clearUpdateInfos` 函数保留但 feel.md **不调用**（Feel 不能 import TS），函数单测仅覆盖函数 API 本身；模板断言须断言 feel.md 用 **edit 工具勾选（`- [ ]` → `- [x]`）措辞、不含 `resolveUpdateInfo`/`clearUpdateInfos` 调用**。
2. **conflicts 恒空语义**：三态下「无标记 + hash 不匹配」从 conflicts 改为 appended，`writeConflictFile`/`markFileConflict` 保留但本阶段不触发。现有 `update.test.ts` 的冲突用例**改为追加断言**，并新增「conflicts 恒空」断言。
3. **REV-911 全量追加**：构造「全局 state 文件损坏（写非法 JSON）/ 不存在」场景，断言存量全局文件走「追加不覆盖」（`appended` 增加、目标文件内容保留用户区、update_infos.md 写入大量条目），并断言命令层对 `n > 10` 输出警告（`vi.spyOn(console, 'warn')`）。
4. **mock homedir**：所有涉及全局路径的测试用 `vi.hoisted` + `vi.mock('node:os', ...)`（stage-37 op-005 先例），`beforeEach` 设临时 HOME，`afterEach` 清理。

## 实施步骤

### 步骤 1：新建 `test/core/update-infos.test.ts`

- 顶部 `vi.hoisted` + `vi.mock('node:os', ...)` 指向临时 HOME（复用 stage-37 op-005 范式），确保 `getGlobalUpdateInfosPath()` 落在临时目录。
- 用例：
  - `loadUpdateInfos()` 文件不存在 → `[]`。
  - `appendUpdateInfo('appended', { absolutePath })` → 文件创建、含「追加」节条目、`resolved=false`；再次 `loadUpdateInfos` 回读该条目字段一致（kind/absolutePath/timestamp/resolved）。
  - `appendUpdateInfo('appended', { projectRoot, relativePath })` → 条目 display 为 `相对路径 (项目: 根)`；回读还原 `projectRoot`/`relativePath`（REV-903 二元组）。
  - `appendUpdateInfo('anomaly', ...)` → 落「异常」节，kind=anomaly。
  - `resolveUpdateInfo({ absolutePath })` → 匹配条目 `resolved` 变 true（`- [ ]` → `- [x]`）；不匹配 target 不报错、无变化。
  - `clearUpdateInfos()` → 文件内容为仅含骨架（无条目行）。
  - 损坏文件（写非法内容）→ `loadUpdateInfos()` 返回 `[]` 且 `vi.spyOn(console, 'warn')` 被调用（降级不抛错）。
  - 并发追加：`Promise.all` 多次 `appendUpdateInfo` 后条目数等于追加次数、文件未损坏（复用 stage-35 并发测试范式，可选）。

### 步骤 2：`test/core/update.test.ts` 扩展（三态 + appended + 幂等 + 区外保留）

- 顶部补 mock homedir（若 op-005 尚未覆盖则补，避免 `recordProjectLang` 等污染真实全局）。
- 新增/改造用例：
  - **created**：首次 `updateProject` 后全局 agents/skills/core.md 文件含 `<!-- openfeel:begin -->` 与 `<!-- openfeel:end -->`（标记包裹），结果 `created` 含对应路径。
  - **含标记 updated + 区外保留**：预置一个含标记的全局 agent 文件，在标记区**外**追加用户自定义内容 + 在标记区**内**篡改框架内容 → `updateProject` 后断言：区内内容恢复为框架模板、区外用户内容**逐字符保留**、结果 `updated`。
  - **含标记 skipped（REV-901）**：区内内容与 incoming 一致 → 结果 `skipped`、文件 mtime/内容不变。
  - **无标记 + hash 匹配 → adopt**：预置无标记文件且其 hash 记录在 state（`status: clean`）→ `updateProject` 后文件被替换为带标记的新框架内容、结果 `updated`（adopt 记 updated）。
  - **无标记 + hash 不匹配 → 追加**：预置无标记文件、state hash 与其不符 → `updateProject` 后文件末尾追加受管区、结果 `appended`、`update_infos.md` 写入 kind=appended 条目、**原文用户内容不变**。
  - **无标记 + 无 state 记录 → 追加**：state 无该文件记录 → 同上追加。
   - **malformed → anomaly（REV-1001 修订）**：预置含两对 begin/end 的文件 → `updateProject` 后**不写盘、不追加**，`update_infos.md` 写 kind=anomaly 条目，结果 `skipped`、文件内容不变。
   - **幂等（N2）**：追加后再跑一次 `updateProject` → 不再重复追加（`appended` 为空、文件无第二个标记区）。
   - **malformed 二次 update 幂等（REV-1001 新增）**：对同一 malformed 文件连续跑两次 `updateProject` → 两次均不写盘（文件内容两次都逐字符不变）、不追加标记区，仅 update_infos.md 各记一条 anomaly 条目；手动将标记修复为单对完整标记后，第三次 `updateProject` 走「含标记 updated/skipped」正常路径（不再记 anomaly）。
  - **conflicts 恒空**：原冲突用例改为断言 `result.conflicts.length === 0`、`result.appended` 非空。
  - **REV-911 全量追加**：构造全局 state 损坏（写非法 JSON）→ `updateProject` 后存量全局文件走追加（`appended` 大量增加）、不覆盖用户内容。
  - **frontmatter 合并**：预置 agent 文件 frontmatter 含用户自定义字段（如 `model: x`）→ update 后框架字段（description/mode 等）覆盖、用户字段保留。
  - **AGENTS.md 项目 state**：追加场景断言 AGENTS.md 条目落 `update_infos.md` 为「项目根 + 相对路径」二元组；hash 落**项目** `state` 而非全局 state。
