## 必查项（六维度）

1. **正确性**：`build.js` **幂等性**与产物确定性（`npm run build` 重跑零 diff）；各步骤（1~8）与断言段（`validateSkillDefinitions`/`validateOpencodeSkillDefinitions`/agents-md 校验/单源一致性）覆盖完整。
2. **一致性**：`ci.yml` 步骤充分性（版本门禁 ×2 job、`lint i18n`、**环境守卫覆盖窗口**——REV-48 REV-009① 指出 `version guard`/`lint i18n` 两 step 在 snapshot→guard 窗口**之外**，实测只读无风险，属**可选增强**）；`package.json` `files` 与 `npm pack` 实际内容一致。
3. **文档-实现对齐**：`engines`/`bin` 与 `README` 声明一致；`scripts` 与 CI 使用一致。
4. **边界与健壮性**：`node bin/openfeel.js` 各命令可执行性（`--help`/`--version`）；非 UTF-8/GBK 文件（`.openfeel/config.yaml`）在 build 中不被整文件重写；build 失败时的半成品状态（是否可重跑收敛）。
5. **安全面**：publish 链路（`NODE_AUTH_TOKEN`、`registry`、`if: changed` 条件）无死配置/无凭据泄漏；`files` 是否漏带运行必需文件或误带敏感文件。
6. **过度设计 / 依赖**：依赖与 `package-lock` 一致性（含**既有 1.0.7 漂移**——stage-43/47 已裁定「手工同步 root version 两行」）；`dependencies` 是否均为运行必需；**`src/index.ts:10 export const VERSION = '0.1.0'`**（U2 转来）与 `package.json.version`(1.1.2) 漂移且全仓零引用 → 判定「死导出/应删或应同步」，给结论与归属。
