# 代码审查可信度规范（core/code-review）

> 模块文档，规定 REV 审查记录的可信度与独立复核规范。对应实践：`REV-v1.1.2-stage-44/45/46` 的可信度声明、v1.1.2-stage-48 事件 A 加固。

## 职责

规定 REV 审查记录（`.openfeel/users/{username}/code_review/REV-*.md`）在**审查会话工具异常 / 结论与实测冲突 / 会话被判定可疑**时的可信度处置与独立复核要求，保证审计链可追溯、结论可复现。

## 可信度声明写法

当某份 REV 文件的写入会话被判定可疑（或结论不可采信）时，**保留原文不删**，在文件顶部（或相关条目处）追加「可信度声明」：

> 本文件由 {会话描述} 于 {时间} 写入；{后续会话} 不采信原验收文字，对全部实体断言**独立取证**（命令 + 版本 + 环境见下）。

原则：

1. **保留原文不删**，仅**追加**声明与独立复核记录（与「不回改历史归档」一致）。
2. 独立复核须给出**可复现三要素**：命令 + 版本（`node -v` / 仓库 commit / `opencode --version`）+ 环境（隔离 HOME 与否）。
3. 复核结论与被复核条目的分歧须显式并列，**不得覆盖原文**。

## 可疑会话产出的处置（REV-48-005）

判定可疑的会话，其已写出的 **REV 条目 / 验收记录自动降级为「待复核」**：

- **不得**被后续会话或 Feel 直接引用推进流水线；
- 须由新会话**独立复核关键结论后**，方可据此推进；
- 复核通过后追加「可信度声明」并记录复核命令与结果。

## 取证纪律

- **命令行优先**：关键事实（文件内容、行号、计数、状态）以 `rg` / `Get-Content` / `node -e` 实测为唯一权威；与 `read` / `glob` 冲突时以命令行为准。
- **工具异常即中止**：工具调用异常（结果缺失 / 重放 / 乱码 / 路径漂移）时立即中止本轮，如实报告，**不得臆造、续写或补全结论**。
- **可复现三要素**：命令 + 版本 + 环境；无法复现的结论标注「未确证」。
