## 变更目标

把 `src/core/**` 与 `src/commands/**` 中**注释 / 帮助文案 / 日志文案 / 错误文案**里「opencode 是唯一 harness」的表述泛化为「当前 harness / 平台适配器」；opencode 具体路径仅在适配器实现语境保留并**显式标注**。**零行为变更**（路径解析逻辑、常量值、控制流一律不动）。

**需求映射**：用户指令「检查所有强限定平台的内容，并更新为无平台限制的描述」；`plan.md §一/§三 op-001`。

> 参见 kb/patterns.md #约束/操作分离模式、#i18n 键对称性校验模式；kb/troubleshooting.md #opencode 模型解析优先级排查（适配器细节须保留准确）。

## 泛化词典（全阶段统一，op-002/003/004 沿用）

| 原表述 | 泛化后表述 |
|--------|-----------|
| 全局 opencode 配置目录 / `~/.config/opencode` | 全局配置目录（**opencode 适配器**：`~/.config/opencode`） |
| `opencode.jsonc`（作为框架部署产物） | 平台适配器配置文件（当前：`opencode.jsonc`） |
| 重启 opencode | 重启当前 harness（opencode） |
| 目前仅支持 opencode / 唯一 harness | 当前默认适配 opencode；框架面向多 harness 适配（其余适配器预留） |
| 模块级 opencode 路径/字段密集处 | 在**模块头注释**加标注：「本模块属 **opencode 适配器实现**；下文 `opencode` / `opencode.jsonc` / `~/.config/opencode` 均为该适配器细节」 |

**判定原则**：若文字在**断言「平台就是 opencode」**（描述性/用户可见）→ 泛化；若文字在**说明 opencode 这个东西的具体用法/路径**（实现细节）→ **保留 + 标注**。
